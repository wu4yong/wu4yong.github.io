    mysql-14-内置函数

    📅 2022-11-24

    内置函数：字符串、日期与 JSON

    函数用得越顺手，越容易在 WHERE 里把索引包死——先看函数，再看它能不能下推｜依据 MySQL 8.4 Functions 章节自绘

    一、学习目标

    1. 掌握字符串处理最常用的八个函数，分清 LENGTH 与 CHAR_LENGTH；
    2. 把日期计算从「Java 里算完再传参」改成「SQL 里用可走索引的区间条件」；
    3. 会用 JSON 函数读写与展开，并知道什么时候该给函数建索引。

    二、前置知识

    类型与单表查询。知道函数包住索引列会让索引失效即可。

    三、理论讲解（官方定义）

    MySQL 内置函数按族分：字符串、数值、日期时间、JSON、聚合、窗口、信息函数（VERSION()、DATABASE()、LAST_INSERT_ID()）。它们都是逐行求值的标量函数，因此出现在 WHERE 里时，能否走索引取决于是否作用在列上。

    官方要点：

    • LENGTH() 返回字节数，CHAR_LENGTH() 返回字符数，utf8mb4 下「中文」是 6 与 2；
    • 日期函数受会话时区影响：NOW() 取会话时区，UTC_TIMESTAMP() 取 UTC；
    • JSON 有 ->（等价 JSON_EXTRACT）与 ->>（抽出并去引号）两种取值运算符；
    • 8.0.13 起支持函数索引，把「对列用函数」的查询变成可索引。

    四、原理拆解

    函数本身很快，问题在于它出现在索引列上时会让 B+Tree 失去有序性｜依据 MySQL 8.4 Functions 与索引章节自绘

    1. 字符串：八个够用的函数

    函数 用途 注意
    CONCAT / CONCAT_WS 拼接 / 带分隔符拼接 任一参数为 NULL，CONCAT 返回 NULL
    SUBSTRING_INDEX 按分隔符取第 N 段 解析 URL、路径最常用
    GROUP_CONCAT 分组内拼接 默认 1024 字节上限
    LPAD / RPAD 左/右补位 生成定长编码
    TRIM 去首尾空格 中间空格要用 REPLACE
    REPLACE 字符串替换 不支持正则
    REGEXP_REPLACE / REGEXP_LIKE 正则替换 / 匹配 8.0 起可用，无法走索引
    LEFT / RIGHT / LOCATE 截取 / 定位 与 SUBSTRING 配合

    CONCAT 的 NULL 传染是最常见的坑：CONCAT('a', NULL) 得 NULL，而 CONCAT_WS 会跳过 NULL。

    2. 日期：把计算放回 SQL，但别包住列

    -- 错：列被函数包住，索引失效
WHERE DATE(created_at) = '2022-11-24';
-- 对：改写为半开区间
WHERE created_at >= '2022-11-24' AND created_at < '2022-11-25';

    常用函数：

    • DATE_FORMAT(d, '%Y-%m-%d')：格式化，展示用；
    • STR_TO_DATE('2022-11-24', '%Y-%m-%d')：字符串转日期；
    • DATE_ADD(d, INTERVAL 1 DAY) / DATE_SUB：日期加减；
    • TIMESTAMPDIFF(MINUTE, a, b)：跨单位差值；
    • DATEDIFF(a, b)：只算日期差；
    • LAST_DAY(d)：当月最后一天，做月报边界；
    • UNIX_TIMESTAMP / FROM_UNIXTIME：与秒级时间戳互转。

    3. JSON：取值、改写、展开

    SELECT payload->>'$.user_id'            AS uid,        -- 取值并去引号
       JSON_EXTRACT(payload, '$.tags')  AS tags,        -- 取子文档
       JSON_UNQUOTE(payload->'$.city')  AS city
FROM t_event;

UPDATE t_event SET payload = JSON_SET(payload, '$.vip', true) WHERE id = 1;
SELECT jt.tag FROM t_event, JSON_TABLE(payload, '$.tags[*]' COLUMNS (tag VARCHAR(32) PATH '$')) AS jt;

    JSON_SET 改已存在的键、JSON_INSERT 只加不覆盖、JSON_REPLACE 只改不新增；判断包含用 JSON_CONTAINS，重叠判断用 JSON_OVERLAPS。

    4. 让函数查询也能走索引

    -- 方案一：函数索引（8.0.13+）
ALTER TABLE t_order ADD KEY idx_created_day ((DATE(created_at)));

-- 方案二：生成列 + 普通索引（更通用，也更易读）
ALTER TABLE t_order ADD COLUMN created_day DATE
  GENERATED ALWAYS AS (DATE(created_at)) STORED, ADD KEY idx_day (created_day);

    函数索引适合「查询形态固定」的场景；生成列还能被其他查询复用，团队里更推荐后者。

    五、场景说明

    1. 手机号脱敏：CONCAT(LEFT(phone,3),'****',RIGHT(phone,4))；
    2. 拆标签：SUBSTRING_INDEX(tags, ',', 1) 取第一个标签；
    3. 按月报表：DATE_FORMAT(created_at,'%Y-%m') 展示，过滤仍用区间；
    4. 保留 N 天数据：WHERE created_at < DATE_SUB(NOW(), INTERVAL 30 DAY)；
    5. JSON 扩展字段读取：payload->>'$.order_id'；
    6. JSON 数组展开成行：JSON_TABLE。

    六、示例代码/实操步骤

    1. 字符串常用组合

    SELECT CONCAT_WS('-', '2022', '11', '24')                     AS d,        -- 2022-11-24
       SUBSTRING_INDEX('a.b.c', '.', -1)                      AS last_seg, -- c
       LPAD('7', 4, '0')                                       AS code,     -- 0007
       CHAR_LENGTH('中文')                                     AS chars,    -- 2
       LENGTH('中文')                                          AS bytes;    -- 6

    2. 日期区间与格式化

    SELECT NOW(), UTC_TIMESTAMP(), @@session.time_zone;
SELECT DATE_FORMAT(created_at, '%Y-%m-%d %H:%i') AS t,
       TIMESTAMPDIFF(MINUTE, created_at, NOW())  AS mins_ago
FROM t_order WHERE created_at >= CURDATE() ORDER BY id DESC LIMIT 5;

SELECT LAST_DAY('2022-11-24') AS month_end;   -- 2022-11-30

    3. JSON 读写与展开

    UPDATE t_event SET payload = JSON_SET(payload, '$.vip', true, '$.level', 3) WHERE id = 1;
SELECT JSON_CONTAINS(payload->'$.tags', '"mysql"') FROM t_event WHERE id = 1;
SELECT e.id, jt.tag
FROM t_event e, JSON_TABLE(e.payload, '$.tags[*]' COLUMNS (tag VARCHAR(32) PATH '$')) jt
WHERE jt.tag = 'mysql';

    4. 验证函数索引是否生效

    EXPLAIN SELECT * FROM t_order WHERE DATE(created_at) = '2022-11-24';
-- 建函数索引后，key 列应显示 idx_created_day

    Java 侧怎么落地：该在 SQL 算还是在应用算

    1. 展示格式化放应用层：DATE_FORMAT 只影响可读性，交给 DateTimeFormatter 更灵活，SQL 保持返回原始时间；
    2. 时间边界一定在 SQL 侧用区间，Java 传 LocalDateTime 参数，避免拼接字符串；
    3. GROUP_CONCAT 结果长度：默认 1024 字节，超长会静默截断，必要时 SET SESSION group_concat_max_len = 8192；
    4. JSON 字段用 Jackson 序列化后再写，避免手工拼 JSON_OBJECT 时引号转义出错；
    5. 别把业务规则写进 SQL 函数：脱敏、编码这类逻辑放应用层，SQL 里只留过滤与聚合，方便测试与复用。

    七、常见坑

    1. WHERE DATE(col) = ...：索引失效，改区间或函数索引；
    2. LENGTH 当字符数用：utf8mb4 下差 3 倍；
    3. CONCAT 遇 NULL 全变 NULL：用 CONCAT_WS 或 IFNULL；
    4. GROUP_CONCAT 截断：默认 1024 字节；
    5. NOW() 与 UTC_TIMESTAMP() 混用：跨时区统计错位；
    6. REGEXP 查询：全表扫描，且无法走索引；
    7. JSON 直接比较大小：类型与格式不一致时结果反直觉，比较前先 CAST。

    八、版本差异

    • 5.7：无 REGEXP_REPLACE、无函数索引、JSON 支持有限；
    • 8.0：新增 REGEXP_* 系列、JSON_TABLE、函数索引（8.0.13）、JSON_VALUE（8.0.21）；
    • 8.4：函数集延续 8.0，无破坏性变更；utf8mb3 弃用影响 CONVERT(... USING utf8) 这类写法。

    九、课后小结

    • LENGTH 是字节，CHAR_LENGTH 是字符；
    • 日期过滤用半开区间，别把函数套在索引列上；
    • JSON 取值用 ->>，展开用 JSON_TABLE，修改用 JSON_SET；
    • 必须对列用函数时，建生成列或函数索引；
    • 展示格式化放应用层，SQL 只做过滤与聚合。

    十、思考题

    1. LENGTH('中文') 与 CHAR_LENGTH('中文') 分别返回什么，为什么？

      参考回答：返回 6 和 2。utf8mb4 下每个汉字占 3 字节，LENGTH 统计字节数，CHAR_LENGTH 统计字符数。

    2. 为什么 WHERE DATE(created_at) = '2022-11-24' 用不上索引，怎么改？

      参考回答：函数作用在索引列上，B+Tree 的有序性无法用于比较，只能逐行求值。改成 created_at >= '2022-11-24' AND created_at < '2022-11-25' 即可走范围扫描；也可建 (DATE(created_at)) 函数索引。

    3. CONCAT('a', NULL) 与 CONCAT_WS('-', 'a', NULL) 的结果差别？

      参考回答：前者返回 NULL（任参数为 NULL 则整体为 NULL）；后者跳过 NULL，返回 a。

    4. JSON 字段要按某个键过滤，怎么让它走索引？

      参考回答：把该键抽成 STORED 生成列（如 payload->>'$.user_id'），在生成列上建索引，查询时直接比较生成列。

    5. GROUP_CONCAT 拼接出来的列表少了几条，可能是什么原因？

      参考回答：group_concat_max_len 默认 1024 字节，超长会被静默截断；另外 GROUP_CONCAT 会跳过 NULL 值，也可能造成条数变少。
