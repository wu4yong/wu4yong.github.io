    Spring Data（二）JPA 实体映射与关联

    📅 2022-08-28

    JPA 实体映射与关联关系

    实体映射是 JPA 里最容易”看起来跑通了、实际有坑”的部分：主键策略选错导致批量插入慢、ManyToOne 默认 EAGER 导致 N+1、双向关联忘了 mappedBy 导致多出一张中间表。这一篇把常用映射与坑位过一遍。

    实体字段映射到表结构，关联关系用外键连起来

    1.1 基础注解

    @Entity
@Table(name = "tb_user", indexes = @Index(name = "idx_username", columnList = "username"))
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "user_name", length = 32, nullable = false, unique = true)
    private String username;

    @Transient                       // 不映射到表
    private String tempToken;

    @Enumerated(EnumType.STRING)     // 存字符串，别用 ORDINAL
    private UserStatus status;

    @Version                         // 乐观锁
    private Integer version;
}
    注解
    作用
    注意
    @Entity
    声明为实体
    必须有无参构造
    @Table
    表名/索引
    不写则用类名（驼峰转下划线）
    @Id
    主键
    必须有
    @GeneratedValue
    主键生成策略
    见 1.2
    @Column
    列名/长度/唯一
    nullable=false 只在 DDL 生效
    @Transient
    不持久化
    常用于 DTO 混合字段
    @Enumerated
    枚举存储方式
    一律 STRING
    @Version
    乐观锁字段
    见第四篇

    1.2 主键策略

    策略
    生成方式
    性能
    适用
    IDENTITY
    数据库自增
    批量插入慢（每次要回查）
    MySQL 单库，简单
    SEQUENCE
    序列（Oracle/PG）
    批量友好
    支持序列的库
    TABLE
    单独一张表发号
    慢
    兼容性场景
    AUTO
    由方言决定
    不透明
    不推荐
    UUID / 自定义
    @GenericGenerator 或 @PrePersist
    无库依赖
    分库分表
    @Id
@GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "user_seq")
@SequenceGenerator(name = "user_seq", sequenceName = "user_seq", allocationSize = 50)
private Long id;

    MySQL 用 IDENTITY 时，Hibernate 无法批量插入（每条 insert 都要拿回主键）。需要批量导入的场景，allocationSize + SEQUENCE 或雪花 ID 更合适。

    1.3 四种关联

    // 多对一：订单 → 用户（最常用）
@ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "user_id")
private User user;

// 一对多：用户 → 订单（必须写 mappedBy，否则多一张中间表）
@OneToMany(mappedBy = "user", cascade = CascadeType.PERSIST, fetch = FetchType.LAZY)
private List<Order> orders = new ArrayList<>();

// 一对一：用户 → 身份证
@OneToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "card_id")
private IdCard card;

// 多对多：订单 ↔ 商品（一定要有中间表）
@ManyToMany
@JoinTable(name = "tb_order_item",
        joinColumns = @JoinColumn(name = "order_id"),
        inverseJoinColumns = @JoinColumn(name = "item_id"))
private List<Item> items = new ArrayList<>();
    关联
    默认 fetch
    建议
    @ManyToOne
    EAGER
    一律改 LAZY
    @OneToOne
    EAGER
    改 LAZY
    @OneToMany
    LAZY
    保持 LAZY
    @ManyToMany
    LAZY
    保持，且慎用

    @ManyToOne 默认 EAGER 是 N+1 的头号来源：查 100 条订单会顺带发 100 条用户查询。

    1.4 双向关联的三条铁律

    1. @OneToMany 一侧必须写 mappedBy，值是对应字段名
    2. 维护关系的永远是”多”的一方（有 @JoinColumn 的那边）
    3. 保存时先存”多”的一方，或在一方加 cascade
    // 正确：由多的一方维护外键
Order order = new Order();
order.setUser(user);          // 只设 user，不要同时 user.getOrders().add(order) 后再手动维护
orderRepository.save(order);

    漏写 mappedBy 的后果：Hibernate 认为这是两个独立关联，额外建一张 tb_user_orders 中间表，数据双份。

    1.5 级联

    @OneToMany(mappedBy = "user", cascade = {CascadeType.PERSIST, CascadeType.MERGE})
private List<Order> orders;
    级联类型
    含义
    风险
    PERSIST
    保存父时一并保存子
    低
    MERGE
    合并父时一并合并子
    低
    REMOVE
    删父时删子
    高，容易误删
    ALL
    上面全包
    极高

    CascadeType.REMOVE 在 @ManyToMany 上等于”删一个订单把所有商品删掉”，非常危险。

    1.6 懒加载与 N+1

    // 方案一：JPQL fetch join（推荐，单条 SQL）
@Query("select o from Order o join fetch o.user where o.status = :status")
List<Order> findWithUser(@Param("status") String status);

// 方案二：EntityGraph（不改 SQL 的写法）
@EntityGraph(attributePaths = {"user", "items"})
List<Order> findByStatus(String status);

// 方案三：批量抓取（全局配置）
    spring:
  jpa:
    properties:
      hibernate:
        default_batch_fetch_size: 50      # 把 N 次查询合并成 N/50 次

    懒加载还有个大坑：在事务外访问懒加载属性会抛 LazyInitializationException。要么在事务内组装好 DTO 返回，要么用 fetch join 一次取齐。

    1.7 命名策略

    spring:
  jpa:
    hibernate:
      naming:
        physical-strategy: org.hibernate.boot.model.naming.PhysicalNamingStrategyStandardImpl
    默认策略
    效果
    何时改
    CamelCaseToUnderscoresNamingStrategy
    userName → user_name
    默认，一般不改
    PhysicalNamingStrategyStandardImpl
    保持原样
    表字段已是驼峰（老库）
    自定义
    加前缀/后缀
    多租户、分表

    • 实体映射：https://docs.spring.io/spring-data/jpa/docs/2.5.x/reference/html/#jpa.entities
    • 关联映射：https://docs.spring.io/spring-data/jpa/docs/2.5.x/reference/html/#jpa.repositories
    • Hibernate 用户指南：https://docs.jboss.org/hibernate/orm/5.6/userguide/html_single/Hibernate_User_Guide.html

    1.9 清单

    1. @ManyToOne / @OneToOne 默认 EAGER，一律显式改 LAZY
    2. @OneToMany 必须写 mappedBy，否则多一张中间表 + 双份数据
    3. 关系由”多”的一方维护，别两边都 set
    4. 枚举一律 EnumType.STRING，ORDINAL 改枚举顺序就全乱
    5. MySQL 下 IDENTITY 无法批量插入，批量场景换 SEQUENCE 或雪花 ID
    6. N+1 用 fetch join 或 @EntityGraph 解决，兜底配 default_batch_fetch_size
    7. 懒加载属性必须在事务内取完，否则 LazyInitializationException
