分类：java · springsession ｜ 标签：SpringSession

JDBC、Mongo 与自定义 Session 存储

不是所有项目都能上 Redis：有的客户环境只有数据库，有的已有 Mongo 集群。Spring Session 把存储抽象成 SessionRepository，换实现只改依赖与配置。

同一份会话可落到关系表、文档集合或键值桶

1.2 JDBC 实现

<dependency>
    <groupId>org.springframework.session</groupId>
    <artifactId>spring-session-jdbc</artifactId>
</dependency>
spring:
  session:
    store-type: jdbc
    jdbc:
      initialize-schema: always        # 开发期自动建表，生产改 never
      table-name: SPRING_SESSION
      cleanup-cron: "0 * * * *"        # 每小时清一次过期会话

建表语句（MySQL）：

CREATE TABLE SPRING_SESSION (
  PRIMARY_ID CHAR(36) NOT NULL,
  SESSION_ID CHAR(36) NOT NULL,
  CREATION_TIME BIGINT NOT NULL,
  LAST_ACCESS_TIME BIGINT NOT NULL,
  MAX_INACTIVE_INTERVAL INT NOT NULL,
  EXPIRY_TIME BIGINT NOT NULL,
  PRINCIPAL_NAME VARCHAR(100),
  CONSTRAINT SPRING_SESSION_PK PRIMARY KEY (PRIMARY_ID)
);

CREATE UNIQUE INDEX SPRING_SESSION_IX1 ON SPRING_SESSION (SESSION_ID);
CREATE INDEX SPRING_SESSION_IX2 ON SPRING_SESSION (EXPIRY_TIME);
CREATE INDEX SPRING_SESSION_IX3 ON SPRING_SESSION (PRINCIPAL_NAME);

属性表是一行一个属性，属性多时会话读写会变成多行操作，性能明显低于 Redis。

1.3 Mongo 实现

<dependency>
    <groupId>org.springframework.session</groupId>
    <artifactId>spring-session-data-mongodb</artifactId>
</dependency>
spring:
  session:
    store-type: mongodb
    mongodb:
      collection-name: sessions

Mongo 实现依赖 TTL 索引自动清理：

db.sessions.createIndex({ "lastModifiedTime": 1 },
    { expireAfterSeconds: 1800 })

TTL 清理是后台线程（约 60 秒一轮），所以”过期后还能读到”会有一个延迟窗口，业务不能依赖它做严格的失效判断。

1.5 自定义 SessionRepository

接口核心方法：

public interface SessionRepository<S extends Session> {
    S createSession();
    void save(S session);
    S findById(String id);
    void deleteById(String id);
}

实现自己的存储（例如存到公司内部的 KV 平台）：

public class CustomSessionRepository implements SessionRepository<MapSession> {

    private final KvClient kv;
    private final Duration defaultMaxInactiveInterval = Duration.ofMinutes(30);

    @Override
    public MapSession createSession() {
        MapSession s = new MapSession();
        s.setMaxInactiveInterval(defaultMaxInactiveInterval);
        return s;
    }

    @Override
    public void save(MapSession session) {
        kv.setex("sess:" + session.getId(), session.getMaxInactiveInterval().getSeconds(),
                 serialize(session));
    }

    @Override
    public MapSession findById(String id) {
        byte[] data = kv.get("sess:" + id);
        return data == null ? null : deserialize(data);
    }

    @Override
    public void deleteById(String id) {
        kv.del("sess:" + id);
    }
}

注册：

@Configuration
@EnableSpringHttpSession
public class SessionConfig {
    @Bean
    public SessionRepository<? extends Session> sessionRepository(KvClient kv) {
        return new CustomSessionRepository(kv);
    }
}

自定义实现的注意点：findById 返回值必须刷新 lastAccessedTime，否则会话不会续期。

1.8 清单

  1. 三种实现共用 SessionRepository 接口，业务代码不用改
  2. JDBC 是”多行存属性”，属性越多越慢，只适合低并发
  3. Mongo 靠 TTL 索引清理，有分钟级延迟，别依赖它做严格失效
  4. 自定义实现必须刷新 lastAccessedTime，否则会话不续期
  5. 多服务共用会话时序列化方式必须统一
  6. 生产关掉 initialize-schema=always，建表交给迁移脚本
  7. 高并发场景优先 Redis，别用数据库硬扛会话读写
