Spring Session（二）并发登录、过期与事件

分类：java · springsession ｜ 标签：SpringSession

并发登录控制、会话过期与事件

会话共享解决”多机一致”，接着要解决三个现实问题：同一账号能开几个会话、会话多久过期、过期/销毁时要不要做清理（比如释放占用的资源、记录登出日志）。

同一账号的多个会话被统一管理

1.1 并发会话控制

RedisIndexedSessionRepository 维护 principals:<user> 索引，可以按用户查所有会话。

方式一，限制最大会话数（新登录踢掉最旧的）：

@Component
public class SessionLimitListener implements ApplicationListener<SessionCreatedEvent> {

    private final FindByIndexNameSessionRepository<? extends Session> repository;
    private final int maxSessions;

    @Override
    public void onApplicationEvent(SessionCreatedEvent event) {
        Session session = (Session) repository.findById(event.getSessionId());
        String principal = session.getAttribute(FindByIndexNameSessionRepository.PRINCIPAL_NAME_INDEX_NAME);
        if (principal == null) return;

        Map<String, ? extends Session> sessions =
                repository.findByPrincipalName(principal);
        if (sessions.size() > maxSessions) {
            sessions.values().stream()
                    .sorted(Comparator.comparing(Session::getLastAccessedTime))
                    .limit(sessions.size() - maxSessions)
                    .forEach(s -> repository.deleteById(s.getId()));
        }
    }
}

方式二，禁止第二处登录（登录时先清掉同账号的旧会话）：

Map<String, ? extends Session> exist = repository.findByPrincipalName(username);
exist.values().forEach(s -> repository.deleteById(s.getId()));

timeout 只表示”闲置时长”，用户一直操作就能一直续命。要”绝对过期”（登录满 8 小时强制下线），必须在 Session 里存 loginTime 并自己校验：

Long loginTime = (Long) session.getAttribute("loginTime");
if (loginTime != null && System.currentTimeMillis() - loginTime > 8 * 3600_000L) {
    session.invalidate();
}

@Component
public class SessionDestroyedListener implements ApplicationListener<SessionDestroyedEvent> {
    @Override
    public void onApplicationEvent(SessionDestroyedEvent event) {
        String userId = event.getSession().getAttribute("userId");
        log.info("会话结束 userId={} reason={}", userId, event.getSession().getId());
        // 释放占用的坐席、记录在线时长
    }
}

注意：SessionDestroyedEvent 在主动 invalidate 与过期时都会触发，但过期事件的触发依赖 Redis 的 keyspace 通知或轮询清理，可能有分钟级延迟——不能当实时登出用。

Spring Security 的并发控制依赖 SessionRegistry，与 Spring Session 的 principal 索引是两套机制，同时用要确认 SessionRegistry 实现为 SpringSessionBackedSessionRegistry。

1.6 常见坑

  1. principal 索引没写 → findByPrincipalName 永远返回空 → 并发控制不生效
  2. 只在登录处写 PRINCIPAL_NAME_INDEX_NAME，注销时忘了清 → 残留会话
  3. timeout 设成 8h 却当成”登录有效期” → 用户一直操作就永不下线
  4. 依赖过期事件做资源释放 → 事件延迟导致资源长时间占用
  5. 前后端跨域用了 SameSite=Strict → 登录成功后立刻掉登录

1.8 清单

  1. 并发控制靠 principals:<user> 索引，登录时必须写入 principal
  2. 限制会话数的两种策略：踢最旧、只留最新
  3. timeout 是闲置时长，绝对过期要自己存 loginTime 判断
  4. 过期事件有延迟，不能用于实时资源释放
  5. 需要”一键踢人”用 Session，纯 API 跨域倾向 JWT
  6. Spring Security 并发控制要确认 SessionRegistry 是 Session 后端实现
  7. 注销时同时清 principal 索引，否则残留
