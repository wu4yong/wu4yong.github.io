Spring Session（一）集群会话共享落地 Redis

分类：java · springsession ｜ 标签：SpringSession

集群会话共享：把 Session 放进 Redis

单机时 HttpSession 存在 Tomcat 内存里，扩到两台就出问题：负载均衡把第二次请求打到另一台，用户就”掉登录”。Spring Session 的思路很直接——把 Session 从容器内存里搬到外部存储。

多台服务器共享同一份会话数据

1.1 引入与开启

<dependency>
    <groupId>org.springframework.session</groupId>
    <artifactId>spring-session-data-redis</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>
spring:
  session:
    store-type: redis
    timeout: 30m
    redis:
      namespace: "session:demo"
      flush-mode: on_save
  redis:
    host: 127.0.0.1
    port: 6379

2.x 起 starter 会自动装配 RedisIndexedSessionRepository，无需手写 @EnableRedisHttpSession。若用 1.x 或自定义，加注解：

@EnableRedisHttpSession(maxInactiveIntervalInSeconds = 1800)

关键价值不只是”共享”，还有差量更新：原生 Session 每次请求结束都要把整个对象序列化写回，属性多时很重；Spring Session 只写有变化的属性。

前后端分离 + 跨域时，”登录后仍 401” 往往是 same-site 与 secure 组合不对，而不是 Session 没存上。

1.5 Redis 里的结构

# 会话主数据（hash）
HGETALL spring:session:session:demo:sessions:xxxx

# 过期索引（zset，按过期时间排序，用于清理）
ZRANGE spring:session:session:demo:expirations 0 10

# 属性名索引（set，按属性名可查）
SMEMBERS spring:session:session:demo:sessions:attrName
键
类型
作用
sessions:<id>
hash
会话属性 + 创建/最后访问时间
expirations
zset
过期调度，SessionExpiredEvent 靠它
sessions:attrName
set
按属性名查会话
principals:<user>
set
按登录用户查会话（并发控制用）

多环境共用一套 Redis 时，namespace 必须区分，否则 dev 的会话会顶掉 prod。

1.6 与网关/负载均衡的关系

粘性会话（ip_hash）只是”把问题概率降低”，节点重启/扩缩容照样掉，不是解决方案。

1.8 清单

  1. Session 共享靠外部存储，不是靠负载均衡粘性
  2. Spring Boot 2.x 引入 starter 即自动装配，不必手写 @EnableRedisHttpSession
  3. namespace 必须按环境区分，避免互相覆盖
  4. Session 里只放 ID 等轻量数据，别放 Bean 和大对象
  5. 跨站场景 same-site 与 secure 必须配对正确
  6. Redis 里是 hash + zset + set 三套索引，过期靠 zset 调度
  7. 粘性会话不能替代会话共享，节点故障一律掉线
