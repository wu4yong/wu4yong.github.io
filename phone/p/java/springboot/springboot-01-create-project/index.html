创建第一个 Spring Boot 工程

Spring Boot 的第一课不是写代码，而是搞清楚”一个能跑起来的工程由哪几块拼出来”。这一篇从 start.spring.io 点出工程开始，把目录结构、pom 里三件关键的东西、启动类的三段注解、打包运行全部走一遍，最后列一遍新手必踩的坑。

从 Spring Initializr 选依赖到得到一个可运行的项目骨架

1.1 用 Spring Initializr 生成骨架

https://start.spring.io（IDE 里 New Project → Spring Initializr 走的是同一个服务）。各字段怎么选：

下载解压后先跑一次 mvn spring-boot:run，确认能起来，再动手改代码——先证明骨架是好的，这是排查问题的基线。

1.2 目录结构

demo
├── pom.xml
├── mvnw / mvnw.cmd              # Maven Wrapper，不装 Maven 也能构建
└── src
    ├── main
    │   ├── java/com/example/demo
    │   │   ├── DemoApplication.java        # 启动类
    │   │   └── controller/HelloController.java
    │   └── resources
    │       ├── application.yml             # 配置文件（默认给的是 .properties）
    │       ├── static/                     # 静态资源，映射到 /
    │       └── templates/                  # 模板文件（Thymeleaf 等）
    └── test/java/com/example/demo
        └── DemoApplicationTests.java

src/main/resources 下的 static、templates 是 Spring Boot 约定的默认位置，不用额外配置就能被找到。

1.3 pom 里的三件关键物

<!-- 1. parent：统一管理依赖版本与插件版本 -->
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>2.5.0</version>
    <relativePath/>
</parent>

<dependencies>
    <!-- 2. starter：一组依赖的打包入口 -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
</dependencies>

<build>
    <plugins>
        <!-- 3. 插件：把项目打成可执行 fat jar -->
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
        </plugin>
    </plugins>
</build>
组件
作用
关键点
parent
版本仲裁
引入后 starter 无需写版本号
starter-web
依赖集合
内含 spring-webmvc、tomcat、jackson
maven-plugin
可执行 jar
生成 BOOT-INF 结构 + JarLauncher

这三个东西合起来就是”零配置启动”的物理基础：parent 定版本、starter 定依赖、plugin 定打包方式。

1.4 启动类与三段注解

@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}

@SpringBootApplication 是三个注解的组合：

注解
作用
关键细节
@SpringBootConfiguration
标记配置类
本质是 @Configuration，一个应用只应有一个
@EnableAutoConfiguration
开启自动配置
导入 AutoConfigurationImportSelector
@ComponentScan
扫描组件
默认扫启动类所在包及其子包

第三条最容易出事：启动类放在 com.example.demo，那么 com.example.other 下的 @Service 根本不会被扫描到。要么把启动类放到最外层包，要么显式 @ComponentScan("com.example")。

1.5 第一个接口

@RestController
@RequestMapping("/hello")
public class HelloController {

    @GetMapping("/{name}")
    public Map<String, Object> hello(@PathVariable String name,
                                     @RequestParam(defaultValue = "1") int times) {
        Map<String, Object> r = new LinkedHashMap<>();
        r.put("msg", "hello " + name);
        r.put("times", times);
        return r;
    }
}

访问 http://localhost:8080/hello/tom?times=3，得到 JSON。@RestController = @Controller + @ResponseBody，不需要模板引擎就能直接返回对象。

1.6 配置与端口

server:
  port: 8080
  servlet:
    context-path: /api          # 全局前缀，接口地址变成 /api/hello/tom

spring:
  application:
    name: demo

改端口优先用配置，而不是在代码里 setPort——后者会让部署脚本没法统一覆盖。

1.7 打包与运行

# 打包（跳过测试先跑通流程）
mvn clean package -DskipTests

# 产物：target/demo-0.0.1-SNAPSHOT.jar，可直接运行
java -jar target/demo-0.0.1-SNAPSHOT.jar

# 指定端口与 profile
java -jar demo.jar --server.port=9090 --spring.profiles.active=dev

fat jar 内部结构：

BOOT-INF/classes/           # 你的类与资源
BOOT-INF/lib/               # 依赖 jar
org/springframework/boot/loader/JarLauncher.class   # 入口

这也解释了为什么 java -cp demo.jar 跑不起来——入口不是你的 main 类，而是 Spring Boot 的 JarLauncher。

1.8 新手五个坑

  1. 包扫描：启动类位置不对，@Service 不生效（最常见）
  2. 端口占用：Web server failed to start. Port 8080 was already in use，换端口或杀进程
  3. 依赖没刷新：改完 pom 一定要 reload Maven，否则 ClassNotFoundException
  4. 配置文件放错：application.yml 必须在 src/main/resources 根下
  5. 单元测试连数据库：@SpringBootTest 会加载全上下文，测试里要么 mock，要么用 H2

1.10 清单

  1. start.spring.io 选 GA 版本 + Jar 打包，先跑通骨架再改代码
  2. parent 管版本、starter 管依赖、plugin 管打包，三者缺一不可
  3. @SpringBootApplication = 配置类 + 自动配置 + 组件扫描
  4. 启动类必须放在最外层包，否则子包扫描不到
  5. 端口、context-path 一律写配置，别写死在代码里
  6. fat jar 的入口是 JarLauncher，不是你的 main 类
  7. 打包命令 mvn clean package，运行 java -jar，参数用 --key=value
