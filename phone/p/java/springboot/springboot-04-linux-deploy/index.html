基于 Linux 发布 Spring Boot 工程

Spring Boot 的部署比传统 war 简单很多：一个 java -jar 就完事。但”能跑”和”能长期稳定跑”之间隔着 systemd、Nginx、日志滚动、JVM 参数、非 root 用户这几件事。这一篇给一套可直接落地的发布流程。

jar 打包、服务器托管、Nginx 反代三段式上线

1.1 打包

mvn clean package -DskipTests
# 产物 target/demo-0.0.1-SNAPSHOT.jar，含依赖，可直接 java -jar

-Dmaven.test.skip=true

mvn package -Pprod

打包后本地先验证一次 java -jar，确认不是”能编不能跑”。

1.2 上传与目录规划

# 服务器上的目录约定
/opt/app/
├── demo.jar              # 应用包
├── config/               # 外部配置（优先级高于 jar 内）
│   └── application-prod.yml
├── logs/                 # 日志输出
└── run.sh                # 启停脚本
scp target/demo-0.0.1-SNAPSHOT.jar user@10.0.0.12:/opt/app/demo.jar

把 config/ 放在 jar 外面，是为了”改配置不用重新打包”——Spring Boot 会自动加载 jar 同级的 config/ 目录（第五篇详述）。

1.3 直接运行：先确认参数组合

java -Xms512m -Xmx512m \
     -XX:+UseG1GC \
     -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/opt/app/logs \
     -Duser.timezone=Asia/Shanghai \
     -jar /opt/app/demo.jar \
     --spring.profiles.active=prod \
     --server.port=8080
参数
作用
建议值
-Xms / -Xmx
堆初始/最大
容器里设为同一值，避免动态扩堆
-XX:+UseG1GC
GC 策略
大堆首选
-XX:+HeapDumpOnOutOfMemoryError
OOM 时导 dump
一定加，配好路径
-Duser.timezone
时区
与数据库一致
--spring.profiles.active
激活环境
部署脚本必带
--server.port
端口
与 Nginx 上游一致

容器环境（cgroup 限制内存）要额外注意：JDK 8 早期版本不识别容器内存上限，-Xmx 会按宿主机算，容易被 OOM Killer 干掉。要么用 JDK 11，要么显式写 -Xmx + -XX:MaxRAMPercentage=75。

1.4 systemd 托管（推荐）

直接 nohup java -jar & 的问题：重启机器不自启、进程挂了没人拉、日志没轮转。用 systemd 一次解决。

# /etc/systemd/system/demo.service
[Unit]
Description=demo spring boot app
After=network.target

[Service]
Type=simple
User=appuser
Group=appuser
WorkingDirectory=/opt/app
ExecStart=/usr/bin/java -Xms512m -Xmx512m -XX:+UseG1GC \
          -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/opt/app/logs \
          -jar /opt/app/demo.jar --spring.profiles.active=prod
SuccessExitStatus=143
Restart=always
RestartSec=10
StandardOutput=journal
StandardError=journal

# 安全加固
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable demo
sudo systemctl start demo
sudo systemctl status demo
journalctl -u demo -f          # 跟日志

SuccessExitStatus=143 是给 SIGTERM 用的（正常停止的退出码是 143，不写会被 systemd 判为失败）。

1.5 Nginx 反向代理

upstream demo_backend {
    server 127.0.0.1:8080;
    keepalive 32;
}

server {
    listen 80;
    server_name demo.example.com;

    client_max_body_size 20m;

    location / {
        proxy_pass http://demo_backend;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Connection        "";

        # SSE / WebSocket 需要长连接
        proxy_read_timeout 3600s;
        proxy_buffering off;
    }
}

应用侧要配合，否则拿到的 IP 全是 Nginx 的：

server:
  forward-headers-strategy: framework   # 让框架读 X-Forwarded-*
  tomcat:
    remoteip:
      remote-ip-header: X-Real-IP

1.6 日志

<!-- logback-spring.xml 关键片段 -->
<appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
    <file>/opt/app/logs/app.log</file>
    <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
        <fileNamePattern>/opt/app/logs/app.%d{yyyy-MM-dd}.%i.log.gz</fileNamePattern>
        <maxFileSize>100MB</maxFileSize>
        <maxHistory>30</maxHistory>
        <totalSizeCap>5GB</totalSizeCap>
    </rollingPolicy>
    <encoder>
        <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} %-5level [%thread] %logger{36} - %msg%n</pattern>
    </encoder>
</appender>

两条经验：日志一定要按大小+时间双维度滚动（只看日期会爆盘），以及别把日志打到系统盘。

1.7 优雅停机

server:
  shutdown: graceful               # 停止时先处理完在途请求

spring:
  lifecycle:
    timeout-per-shutdown-phase: 30s

配合 systemd 的 ExecStop=/bin/kill -TERM $MAINPID（默认行为即发 SIGTERM），systemctl stop demo 就不会杀掉正在处理的请求。

1.8 发布脚本

#!/usr/bin/env bash
set -e
NEW_JAR="/tmp/demo-new.jar"
APP_DIR="/opt/app"

# 1. 备份旧包
cp "$APP_DIR/demo.jar" "$APP_DIR/demo.jar.bak.$(date +%Y%m%d%H%M)" || true
# 2. 替换
mv "$NEW_JAR" "$APP_DIR/demo.jar"
# 3. 重启并检查
systemctl restart demo
sleep 15
curl -sf http://127.0.0.1:8080/actuator/health || { echo "health check failed"; exit 1; }

要点：先备份、再替换、最后做健康检查；失败就回滚到 demo.jar.bak.*。

1.11 清单

  1. 打 fat jar 上传，配置放 jar 外 config/ 目录
  2. JVM 参数要写全：堆、GC、HeapDump、时区
  3. 用 systemd 托管，别用 nohup；SuccessExitStatus=143 别漏
  4. Nginx 反代要带 X-Forwarded-*，应用侧开 forward-headers-strategy
  5. 日志按大小+时间滚动，并设 totalSizeCap
  6. 开启 server.shutdown: graceful 支持优雅停机
  7. 应用用非 root 用户跑，端口只监听内网
  8. 发布脚本 = 备份 + 替换 + 重启 + 健康检查 + 失败回滚
