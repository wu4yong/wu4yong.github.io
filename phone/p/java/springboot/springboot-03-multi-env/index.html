Spring Boot（三）多环境开发

分类：java · springboot ｜ 标签：SpringBoot

多环境开发

开发、测试、生产三套环境，配置到底怎么分。Spring Boot 的事实标准是 application-{profile}.yml + spring.profiles.active，再加上 Maven profile 做打包联动。这一篇把配置怎么拆、profile 怎么切换、优先级谁高谁低一次讲清。

dev / test / prod 三套配置，靠 profile 开关切换

1.1 拆分方式

resources/
├── application.yml           # 公共配置 + 激活哪个 profile
├── application-dev.yml       # 开发：本地库、DEBUG 日志
├── application-test.yml      # 测试：测试库、INFO 日志
└── application-prod.yml      # 生产：生产库、WARN 日志、线程池更大
# application.yml —— 公共部分
spring:
  application:
    name: demo
  profiles:
    active: dev              # 默认（生产环境会被启动参数覆盖）

server:
  port: 8080
# application-prod.yml —— 只写差异，别重复公共配置
spring:
  datasource:
    url: jdbc:mysql://10.0.0.12:3306/demo?serverTimezone=Asia/Shanghai
    username: ${DB_USER}
    password: ${DB_PWD}

logging:
  level:
    root: warn

1.2 激活 profile 的四种方式

# 1. 配置文件里写死（默认，适合本地开发）
spring.profiles.active: dev

# 2. 启动命令行参数（推荐用于部署脚本）
java -jar demo.jar --spring.profiles.active=prod

# 3. 环境变量（容器里最常用）
SPRING_PROFILES_ACTIVE=prod java -jar demo.jar

# 4. JVM 系统属性
java -Dspring.profiles.active=prod -jar demo.jar

优先级：命令行 > JVM 属性 > 环境变量 > 配置文件。所以线上用启动参数覆盖是安全做法——哪怕 jar 里默认写的是 dev，也能强制成 prod。

1.3 同时激活多个 profile

profile 可以叠加，后面的覆盖前面的：

java -jar demo.jar --spring.profiles.active=prod,db-prod
# application-db-prod.yml
spring:
  datasource:
    url: jdbc:mysql://10.0.0.12:3306/demo

常见组合：prod（通用生产参数）+ db-prod（数据库）+ mq-prod（消息队列），按基础设施拆开，避免一个文件几十行混在一起。

2.4 之后还支持 profile group，把常用组合起个名字：

spring:
  profiles:
    active: dev
    group:
      prod: prod,db-prod,mq-prod

之后 --spring.profiles.active=prod 就等于一次激活三个。

1.4 单文件多环境（2.4+ 的 on-profile）

不想开一堆文件时，可以在同一个 application.yml 里按 profile 分段：

spring:
  config:
    activate:
      on-profile: dev
server:
  port: 8080
---
spring:
  config:
    activate:
      on-profile: prod
server:
  port: 80

用 --- 分隔多个文档，每段用 on-profile 标记。好处是对比方便；坏处是一旦文件变长，找配置变慢。团队里两种都有人用，选一种统一即可。

1.6 与 Maven profile 联动

如果不同环境要打不同的 jar（比如控件的开关、依赖的差异），就在 pom 里定义 Maven profile，并用资源过滤把值写进 application.yml：

<profiles>
    <profile>
        <id>dev</id>
        <properties>
            <profiles.active>dev</profiles.active>
        </properties>
        <activation><activeByDefault>true</activeByDefault></activation>
    </profile>
    <profile>
        <id>prod</id>
        <properties>
            <profiles.active>prod</profiles.active>
        </properties>
    </profile>
</profiles>

<build>
    <resources>
        <resource>
            <directory>src/main/resources</directory>
            <filtering>true</filtering>       <!-- 开启占位符替换 -->
        </resource>
    </resources>
</build>
# application.yml 里写占位符
spring:
  profiles:
    active: @profiles.active@     # Maven 过滤时会替换

打包：

mvn clean package -Pprod

注意启用 filtering 后，application.yml 会被 Maven 处理，其它二进制资源（如图片）也走同一套规则可能被破坏——必要时用 <excludes> 排除。

实践建议：默认只用一个 jar + Spring profile，这样”构建一次、到处部署”。只有在依赖或代码确实需要裁剪时才上 Maven profile。

1.8 常见坑

  1. application-prod.yml 里把公共配置复制一遍，改了公共部分两边漂移 → 只写差异
  2. profile 名字拼错，application-prodd.yml 静默不加载，用的还是默认配置
  3. 用 @profiles.active@ 却没开 filtering，启动时报”无法解析占位符”
  4. 线上用 ${DB_USER} 环境变量，容器里没注入，启动时 IllegalArgumentException: Could not resolve placeholder
  5. 多个 profile 同名 key，误以为后面的会覆盖前面的——后者确实覆盖前者，但顺序依赖命令行书写顺序，容易踩

1.10 清单

  1. 公共配置留 application.yml，各环境只写差异
  2. 激活方式优先用启动参数 --spring.profiles.active=prod，可覆盖 jar 内默认值
  3. profile 可叠加，按基础设施拆成 prod + db-prod，或用 profile group 打包
  4. 单文件多环境用 on-profile，适合配置少的项目
  5. jar 外 config/ 优先级高于 jar 内，命令行高于一切
  6. Maven profile 只在”依赖/代码确实要裁剪”时使用
  7. 开了 filtering 才能用 @profiles.active@，注意排除二进制资源
