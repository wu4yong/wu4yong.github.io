Spring Boot（八）自动配置原理

分类：java · springboot ｜ 标签：SpringBoot

理解整合第三方技术的原理：自动配置

为什么加一个 starter、写几行 yml，DataSource、RedisTemplate、RestTemplate 就自动出现了？答案全在 @EnableAutoConfiguration 与几十个 XxxAutoConfiguration 类里。这一篇把”名单从哪来、条件怎么判、顺序怎么排、怎么覆盖”讲清。

自动配置：名单 → 条件闸门 → 装配好的 Bean

1.1 触发链

@SpringBootApplication
  └─ @EnableAutoConfiguration
       └─ @Import(AutoConfigurationImportSelector.class)

AutoConfigurationImportSelector 干三件事：

  1. 从所有 jar 里收集”自动配置类名单”
  2. 用 AutoConfigurationMetadata 与条件注解过滤掉不满足的
  3. 按 @AutoConfigureOrder / @AutoConfigureBefore / @AutoConfigureAfter 排序后返回

返回的类名会被 Spring 当作 @Configuration 类注册，于是它们的 @Bean 方法生效。

一个真实的自动配置类长这样（简化自 RedisAutoConfiguration）：

@Configuration(proxyBeanMethods = false)          // 不生成 CGLIB 代理，轻量
@ConditionalOnClass(RedisOperations.class)         // 有 Redis 依赖才生效
@EnableConfigurationProperties(RedisProperties.class)   // 绑定 spring.redis.*
@Import({ LettuceConnectionConfiguration.class })   // 只有用 Lettuce 时才导入连接工厂
public class RedisAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean(name = "redisTemplate")   // 用户没定义才给默认的
    public RedisTemplate<Object, Object> redisTemplate(
            RedisConnectionFactory factory) {
        RedisTemplate<Object, Object> t = new RedisTemplate<>();
        t.setConnectionFactory(factory);
        return t;
    }

    @Bean
    @ConditionalOnMissingBean                       // 按类型判断
    public StringRedisTemplate stringRedisTemplate(RedisConnectionFactory f) { ... }
}

1.4 顺序：谁先谁后

自动配置类之间的依赖也用注解声明：

@AutoConfigureAfter(DataSourceAutoConfiguration.class)
public class JdbcTemplateAutoConfiguration { }

排序规则：@AutoConfigureOrder（绝对顺序，数字越小越前）> @AutoConfigureBefore/@AutoConfigureAfter（相对）> 名单原始顺序。

为什么要排序：JdbcTemplateAutoConfiguration 依赖数据源，必须排在 DataSourceAutoConfiguration 之后；否则 @ConditionalOnSingleCandidate(DataSource.class) 会判定失败，JdbcTemplate 就装不上。

1.5 拿不到 Bean 时的排查顺序

  1. 依赖加了吗？（@ConditionalOnClass 的第一道关）
  2. 启动加 --debug，看 Negative matches 里是不是你的类，以及”did not match”的具体原因
  3. 配置项前缀对不对？（属性没绑上，@ConditionalOnProperty 就会失效）
  4. 有没有被 spring.autoconfigure.exclude 排掉？
  5. 自己定义的 Bean 名字/类型是否与 @ConditionalOnMissingBean 的判定一致？
java -jar demo.jar --debug 2>&1 | grep -A3 "RedisAutoConfiguration"
RedisAutoConfiguration matched:
  - @ConditionalOnClass found required class 'org.springframework.data.redis.core.RedisOperations'
RedisAutoConfiguration#redisTemplate:
  Did not match:
     - @ConditionalOnMissingBean (types: ...; SearchStrategy: all) found beans of type ...

“Did not match” 这一行往往直接给出结论。

1.6 排除与裁剪

spring:
  autoconfigure:
    exclude:
      - org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration
@SpringBootApplication(exclude = { DataSourceAutoConfiguration.class })

适用场景：多数据源自己管理、引了 JDBC 依赖却不想让 Spring 建默认数据源、单元测试里想跳过某些装配。

1.9 清单

  1. @EnableAutoConfiguration 通过 AutoConfigurationImportSelector 拉名单
  2. 名单在 2.7 前是 spring.factories，2.7 后是 AutoConfiguration.imports
  3. 装配与否由条件注解决定，@ConditionalOnMissingBean 是”允许覆盖”的关键
  4. 类之间用 @AutoConfigureBefore/After 排序，顺序错了会连带装配失败
  5. 拿不到 Bean 就 --debug 看条件评估报告，Negative matches 里有答案
  6. 不想用某项能力就 exclude，别硬留一个错误配置
  7. 自定义 Bean 的名字/类型必须与自动配置的判定完全一致才覆盖得上
