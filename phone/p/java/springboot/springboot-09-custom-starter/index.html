Spring Boot（九）自定义 Starter

分类：java · springboot ｜ 标签：SpringBoot

实现自定义开发整合组件（Starter）

前面几篇把别人的自动配置拆了个遍，这一篇反过来：自己写一个 xxx-spring-boot-starter，让别人加个依赖、写两行配置就能用。这是把公司内部中间件（统一日志、统一鉴权、内部 RPC 客户端）收敛成”一个依赖”的标准做法。

starter 与 autoconfigure 双模块 + 自动配置类 + 可复用组件

1.1 为什么要拆两个模块

模块
内容
依赖
demo-spring-boot-autoconfigure
自动配置类、Properties、核心实现
依赖 Spring Boot 与第三方库
demo-spring-boot-starter
几乎空的 pom
依赖 autoconfigure + 必要的传递依赖

拆分的意义：别人可以只用实现、不要自动配置（自己在 @Configuration 里手动装配），也可以只引 starter 全自动。官方所有 starter 都是这个结构（spring-boot-autoconfigure + spring-boot-starter-*）。

demo-spring-boot/
├── demo-spring-boot-autoconfigure/
│   ├── pom.xml
│   └── src/main/
│       ├── java/com/example/demo/autoconfigure/
│       │   ├── DemoProperties.java
│       │   ├── DemoService.java
│       │   └── DemoAutoConfiguration.java
│       └── resources/META-INF/spring/...AutoConfiguration.imports
└── demo-spring-boot-starter/
    └── pom.xml

1.2 autoconfigure 模块

pom 关键点：Spring Boot 依赖用 provided，不要传递出去污染使用者。

<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-autoconfigure</artifactId>
        <scope>provided</scope>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-configuration-processor</artifactId>
        <optional>true</optional>        <!-- 只为生成配置元数据，不传递 -->
    </dependency>
    <dependency>
        <groupId>com.example</groupId>
        <artifactId>demo-core</artifactId>   <!-- 真实实现 -->
        <optional>true</optional>            <!-- 让使用者可选 -->
    </dependency>
</dependencies>

属性类：

@Data
@ConfigurationProperties(prefix = "demo")
public class DemoProperties {
    /** 是否启用 */
    private boolean enabled = true;
    /** 服务端地址 */
    private String endpoint = "http://127.0.0.1:9000";
    /** 超时时间 */
    private Duration timeout = Duration.ofSeconds(3);
    /** 重试次数 */
    private int retry = 2;
}

核心服务：

public class DemoClient {
    private final DemoProperties props;

    public DemoClient(DemoProperties props) { this.props = props; }

    public String ping() {
        // 这里是真实实现：建连接、发请求、带重试
        return "pong from " + props.getEndpoint();
    }
}

自动配置类：

@Configuration(proxyBeanMethods = false)
@ConditionalOnClass(DemoClient.class)                 // 有核心类才生效
@ConditionalOnProperty(prefix = "demo", name = "enabled",
        havingValue = "true", matchIfMissing = true)   // demo.enabled=false 可关掉
@EnableConfigurationProperties(DemoProperties.class)   // 绑定 demo.*
public class DemoAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean                          // 使用者自定义优先
    public DemoClient demoClient(DemoProperties props) {
        return new DemoClient(props);
    }
}

三个注解缺一不可：@ConditionalOnClass 保证”没引入核心包时不报错”，@ConditionalOnProperty 给对方一个开关，@ConditionalOnMissingBean 保证可覆盖。

1.3 注册：版本不同写法不同

# 2.7+（推荐）
src/main/resources/META-INF/spring/
  org.springframework.boot.autoconfigure.AutoConfiguration.imports
内容：com.example.demo.autoconfigure.DemoAutoConfiguration
# 2.7 之前
src/main/resources/META-INF/spring.factories
org.springframework.boot.autoconfigure.EnableAutoConfiguration=\
com.example.demo.autoconfigure.DemoAutoConfiguration

两个都放也行（过渡期做法），但注意 2.7+ 只认 imports 里的名单，spring.factories 里多写的会被忽略；Spring Boot 3 完全不读 spring.factories 的这个键。

1.4 starter 模块

<dependencies>
    <dependency>
        <groupId>com.example</groupId>
        <artifactId>demo-spring-boot-autoconfigure</artifactId>
        <version>${project.version}</version>
    </dependency>
    <!-- 把"用这个组件必须有的依赖"也传递出去 -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter</artifactId>
    </dependency>
</dependencies>

starter 模块里不要写任何 Java 代码，它只是一个”依赖清单”。

1.5 使用方怎么接

<dependency>
    <groupId>com.example</groupId>
    <artifactId>demo-spring-boot-starter</artifactId>
    <version>1.0.0</version>
</dependency>
demo:
  endpoint: http://demo-svc:9000
  timeout: 5s
  retry: 3
@RestController
@RequiredArgsConstructor
public class DemoController {
    private final DemoClient client;      // 自动注入，无需任何配置类
    @GetMapping("/ping")
    public String ping() { return client.ping(); }
}

整个过程使用者没有写一行 @Configuration，这就是 starter 的价值。

1.6 测试自动配置

官方推荐用 ApplicationContextRunner 做单元测试，不需要起完整应用：

class DemoAutoConfigurationTest {

    private final ApplicationContextRunner runner = new ApplicationContextRunner()
            .withConfiguration(AutoConfigurations.of(DemoAutoConfiguration.class));

    @Test
    void 默认配置下会装配() {
        runner.run(ctx -> assertThat(ctx).hasSingleBean(DemoClient.class));
    }

    @Test
    void 关闭开关后不装配() {
        runner.withPropertyValues("demo.enabled=false")
              .run(ctx -> assertThat(ctx).doesNotHaveBean(DemoClient.class));
    }

    @Test
    void 自定义Bean优先() {
        runner.withUserConfiguration(CustomConfig.class)
              .run(ctx -> assertThat(ctx.getBean(DemoClient.class))
                      .isSameAs(CustomConfig.CUSTOM));
    }
}

覆盖条件分支（开/关/缺类/自定义 Bean）都测一遍，是 starter 质量的分水岭。

1.7 版本与依赖纪律

规则
原因
Spring Boot 依赖用 provided / optional
不要把框架版本传递给使用者
第三方库版本尽量交给使用者的 BOM
强制版本容易冲突
必须传递的依赖放 starter 模块
使用者”加一个依赖就够”
spring-boot-configuration-processor 用 optional
只为 IDE 提示，不必传递
不写死 spring-boot.version
由使用者的 parent 决定，保证兼容

版本冲突排查：

mvn dependency:tree -Dincludes=org.springframework.boot

1.8 常见坑

  1. 忘了 @EnableConfigurationProperties，Properties 类永远拿不到值
  2. 名单写错类名（拼错一个字母），静默不生效，最难查
  3. 自动配置类上写 @ComponentScan("com.example")，把使用者的包也扫进来（灾难）
  4. @ConditionalOnMissingBean 放在 @Bean 方法上却放在类上，语义完全不同
  5. 把 spring-boot-starter-web 硬依赖进 starter，使用者被迫接受 Web 环境
  6. 用了 spring.factories 却在 2.7+ 环境测试，一切正常，升到 3.0 全崩

1.10 清单

  1. 双模块：autoconfigure 放实现，starter 只放依赖
  2. 三个注解撑起自动配置：@ConditionalOnClass + @ConditionalOnProperty + @ConditionalOnMissingBean
  3. 注册方式看版本：2.7 前 spring.factories，2.7 后 AutoConfiguration.imports
  4. 框架依赖一律 provided/optional，别把版本传递给使用者
  5. 用 ApplicationContextRunner 测四种分支，不依赖完整应用启动
  6. 自动配置类里绝不写 @ComponentScan
  7. 类名拼错是”不生效”的第一嫌疑，改完先 --debug 验证
