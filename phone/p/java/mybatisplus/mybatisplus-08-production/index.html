生产实践、性能与故障排查

前面的能力会用之后，真正决定系统稳不稳的是这些：批量写怎么才快、SQL 怎么观测、updateById 的隐性行为、分页 count 为何不准、事务与缓存怎么配合。

SQL 执行经监控探针到批量处理

关键 JDBC 参数：

spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/demo?rewriteBatchedStatements=true&useServerPrepStmts=false

没有 rewriteBatchedStatements=true，MySQL 驱动不会把多条 insert 合成一条，批处理形同虚设。

1.2 saveBatch 的真实行为

userService.saveBatch(list, 1000);   // 每 1000 条 flush 一次
现象
原因
偶发 DuplicateKeyException
批内重复主键，ASSIGN_ID 碰撞或手写 ID 重复
内存暴涨
一次 saveBatch 10 万条，批大小过大
事务过长
整个批次在一个事务里，锁持有久

大批量导入拆成”分片 + 独立事务”，别一个事务干到底。

1.6 事务与 Service 层

@Service
@RequiredArgsConstructor
public class OrderServiceImpl extends ServiceImpl<OrderMapper, Order> implements OrderService {

    @Transactional(rollbackFor = Exception.class)
    public void create(OrderDTO dto) {
        save(dto.toEntity());
        otherService.deduct(dto.getItemId());   // 跨服务调用别放事务里
    }
}
原则
说明
事务在 Service
不在 Controller、不在 Mapper
只读加 readOnly
减少事务开销（对 MyBatis 影响有限，但语义清晰）
远程调用移出事务
否则连接被占用、超时累积
批处理独立事务
分片提交，避免长事务

1.10 清单

  1. 批量写入必须开 rewriteBatchedStatements=true，否则批处理无效
  2. saveBatch 分片 + 独立事务，别一个事务干 10 万条
  3. 生产 SQL 日志用 Slf4jImpl 并采样，别全量
  4. updateById 跳过 null，清空字段用 Wrapper
  5. 分页 total 不准先查 count 语句与 optimizeJoin
  6. 事务放 Service，远程调用移出事务
  7. 两个 mybatis starter 混用是第一大启动失败原因
