条件构造器：Wrapper 家族

Wrapper 是 MyBatis-Plus 最核心的能力：把”查询条件”变成对象，动态拼装、类型安全、可复用。搞不定它的嵌套与优先级，就会拼出错误的 SQL。

条件积木串联成 SQL 条件链

一律用 Lambda 版本：字符串字段名改了不会编译报错，只会在运行时 SQL 报错。

1.2 基本用法

// 查询
LambdaQueryWrapper<User> w = Wrappers.<User>lambdaQuery()
        .eq(User::getUsername, "jack")
        .gt(User::getAge, 18)
        .like(User::getNickname, "ja")
        .orderByDesc(User::getCreateTime);

userMapper.selectList(w);

// 更新：set 指定字段，where 指定条件
LambdaUpdateWrapper<User> uw = Wrappers.<User>lambdaUpdate()
        .set(User::getUsername, "jack2")
        .set(User::getAge, null)          // 显式置 null 只能用 wrapper
        .eq(User::getId, 1L);
userMapper.update(null, uw);

in 传空集合的行为：3.x 会生成 IN () 报错，务必先判空。

嵌套用”函数式参数”，不要用 and() 无参形式：那只是插入一个 AND 关键字，并不会加括号。

1.5 条件生效与默认值

// 条件为 null/false 时不拼接
w.eq(age != null, User::getAge, age)
 .like(StringUtils.isNotBlank(name), User::getName, name);

boolean condition 是第一个参数，动态条件首选这种写法，比在外面包 if 更紧凑。

1.6 链式 Wrapper（Service 层）

// 直接执行，不用再调 mapper
List<User> list = userService.lambdaQuery()
        .eq(User::getStatus, "ACTIVE")
        .list();

userService.lambdaUpdate()
        .set(User::getStatus, "DISABLED")
        .eq(User::getId, 1L)
        .update();

链式写法适合”一次查询即结束”的场景；需要复用的条件还是抽成 Wrapper 方法。

1.7 复用与抽取

public class UserWrappers {
    public static LambdaQueryWrapper<User> active() {
        return Wrappers.<User>lambdaQuery().eq(User::getStatus, "ACTIVE");
    }
}
userMapper.selectList(UserWrappers.active().like(User::getName, keyword));

注意：Wrapper 是可变对象，复用时要 .clone()，否则第二次调用会叠加条件。

1.9 清单

  1. 一律用 LambdaQueryWrapper，字符串字段名改不了会静默出错
  2. 嵌套只能用 .and(w -> ...) / .or(w -> ...)，无参形式不加括号
  3. in 空集合会生成 IN ()，先判空
  4. 动态条件用 eq(condition, column, value) 重载，不要手写 if
  5. set(xxx, null) 是清空字段的唯一正路
  6. apply 传参用 {0} 占位，别字符串拼接
  7. 复用 Wrapper 前先 clone()，它是可变对象
