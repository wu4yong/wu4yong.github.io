MyBatis-Plus（六）自动填充、逻辑删除与乐观锁

分类：java · mybatisplus ｜ 标签：MyBatisPlus

自动填充、逻辑删除与乐观锁

这三个能力都是”加个注解就生效”，但每个都有前提条件，缺一条就静默失效——不报错，只是数据不对。

字段自动写入与版本锁并存

1.1 自动填充

@Component
public class MyMetaObjectHandler implements MetaObjectHandler {

    @Override
    public void insertFill(MetaObject metaObject) {
        this.strictInsertFill(metaObject, "createTime", LocalDateTime.class, LocalDateTime.now());
        this.strictInsertFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
    }

    @Override
    public void updateFill(MetaObject metaObject) {
        this.strictUpdateFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
    }
}
@TableField(fill = FieldFill.INSERT)
private LocalDateTime createTime;

@TableField(fill = FieldFill.INSERT_UPDATE)
private LocalDateTime updateTime;
FieldFill
触发时机
INSERT
插入时填
UPDATE
更新时填
INSERT_UPDATE
两者都填

失效的三种常见原因：

  1. 字段没加 @TableField(fill = ...)
  2. MetaObjectHandler 没交给 Spring 管理（缺 @Component）
  3. 用了自定义 XML 的 insert，绕过了 MP 的填充逻辑

“用户手动设置了创建时间就别覆盖”这条语义，只有 strictXxxFill 才满足。

1.3 逻辑删除

      logic-not-delete-value: 0

说明

UPDATE ... SET deleted=1 WHERE id=?
不是物理删除

自动追加条件

Wrapper 里条件照常

自动追加 deleted=0

这是最大的坑：XML 里的手写 SQL 不受逻辑删除保护，会查/改到已删除数据。

<!-- 必须自己带条件 -->
<select id="selectCustom" resultType="User">
    SELECT * FROM tb_user WHERE deleted = 0 AND status = #{status}
</select>

1.4 逻辑删除的边界

场景
建议
唯一索引
用 (username, deleted) 联合唯一，否则删了不能重名
需要恢复
提供 update ... set deleted=0 的恢复接口
物理清理
定期归档任务扫 deleted=1 且超期的数据
统计
所有报表 SQL 都要带 deleted=0

唯一索引 + 逻辑删除是经典冲突：username 单列唯一时，用户被逻辑删除后同名字无法再注册。解法是联合唯一或加删除时间戳。

1.5 乐观锁

@Version
private Integer version;
@Bean
public MybatisPlusInterceptor mybatisPlusInterceptor() {
    MybatisPlusInterceptor i = new MybatisPlusInterceptor();
    i.addInnerInterceptor(new OptimisticLockerInnerInterceptor());
    return i;
}
User u = userMapper.selectById(1L);   // version = 1
u.setAge(30);
userMapper.updateById(u);             // SET age=30, version=2 WHERE id=1 AND version=1

必须

必须

不生效

返回值为 0 表示版本冲突，业务要处理（重试或提示）。

1.6 乐观锁的三个注意点

  1. 必须重新查询再更新：从 DTO 构造实体时 version 为 null，等于关掉锁
  2. version 字段类型用 Integer/Long，别用 int（null 无法表达”未设置”）
  3. updateById 里 version 会被自动 +1，不要手动 set

1.7 三者组合的典型实体

@Data
@TableName("tb_order")
public class Order {
    @TableId(type = IdType.ASSIGN_ID)
    private Long id;
    private String orderNo;
    private BigDecimal amount;

    @Version
    private Integer version;

    @TableLogic
    private Integer deleted;

    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;

    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;
}

1.9 清单

  1. 自动填充要三件套齐全：注解 + Handler + @Component
  2. 用 strictXxxFill，别用会覆盖用户赋值的旧 API
  3. 逻辑删除对自定义 XML 无效，必须手写 deleted=0
  4. 唯一索引与逻辑删除冲突，用联合唯一解决
  5. 乐观锁要注册拦截器，且从数据库查出的实体才能带上 version
  6. update 返回 0 是版本冲突，业务要处理
  7. version 用包装类型，别用基本类型
