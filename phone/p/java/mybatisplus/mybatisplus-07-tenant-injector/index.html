MyBatis-Plus（七）多租户与 SQL 注入器

分类：java · mybatisplus ｜ 标签：MyBatisPlus

多租户、防全表与自定义 SQL 注入器

多租户要求”同一个库里按租户隔离数据”，防全表与 SQL 规范是做安全兜底，SQL 注入器是把重复 SQL 抽成可复用的方法。

数据管道按租户分流后落入同一张表

1.1 多租户插件

@Bean
public MybatisPlusInterceptor mybatisPlusInterceptor() {
    MybatisPlusInterceptor i = new MybatisPlusInterceptor();
    i.addInnerInterceptor(new TenantLineInnerInterceptor(new TenantLineHandler() {
        @Override
        public Expression getTenantId() {
            return new LongValue(TenantContext.getTenantId());
        }

        @Override
        public String getTenantIdColumn() {
            return "tenant_id";
        }

        @Override
        public boolean ignoreTable(String tableName) {
            // 白名单表不加租户条件
            return "sys_dict".equals(tableName) || tableName.startsWith("sys_");
        }
    }));
    i.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
    return i;
}

1.2 租户上下文怎么传

public class TenantContext {
    private static final ThreadLocal<Long> HOLDER = new ThreadLocal<>();
    public static void set(Long id) { HOLDER.set(id); }
    public static Long getTenantId() { return HOLDER.get(); }
    public static void clear() { HOLDER.remove(); }
}
@Component
public class TenantFilter implements Filter {
    @Override
    public void doFilter(ServletRequest req, ServletResponse resp, FilterChain chain)
            throws IOException, ServletException {
        try {
            String tid = ((HttpServletRequest) req).getHeader("X-Tenant-Id");
            TenantContext.set(Long.valueOf(tid));
            chain.doFilter(req, resp);
        } finally {
            TenantContext.clear();      // 必须清，线程复用会串租户
        }
    }
}

不清 ThreadLocal 是最危险的多租户漏洞：Tomcat 线程复用，下一个请求可能带着上一个租户的 ID 查数据。

1.5 SQL 规范校验

i.addInnerInterceptor(new IllegalSQLInnerInterceptor());

它会拦截：select * 之外的隐式转换、in 子查询过多、缺少 limit 的大表查询等（规则随版本变化）。属于”锦上添花”，不要指望它替代 code review。

1.6 SQL 注入器

目标是把重复的自定义 SQL 抽成方法，像 BaseMapper 一样调用。

public class MyInsertBatch extends AbstractMethod {
    @Override
    public MappedStatement injectMappedStatement(Class<?> mapperClass, Class<?> modelClass,
                                                 TableInfo tableInfo) {
        String sql = "<script>INSERT INTO %s %s VALUES %s</script>";
        SqlMethod sqlMethod = SqlMethod.INSERT_ONE;
        String columnScript = SqlScriptUtils.convertIf(
                "(" + tableInfo.getAllInsertSqlColumnMaybeIf(null) + ")",
                "list != null and list.size() > 0", true);
        String valuesScript = SqlScriptUtils.convertForeach(
                tableInfo.getAllInsertSqlPropertyMaybeIf(null), "list", null, ",", "(", ")");
        String keyProperty = tableInfo.getKeyProperty();
        String keyColumn = tableInfo.getKeyColumn();
        String sqlScript = String.format(sql, tableInfo.getTableName(), columnScript, valuesScript);
        SqlSource sqlSource = languageDriver.createSqlSource(configuration, sqlScript, modelClass);
        return this.addInsertMappedStatement(mapperClass, modelClass, "insertBatchSomeColumn",
                sqlSource, new NoKeyGenerator(), keyProperty, keyColumn);
    }
}
public class MySqlInjector extends DefaultSqlInjector {
    @Override
    public List<AbstractMethod> getMethodList(Class<?> mapperClass, TableInfo tableInfo) {
        List<AbstractMethod> methods = new ArrayList<>(super.getMethodList(mapperClass, tableInfo));
        methods.add(new MyInsertBatch());
        return methods;
    }
}
public interface UserMapper extends BaseMapper<User> {
    int insertBatchSomeColumn(List<User> list);
}

1.7 插件组合与性能

每多一个 InnerInterceptor 就多一次 SQL 解析，高并发下开销可观测。原则：

  1. 只开确实需要的插件
  2. 多租户 + 分页是刚需，防全表建议开
  3. IllegalSQLInnerInterceptor 解析最重，压测后再决定是否上生产

1.9 清单

  1. 多租户用 TenantLineInnerInterceptor，租户 ID 从上下文取
  2. ThreadLocal 必须在 finally 里清理，否则串租户
  3. 联合唯一索引必须包含 tenant_id
  4. 跨租户操作用 @InterceptorIgnore(tenantLine="true")
  5. 生产必开 BlockAttackInnerInterceptor
  6. IllegalSQLInnerInterceptor 解析成本高，按需开启
  7. 注入器只用于高频重复的单表 SQL，复杂查询仍写 XML
