MyBatis-Plus（四）分页插件与拦截器体系

分类：java · mybatisplus ｜ 标签：MyBatisPlus

分页插件与拦截器体系

3.4.0 之后所有插件都挂在 MybatisPlusInterceptor 下，分页只是其中一个 InnerInterceptor。顺序挂错，分页与多租户/乐观锁就会互相踩。

拦截层把数据流切成整齐的页

1.1 注册 MybatisPlusInterceptor

@Configuration
@MapperScan("cn.demo.mapper")
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}
要点
说明
DbType.MYSQL
显式指定方言，避免每次分页都去探测数据库类型
只能注册一次
一个 MybatisPlusInterceptor 里加多个 InnerInterceptor
3.4.0+
老版本 PaginationInterceptor 已废弃

1.2 分页参数

PaginationInnerInterceptor p = new PaginationInnerInterceptor(DbType.MYSQL);
p.setMaxLimit(500L);     // 单页最大条数，防止 pageSize=10000
p.setOverflow(true);     // 超过最大页回到首页
p.setOptimizeJoin(true); // count 时优化 join
interceptor.addInnerInterceptor(p);

生产必须设 maxLimit：pageSize=100000 一次能把数据库打满。

1.3 用法

Page<User> page = new Page<>(1, 10);
Page<User> result = userMapper.selectPage(page, Wrappers.<User>lambdaQuery()
        .eq(User::getStatus, "ACTIVE"));

result.getRecords();      // 当前页
result.getTotal();        // 总数
result.getPages();        // 总页数
构造方式
是否查 total
场景
new Page<>(current, size)
查
普通列表
new Page<>(current, size, false)
不查
无限滚动、已知总数
new Page<>(current, size, true)
查
默认

Page 传给 Mapper 时必须是第一个参数，否则插件不生效——这是”分页没生效、返回全表”的头号原因。

1.4 多插件顺序（官方明确要求）

interceptor.addInnerInterceptor(new TenantLineInnerInterceptor(handler));    // 多租户
interceptor.addInnerInterceptor(new DynamicTableNameInnerInterceptor());      // 动态表名
interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));// 分页
interceptor.addInnerInterceptor(new OptimisticLockerInnerInterceptor());      // 乐观锁
interceptor.addInnerInterceptor(new BlockAttackInnerInterceptor());           // 防全表更新删除
顺序
插件
理由
1
多租户 / 动态表名
先改 SQL 的表与条件
2
分页 / 乐观锁
基于已改好的 SQL 做分页与版本
3
SQL 规范 / 防全表
对最终 SQL 做安全校验

官方原话：对 SQL 做单次改造的优先放入，不做 SQL 改造的最后放入。顺序错了典型症状是”多租户没加到 count 里、total 翻倍”。

1.5 忽略拦截

@InterceptorIgnore(tenantLine = "true")
List<User> selectAllAcrossTenant();
注解属性
对应插件

多租户
dynamicTableName
动态表名
blockAttack
防全表更新删除
illegalSql
SQL 规范校验

3.5.3+ 还支持代码级忽略（优先级高于注解），用完必须 clear：

InterceptorIgnoreHelper.handle(IgnoreStrategy.builder().tenantLine(true).build());
try {
    // 跨租户统计
} finally {
    InterceptorIgnoreHelper.clearIgnoreStrategy();
}

PageHelper.startPage() 依赖 ThreadLocal，与 MP 的 Page 参数机制完全不同，混用会出现”分页了两次”。

1.7 常见坑

  1. Page 不是第一个参数 → 插件不介入，返回全表
  2. 忘了注册 MybatisPlusInterceptor → selectPage 退化为普通查询
  3. 多个 MybatisPlusInterceptor Bean → 只有最后一个生效
  4. maxLimit 没设 → 前端传 size=100000 直接拖库
  5. count 语句写错（select distinct ...）→ 总数不准，用 optimizeCountSql 或自定义 count 方法

1.9 清单

  1. 3.4.0+ 只用 MybatisPlusInterceptor + PaginationInnerInterceptor
  2. 显式传 DbType，并设 maxLimit
  3. Page 必须是 Mapper 方法的第一个参数
  4. 多插件顺序：租户/动态表名 → 分页/乐观锁 → 防全表/SQL 规范
  5. 跨租户查询用 @InterceptorIgnore 或 IgnoreStrategy，用完清理
  6. 不要与 PageHelper 混用
  7. 不需要总数时传 searchCount=false，省一次 count
