Spring Cloud（三）OpenFeign 声明式远程调用

分类：java · springcloud ｜ 标签：SpringCloud

OpenFeign 声明式远程调用

跨服务调用最怕写一堆 HttpClient + 手拼 URL + 手解 JSON。OpenFeign 把它变成”写一个接口、加一个注解”，底层还是 HTTP，但编码、超时、重试、负载均衡、日志全帮你做了。

本地接口契约映射到远端服务

1.1 引依赖

<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-openfeign</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-loadbalancer</artifactId>
</dependency>

启动类加 @EnableFeignClients，并指定扫描包：

@EnableFeignClients(basePackages = "cn.itcast.feign.clients")

1.2 定义客户端

@FeignClient(name = "user-service")
public interface UserClient {

    @GetMapping("/user/{id}")
    User findById(@PathVariable("id") Long id);

    @GetMapping("/user/list")
    List<User> findByIds(@RequestParam("ids") List<Long> ids);
}
要点
说明
name
必须是注册中心里的服务名，Feign 靠它拉实例列表
path
服务有 context-path 时用它指定前缀
url
直连地址，测试用，生产别写死
注解显式写名字
@PathVariable("id") 不写名字在编译丢失参数名后会报错
返回类型
直接用 POJO，Feign 自动反序列化

看服务端：

@RestController
@RequestMapping("/user")
public class UserController {
    @GetMapping("/{id}")
    public User findById(@PathVariable Long id) { ... }
}

签名一致即可，不需要任何共享 jar——但实践中建议把接口抽到 api 模块共用，避免两边改签名时漏改。

1.3 契约接口共用（推荐）

// user-api 模块
public interface UserApi {
    @GetMapping("/user/{id}")
    User findById(@PathVariable("id") Long id);
}

// 调用方
@FeignClient(name = "user-service")
public interface UserClient extends UserApi { }

好处：一处改动，两边编译都会报错，不会上线才发现 404。

1.4 日志级别

feign:
  client:
    config:
      default:                       # 全局
        logger-level: BASIC
      user-service:                  # 单服务
        logger-level: FULL
        connect-timeout: 3000
        read-timeout: 5000

1.5 超时与重试

feign:
  client:
    config:
      default:
        connect-timeout: 2000
        read-timeout: 5000
  httpclient:
    enabled: true         # 换用 Apache HttpClient，连接池更优
  compression:
    request.enabled: true
    response.enabled: true

重试用 Spring Retry，别在 Feign 层面硬开：

@Configuration
public class RetryConfig {
    @Bean
    public Retryer feignRetryer() {
        // 周期 100ms，最大周期 1s，最多 3 次
        return new Retryer.Default(100, 1000, 3);
    }
}

注意：只有幂等接口才适合重试，下单接口重试会造成重复订单。

1.6 传递登录用户

Feign 默认不带请求头，下游拿不到 Authorization，鉴权会失败。用拦截器透传：

@Component
public class FeignAuthInterceptor implements RequestInterceptor {
    @Override
    public void apply(RequestTemplate template) {
        ServletRequestAttributes attrs =
                (ServletRequestAttributes) RequestContextHolder.getRequestAttributes();
        if (attrs != null) {
            String token = attrs.getRequest().getHeader("Authorization");
            if (token != null) template.header("Authorization", token);
        }
        // 全链路追踪的 traceId 也在这里带出去，见第九篇
        String traceId = MDC.get("traceId");
        if (traceId != null) template.header("X-Trace-Id", traceId);
    }
}

1.7 文件上传与下载

// 上传：用 Spring 的 MultipartFile，需引 feign-form
@PostMapping(value = "/file/upload", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
void upload(@RequestPart("file") MultipartFile file);

// 下载：返回 feign.Response，自己写流
@GetMapping("/file/{id}")
Response download(@PathVariable("id") Long id);

注意 @RequestPart 而非 @RequestParam，否则服务端可能收不到文件。

1.8 降级（配合 Sentinel 或 Hystrix）

@FeignClient(name = "user-service", fallbackFactory = UserClientFallbackFactory.class)
public interface UserClient extends UserApi { }
@Component
public class UserClientFallbackFactory implements FallbackFactory<UserClient> {
    @Override
    public UserClient create(Throwable cause) {
        return new UserClient() {
            @Override
            public User findById(Long id) {
                log.warn("查询用户失败，走降级 id={}", id, cause);
                return new User(id, "未知用户");   // 返回兜底数据，不让链路断
            }
        };
    }
}

降级要开 feign.hystrix.enabled=true（Hoxton 阶段仍用 Hystrix 承载），或用 Sentinel 的资源规则。降级返回”空对象而非异常”，是保证下单链路不崩的关键。

1.10 清单

  1. @FeignClient(name=...) 的 name 必须等于服务名，Feign 靠它查实例
  2. 路径与参数注解显式写名字，避免参数名丢失导致 404/400
  3. 契约接口抽到 api 模块共用，改签名两边一起编译报错
  4. 生产日志用 BASIC，FULL 只在定位报文时临时开
  5. 超时用 connect-timeout/read-timeout，重试用 Retryer，且只对幂等接口
  6. 鉴权头、traceId 必须用 RequestInterceptor 透传
  7. 降级返回兜底对象而不是异常，保住主链路
