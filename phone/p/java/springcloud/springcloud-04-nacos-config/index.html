Spring Cloud（四）Nacos 配置中心

分类：java · springcloud ｜ 标签：SpringCloud

Nacos 配置中心

配置散在十几个工程的 application.yml 里，改一个数据库地址要重新打包十几个服务——配置中心就是来解决这个的：配置集中在 Nacos，服务启动时拉，改完还能热更新。

配置文件集中托管并按环境下发到各服务

1.1 引依赖与接入

<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-config</artifactId>
</dependency>

Hoxton 阶段配置要写在 bootstrap.yml（不是 application.yml，因为配置中心地址必须最早加载）：

spring:
  application:
    name: user-service
  profiles:
    active: dev
  cloud:
    nacos:
      config:
        server-addr: 127.0.0.1:8848
        file-extension: yaml        # 决定去 Nacos 找 user-service-dev.yaml
        namespace: public

Nacos 上的 Data ID 规则：${spring.application.name}-${spring.profiles.active}.${file-extension}，即 user-service-dev.yaml。

所以标准做法：公共配置放不带 profile 的、差异化配置放带 profile 的、本地只留必要默认值。

# user-service.yaml（共享）
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true

# user-service-dev.yaml（dev 独有）
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/cloud_user?serverTimezone=Asia/Shanghai
    username: root
    password: root

1.3 热更新

配置中心改了值，服务不重启也能生效——前提是 Bean 上加了 @RefreshScope：

@Data
@Component
@RefreshScope
@ConfigurationProperties(prefix = "pattern")
public class PatternProperties {
    private String dateformat;
}
情况
是否生效
说明
@RefreshScope + @Value
生效
重新创建 Bean
@RefreshScope + @ConfigurationProperties
生效
推荐写法
普通 @Component 里读的字段
不生效
只在启动时读一次
静态常量 / 线程池参数
不生效
需要自己监听事件重建

@RefreshScope 的原理是销毁该 Bean 并重建，因此不要用在持有连接池、长连接的 Bean 上，会打断在用连接。

1.4 监听配置变更

不想用 @RefreshScope 时，可以自己监听：

@Component
public class ConfigChangeListener {
    @NacosConfigListener(dataId = "user-service-dev.yaml")
    public void onChange(String content) {
        log.info("配置变更，长度={}", content.length());
        // 自己解析、自己刷新业务对象
    }
}

适合”改配置要重建线程池”这类无法靠 Bean 重建解决的场景。

Nacos 每次发布都会留历史版本，回滚不需要重新打包，这是它比”改 Git 再发版”最大优势。

国内项目直接选 Nacos，省一套组件、省一套运维。

1.7 常见坑

  1. 配置写在 application.yml 里 → 启动顺序不对，读不到远程配置，必须放 bootstrap.yml
  2. file-extension 写成 yml，但 Nacos 上建的是 .yaml → 静默读不到，走本地默认
  3. spring.profiles.active 没设置 → Data ID 变成 user-service-.yaml，永远匹配不上
  4. 只想热更新却忘了 @RefreshScope → 改完没反应，误以为是 Nacos 的问题
  5. 敏感信息（数据库密码）直接明文放配置中心 → 至少要开 namespace 权限或加密

1.9 清单

  1. 配置中心地址必须放 bootstrap.yml，且要早于 application.yml 加载
  2. Data ID 由 服务名-profile.后缀 拼出来，profile 不设就永远匹配不上
  3. 共享配置不带 profile，差异化配置带 profile，本地只留默认值
  4. 热更新靠 @RefreshScope，但它会重建 Bean，别用在连接池上
  5. 无法靠重建解决的（线程池、静态参数）用 @NacosConfigListener 自己刷
  6. 高风险改动走灰度 Data ID，出问题用历史版本回滚，不要重新发版
  7. 国内项目 Nacos 比 Spring Cloud Config 少一套运维，优先选它
