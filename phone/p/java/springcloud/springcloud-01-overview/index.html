微服务拆分与 Spring Cloud 组件全景

Spring Cloud 不是”一个框架”，而是一组针对分布式系统的解决方案集合：注册、调用、配置、网关、熔断、事务、消息、追踪。这一篇先把”为什么要拆、按什么维度拆、拆完由谁来管”讲清，再给一张组件对照表，最后说版本怎么选——版本选错是新手 80% 的报错来源。

单体应用拆分为多个服务，由统一的基础设施串联

1.1 什么时候该拆

拆分的准则是业务边界（订单、用户、商品各自独立），不是技术分层（controller/service/dao 拆成三个服务）。

1.2 典型拆分方式

按业务：user-service / order-service / item-service / pay-service
按功能：gateway / auth-service / file-service / search-service
按读写：order-service（写）+ order-query（读）

拆分后必然带来新问题，这才轮到 Spring Cloud：

  • 服务地址天天变 → 注册中心
  • 跨服务调用要写 HTTP 客户端 → 声明式远程调用
  • 配置散在 N 个工程 → 配置中心
  • 前端要记住 N 个地址 → 统一网关
  • 一个服务慢拖垮全链路 → 熔断降级
  • 跨库事务写不进去 → 分布式事务

1.4 版本怎么选

Spring Cloud 的版本必须和 Spring Boot 对齐，否则启动就报 NoSuchMethodError。

Spring Cloud
Spring Boot
备注
Hoxton.SR9
2.3.x
稳定，多数教程基于它
Hoxton.SR10/SR11
2.4.x
可与 2.4 搭配
2020.0.x（Ilford）
2.4.x
起改名”日历版本”，生态兼容性差
Spring Cloud Alibaba 2.2.6.RELEASE
Hoxton 系
Nacos/Sentinel/Seata 全家桶

统一在父工程里锁版本：

<properties>
    <spring-cloud.version>Hoxton.SR9</spring-cloud.version>
    <spring-cloud-alibaba.version>2.2.6.RELEASE</spring-cloud-alibaba.version>
</properties>

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.cloud</groupId>
            <artifactId>spring-cloud-dependencies</artifactId>
            <version>${spring-cloud.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
        <dependency>
            <groupId>com.alibaba.cloud</groupId>
            <artifactId>spring-cloud-alibaba-dependencies</artifactId>
            <version>${spring-cloud-alibaba.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

子模块里就不写版本号了：

<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>

1.9 清单

  1. 拆分依据业务边界，不是技术分层，业务未定型时不要拆
  2. 拆分后必然出现的六类问题，就是 Spring Cloud 各组件的存在理由
  3. 新项目用 Alibaba 系（Nacos / Sentinel / Seata），Netflix 系已进入维护
  4. 版本必须三角对齐：Spring Boot + Spring Cloud + Alibaba
  5. 版本统一在父工程的 dependencyManagement 里锁，子模块不写版本
  6. 端口与服务名先约定好，后面配网关和规则省一半时间
  7. 报 NoSuchMethodError 先查 dependency:tree，别怀疑代码
