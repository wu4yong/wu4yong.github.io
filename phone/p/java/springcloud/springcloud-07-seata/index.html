分类：java · springcloud ｜ 标签：SpringCloud

Seata 分布式事务

下单要同时写订单库和库存库，两个库各自本地事务都成功、其中一个提交失败，数据就错了。Seata 用一个”全局事务”把多个本地事务绑成一个整体：要么全提交，要么全回滚。

全局事务协调器编织多个分支事务

1.1 三个角色

角色
名称
作用
TC
Transaction Coordinator
协调者，维护全局事务状态、决定提交或回滚
TM
Transaction Manager
管理分支事务，向 TC 注册
RM
Resource Manager
管理本地资源（数据源），执行分支的提交/回滚

一个服务里 TM 与 RM 通常是同一个进程（seata-spring-boot-starter 全包了）。

1.2 部署 Seata Server

  type = "nacos"

    serverAddr = "127.0.0.1:8848"

  type = "nacos"
  nacos {
    serverAddr = "127.0.0.1:8848"
    dataId = "seataServer.properties"

  }
}

store.mode=db

store.mode=db 生产必选，file 只适合单机试玩。

每个参与事务的库都要建 undo_log 表（AT 模式依赖它回滚）：

CREATE TABLE `undo_log` (
  `id` BIGINT NOT NULL AUTO_INCREMENT,
  `branch_id` BIGINT NOT NULL,
  `xid` VARCHAR(100) NOT NULL,
  `context` VARCHAR(128) NOT NULL,
  `rollback_info` LONGBLOB NOT NULL,
  `log_status` INT NOT NULL,
  `log_created` DATETIME(6) NOT NULL,
  `log_modified` DATETIME(6) NOT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `ux_undo_log` (`xid`, `branch_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

1.4 发起全局事务

@GlobalTransactional(name = "create-order", rollbackFor = Exception.class)
public Long createOrder(OrderDTO dto) {
    // 1. 本地：创建订单（分支事务 1）
    orderMapper.insert(order);
    // 2. 远程：扣减库存（分支事务 2，Feign 调用）
    itemClient.deduct(dto.getItemId(), dto.getNum());
    // 3. 远程：扣减余额（分支事务 3）
    accountClient.deduct(dto.getUserId(), dto.getMoney());
    return order.getId();
}

@GlobalTransactional 只需加在发起方，参与方只要有 @Transactional 与 Seata 依赖即可。

验证：TC 日志出现 begin new global transaction；失败时三个库自动回滚，undo_log 有记录。

AT 模式没有全局读隔离：别人可能读到未提交的中间态（脏读）。要读已提交，用 @GlobalLock + selectForUpdate：

@GlobalLock
@Transactional
public Item queryItem(Long id) {
    return itemMapper.selectForUpdate(id);   // 会尝试拿全局锁
}

1.6 AT 模式回滚原理

1. 分支执行前：RM 把"前镜像"写进 undo_log
2. 分支执行：本地事务提交
3. 全局提交：TC 通知各分支删除 undo_log
4. 全局回滚：TC 通知各分支用 undo_log 反向补偿

这解释了为什么 undo_log 表必须存在、且各库结构一致：它是回滚的唯一依据。表丢了 → 回滚直接失败 → 数据长期不一致。

1.7 常见坑

  1. 忘了建 undo_log → 回滚失败，日志报 Branch rollback failed
  2. tx-service-group 与服务端 vgroup-mapping 不一致 → 报 no available service 'xxx' found
  3. 库表主键/字段名改动后 undo_log 里前镜像失效 → 部分回滚异常
  4. 远程调用没走 Feign（如直接 HttpClient）→ XID 不传递，分支不在同一个全局事务里
  5. 全局事务里做长耗时操作（发短信、调外部 API）→ 全局锁持有过久，其他事务全卡住

1.8 XID 是怎么传的

Seata 通过 RootContext 在请求线程里保存 XID，Feign 的 RequestInterceptor 把 TX_XID 塞进请求头，参与方用 TransactionPropagationInterceptor 取出并绑定。所以必须用 Seata 的 Feign 集成（seata-spring-boot-starter 自动注册），自己写 HTTP 调用会把 XID 丢掉。

1.10 清单

  1. TC 定成败，TM 管分支，RM 执行本地提交/回滚
  2. 每个参与库必须有 undo_log，它是回滚的唯一依据
  3. tx-service-group 必须与服务端 vgroup-mapping 对上
  4. @GlobalTransactional 只加发起方，参与方 @Transactional 就够
  5. AT 模式无全局读隔离，要读已提交用 @GlobalLock + selectForUpdate
  6. 远程调用必须走 Seata 集成的 Feign，否则 XID 传不出去
  7. 全局事务内别做长耗时外部调用，会把全局锁拖死
