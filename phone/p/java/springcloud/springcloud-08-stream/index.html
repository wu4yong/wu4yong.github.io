Spring Cloud Stream 消息驱动

服务之间除了同步调用（Feign），还需要异步解耦（消息）。Spring Cloud Stream 的价值在于：同一套代码，换一个 binder 就能从 RabbitMQ 切到 RocketMQ/Kafka，业务逻辑完全不用动。

生产者与消费者通过消息管道解耦

1.2 引入 RocketMQ Binder

<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-stream-rocketmq</artifactId>
</dependency>
spring:
  cloud:
    stream:
      rocketmq:
        binder:
          name-server: 127.0.0.1:9876
      bindings:
        output:
          destination: order-topic
          content-type: application/json
        input:
          destination: sms-topic
          group: sms-consumer-group

1.3 生产者

public interface OrderSource {
    @Output("orderOutput")
    MessageChannel output();
}
@Service
@EnableBinding(OrderSource.class)          // 3.x 后改用函数式，见 1.6
public class OrderPublisher {
    @Autowired
    private OrderSource source;

    public void send(Order order) {
        source.output().send(MessageBuilder.withPayload(order).build());
    }
}

1.4 消费者

public interface SmsSink {
    @Input("smsInput")
    SubscribableChannel input();
}
@Service
@EnableBinding(SmsSink.class)
public class SmsListener {
    @StreamListener("smsInput")
    public void onMessage(String payload) {
        log.info("收到短信任务：{}", payload);
        smsService.send(payload);
    }
}

1.6 函数式定义（推荐的写法）

@Bean
public Supplier<Order> orderSupplier() {
    return () -> orderQueue.poll();      // 轮询产出
}

@Bean
public Consumer<Order> orderConsumer() {
    return order -> log.info("处理订单 {}", order.getId());
}
spring:
  cloud:
    stream:
      function:
        definition: orderSupplier;orderConsumer
      bindings:
        orderSupplier-out-0:
          destination: order-topic
        orderConsumer-in-0:
          destination: order-topic

命名规则：<函数名>-<in|out>-<索引>。函数式写法不依赖 @EnableBinding，Spring Cloud Stream 3.1+ 推荐。

Stream 的优点是可替换性，代价是部分中间件特性被抽象掉（如 RocketMQ 的事务消息、顺序消息需要额外配置才能用）。

1.8 幂等与顺序

消息中间件只保证”至少一次”，不保证”仅一次”：

// 消费幂等：以业务唯一键做去重
if (!redis.setIfAbsent("msg:" + order.getId(), "1", Duration.ofMinutes(10))) {
    log.info("重复消息，忽略 {}", order.getId());
    return;
}

顺序消息：RocketMQ 用 MessageQueueSelector 按业务键选队列，消费端 concurrency: 1 且单队列单线程，才能保证局部有序。

1.10 清单

  1. Binder 决定中间件，业务代码与绑定配置解耦
  2. group 决定消费者组，组内是竞争消费（负载均衡）
  3. 重试要配退避与死信队列，否则坏消息无限重投
  4. 3.1+ 用函数式 Supplier/Consumer + definition 更清晰
  5. 消息是”至少一次”，消费端必须做幂等
  6. 需要顺序时按业务键选队列 + 单线程消费
  7. 追求极致性能或中间件特有时，直接用原生 SDK 更合适
