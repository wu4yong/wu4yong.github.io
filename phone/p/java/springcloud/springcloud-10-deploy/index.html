分类：java · springcloud ｜ 标签：SpringCloud

容器化打包与整体部署

一个微服务项目要上线，需要按序起 Nacos、MySQL、Seata、Redis、七八个服务、网关。手写一堆启动脚本很快就乱，标准做法是每个服务一个镜像 + 一份 compose 编排。

容器化后按依赖顺序编排整组服务

1.1 多阶段 Dockerfile

# 阶段一：构建
FROM maven:3.8-openjdk-11 AS build
WORKDIR /build
COPY pom.xml .
RUN mvn -B dependency:go-offline
COPY src ./src
RUN mvn -B clean package -DskipTests

# 阶段二：运行
FROM openjdk:11-jre-slim
WORKDIR /app
COPY --from=build /build/target/*.jar app.jar
ENV TZ=Asia/Shanghai JAVA_OPTS="-Xms256m -Xmx512m"
EXPOSE 8081
ENTRYPOINT ["sh","-c","java $JAVA_OPTS -jar app.jar"]
要点
原因
先 COPY pom 再 COPY src
依赖层可复用，改代码不重拉依赖
分两个 FROM
运行镜像不含 Maven 与源码，体积小一半
-DskipTests
测试在 CI 阶段跑，镜像构建别重复
固定 TZ
容器默认 UTC，日志时间会差 8 小时

1.3 compose 编排

version: "3.8"
services:
  mysql:
    image: mysql:5.7
    environment:
      MYSQL_ROOT_PASSWORD: root
      TZ: Asia/Shanghai
    volumes:
      - ./sql:/docker-entrypoint-initdb.d
    ports: ["3306:3306"]

  nacos:
    image: nacos/nacos-server:1.4.2
    environment:
      MODE: standalone
      SPRING_DATASOURCE_PLATFORM: mysql
      MYSQL_SERVICE_HOST: mysql
      MYSQL_SERVICE_DB_NAME: nacos_config
      MYSQL_SERVICE_USER: root
      MYSQL_SERVICE_PASSWORD: root
    depends_on: [mysql]
    ports: ["8848:8848"]

  seata:
    image: seataio/seata-server:1.4.2
    environment:
      SEATA_IP: seata
    depends_on: [nacos]
    ports: ["8091:8091"]

  user-service:
    image: user-service:1.0
    environment:
      SPRING_PROFILES_ACTIVE: dev
      NACOS_ADDR: nacos:8848
    depends_on: [nacos]
    ports: ["8081:8081"]

  gateway:
    image: gateway:1.0
    environment:
      NACOS_ADDR: nacos:8848
    depends_on: [user-service]
    ports: ["10010:10010"]

depends_on 只保证启动顺序，不保证”服务已就绪”，所以必须配健康检查。

1.4 健康检查

user-service:
  image: user-service:1.0
  healthcheck:
    test: ["CMD", "curl", "-f", "http://localhost:8081/actuator/health"]
    interval: 10s
    timeout: 3s
    retries: 5
    start_period: 30s
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
management:
  endpoints:
    web:
      exposure:
        include: health,info

没有健康检查时，网关会在服务还没起来时就开始转发，导致一串 502。

1.5 配置外置

镜像里不要打包生产配置，靠环境变量注入：

spring:
  cloud:
    nacos:
      discovery:
        server-addr: ${NACOS_ADDR:127.0.0.1:8848}
      config:
        server-addr: ${NACOS_ADDR:127.0.0.1:8848}
user-service:
  environment:
    NACOS_ADDR: nacos:8848
    JAVA_OPTS: "-Xms512m -Xmx512m"

同一个镜像可以进 dev / test / prod，只换环境变量。

1.6 上线顺序

1. mysql / redis        （有状态，最后停、最先起）
2. nacos                （注册与配置中心）
3. seata                （依赖 nacos 取配置）
4. 业务服务（user → item → order）
5. gateway              （最后开，避免把流量引到半启动集群）

下线顺序反过来：先摘网关流量，再停业务，最后停基础设施。

1.7 常见坑

  1. 容器里注册到 Nacos 的是内网 IP（172.x），外部调不通 → 用 host 网络或显式配 discovery.ip
  2. 容器时区 UTC 导致日志差 8 小时 → ENV TZ + -Duser.timezone
  3. 把 depends_on 当成”等就绪” → 加 healthcheck + condition: service_healthy
  4. 镜像里带生产密码 → 一律环境变量注入
  5. 每次构建都重拉全部依赖 → 分层写错，先 COPY pom

1.9 清单

  1. 多阶段构建：构建镜像带 Maven，运行镜像只带 JRE
  2. 先 COPY pom 再 COPY src，依赖层可复用
  3. depends_on 只管顺序，就绪靠 healthcheck
  4. 生产配置一律环境变量注入，镜像要能跨环境复用
  5. 注册地址在多网卡/容器里必须显式指定，否则注册内网 IP
  6. 上线按”基础设施 → 业务 → 网关”，下线反过来
  7. 容器时区固定 Asia/Shanghai，否则日志时间全错
