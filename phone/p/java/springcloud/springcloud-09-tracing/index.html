链路追踪与日志串联

一个请求穿过网关、订单、用户、库存四个服务，出问题时只看单个服务的日志根本串不起来。链路追踪给每个请求发一张”通行证”（traceId），所有服务、所有日志都带上它，一次检索就能还原整条路径。

一条请求在各个服务节点上留下可检索的轨迹

1.1 两代方案

方案
版本
说明
Spring Cloud Sleuth
Boot 2.x
基于 Brave，自动埋点，日志带 [service,traceId,spanId]
Micrometer Tracing
Boot 3.x
Sleuth 停止维护后的官方替代
Zipkin / SkyWalking
独立服务
收集、存储、展示调用链

Hoxton 阶段用 Sleuth + Zipkin；新项目或升级 Boot 3 时用 Micrometer Tracing。

1.2 接入 Sleuth

<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-sleuth</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-zipkin</artifactId>
</dependency>
spring:
  sleuth:
    sampler:
      probability: 1.0        # 采样率，测试用 1.0，生产 0.1~0.3
  zipkin:
    base-url: http://127.0.0.1:9411

启动后日志自动多出两段：

2021-05-13 10:00:00.123  INFO [order-service,4f2a1b8c9d0e3f11,9a8b7c6d5e4f3a21] 1 --- [nio-8082-exec-1] c.i.o.OrderController : 创建订单

格式是 [服务名,traceId,spanId]，traceId 全链路一致，spanId 每跳不同。

自己写 HTTP 客户端时手动补头：

headers.add("X-B3-TraceId", MDC.get("traceId"));
headers.add("X-B3-SpanId", MDC.get("spanId"));
headers.add("X-B3-Sampled", "1");

1.4 日志格式统一

Logback 里把 traceId 打进 pattern，所有服务统一：

<appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
    <encoder>
        <pattern>%d{HH:mm:ss.SSS} %-5level [%X{traceId:-},%X{spanId:-}] [%thread] %logger{36} - %msg%n</pattern>
    </encoder>
</appender>

%X{traceId:-} 中的 :- 表示取不到时输出空，避免日志里出现 null。

1.5 线程池里的追踪

Sleuth 的 traceId 存在 MDC（ThreadLocal），提交到线程池后上下文丢失，异步日志就没有 traceId。解决：

@Bean
public ExecutorService traceableExecutor() {
    return new TraceableExecutorService(
            Executors.newFixedThreadPool(10), "order-async");
}

CompletableFuture 场景用 TraceableExecutorService 包装，或手动把 traceId 作为参数传进任务。

1.9 清单

  1. Sleuth 自动给日志加 [服务,traceId,spanId]，Boot 3 换 Micrometer Tracing
  2. Feign / RestTemplate / Gateway / MQ 都能自动透传，手写 HttpClient 必须手动补头
  3. 日志 pattern 统一用 %X{traceId:-}，各服务一致才能串起来
  4. 线程池与异步任务会丢 MDC，用 TraceableExecutorService 包装
  5. 生产采样率别开 1.0，0.1~0.3 足够定位问题
  6. Zipkin 的 Dependency 视图直接告诉你哪一跳慢
  7. 采样标记贯穿全链路，不会出现半条链路
