Sentinel 流控与熔断降级

一个慢接口能把整条链路拖死：线程池占满、上游等超时、调用方层层堆积。Sentinel 的两件事就是保住系统——限制进来的流量（流控），切掉坏掉的依赖（熔断 + 降级）。

流量越过闸门，熔断后就切断并发回兜底

1.1 接入

<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
</dependency>
spring:
  cloud:
    sentinel:
      transport:
        dashboard: 127.0.0.1:8858      # 控制台地址，配了才会被"懒加载"进来
        port: 8719                     # 客户端与服务端通信端口
      eager: true                      # 立即初始化，不懒加载

启动后访问控制台 http://127.0.0.1:8858（默认账号 sentinel/sentinel），在「簇点链路」里能看到所有被监控的接口。

1.3 熔断规则

熔断看的是”坏”，不是”多”：

慢调用比例
统计窗口内慢请求占比超过阈值 → 熔断
下游变慢
异常比例
异常数占比超过阈值 → 熔断
下游报错
异常数
窗口内异常数超过阈值 → 熔断
下游挂了

关键参数：

  • 统计时长（默认 1000ms）
  • 最小请求数（默认 5，样本不足不触发，避免误判）
  • 最大 RT（超过即算慢调用，如 200ms）
  • 比例阈值（如 0.5 表示一半是慢调用就熔断）
  • 熔断时长（熔断后多久进入半开探测）

1.4 代码侧：定义资源与降级

@GetMapping("/{id}")
@SentinelResource(value = "userById",
        blockHandler = "handleBlock",        // 被限流/熔断时走它
        fallback = "handleFallback")         // 业务异常时走它
public User findById(@PathVariable Long id) {
    if (id == 1) throw new RuntimeException("测试异常");
    return userService.getById(id);
}

// 签名必须与原方法一致，末尾多一个 BlockException
public User handleBlock(Long id, BlockException ex) {
    return new User(id, "限流降级用户");
}

public User handleFallback(Long id, Throwable t) {
    return new User(id, "异常降级用户");
}
回调
触发条件
签名要求
blockHandler
被流控/熔断拦截
参数一致 + 末尾 BlockException
fallback
业务抛异常
参数一致 + 末尾 Throwable
defaultFallback
全局兜底
无参或单个 Throwable
exceptionsToIgnore
指定异常不走 fallback
数组

fallback 与 blockHandler 同时存在时，限流走 block、业务异常走 fallback，两者不冲突。

1.5 Feign 整合

feign:
  sentinel:
    enabled: true

打开后 Feign 调用自动成为 Sentinel 资源，可以在控制台给 Feign 客户端配熔断规则，降级用 fallbackFactory（见第三篇）。

1.6 规则持久化

控制台配的规则默认在内存，重启就丢。生产必须持久化到 Nacos：

<dependency>
    <groupId>com.alibaba.csp</groupId>
    <artifactId>sentinel-datasource-nacos</artifactId>
</dependency>
spring:
  cloud:
    sentinel:
      datasource:
        ds1:
          nacos:
            server-addr: 127.0.0.1:8848
            dataId: user-service-sentinel
            data-type: json
            rule-type: flow
[
  {
    "resource": "/user/{id}",
    "limitApp": "default",
    "grade": 1,
    "count": 100,
    "strategy": 0,
    "controlBehavior": 0,
    "clusterMode": false
  }
]

strategy: 0 为直接限流，controlBehavior: 0 为快速失败。

1.9 清单

  1. 流控限”进来的量”，熔断看”下游的坏”，两件事不要混用
  2. 快速失败适合保护，排队等待只给必须削峰的批量任务
  3. blockHandler 接限流熔断，fallback 接业务异常，签名都多一个参数
  4. Feign 打开 feign.sentinel.enabled 后可直接在控制台配规则
  5. 控制台规则默认内存态，生产必须持久化到 Nacos
  6. 阈值按压测的 70% 定，最小请求数别太小
  7. 降级返回兜底对象，保证主链路能继续
