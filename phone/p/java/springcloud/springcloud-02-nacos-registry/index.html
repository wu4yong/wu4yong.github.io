Spring Cloud（二）Nacos 服务注册与发现

分类：java · springcloud ｜ 标签：SpringCloud

Nacos 服务注册与发现

拆成多个服务之后，第一个问题就是”对方在哪”。硬编码 IP 迟早失效，Nacos 正是为此存在：服务启动时把自己登记上去，调用方按服务名查询可用实例，实例挂了自动剔除。

服务节点向注册中心心跳上报，调用方按名查找

1.1 启动 Nacos

# 单机模式（2.x/1.x 通用启动脚本）
sh startup.sh -m standalone
# 控制台
# http://localhost:8848/nacos  默认 nacos/nacos

生产环境用集群 + MySQL 持久化：

# conf/application.properties
spring.datasource.platform=mysql
db.num=1
db.url.0=jdbc:mysql://127.0.0.1:3306/nacos_config?characterEncoding=utf8&serverTimezone=UTC
db.user.0=nacos
db.password.0=nacos

1.2 服务注册

spring:
  application:
    name: user-service
  cloud:
    nacos:
      discovery:
        server-addr: 127.0.0.1:8848
        namespace: public
        group: DEFAULT_GROUP

启动类加注解（2.2.x 之后可以省略，但显式写上更清晰）：

@EnableDiscoveryClient
@SpringBootApplication
public class UserApplication { ... }

启动后控制台「服务管理 → 服务列表」能看到 user-service，详情里显示实例 IP、端口、权重、健康状态。

多网卡（虚拟机、Docker）场景最常见的问题：注册上去的是 172.17.0.1，调用方根本连不上。手写 spring.cloud.nacos.discovery.ip 解决。

1.4 服务发现方式

方式一，直接用 DiscoveryClient：

@Autowired
private DiscoveryClient discoveryClient;

public List<ServiceInstance> instances() {
    return discoveryClient.getInstances("user-service");
}

方式二（推荐），交给负载均衡与 Feign，见第三篇。

临时实例 vs 持久实例：临时实例适合”随时可复制、可下线”的无状态服务；持久实例适合需要保留实例清单的场景（如运维要知道历史上线过哪些节点）。

1.5 命名空间做环境隔离

namespace: dev    → dev 环境的服务只看见 dev 的服务
namespace: test
namespace: prod
隔离手段
粒度
适用

dev/test/prod 完全隔离

业务线级

好处是同一套代码、同一套配置模板，靠 namespace 参数切换环境，不用改服务名。

1.6 健康检查与实例摘除

现象
原因
处理
调用方偶尔报连接超时
实例已挂但还在列表里
缩短 heart-beat-timeout，或接熔断
控制台显示”不健康”
心跳超时
查网络与 heart-beat-interval
实例反复上下线
服务启动慢于心跳
调大 heart-beat-timeout
同 IP 多实例冲突
多网卡/容器
显式指定 ip 与 port

Nacos 的剔除是”标记不健康 + 负载均衡跳过”，不是立刻删除，因此下游组件（Feign、Gateway）必须具备重试与熔断，否则一次超时就会把请求打到坏节点上。

1.7 常用运维接口

# 查服务实例列表
curl "http://127.0.0.1:8848/nacos/v1/ns/instance/list?serviceName=user-service"

# 查某个实例详情
curl "http://127.0.0.1:8848/nacos/v1/ns/instance?serviceName=user-service&ip=192.168.1.10&port=8081"

# 手动下线（灰度摘流用）
curl -X PUT "http://127.0.0.1:8848/nacos/v1/ns/instance?serviceName=user-service&ip=192.168.1.10&port=8081&enabled=false"

灰度发布时先调 enabled=false 摘掉实例，等存量请求走完再停进程，比直接 kill 安全。

1.9 清单

  1. spring.application.name 就是服务名，注册与发现都以它为准
  2. namespace 做环境隔离，group 做业务分组，别用改服务名的方式区分环境
  3. 临时实例心跳一停就删，持久实例保留但标不健康
  4. 多网卡机器必须显式配置 discovery.ip，否则注册的是内网地址
  5. 实例摘除是”标记”不是”删除”，下游必须有重试和熔断
  6. 灰度用 OpenAPI 手动 enabled=false 摘流，比 kill 进程稳
  7. 排查”注册不上”先看 namespace 是否一致、artifactId 是否引对
