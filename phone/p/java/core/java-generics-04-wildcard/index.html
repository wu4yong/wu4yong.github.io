Java 泛型（四）类型通配符

分类：java · core ｜ 标签：Java

类型通配符：extends 与 super

泛型不变带来一个副作用：List<String> 传不进 List<Object> 参数。通配符就是编译器给的受控出口——? extends T 放宽了”能接受哪些类型”，同时也明确了”哪些操作被禁止”。记一句话：PECS，Producer Extends, Consumer Super。

通配符的两条方向：extends 向上收窄只读，super 向下放宽只写

1.1 三种形式

形式
名称
能接什么
方法体里能做什么
List<?>
无界通配符
任意 List<T>
只能 size/clear/iterator，不能 add（除 null）
List<? extends T>
上界通配符
List<T> 及其子类型
只能读，读出来的元素类型是 T
List<? super T>
下界通配符
List<T> 及其父类型
只能写 T（及 T 的子类），读出来是 Object
List<? extends Number> a = new ArrayList<Integer>();     // 可以
List<? super Integer> b = new ArrayList<Number>();       // 可以
List<? super Integer> c = new ArrayList<Object>();        // 可以

// List<? extends Number> d = new ArrayList<Object>();   // 不行：Object 不是 Number 的子类型

1.2 为什么需要它：一个真实场景

// 想打印任意类型的列表
public static void printAll(List<Object> list) { ... }

List<Integer> ints = Arrays.asList(1, 2, 3);
printAll(ints);                  // 编译错误：List<Integer> 不是 List<Object>

改成无界通配符：

public static void printAll(List<?> list) {
    for (Object o : list) System.out.println(o);   // 只读，安全
}
printAll(ints);                  // 通过

List<?> 的语义是”我不知道装什么，但我保证不改它”。因此编译器只允许你调用不依赖元素类型的方法（size、isEmpty、clear），add("x") 一律拒绝——因为无法确认列表实际装的是 String 还是 Integer。

1.3 ? extends T：读得出，写不进

List<? extends Number> nums = new ArrayList<Integer>();

Number n = nums.get(0);          // 可以：读出来至少是 Number
// nums.add(1);                  // 编译错误：可能是 List<Double>，塞 int 不安全
// nums.add(1.0);                // 同样错误

再看一个容易混淆的点：读出来是上界类型，不是具体类型。

List<? extends Number> nums = ...;
Integer i = nums.get(0);         // 编译错误：编译器只知道是 Number
Number n = nums.get(0);          // 正确

1.4 ? super T：写得出，读不准

List<? super Integer> sink = new ArrayList<Number>();

sink.add(1);                     // 可以：Integer 一定装得下
Object o = sink.get(0);          // 只能当 Object 读（实际类型可能是 Number 或 Object）
// Integer i = sink.get(0);      // 编译错误

典型用途是”收集结果”：

public static void fill(List<? super Integer> list) {
    for (int i = 0; i < 10; i++) list.add(i);   // 只写
}
fill(new ArrayList<Integer>());    // 可以
fill(new ArrayList<Number>());     // 可以
fill(new ArrayList<Object>());     // 可以

1.5 PECS 原则

Producer Extends, Consumer Super：

参数角色
只看不写（生产数据给你）
只写不读（消费你给的数据）
写法
? extends T
? super T
方法体允许
get
add
典型 JDK 签名
Collection<? extends T> c
Collection<? super T> c

经典案例：Collections.copy(dest, src)：

public static <T> void copy(List<? super T> dest, List<? extends T> src)
  • src 是生产者（读元素给你）→ extends
  • dest 是消费者（收你的元素）→ super

同理：

boolean addAll(Collection<? extends E> c);        // 只是读 c，往里 add
Stream<T> filter(Predicate<? super T> p);         // 谓词消费 T
<R> Stream<R> map(Function<? super T, ? extends R> mapper);   // 一读一写

只要看到 JDK 源码里 super 和 extends 交替出现，用 PECS 一套就通了。

1.6 通配符捕获

编译器在特定场景会把 ? “捕获”成一个匿名的具体类型，让代码能跑：

public static void swap(List<?> list, int i, int j) {
    // swapHelper(list, i, j);      // 直接 list.set(i, list.get(j)) 会编译失败
    swapHelper(list, i, j);
}
private static <T> void swapHelper(List<T> list, int i, int j) {
    T tmp = list.get(i);
    list.set(i, list.get(j));
    list.set(j, tmp);
}

swap 里没法 set（? 不能当类型用），但把同一个列表传给 swapHelper 时，编译器捕获出 T，就能读了写、写了读。这是”通配符不能就地操作时，用私有泛型方法捕获”的标准解法。

1.7 通配符不能用在哪些地方

// 1. 不能声明变量（? 不是类型）
// List<?> list = ... 是合法的（这里 ? 是类型实参位置）
// ? x = null;          // 错误

// 2. 不能作为类型参数传入
// List<List<?>> ok;    合法（? 在实参位置）
// class Foo<?> {}      错误（声明位置不允许 ?）

// 3. 不能 new
// new ArrayList<?>()   错误：无法确定具体类型

1.8 通配符 vs 泛型方法：该用哪个

接口/参数对面（给调用方用）→ 通配符更宽松，接收面更大：

public void log(Collection<?> items) { ... }     // 任何集合都能传

方法体内需要操作类型（要读要写、要声明变量）→ 泛型方法：

public <T> T firstOf(Collection<T> items) { ... }  // 需要返回 T

一句话判断：只”看一眼”用通配符，需要”留住”用泛型方法。

1.9 清单

  1. List<?> 只能读与清空，add 一律禁止（add(null) 除外）
  2. ? extends T 读得出、写不进，读出来的静态类型是 T
  3. ? super T 写得出、读不准，读出来只能当 Object
  4. PECS：生产者用 extends，消费者用 super
  5. Collections.copy、Stream.map 的签名就是 PECS 的教科书
  6. 通配符不能就地读写时，用私有泛型方法”捕获”
  7. ? 只能出现在类型实参位置，不能出现在类声明或 new 里
  8. 对外接口用通配符放宽，方法内部需要保留类型则用泛型方法
