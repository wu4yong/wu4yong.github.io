函数与函数对象

Java 的函数式编程有个前提常被忽略：Java 里没有”函数”这个类型，只有对象。所以一切函数式写法，本质都是”把一段逻辑包装成对象，再把这个对象当参数传”。理解了”函数对象”，后面 Lambda、方法引用、Stream 才不是背语法。

函数在 Java 里被包装成对象后，才可传递、可组合、可缓存

1.1 函数式编程的三条支柱

函数式编程不是”用 Lambda 就算”，它有三条可以验证的支柱：

支柱
含义
在 Java 里怎么落地
一等函数
函数能赋值给变量、能当参数、能当返回值
用函数式接口包装成对象
纯函数
相同输入必得相同输出，不改外部状态
自己约束：不在 Lambda 里改共享变量
不可变
数据尽量只读，改数据 = 造新数据
final 字段、record（Java 14）、List.copyOf

三条里只有第一条是语言强制的，另两条靠约定。所以 Java 的”函数式”更准确的说法是函数式接口 + 不可变数据 + 无副作用约定，而不是”函数式语言”。

1.2 Java 的函数是”接口对象”

函数要能被传递，就必须有个类型。Java 选择的方案是：只有一个抽象方法的接口（Single Abstract Method，SAM）。这个接口的实例就是一个”函数对象”。

// 这就是一个函数式接口：只有一个抽象方法
@FunctionalInterface
interface Transformer {
    String apply(String input);
}

@FunctionalInterface 不做任何魔法，只是让编译器在你多写一个抽象方法时报错。真正起作用的是”只有一个抽象方法”这个结构——它让编译器能从一个 Lambda 推断出要实现的接口。

反过来，任何只有一个抽象方法的接口都能当函数式接口用，哪怕它写在十年前：

// JDK 1.2 就有了，Java 8 之后可以直接传 Lambda
Comparator<String> c = (a, b) -> a.length() - b.length();

Runnable r = () -> System.out.println("run");   // JDK 1.0 的老接口

这就是 Java 8 能平滑升级的原因：没有新造函数类型，只是给老接口找到了新写法。

1.3 演进：从匿名内部类到函数对象

同一个需求——“按字符串长度排序”——三代写法：

// 第一代：匿名内部类（Java 7 及以前）
Collections.sort(list, new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return a.length() - b.length();
    }
});
// 第二代：抽出函数对象，可复用
Comparator<String> byLength = new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return a.length() - b.length();
    }
};
Collections.sort(list, byLength);
// 第三代：函数对象用 Lambda 建，还能组合
Comparator<String> byLength = Comparator.comparingInt(String::length);
list.sort(byLength);
list.sort(byLength.reversed());
list.sort(byLength.thenComparing(Comparator.naturalOrder()));

第三代和第一代的差别不在”代码短”，而在中间产物成了可以复用的值：byLength 能被存进字段、能被 reversed() 派生、能传给别的工具方法。第一代那个匿名对象，除了当场用一次，什么也做不了。

1.4 函数对象能做的三件事

（1）传递：把行为当参数交给框架，框架决定何时调用。这是回调的本质。

// 自己写一个"模板方法"式的工具：把变化的部分当参数传进来
static void withRetry(int times, Runnable task) {
    for (int i = 0; i < times; i++) {
        try {
            task.run();          // 行为由调用方提供
            return;
        } catch (Exception e) {
            if (i == times - 1) throw e;
        }
    }
}

（2）组合：函数对象之间可以串接、取反、并发执行。

Predicate<String> notBlank = s -> !s.trim().isEmpty();
Predicate<String> isLong = s -> s.length() > 20;
Predicate<String> valid = notBlank.and(isLong.negate());

Function<String, String> clean = ((Function<String, String>) String::trim)
        .andThen(String::toLowerCase);

（3）缓存：函数对象是普通对象，可以放进 Map 做”按 key 取策略”。

Map<String, Function<Integer, Integer>> ops = new HashMap<>();
ops.put("inc", x -> x + 1);
ops.put("double", x -> x * 2);
int r = ops.get("double").apply(10);      // 20

用 if/else 写同样的逻辑，新增一种操作就要改分支；换成 Map + 函数对象，新增操作只是多一个 put。这是策略模式在函数式写法下的自然退化。

几个变体是”防装箱”用的：IntFunction、ToIntFunction、IntPredicate、IntUnaryOperator——参数或返回值是 int/long/double 时优先用它们，避免 Integer 装箱。Function 还提供 Function.identity()，常用来当 toMap 的默认值函数。

// 典型对照：装箱 vs 不装箱
Function<String, Integer> boxed = s -> s.length();        // 返回 Integer
ToIntFunction<String> raw = String::length;               // 返回 int，省一次装箱

IntStream.range(0, 1000).map(i -> i * 2);                 // 全 int 链路

1.7 清单

  1. Java 没有函数类型，函数一律被包装成”只有一个抽象方法的接口对象”
  2. @FunctionalInterface 只是编译期检查，真正的约束是”一个抽象方法”
  3. 老接口（Comparator、Runnable）天然可当函数式接口用，这是升级平滑的原因
  4. 函数对象的价值在”可传递、可组合、可缓存”，不是”代码短”
  5. 策略模式用 Map<String, Function> 实现，比 switch 更好扩展
  6. java.util.function 只需记 9 个接口，其余是同族变体
  7. 参数或返回值是基本类型时，选 IntXxx 变体避免装箱
