Java 泛型（三）泛型方法

分类：java · core ｜ 标签：Java

泛型方法

类型参数写在自己名字前面，就是泛型方法——它比泛型类灵活得多：静态方法能用、可以只对某个方法生效、调用时还能靠实参推断出类型不必显式写尖括号。

泛型方法：类型参数写在返回值前，调用时由实参推断

1.1 声明位置：返回值前，修饰符后

public class Util {
    // 泛型方法：<T> 写在修饰符之后、返回值 T 之前
    public static <T> T identity(T value) {
        return value;
    }
}

对比一下泛型类里的普通方法：

public class Box<T> {
    public T get() { return value; }        // 用的是类级 T，不是泛型方法
    public <R> R map(Function<T, R> f) {    // 自己声明 R，是泛型方法
        return f.apply(value);
    }
}

1.2 类型推断：调用时省略尖括号

编译器会根据实参推断类型参数，所以绝大多数调用不用写 <String>：

String s = Util.identity("hello");        // 推断 T = String
Integer i = Util.<Integer>identity(1);    // 也可显式指定（少见）

List<String> empty = Collections.emptyList();               // T 由目标类型推断
Map<String, Integer> m = Collections.emptyMap();            // 由赋值左侧推断

Java 8 之后引入”目标类型推断”，返回值也能参与推断：

List<String> list = Collections.singletonList("a");   // 左侧类型足以推断
Function<String, Integer> f = Collections::emptyList;  // 复杂场景偶有失败

推断失败时（比如链式调用中间层没有上下文），编译器会退回 Object 或报 “cannot infer”，这时显式写尖括号即可。

1.3 常见形态

// 1. 通用工具：交换
public static <T> void swap(T[] arr, int i, int j) {
    T tmp = arr[i]; arr[i] = arr[j]; arr[j] = tmp;
}

// 2. 工厂：延迟创建
public static <T> List<T> listOf(T... items) {
    return new ArrayList<>(Arrays.asList(items));
}

// 3. 带约束：只接受可比较的类型
public static <T extends Comparable<T>> T max(List<T> list) {
    T max = list.get(0);
    for (T t : list) if (t.compareTo(max) > 0) max = t;
    return max;
}

// 4. 组合：转换 + 兜底
public static <T, R> R applyOrDefault(T input, Function<T, R> f, R def) {
    return input == null ? def : f.apply(input);
}

第 3 种的上界 T extends Comparable<T> 是递归边界，JDK 里到处都是（Collections.max、Stream.max 的签名就是这样）。少写一次，compareTo 就编译不过。

1.4 构造器也能泛型

public class Box<T> {
    private T value;

    // 普通构造器：T 来自类的类型参数
    public Box(T value) { this.value = value; }

    // 泛型构造器：自己声明参数，可做额外转换
    public <U extends CharSequence> Box(U src) {
        this.value = (T) src.toString();
    }
}

泛型构造器用得不多，典型场景是”从一种类型构造另一种”（如 Builder 里把 String 构造为 T），但强转会有 unchecked 警告，能避免就避免。

1.5 可变参数与 @SafeVarargs

泛型 + 可变参数 = 泛型数组，天然不安全（原因见第六篇），编译器会给出 unchecked 警告：

@SafeVarargs                       // 只能标在 static / final / private 方法上
public static <T> List<T> listOf(T... items) {
    return new ArrayList<>(Arrays.asList(items));
}

@SafeVarargs 是”我保证不往这个数组里存东西”的承诺书，不是消除警告的万能符。方法体里只要出现”把 items 赋值出去、或往里写元素”，就不能标。

@SafeVarargs
public static <T> void printAll(T... items) {
    for (T t : items) System.out.println(t);   // 只读 → 安全
}

// 危险：把泛型数组暴露出去
static <T> T[] leaky(T... items) { return items; }   // 调用方可能塞错类型

1.6 泛型方法 vs 泛型类：怎么选

一个实用判断：类型参数只需要活一个方法调用周期 → 泛型方法；需要跨方法共享 → 泛型类。

1.7 与通配符的取舍

同一件事，泛型方法和通配符都能表达，但语义不同：

// 写法 A：泛型方法（推荐，因为能捕获具体类型）
public static <T> void copy(List<? super T> dest, List<T> src) { }

// 写法 B：全用通配符（无法在方法体内引用具体类型）
public static void copy2(List<? super Object> dest, List<?> src) { }

区别在于：泛型方法里的 T 是具名的，方法体中能声明 T 类型的变量、能调 T 上的方法；通配符是匿名的，只能读、不能写（细节见下一篇 PECS）。

1.8 清单

  1. 泛型方法把 <T> 写在修饰符之后、返回值之前
  2. 静态方法必须自己声明类型参数，不能用类上的
  3. 调用时通常省略尖括号，由实参 + 目标类型推断
  4. 推断失败（链式调用、三元表达式）时显式写 Util.<T>method(...)
  5. 递归上界 <T extends Comparable<T>> 是排序/最大值类工具的标配
  6. 泛型可变参数会退化成泛型数组，需要 @SafeVarargs 且方法体只读
  7. 类型参数只活一次调用 → 泛型方法；要落到字段 → 泛型类
  8. 方法内要引用具体类型时用泛型方法，只读不写时才用通配符
