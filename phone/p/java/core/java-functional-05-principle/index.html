Java 函数式编程（五）实现原理

分类：java · core ｜ 标签：Java

实现原理：字节码、Sink 与切分

会写之后，值得知道它到底怎么跑。这一篇从 javap 的字节码开始，讲清 Lambda 为什么不是匿名类、方法引用绑的是什么、Stream 的惰性靠什么实现、并行又凭什么叫”可切分”。参考官方文档：LambdaMetafactory https://docs.oracle.com/javase/8/docs/api/java/lang/invoke/LambdaMetafactory.html、Spliterator https://docs.oracle.com/javase/8/docs/api/java/util/Spliterator.html、java.util.stream 包说明。

实现原理的三个现场：invokedynamic、Sink 流水线、ForkJoin 切分树

1.1 先看字节码：Lambda 长什么样

写一个最简单的例子，编译后反汇编：

public class Demo {
    public static void main(String[] args) {
        Runnable r = () -> System.out.println("hi");
        r.run();
    }
}
javac Demo.java && javap -c -p Demo.class

关键几行（省略无关指令）：

0: invokedynamic #2,  0     // InvokeDynamic #0:run:()Ljava/lang/Runnable;
5: astore_1
6: aload_1
7: invokeinterface #3,  1   // InterfaceMethod java/lang/Runnable.run:()V

private static void lambda$main$0();     // 合成方法，Lambda 体在这里

两件事值得记住：

  1. Lambda 体被编译成一个 private static 合成方法（这里是 lambda$main$0）
  2. 调用点是一条 invokedynamic，而不是 new Demo$1 这种匿名类

所以 Lambda 不产生额外的 class 文件，这是它比匿名内部类轻的根本原因。

1.2 invokedynamic 与 LambdaMetafactory

invokedynamic 的语义是”首次执行时再决定怎么调用“。引导方法（bootstrap method）由编译器写进常量池，对 Lambda 而言固定是 LambdaMetafactory：

BootstrapMethods:
  0: #55 REF_invokeStatic java/lang/invoke/LambdaMetafactory.metafactory:
     (Ljava/lang/invoke/MethodHandles$Lookup;Ljava/lang/String;
      Ljava/lang/invoke/MethodType;Ljava/lang/invoke/MethodType;
      Ljava/lang/invoke/MethodHandle;Ljava/lang/invoke/MethodType;)
      Ljava/lang/invoke/CallSite;

metafactory 干的活：在运行时生成一个实现了目标接口的类（只在内存里，不落盘），把 apply/run/accept 转发到那个合成方法。

想亲眼看那个代理类，加启动参数即可：

java -Djdk.internal.lambda.dumpProxyClasses=/tmp/dump Demo
# 会看到 /tmp/dump/Demo$$Lambda$1/xxx.class

1.3 非捕获 Lambda 会被复用

这一点和直觉相反：不捕获任何外部变量的 Lambda，JVM 可以复用同一个实例。

Runnable a = () -> System.out.println("x");   // 不捕获
Runnable b = () -> System.out.println("x");
// a 与 b 可能是同一个对象（实现类被缓存）

int base = 1;
Function<Integer, Integer> c = x -> x + base;  // 捕获了 base
Function<Integer, Integer> d = x -> x + base;
// c 与 d 一定是不同实例：捕获值不同

由此带来两个实践结论：

  • 非捕获 Lambda 没有”每次新建对象”的开销，可以放心在热路径用
  • 捕获型 Lambda 每次求值都要新建实例，如果放在循环里创建、又要长期持有，就会有分配压力

1.4 方法引用绑的是什么

String::length 和 s -> s.length() 编译结果类似，但方法引用可以直接绑定已有方法，不必生成一个转发用的合成方法：

Function<String, Integer> f1 = String::length;   // 直接绑定
Function<String, Integer> f2 = s -> s.length();  // 生成 lambda$... 合成方法

绑定之物是 MethodHandle（REF_invokeVirtual java/lang/String.length）。这也解释了方法引用为什么更快一点：少一层转发。而 System.out::println 属于”绑定到已存在对象”，会把 System.out 这个接收者一并捕获进 CallSite。

1.5 闭包捕获：编译成参数，不是字段

int base = 10;
Function<Integer, Integer> f = x -> x + base;

对应的合成方法签名是：

private static Integer lambda$main$1(int base, Integer x) { return x + base; }

外层变量 base 变成了方法的第一个参数（部分实现会放在合成类的字段里，取决于捕获来源与 JVM 版本，但语义一致：捕获即复制值）。这也解释了那条编译规则：捕获的局部变量必须 effectively final——因为复制的是值，后续再改就会”两份不一致”。

1.6 Stream 的流水线结构

list.stream().filter(...).map(...).collect(...) 在内存里是一条双向链表：

节点
类型
职责
Head
ReferencePipeline.Head
持有源头（集合、Spliterator），提供 spliterator
中间 stage
StatelessOp / StatefulOp
记录操作与上游，生成对应 Sink
终止
TerminalOp
触发 evaluate，把 Sink 链串起来灌数据

核心对象是 Sink（继承 Consumer），三段式协议：

interface Sink<T> extends Consumer<T> {
    default void begin(long size) { }
    void accept(T t);              // 处理一个元素
    default void end() { }
}

终止操作触发时，每个 stage 提供一个 Sink，串成 A -> B -> C，然后源头逐个 accept 下去——数据只走一遍，不是每个操作各遍历一次。这就是 Stream 与”多次 for 循环”的根本差别。

peek 的实现也由此而来：它只是插入一个”顺手打印再转发”的 Sink，转发没被调用（没有终止操作），打印自然不发生。

1.7 惰性与短路怎么实现

  • 惰性：中间操作只构造 stage，不产生 Sink 链，也没有数据流动
  • 短路：limit、findFirst、anyMatch 的 Sink 在处理完所需元素后返回 false（Sink 接口用 boolean 值传递”还要不要继续”），上游据此停止灌数据
// 只处理前 3 个元素，后面的 map 一次都不会执行
Stream.of(1, 2, 3, 4, 5)
      .map(x -> { System.out.println("map " + x); return x; })
      .limit(3)
      .forEach(x -> { });
// 输出：map 1 / map 2 / map 3

注意 limit 位置：放在 map 之前，map 也只会跑 3 次；放错位置就白算。

1.8 Spliterator：并行的物理基础

并行能力来自 Spliterator（splitable iterator），它比 Iterator 多两个方法：

boolean tryAdvance(Consumer<? super T> action);   // 消费一个
Spliterator<T> trySplit();                        // 切一半给自己，一半交出去
long estimateSize();                              // 估算剩余数量
int characteristics();                            // 特征位
特征位
含义
对流水线的影响
ORDERED
有序
并行 findFirst 更贵
SORTED
已排序
可省去 sorted 的开销
DISTINCT
元素唯一
distinct 可被短路优化
SIZED
有确切大小
count 直接返回，不遍历
IMMUTABLE / CONCURRENT
不可变 / 支持并发
决定能否免锁处理

并行执行时，ForkJoin 用 trySplit 递归对半切，切到阈值以下交给工作线程，最后合并结果。所以：

  • ArrayList 的 Spliterator 基于数组下标，trySplit 只是算个中点，几乎零成本
  • LinkedList 只能顺序遍历，切分要走到中点，代价高，parallelStream 常常更慢
  • Stream.iterate 的 trySplit 在 Java 8 里基本不可用（无法高效切分）

这就是”并行前先看源”的物理原因，而不是经验之谈。

1.9 清单

  1. Lambda 编译成一条 invokedynamic + 一个 private static 合成方法，不产生额外 class
  2. 链接发生在首次调用，之后走 CallSite 缓存，可用 -Djdk.internal.lambda.dumpProxyClasses 观察代理类
  3. 非捕获 Lambda 可能被复用同一实例，捕获型每次求值新建
  4. 方法引用直接绑 MethodHandle，比 Lambda 少一层合成方法转发
  5. 闭包捕获是把外部变量当作合成方法的参数复制进去，所以必须 effectively final
  6. Stream 是一条 stage 链表 + 一条 Sink 链，数据只走一遍
  7. 惰性 = 中间操作只建 stage；短路 = Sink 返回”不再需要”
  8. limit 尽量放在 map 之前，让后面的转换少做
  9. 并行靠 Spliterator.trySplit 递归切分，源的切分成本决定并行是否有收益
