Java 函数式编程（四）落地场景

分类：java · core ｜ 标签：Java

落地场景：统计、异步、框架

语法看完不等于会用。这一篇只讲项目里真正会遇到的六类场景：报表统计、集合转换、异步编排、框架集成、事件派发、批处理，每个都给可直接改造的代码片段，并标出踩过的坑。官方 Collectors 文档：https://docs.oracle.com/javase/8/docs/api/java/util/stream/Collectors.html。

函数式的落地面：统计、异步、框架与事件，由一条光轨串起

1.1 场景一：报表统计

一次遍历出多个指标，是 Stream 最实用的能力。

// 基础聚合：一次拿到 count/sum/min/max/avg
IntSummaryStatistics stat = orders.stream()
        .mapToInt(Order::getAmount)
        .summaryStatistics();

// 多级分组：按城市分组，再按状态分区，最后只留金额
Map<String, Map<Boolean, List<Order>>> grouped = orders.stream()
        .collect(Collectors.groupingBy(Order::getCity,
                 Collectors.partitioningBy(o -> o.getStatus() == PAID)));

// 每组 Top3：collectingAndThen 把下游结果再加工
Map<String, List<Order>> top3 = orders.stream()
        .collect(Collectors.groupingBy(Order::getCity,
                 Collectors.collectingAndThen(
                         Collectors.toList(),
                         l -> l.stream()
                               .sorted(Comparator.comparingInt(Order::getAmount).reversed())
                               .limit(3)
                               .collect(Collectors.toList()))));

要点：groupingBy 的下游可以是任意收集器，嵌套两层就是二维报表，不必写双重循环。

1.2 场景二：集合转换与字典

// List → Map（建索引，重复 key 保留先出现的）
Map<Long, User> byId = users.stream()
        .collect(Collectors.toMap(User::getId, Function.identity(), (a, b) -> a));

// List → Map<K, Set<V>>（值去重）
Map<String, Set<String>> tagsByCity = users.stream()
        .collect(Collectors.groupingBy(User::getCity,
                 Collectors.mapping(User::getTag, Collectors.toSet())));

// 对象列表 → DTO 列表（DTO 构造器引用）
List<UserDto> dtos = users.stream()
        .map(UserDto::from)          // 静态工厂
        .collect(Collectors.toList());

// Map → List（entrySet 走流）
List<String> keys = map.entrySet().stream()
        .filter(e -> e.getValue() > 0)
        .map(Map.Entry::getKey)
        .collect(Collectors.toList());

顺带记两个 Map 上的函数式 API，比手写 if 判断干净得多：

// 没有就创建，避免 get-null-check-put
map.computeIfAbsent("k", k -> new ArrayList<>()).add("v");

// 合并：存在则用函数合并，不存在则直接放
map.merge("k", 1, Integer::sum);

// 批量遍历
map.forEach((k, v) -> System.out.println(k + "=" + v));

1.3 场景三：异步编排

CompletableFuture 负责”异步”，Stream 负责”发起一批、统一等齐”。

ExecutorService pool = Executors.newFixedThreadPool(8);

List<CompletableFuture<String>> futures = ids.stream()
        .map(id -> CompletableFuture.supplyAsync(() -> rpc.call(id), pool))
        .collect(Collectors.toList());

CompletableFuture.allOf(futures.toArray(new CompletableFuture[0])).join();
List<String> results = futures.stream()
        .map(CompletableFuture::join)     // 已完成，join 不阻塞
        .collect(Collectors.toList());

更常用的形态是”带异常兜底 + 超时”：

CompletableFuture<String> f = CompletableFuture
        .supplyAsync(() -> rpc.call(id), pool)
        .exceptionally(e -> "fallback")           // 失败降级
        .orTimeout(3, TimeUnit.SECONDS)           // Java 9
        .handle((v, e) -> e == null ? v : "err");  // 统一出口

MyBatis 流式查询的典型用法（必须在事务里消费，否则连接提前关闭）：

@Transactional
public void export() {
    try (Stream<Record> s = mapper.selectStream(query)) {
        s.filter(r -> r.getAmount() > 0)
         .forEach(r -> writer.write(r));
    }
}

1.5 场景五：事件与回调

不引第三方库，用函数对象就能搭一个轻量总线：

public class EventBus {
    private final Map<String, List<Consumer<Event>>> handlers = new ConcurrentHashMap<>();

    public void on(String topic, Predicate<Event> filter, Consumer<Event> handler) {
        handlers.computeIfAbsent(topic, k -> new CopyOnWriteArrayList<>())
                .add(e -> { if (filter.test(e)) handler.accept(e); });
    }

    public void emit(String topic, Event e) {
        handlers.getOrDefault(topic, Collections.emptyList()).forEach(h -> h.accept(e));
    }
}

CopyOnWriteArrayList 保证”注册时可并发、派发时无锁”，适合监听器多、事件少的场景；高频事件场景换成 ConcurrentHashMap + 不可变列表快照。

1.6 场景六：批处理与分片

// 按 100 条一批提交，避免一次性打爆下游
int batch = 100;
List<Order> all = loadOrders();
for (int i = 0; i < all.size(); i += batch) {
    List<Order> slice = all.subList(i, Math.min(i + batch, all.size()));
    slice.stream().map(this::convert).forEach(repo::save);
}

// 用 skip/limit 做内存分页（仅小数据量）
List<User> page = users.stream()
        .skip((pageNo - 1) * size)
        .limit(size)
        .collect(Collectors.toList());

注意 skip(n) 在并行流里代价很高（要跳过前 n 个还得保序），大数据分页请交给数据库。

1.8 清单

  1. 报表统计走 groupingBy + 下游收集器，一次遍历出多维结果
  2. toMap 记得给合并函数，否则重复 key 直接抛异常
  3. computeIfAbsent / merge 能替代大量 get-null-check-put
  4. 异步编排：先 allOf 等齐，再在流里 join 取结果
  5. 所有异步任务都要显式线程池、兜底异常、超时控制
  6. 框架的函数式入口（RouterFunction、selectStream、JsonNode.stream）比自造工具更稳
  7. 事件总线用 Consumer 列表 + Predicate 过滤即可，不必引重型框架
  8. 批处理按批提交，分页交给数据库，别用 skip/limit 硬扛大数据
  9. 流里禁止做 IO 与远程调用，装箱密集的场景用数值流到底
