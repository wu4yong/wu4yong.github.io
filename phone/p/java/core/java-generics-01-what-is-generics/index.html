Java 泛型（一）什么是泛型

分类：java · core ｜ 标签：Java

什么是泛型

泛型解决的是一个非常具体的问题：容器里装什么，编译器不知道。Java 5 之前所有集合都是 Object 的垃圾桶，取出来要强转，转错了就在运行期炸。泛型把这件事挪到了编译期——代价是一整套”能写/不能写”的规则。这一篇先讲清它为什么存在、带来了什么、又有哪些天生的限制。

泛型让容器在编译期就知道自己装什么，取出来不用强转

1.1 没有泛型的年代

List list = new ArrayList();
list.add("hello");
list.add(1);                    // 能编译、能运行

String s = (String) list.get(1); // 运行时 ClassCastException

三处隐患：

  1. 类型错误延后到运行期：编译器完全不拦，只有跑到了才抛 ClassCastException
  2. 每次取值都要强转：(String) list.get(i)，写一百遍
  3. 类型信息被抹平：方法签名 List 看不出装什么，只能靠注释和命名约定

1.2 泛型是什么

泛型 = 参数化类型：把”类型”当作参数传进去。List<String> 与 List<Integer> 是同一个类的不同实例化，它们的差异在编译期就被检查，运行期则被擦除（第五篇详述）。

List<String> list = new ArrayList<>();
list.add("hello");
// list.add(1);                 // 编译错误：类型不兼容
String s = list.get(0);         // 不需要强转

一句话概括收益：把”可能出错”变成”编译不过”。这是 Java 引入泛型的唯一理由，其它所有好处都是副产品。

1.3 三条最直观的收益

（1）类型安全：错放进来的东西编译期就被拦。

Map<String, Integer> scores = new HashMap<>();
scores.put("tom", 90);
// scores.put("tom", "hi");        // 编译错误
int v = scores.get("tom");         // 自动拆箱，无需强转

（2）消除强转：get 直接返回 T（这里是 Integer），转型由编译器插入的 checkcast 完成。

（3）可复用的类型无关代码：一个 Box<T> 既能装 String 也能装 Order，不用为每种类型各写一个类。

public class Box<T> {
    private T value;
    public Box(T value) { this.value = value; }
    public T get() { return value; }
}

Box<String> b1 = new Box<>("x");
Box<Integer> b2 = new Box<>(1);   // 同一个类，两种实例化

1.4 与 C++ 模板的区别

对比项 Java 泛型 C++ 模板
实现方式 类型擦除，只有一份字节码 每个类型实例化一份代码
基本类型 不支持，必须用包装类 支持 vector<int>
运行期类型信息 没有（擦除后是 Object/上界） 有完整类型
编译产物大小 不变 随实例化数量增长

Java 选择擦除的根本原因是向后兼容：Java 5 时 ArrayList、HashMap 已经被全世界用着，不能让老代码和老字节码失效。代价就是后面几篇要讲的一堆”不能”。

1.5 一开始就会撞上的三个限制

// 1. 类型参数不能是基本类型
// List<int> bad;                  // 编译错误
List<Integer> ok = new ArrayList<>();   // 只能装箱

public class Box<T> {
    // T t = new T();               // 编译错误：擦除后不知道 T 是什么

1.6 泛型不是”更强的注释”

一个常见误解：泛型只是”写给编译器看的提示”。实际上它影响三件事：

  1. 编译期检查：直接决定代码能不能编译
  2. 编译器插入代码：取值时的 checkcast、装箱拆箱、桥方法，都是泛型带来的字节码
  3. 反射可见：Signature 属性保留了泛型签名，Spring、Jackson 都靠它做类型推断

所以 List<String> 和 List 的字节码并不相同——后者是一份数据，前者多了一份签名。

1.8 清单

  1. 泛型的唯一核心目的：把类型错误从运行期挪到编译期
  2. List<String>、List<Integer> 是同一个类的不同实例化，运行期类型相同
  3. 基本类型不能作类型参数，只能装箱
  4. 不能 new T()、不能 instanceof T，要用 Class<T> 绕
  5. Java 选类型擦除是为了兼容 Java 5 之前的老集合，代价是运行期没有类型信息
  6. 泛型不只是注释，它会改变字节码（checkcast、桥方法）与反射结果
