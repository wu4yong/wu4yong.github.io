Java 函数式编程（二）Lambda 与方法引用

分类：java · core ｜ 标签：Java

Lambda 与方法引用

上一篇把”函数在 Java 里是接口对象”讲清了，这一篇就落到写法上：Lambda 怎么被编译器推断成某个接口、变量为什么必须 effectively final、方法引用四种形式各自对应什么、函数怎么串成一条链。每个点都配可以直接粘贴运行的例子。

Lambda 与方法引用：从一段逻辑到一个可传递的函数对象

1.1 Lambda 的三要素

一个 Lambda 表达式由三部分组成：

参数列表        ->        表达式体或代码块
(String a, String b) -> a.compareTo(b)
  • 参数列表：类型可省（编译器推断）；只有一个参数时括号也可省（s -> ...）
  • 箭头：->，Java 用文本箭头而不是 =>，没有商量余地
  • 体：单表达式（隐式返回）或代码块（必须显式 return）
// 无参
() -> System.out.println("hi");

// 单参、省略括号与类型
s -> s.length();

// 多参、代码块
(a, b) -> {
    int sum = a + b;
    return sum * 2;
};

1.2 目标类型：Lambda 靠上下文”猜”接口

Lambda 自己没有类型，它的类型来自”目标类型”（target type）。四种常见上下文：

// 1. 变量赋值
Comparator<String> c = (a, b) -> a.length() - b.length();

// 2. 方法入参
list.sort((a, b) -> a.compareTo(b));

// 3. 方法返回值
static Predicate<String> blankChecker() {
    return s -> s.trim().isEmpty();
}

// 4. 强制转型（唯一需要显式写的场景）
Object o = (Runnable) () -> System.out.println("x");

为什么第 4 种少见但重要：当上下文没有类型信息（比如直接传给 Object 参数、或用三元运算符两支都是 Lambda）时，编译器无从推断，就必须强转。

// 三元运算符两支都是 Lambda：必须有共同目标类型
Function<String, Integer> f = flag ? String::length : s -> 0;

// 重载歧义：同一个方法名有两个函数式接口重载，也会报错
// void run(Runnable r);
// void run(Callable<String> c);
// run(() -> "x");   // 编译错误：ambiguous

1.3 变量捕获：为什么必须 effectively final

Lambda 可以读外部的局部变量，但编译器要求它”事实上没被改过”。原因不是语法洁癖，而是实现方式：捕获的局部变量是被当作参数传进合成方法的，不是引用外层栈帧。

int base = 100;                    // 之后没再赋值 → 可捕获
Function<Integer, Integer> plus = x -> x + base;

int count = 0;
count++;                           // 改过 → 不可捕获
// Runnable r = () -> System.out.println(count);   // 编译错误

要改状态，换容器（容器引用本身不变，改的是内容）：

AtomicInteger counter = new AtomicInteger();
list.forEach(s -> counter.incrementAndGet());

int[] buf = new int[1];
list.forEach(s -> buf[0]++);       // 能用，但不推荐：可读性差

还有一个常被误解的点：Lambda 里的 this 指外层实例，不是 Lambda 自己。

class Demo {
    String name = "outer";

    void test() {
        Runnable r = () -> System.out.println(this.name);   // outer
        Runnable anonymous = new Runnable() {
            public void run() { System.out.println(this); } // 匿名类自己的 this
        };
    }
}

在 Lambda 里调 this.name 就是调外层字段；在匿名类里则要先写 Demo.this.name 才行。这一点在写事件监听器时经常导致”取不到外层变量”的错觉。

1.4 方法引用：Lambda 的等价简写

规则只有一条：Lambda 体是”直接调用某个已有方法”，且参数一一对应，就能换成方法引用。

两个高频组合：

// 1. toMap 的 value 直接用对象本身（避免了 Function.identity() 的啰嗦）
Map<Long, User> map = users.stream()
        .collect(Collectors.toMap(User::getId, Function.identity()));

// 2. 方法引用 + 构造器引用做工厂
Supplier<List<String>> listFactory = ArrayList::new;
Function<Integer, String[]> arrFactory = String[]::new;

有个坑要记：this::method 是”绑定到当前对象”，ClassName::method 是”第一个参数当接收者”。两者看起来都能用，但语义不同——前者把 this 提前绑死，后者每次调用用实参当接收者。

class Svc {
    void handle(String s) { }

    void demo() {
        Consumer<String> bound = this::handle;      // 永远是 this 的 handle
        BiConsumer<Svc, String> unbound = Svc::handle;  // 第一个参数决定是谁
    }
}

1.5 函数组合：把逻辑串成链

JDK 的函数式接口自带默认方法做组合，这是”函数对象”相比匿名类最大的实用价值。

// Function 链：trim → 小写 → 去重前缀
Function<String, String> normalize = ((Function<String, String>) String::trim)
        .andThen(String::toLowerCase)
        .andThen(s -> s.replaceFirst("^https?://", ""));

// Predicate 链：组合出校验规则
Predicate<String> notEmpty = s -> !s.isEmpty();
Predicate<String> hasAt = s -> s.contains("@");
Predicate<String> isEmail = notEmpty.and(hasAt);

// Comparator 链：先按年龄降序，年龄相同按名字升序
Comparator<User> cmp = Comparator.comparingInt(User::getAge).reversed()
        .thenComparing(User::getName);

Predicate.and 的短路语义与 && 一致：左边为 false 时右边不执行，所以可以把”便宜且能快速否决”的条件放前面。

1.6 柯里化与高阶函数

柯里化：把 f(a, b) 变成 f(a)(b)。Java 没有语法糖，全靠 Function 套：

// 两参柯里化
Function<Integer, Function<Integer, Integer>> add = a -> b -> a + b;
int r = add.apply(1).apply(2);        // 3

// 三参也能套，但可读性断崖式下降，实际项目里到两层就停
Function<String, Function<String, Function<String, String>>> join =
        sep -> prefix -> suffix -> prefix + sep + suffix;

高阶函数：参数或返回值是函数。项目里真正用到的形态，往往是”工厂式返回函数”：

// 返回一个 Predicate：前缀判断可以复用
static Function<String, Predicate<String>> startsWithFactory() {
    return prefix -> s -> s.startsWith(prefix);
}
Predicate<String> isJavaFile = startsWithFactory().apply("Java");

// 返回 Comparator：按任意字段排序
static <T, U extends Comparable<U>> Comparator<T> by(Function<T, U> key) {
    return Comparator.comparing(key);
}
list.sort(by(User::getName));

Comparator.comparing(...)、Collectors.groupingBy(...)、Collectors.mapping(...) 都是这个形状——接收函数、返回函数对象，所以它们才能层层嵌套。

1.7 五个常见坑

  1. 异常处理：函数式接口不声明受检异常，Function 里调 readFile() 会编译不过。要么在 Lambda 内 try-catch，要么包一个辅助方法：
static <T, R> Function<T, R> unchecked(ThrowingFunction<T, R> f) {
    return t -> {
        try { return f.apply(t); }
        catch (Exception e) { throw new RuntimeException(e); }
    };
}

  1. 装箱：Function<Integer, Integer> 在大数据量下每秒可能多几百万次装箱，改用 IntUnaryOperator。

  2. 副作用：forEach 里往外部 ArrayList 塞数据，串行没问题，改成 parallelStream 立刻线程不安全。要么 collect，要么用并发容器。

  3. 重载歧义：同名方法有两个函数式接口重载时，Lambda 无法推断，用匿名类或转型消歧。

  4. null 判断：Predicate 链里忘了判空，s -> s.length() 碰到 null 直接 NPE，常在 filter 中招。

1.8 清单

  1. Lambda 的类型由目标类型决定，赋值、入参、返回都能推断，必要时显式转型
  2. 捕获的局部变量必须 effectively final，要改状态用 AtomicInteger 这类容器
  3. Lambda 里的 this 是外层实例，跟匿名类的 this 不是一回事
  4. 方法引用的判断标准：Lambda 体是否”直接调用已有方法”
  5. this::m 绑定当前对象，Klass::m 用第一个参数当接收者，别混用
  6. 函数组合优先用自带的 andThen/compose/and/or/negate/thenComparing
  7. 柯里化在 Java 里两层就够，再深就是可读性灾难
  8. 受检异常要包一层 unchecked，否则整条 Stream 链都写不下去
