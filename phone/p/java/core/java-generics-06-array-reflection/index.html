分类：java · core ｜ 标签：Java

泛型的边界：数组与反射

数组是协变的、运行期要检查元素类型；泛型是不变的、运行期没有类型。两者硬碰就产生”不能创建泛型数组”。反过来，反射能读到 Signature 里的泛型声明，所以”泛型 + 反射”又是框架做类型推断的唯一出路。

数组要运行期类型，泛型没有运行期类型——两者交界处就是”不能创建泛型数组”

1.1 为什么不能 new T[]

class Box<T> {
    // T[] arr = new T[10];          // 编译错误：generic array creation
    // List<String>[] l = new List<String>[10];   // 同样错误
    List<String>[] raw = new List[10];            // 只能造裸数组（unchecked 警告）
}

原因拆成两句话：

  1. 数组在运行期知道自己的元素类型，创建时必须确定（new String[3] 的类就是 String[]）
  2. 泛型在运行期没有类型，T 已被擦除，编译器无法生成”元素类型是 T 的数组”

再叠加数组的协变性，就会出现类型漏洞：

Object[] objs = new String[3];         // 数组协变，允许
objs[0] = 123;                         // 运行期抛 ArrayStoreException

如果允许 List<String>[] arr = new List<String>[3]，那么：

Object[] o = arr;                      // 协变 → 合法
o[0] = new ArrayList<Integer>();       // 数组检查只看"List"，放进去了
List<String> x = arr[0];               // 从"字符串列表"里拿出整数 → ClassCastException

也就是说，允许创建泛型数组会破坏类型安全，而且检查点在数组层（List）而不是元素层（String）。编译器选择直接禁止。

// 反射创建真正的泛型数组
@SuppressWarnings("unchecked")
static <T> T[] newArray(Class<T> type, int n) {
    return (T[]) Array.newInstance(type, n);        // 运行期类型是 type[]
}

String[] arr = newArray(String.class, 5);           // 得到真正的 String[]

这是 ArrayList.toArray 的实现思路（Arrays.copyOf 内部同样按运行期类型建数组）。

1.3 可变参数就是泛型数组

static <T> void print(T... items) { }      // items 实际是 T[]

所以泛型可变参数天然带 unchecked 警告，@SafeVarargs 只应标在”方法体不把数组暴露出去”的情况下：

@SafeVarargs
static <T> List<T> listOf(T... items) {
    List<T> r = new ArrayList<>();
    Collections.addAll(r, items);           // 只读数组，安全
    return r;
}

// 危险：返回数组本身
static <T> T[] leak(T... items) { return items; }
// 调用方可能把 Integer 塞进"String[]"里 → 后续 ArrayStoreException

// 读字段的泛型类型
Field f = Repo.class.getDeclaredField("items");
ParameterizedType pt = (ParameterizedType) f.getGenericType();
System.out.println(pt.getRawType());                    // interface java.util.List
System.out.println(pt.getActualTypeArguments()[0]);     // class java.lang.String

Class<?> entity = (Class<?>) sup.getActualTypeArguments()[0];

// 读方法返回值

Type ret = m.getGenericReturnType();                    // List<Order>

1.5 框架怎么用：TypeToken 与 ResolvableType

手写一个 TypeToken（Gson 的思路）：把泛型信息藏在匿名子类的父类签名里，因为类签名不会被擦除。

public abstract class TypeRef<T> {
    private final Type type;

    protected TypeRef() {
        ParameterizedType sup = (ParameterizedType) getClass().getGenericSuperclass();
        this.type = sup.getActualTypeArguments()[0];
    }
    public Type getType() { return type; }
}

// 用法：必须写成匿名子类，才能保留 <List<String>> 这段签名
Type t = new TypeRef<List<String>>() { }.getType();
System.out.println(t);      // java.util.List<java.lang.String>

Jackson 对应 new TypeReference<List<Order>>() {}，原理完全一致。

Spring 用 ResolvableType 把这套逻辑封装成可链式查询：

ResolvableType rt = ResolvableType.forClass(Repo.class).as(Collection.class);
Class<?> generic = rt.getGeneric(0).resolve();      // Order

1.6 instanceof 的替代方案

擦除让 instanceof T 不可用，标准替代是把 Class<T> 传进来：

class Box<T> {
    private final Class<T> type;
    public Box(Class<T> type) { this.type = type; }

    public boolean accept(Object o) { return type.isInstance(o); }

    @SuppressWarnings("unchecked")
    public T cast(Object o) { return type.cast(o); }     // 类型不对直接抛 CCE
}

这也是 Class.cast 存在的意义：把”运行期类型检查”这件事显式交给你，而不是让编译器猜。

1.8 清单

  1. new T[] 与 new List<String>[] 都编译不过，因为数组要运行期类型、泛型没有
  2. 数组协变 + 数组元素检查只看原始类型，是”禁止泛型数组”的真正理由
  3. 合法兜底三种：裸数组 new List[10]、(T[]) new Object[10]、Array.newInstance
  4. 泛型可变参数就是泛型数组，@SafeVarargs 只在”不外泄数组”时可用
  5. 反射能读到声明层泛型：ParameterizedType、TypeVariable、WildcardType
  6. TypeRef/TypeReference 靠匿名子类的父类签名保住泛型实参
  7. instanceof T 的替代是 Class<T>.isInstance 与 cast
  8. 能用集合就别用数组，数组只在性能敏感或 API 约定需要时上
