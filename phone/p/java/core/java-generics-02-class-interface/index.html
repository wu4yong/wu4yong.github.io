Java 泛型（二）泛型类与接口

分类：java · core ｜ 标签：Java

泛型类与接口

类型参数声明在类名后面，就成了泛型类；声明在接口名后面，就成了泛型接口。规则不多，但”继承怎么传、静态成员为什么不能用、List<String> 为什么不是 List<Object> 的子类型”这三处，几乎每个人都会踩一次。

泛型类与泛型接口：类型参数写在类名或接口名后的尖括号里

1.1 泛型类的声明

public class Box<T> {          // T 是类型参数，作用域是整个类体（静态成员除外）
    private T value;

    public Box() { }
    public Box(T value) { this.value = value; }

    public T get() { return value; }
    public void set(T value) { this.value = value; }
}

使用：

Box<String> b = new Box<>("hello");   // 菱形推断，Java 7+
String s = b.get();

1.2 多类型参数与上界

// 两个独立参数
public class Pair<K, V> {
    private final K key;
    private final V value;
    public Pair(K key, V value) { this.key = key; this.value = value; }
    public K getKey() { return key; }
    public V getValue() { return value; }
}

Pair<String, Integer> p = new Pair<>("age", 18);

// 带上界：T 必须是 Comparable 的子类型，才能调 compareTo
public class SortedHolder<T extends Comparable<T>> {
    public int cmp(T a, T b) { return a.compareTo(b); }   // 有上界才编译得过
}

// 多重上界：多个接口用 & 连接，最多一个类且必须写在最前面
public class Repo<T extends Serializable & Comparable<T>> { }

上界决定了擦除后的实际类型（见第五篇）：T 无界 → Object，T extends Number → Number。

1.3 泛型接口

public interface Converter<S, T> {
    T convert(S source);
}

// 实现方式一：固定类型参数
public class StringToIntConverter implements Converter<String, Integer> {
    public Integer convert(String source) { return Integer.valueOf(source); }
}

// 实现方式二：继续泛型
public class IdentityConverter<T> implements Converter<T, T> {
    public T convert(T source) { return source; }
}

JDK 里泛型接口遍地都是：Comparable<T>、Iterable<T>、Function<T,R>、Collector<T,A,R>。理解了这三个声明位置，读 JDK 源码会顺很多。

裸类型（Box 不带尖括号）只在两种场合出现：老代码、以及 Class 字面量（Box.class 本来就是裸的）。

1.5 静态成员为什么不能用类类型参数

public class Box<T> {
    // private static T shared;          // 编译错误：不能从静态上下文引用 T
    private static final List<String> ALL = new ArrayList<>();  // 可以：自己声明类型
}

原因直白：静态成员属于类本身，不属于某个实例化。Box<String> 与 Box<Integer> 共享同一份静态区，T 在这里没有确定值，编译器只能拒绝。

需要静态的”泛型”行为时，改用静态泛型方法（下一篇），它自己声明类型参数：

public static <T> Box<T> of(T value) { return new Box<>(value); }

1.6 List<String> 不是 List<Object> 的子类型

这一点是最反直觉的：Java 泛型是不变的（invariant），List<String> 与 List<Object> 之间没有任何赋值关系。

List<Object> objs = new ArrayList<>();
List<String> strs = new ArrayList<>();

// objs = strs;   // 编译错误：incompatible types

假如允许赋值，会发生什么：

List<String> strs = new ArrayList<>();
List<Object> objs = (List<Object>) (List<?>) strs;   // 强转能过（擦除）
objs.add(123);                                       // 往"字符串列表"里塞了整数
String s = strs.get(0);                              // ClassCastException

也就是说，允许协变就会破坏类型安全。所以编译器宁可禁止，再给你一个”通配符”的受控出口（第四篇）。

数组协变是历史遗留（String[] 能赋给 Object[]，运行时靠 ArrayStoreException 兜底），泛型没有沿用这套做法——这是第六篇要讲的重点。

1.7 嵌套泛型与常见写法

Map<String, List<Order>> grouped;                      // 两层
Map<Long, Map<String, Integer>> matrix;                // 三层（可读性开始崩）
List<? extends Number> numbers;                        // 通配符（下一篇）

// 泛型与集合的经典组合：构造器注入时用菱形推断
Map<String, List<String>> m = new HashMap<>();         // 右侧不用重复写类型

经验：嵌套超过两层就抽一个类型别名类或 DTO，Map<Long, Map<String, List<Integer>>> 这种东西维护成本远高于多写一个类。

1.8 清单

  1. 类型参数写在类名/接口名后，作用域是整个类型（静态成员除外）
  2. T/E/K/V/R 只是命名惯例，真正的约束靠上界
  3. 多重上界用 & 连接，类只能有一个且必须写在最前
  4. 实现泛型接口有两种：固定类型参数、透传类型参数
  5. 裸类型能编译但会关闭泛型检查，除了 Class 字面量都别用
  6. 静态成员不能用类级类型参数，需要时改成静态泛型方法
  7. Java 泛型不变：List<String> 与 List<Object> 无赋值关系
  8. 嵌套超过两层就抽类型别名，可读性比省代码重要
