分类：java · springdata ｜ 标签：SpringData

Spring Data Redis：模板、Repository 与缓存

Redis 在项目里有三种用法：KV 缓存、对象存储、计数器/分布式锁。Spring Data Redis 把前两种做成 RedisTemplate 与 RedisRepository，第三种交给你自己用 opsForXxx()。

应用与键值存储之间双向读写

1.1 配置与序列化

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>

默认 RedisTemplate 用 JDK 序列化，存进去的值带一堆不可读的二进制前缀，还会因为类变更反序列化失败。生产必换：

@Configuration
public class RedisConfig {

    @Bean
    public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
        RedisTemplate<String, Object> t = new RedisTemplate<>();
        t.setConnectionFactory(factory);
        GenericJackson2JsonRedisSerializer json = new GenericJackson2JsonRedisSerializer();
        t.setKeySerializer(new StringRedisSerializer());
        t.setHashKeySerializer(new StringRedisSerializer());
        t.setValueSerializer(json);
        t.setHashValueSerializer(json);
        t.afterPropertiesSet();
        return t;
    }
}

Bean 名字必须是 redisTemplate，否则自动配置的 @ConditionalOnMissingBean(name="redisTemplate") 判定不通过，会出现两个模板，注入报歧义。

1.3 缓存三件套

// 1. 读：先查缓存
String key = "user:" + id;
User user = (User) redisTemplate.opsForValue().get(key);
if (user == null) {
    user = userRepository.findById(id).orElse(null);
    if (user != null) {
        redisTemplate.opsForValue().set(key, user, Duration.ofMinutes(30));
    }
}

1.4 RedisRepository（对象直接映射）

@RedisHash(value = "user", timeToLive = 1800)
public class UserCache {
    @Id
    private Long id;
    @Indexed
    private String username;
    private Integer age;
}
public interface UserCacheRepository extends CrudRepository<UserCache, Long> { }
注解
作用
@RedisHash
哈希前缀 + TTL
@Id
主键，生成 <prefix>:<id>
@Indexed
建立二级索引（prefix:username:xxx → id 集合）
@Reference
关联另一个 RedisHash

@Indexed 会额外维护索引集合，写入成本翻倍，只给确实要按该字段查询的属性加。

1.5 分布式锁

public boolean tryLock(String key, String value, long seconds) {
    Boolean ok = redisTemplate.opsForValue()
            .setIfAbsent(key, value, Duration.ofSeconds(seconds));
    return Boolean.TRUE.equals(ok);
}

public void unlock(String key, String value) {
    // 必须用 Lua 保证"判断是自己的锁 + 删除"原子
    String script = "if redis.call('get', KEYS[1]) == ARGV[1] then " +
                    "return redis.call('del', KEYS[1]) else return 0 end";
    redisTemplate.execute(new DefaultRedisScript<>(script, Long.class),
            Collections.singletonList(key), value);
}

三件事不能省：SETNX 带过期、value 带唯一标识、解锁用 Lua 比对。少任何一条都会出现”删了别人的锁”或”锁永不释放”。

1.8 清单

  1. value 序列化换 JSON，JDK 序列化不可读且不兼容
  2. 自定义模板的 Bean 名必须是 redisTemplate，否则与自动配置冲突
  3. 缓存穿透用空值 + 布隆过滤器，击穿用锁或逻辑过期，雪崩靠随机 TTL
  4. @RedisHash 的 @Indexed 写入成本翻倍，只给必需字段加
  5. 分布式锁必须 SETNX + 过期 + 唯一 value + Lua 解锁
  6. 简单结果缓存用 @Cacheable，复杂结构用 RedisTemplate
  7. 大 key 与热 key 都要提前拆，Redis 单线程，一个大 key 能拖慢全库
