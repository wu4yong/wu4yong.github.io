网络配置与排障

“服务连不上”是运维最高频的工单。把网络拆成四层去查：本机有没有地址、路由通不通、端口有没有在听、对端有没有放行。每一层都有一条对应命令，按顺序跑一遍就能定位。

网络排障路径：本机网卡 → 网关 → DNS → 外网端口

6.1 通俗小故事：前台电话线

网络是一栋写字楼的电话系统：
● IP 地址是内部分机号，ip addr 是本机号码簿
● 网关是总机，出楼必须经过它，ip route 是总机的转接表
● 端口是房间号，ss -lntp 是本楼层哪个房间有电话机
● DNS 是查号台，把”域名”翻成”分机号”
● 防火墙是门卫，号码对、门卫不放行也白搭

排障就是按”号码 → 总机 → 房间 → 门卫”的顺序问一遍。

6.2 本机地址与路由

ip addr                          # 所有网卡的地址（替代 ifconfig）
ip addr show eth0
ip route                         # 路由表，看 default 指向谁
ip route get 8.8.8.8             # 到某地址会走哪条路由
ip neigh                         # ARP 邻居表

临时改地址与路由（重启失效）：

ip addr add 10.0.0.20/24 dev eth0
ip route add 192.168.0.0/16 via 10.0.0.1

持久化配置按发行版走：Debian/Ubuntu 用 /etc/netplan/*.yaml 或 /etc/network/interfaces；RHEL 系用 /etc/sysconfig/network-scripts/ifcfg-eth0 或 NetworkManager 的 nmcli。

6.3 连通性四连测

ping -c 4 10.0.0.1                # 二层/三层通不通
ping -c 4 baidu.com               # 带 DNS 解析，能通说明网络+DNS 都行
nc -zv 10.0.0.20 3306             # 端口是否可连（最直接）
telnet 10.0.0.20 3306             # 没装 nc 时的替代
curl -v http://10.0.0.20:8080/health   # 应用层是否响应
curl -o /dev/null -s -w "%{http_code} %{time_total}\n" http://localhost:8080

ping 通不代表端口通：中间可能有防火墙只放行特定端口。nc -zv 失败也不一定是对端问题，本机出站策略也可能拦。

6.4 谁在监听端口

ss -lntp                          # TCP 监听 + 进程
ss -lnup                          # UDP 监听
ss -s                             # 连接状态汇总（TIME_WAIT 多不多）
ss -tnp state established '( dport = :443 )'
lsof -i :8080                     # 反向：哪个进程占了 8080

ss 替代了 netstat，速度快、信息全。看监听地址很关键：0.0.0.0:8080 是全接口，127.0.0.1:8080 只有本机能连——容器里常见”宿主机连不上”就是这个原因。

6.5 DNS 解析

cat /etc/resolv.conf              # 用的是哪个 DNS
getent hosts api.example.com      # 走系统解析链（含 /etc/hosts）
dig api.example.com +short        # 只看结果
dig @8.8.8.8 api.example.com      # 指定 DNS 对比
dig api.example.com ANY +noall +answer

“能 ping 通 IP、ping 不通域名”就是 DNS 问题；”解析到旧 IP”要查 /etc/hosts 是否写死、DNS 是否有缓存、TTL 是否太长。

6.6 抓包：最后的证据

tcpdump -i eth0 -nn port 8080 -c 20          # 抓 20 个包看流量方向
tcpdump -i any -nn host 10.0.0.20 and port 3306
tcpdump -i eth0 -nn -A port 80 | grep -i host
tcpdump -w /tmp/cap.pcap -i eth0 port 8080   # 存文件给 Wireshark 分析

抓包能一眼看出是”根本没包过去”（对端/防火墙）还是”包到了但没响应”（应用没起来）。这是判断责任边界最快的方式。

6.7 防火墙

# firewalld（RHEL 系）
firewall-cmd --state
firewall-cmd --list-all
firewall-cmd --permanent --add-port=8080/tcp && firewall-cmd --reload

# ufw（Ubuntu）
ufw status verbose
ufw allow 22/tcp
ufw allow from 10.0.0.0/24 to any port 3306

规则的核心原则：默认拒绝入站、只放必要端口、管理端口限定来源网段。改完一定验证 --list-all 或 ufw status，别改完顺手 ssh 断线。

6.8 排障套路

  1. ip addr 确认本机地址、ip route 确认网关
  2. ping 网关 → ping 对端 IP → ping 域名（分层定位）
  3. nc -zv 目标端口，不通再查对端 ss -lntp 与防火墙
  4. 通但业务报错，curl -v 看状态码与响应头
  5. 仍无头绪，tcpdump 抓包看包到底走到哪
  6. 容器场景额外查端口映射与网络模式

6.9 清单

  1. 用 ip、ss 替代 ifconfig、netstat
  2. 监听地址区分 0.0.0.0 与 127.0.0.1
  3. 端口测试用 nc -zv，应用层用 curl -v
  4. ss -s 看 TIME_WAIT，别把连接泄漏当网络故障
  5. 抓包是判断责任边界的最快手段
  6. 防火墙改完立即验证，管理端口限来源
