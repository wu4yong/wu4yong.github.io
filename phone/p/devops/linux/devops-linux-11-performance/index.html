性能排查

“机器卡了”这句话信息量为零。性能排查的第一件事是把”卡”翻译成四个指标之一：CPU、内存、磁盘 IO、网络。四条命令先跑一遍，方向立刻明确，剩下才是细挖。

性能排查四象限：CPU / 内存 / 磁盘 / 网络

11.1 通俗小故事：体检

排查性能像体检，先量身高体重，再做专项。
● uptime 是体温计，看负载
● vmstat 是血常规，一眼看 CPU/内存/IO/上下文切换
● iostat 是拍片，看每块盘忙不忙
● free 是称体重，看内存与 swap
● strace 是穿刺活检，看某个进程卡在哪个系统调用

先粗后细，别一上手就 strace。

11.2 负载与整体

uptime
# 09:12:00 up 3 days,  load average: 0.85, 1.20, 2.40

三个数分别是 1、5、15 分钟的平均负载。判断标准是”和核数比”：

nproc                        # 核数

● 4 核机器负载 4 左右是满载，长期大于核数说明排队
● 负载高但 CPU 使用率低，多半是 IO 等待或 D 状态进程

11.3 vmstat：一屏看全

vmstat 1 5
# procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
#  r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st

看三处：
● r（runnable）持续大于核数 → CPU 排队
● b（blocked）非 0 → 有进程卡在 IO
● wa（IO 等待）高 → 磁盘慢；si/so 持续非 0 → 在换页，内存不足

vmstat 1 适合看瞬时波动，vmstat 1 60 用它出一分钟快照贴工单。

11.4 iostat：每块盘的忙闲

iostat -x 1 5
# Device  r/s  w/s  rkB/s  wkB/s  await  %util

● %util 接近 100 → 盘被压满
● await 明显偏高（机械盘 > 20ms，SSD > 5ms）→ 响应变慢
● aqu-sz 队列长 → 请求在排队

配合 iotop -oPa 找具体是哪个进程在读写。

11.5 内存与 swap

free -h
#               total  used  free  shared  buff/cache  available

只看 available，不看 free。Linux 会把空闲内存拿去做缓存，free 低是正常现象，available 才是”还能给应用多少”。

ps aux --sort=-%mem | head -5
cat /proc/meminfo | grep -E "MemAvailable|SwapTotal|Dirty"
swapoff -a && swapon -a          # 回收 swap（会慢，择时执行）

swap 长期被大量使用（si/so 持续非 0），说明内存真的不够，应扩内存或降 Xmx，而不是调大 swap。

11.6 sar：历史趋势

sar -u 1 5            # CPU
sar -r 1 5            # 内存
sar -d 1 5            # 磁盘
sar -n DEV 1 5        # 网卡
sar -q                # 历史负载（能查到昨天几点开始高）

sar 的价值在”回看”：事后再查”昨天 14:00 到底发生了什么”，vmstat 帮不上，sar 有历史数据（需 sysstat 服务常开）。

11.7 定位到进程与线程

top -H -p 1234                       # 进程内哪个线程在烧 CPU
ps -L -p 1234 -o pid,tid,pcpu,comm --sort=-pcpu | head
printf "%x\n" 12345                  # 线程 tid 转 16 进制
jstack 1234 | grep -A 20 "nid=0x3039"   # Java 线程栈对照

非 Java 场景用 perf top -p 1234 看函数级热点，或 strace -p 1234 -c 统计系统调用耗时。

11.8 卡在文件与网络

lsof -p 1234 | head                  # 这个进程开着哪些文件
lsof +D /data                        # 谁占着这个目录
strace -f -p 1234 -T -e trace=network,read,write 2>&1 | head -30

strace 输出出现长时间 read / connect 挂住，就是”卡在等 IO”或”卡在等网络”，比看 CPU 更直接。

11.9 四类症状的对应动作

症状
先看
常见原因
CPU 打满
top、top -H
死循环、GC、正则灾难、压缩
负载高但 CPU 闲
vmstat 的 b/wa
慢盘、NFS 挂起、锁竞争
内存不足
free、dmesg、ps --sort=-%mem
堆设置过大、缓存无上限、泄漏
网络慢
sar -n DEV、ss -s、tcpdump
带宽打满、重传多、连接泄漏

11.10 清单

  1. 先 uptime + nproc 判断负载是否真的高
  2. vmstat 1 一眼分清 CPU / IO / 内存
  3. 磁盘看 iostat -x 的 %util 与 await，再 iotop 找进程
  4. 内存只看 available，swap 长期在用就是内存不够
  5. 回看历史用 sar，进程内热点用 top -H + jstack
  6. 卡在文件/网络用 lsof 与 strace，别盲猜
