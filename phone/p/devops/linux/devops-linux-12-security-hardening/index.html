DevOps Linux 安全加固

分类：devops · linux ｜ 标签：linux

安全加固

一台暴露在公网的 Linux，默认配置是不够的：root 能直接登录、密码能爆破、端口全开、补丁不跟。加固不复杂，都是几条明确动作，难的是坚持做完并且留痕。

安全加固的五道防线

12.1 通俗小故事：门锁

服务器是一间仓库，安全加固是换锁装监控：
● SSH 是唯一的常开大门，钥匙（私钥）不能复制扩散
● 密码登录是”谁都能试的挂锁”，爆破脚本一天试几十万次
● 防火墙是门卫，只放名单上的人
● 补丁是”把已知的撬锁工具作废”
● 审计是监控录像，出了事能回看谁进过门

安全不是”装个软件”，是关掉多余的门、收紧剩下的门、记下每次开门。

12.2 SSH 加固（最优先）

# /etc/ssh/sshd_config
Port 22222
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
PermitEmptyPasswords no
MaxAuthTries 3
LoginGraceTime 20
ClientAliveInterval 300
ClientAliveCountMax 2
AllowUsers deploy ops
sshd -t                       # 校验配置语法，别让 sshd 挂掉
systemctl reload sshd
ssh -p 22222 deploy@host      # 先另开窗口验证能用，再关旧会话

顺序很重要：先在另一个终端验证新配置能登录，再退出当前会话。改 SSH 不验证就重启，等于把自己锁在门外。

12.3 账号与 sudo 收敛

awk -F: '($3>=1000 && $3!=65534){print $1}' /etc/passwd   # 可登录的普通用户
grep -E "nologin|false" /etc/passwd | wc -l
lastlog | grep -v "Never logged in"

● 删掉/禁用无用账号，服务类账号一律 nologin
● root 只作为应急手段，日常用普通用户 + sudo
● sudo 规则写进 /etc/sudoers.d/，限定到具体命令
● 定期核对 getent group sudo 与 wheel 的成员

usermod -s /usr/sbin/nologin oldservice
passwd -l olduser            # 锁定账号

12.4 防火墙与端口最小化

ss -lntp                     # 先看清到底开了哪些端口
firewall-cmd --list-all
ufw status verbose

原则：默认拒绝入站，只放必要端口，管理端口限定来源。

firewall-cmd --permanent --remove-service=cockpit
firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=10.0.0.0/24 port port=3306 protocol=tcp accept'
firewall-cmd --reload

数据库、Redis、管理后台一律不直接对公网。Kubernetes、Docker 的 API 端口（2375、6443）暴露在公网是最常见的重大隐患。

12.5 补丁与自动更新

apt list --upgradable
unattended-upgrade --dry-run -d          # Debian 系自动安全更新
dnf updateinfo list security
dnf upgrade --security

● 安全补丁按周更新，别等季度维护窗口
● 内核升级要计划重启，dnf needs-restarting -r 可以判断是否需要重启
● 容器镜像里的基础镜像也要定期重建，宿主机打补丁不会修镜像里的漏洞

12.6 SELinux / AppArmor

getenforce                     # Enforcing / Permissive / Disabled
sestatus
aa-status                      # Ubuntu 侧
ausearch -m avc -ts recent     # 看被拦的访问

不要一遇到权限问题就 setenforce 0。先看 ausearch 的具体拒绝记录，再用 semanage fcontext 或策略模块做最小放行。永久关掉等于拆掉这层防护。

12.7 审计与日志外发

systemctl status auditd
auditctl -l                    # 当前规则
# /etc/audit/rules.d/audit.rules
-w /etc/passwd -p wa -k identity
-w /etc/ssh/sshd_config -p wa -k sshd
-w /var/lib/docker -p wa -k docker
-a always,exit -F arch=b64 -S execve -k exec

日志外发到集中平台（rsyslog 转发或 Filebeat），本机被清理也能留存证据。这是”被入侵后能否定性”的分水岭。

12.8 抗爆破

dnf install fail2ban        # 或 apt install fail2ban
# /etc/fail2ban/jail.d/sshd.conf
[sshd]
enabled = true
port = 22222
maxretry = 3
bantime = 1h
findtime = 10m

配合密钥登录之后，密码爆破基本失效；fail2ban 是兜底，防止日志被刷爆、连接被占满。

12.9 上线自检清单

  1. SSH：禁 root、禁密码、改端口、限用户，改完另开窗口验证
  2. 账号：只留必要用户，服务账号 nologin
  3. sudo：分文件、限命令、按需 NOPASSWD
  4. 端口：ss -lntp 逐个确认，默认拒绝入站
  5. 补丁：安全更新按周，镜像同步重建
  6. 强制访问控制：SELinux / AppArmor 保持 Enforcing
  7. 审计：关键文件与命令留痕，日志外发
  8. 兜底：fail2ban、监控告警、定期扫端口

八条做完，一台公网机器从”默认裸奔”变成”需要绕过多层才能进”。安全没有终点，但这八条能挡掉绝大多数自动化扫描与低水平入侵。
