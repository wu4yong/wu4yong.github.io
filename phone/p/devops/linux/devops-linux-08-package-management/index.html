软件包管理

Linux 上的软件有三种来历：发行版仓库装、直接下安装包、源码编译。仓库装的能一键升级、被安全更新覆盖；编译装的版本随意、升级靠自己记。知道各自的边界，才不会被”依赖地狱”和”编译缺库”反复折磨。

软件包管理：索引 → 仓库 → 依赖 → 安装

8.1 通俗小故事：中央仓库

软件包管理是一套带清单的中央仓库：
● 仓库（repo）是货架，apt / dnf 是取货员
● 包（package）是一箱配件，里面写着”我需要哪些别的箱”
● 依赖（dependency）就是配件之间的螺栓关系，缺一个整箱装不上
● 元数据（index）是货架清单，update 是重新抄一遍清单
● 锁文件（lock）是”有人正在搬货，别插手”

apt update 只是刷新清单，apt upgrade 才是真的搬货。这两个动作分不清，是新手最常犯的错。

8.2 Debian / Ubuntu：apt

apt update                       # 刷新索引（必须先做）
apt upgrade                      # 升级已装的包
apt install nginx                # 装
apt install -y nginx curl        # 一次装多个、不询问
apt remove nginx                 # 卸载（保留配置）
apt purge nginx                  # 卸载并删配置
apt search nginx                 # 搜
apt show nginx                   # 看版本、依赖、体积
apt list --installed | grep nginx
apt autoremove                   # 清无用依赖

只装 .deb 时：

dpkg -i app.deb
apt -f install                   # 补上缺失依赖
dpkg -l | grep app               # 已装包列表
dpkg -L nginx                    # 这个包装了哪些文件

dpkg 只管”装”，不管依赖；apt 是它的上层，能自动补齐。

8.3 RHEL 系：yum / dnf

dnf install nginx                # dnf 是 yum 的现代替代，用法一致
dnf remove nginx
dnf upgrade
dnf search nginx
dnf info nginx
dnf list installed | grep nginx
dnf provides "*/nginx"           # 反查某文件属于哪个包
rpm -qa | grep nginx             # 已装 rpm
rpm -qi nginx                    # 包信息
rpm -ql nginx                    # 装出的文件列表
rpm -qf /usr/sbin/nginx          # 这个文件来自哪个包

dnf provides 很实用：报错说”缺 /usr/bin/pg_config“，一条命令就能找到该装哪个包。

8.4 换源与镜像加速

# Ubuntu：改 /etc/apt/sources.list 里的域名
sed -i.bak 's|http://archive.ubuntu.com|https://mirrors.aliyun.com|g' /etc/apt/sources.list
apt update

# RHEL 系：换 repo 地址
sed -i.bak 's|mirrorlist=|#mirrorlist=|; s|#baseurl=http://|baseurl=https://mirrors.aliyun.com|' /etc/yum.repos.d/*.repo
dnf makecache

● 换源只用 HTTPS 地址，避免中间人篡改包
● 企业环境自建 yum/apt 私有仓库（Nexus、Artifactory），比每台机器直连公网可控
● 镜像站的同步时间差一小时很正常，别把”刚发的版本搜不到”当故障

8.5 源码编译安装

tar -xzf nginx-1.25.tar.gz && cd nginx-1.25
./configure --prefix=/usr/local/nginx --with-http_ssl_module
make -j"$(nproc)"
make install

缺库的典型报错与对应包：

报错
需装的包（Debian / RHEL）
C compiler cc is not found
build-essential / gcc gcc-c++ make
pcre.h not found
libpcre3-dev / pcre-devel
zlib.h not found
zlib1g-dev / zlib-devel
openssl/ssl.h not found
libssl-dev / openssl-devel

编译装的软件要自己维护：记版本、记 --prefix、配 systemd unit、写升级脚本。没有这些，半年后会变成没人敢动的黑盒。

echo "/usr/local/nginx/lib" > /etc/ld.so.conf.d/nginx.conf
ldconfig                          # 刷新动态库缓存

8.6 版本锁定与离线安装

apt-mark hold nginx               # 锁定版本，防止被误升级
apt-mark unhold nginx

dnf versionlock add nginx         # 需安装 dnf-plugin-versionlock
dnf versionlock list

# 离线：先把包下全，再去无网环境装
apt-get download pkg && apt-get install --download-only -y pkg
dnf download --resolve nginx

离线环境的关键是”依赖齐”：--download-only、--resolve 这类参数会把整条依赖链拉下来。只拷主安装包，到目标机必然报缺依赖。

8.7 清单

  1. 先 update 刷索引，再 install
  2. 生产慎用无脑 upgrade，尤其跨大版本
  3. 缺文件用 dnf provides / dpkg -S 反查包名
  4. 换源用 HTTPS，企业环境优先私有仓库
  5. 源码编译必须配 unit、写升级记录
  6. 关键组件用 hold / versionlock 锁版本
  7. 离线安装要连依赖一起下
