日志与故障排查

线上出问题，第一反应不该是重启，而是”现场还在不在”。日志、进程状态、内存记录、内核消息——这些证据一旦被重启抹掉，就只能靠猜。这一章讲怎么保住现场、怎么按套路定位。

日志处理链路：采集 → 过滤 → 定位 → 告警

10.1 通俗小故事：黑匣子

服务器像一架飞机，日志是黑匣子。
● 应用日志在 /var/log 或应用自己的目录，记录”业务上发生了什么”
● journald 记录”系统与服务的启停”，谁在什么时候停了什么
● dmesg 是驾驶舱内的即时播报，内核层面的硬件、OOM、驱动异常
● wtmp / last 是登机记录，谁在什么时候登录过

事故复盘时，这四类记录拼起来才是完整时间线。

10.2 日志都在哪

路径
内容
/var/log/messages 或 /var/log/syslog
系统综合日志
/var/log/auth.log 或 /var/log/secure
登录、sudo、SSH
/var/log/kern.log、dmesg
内核消息
/var/log/nginx/、/var/log/mysql/
各服务自己的
journalctl -u xxx
systemd 托管的服务
/var/lib/docker/containers/*/*-json.log
容器标准输出

10.3 日志轮转与采集

logrotate -d /etc/logrotate.d/app     # 干跑看策略
cat /etc/logrotate.d/app
du -sh /var/log/*  | sort -rh | head
/var/log/app/*.log {
    daily
    rotate 30
    compress
    delaycompress
    missingok
    notifempty
    create 0640 app app
    sharedscripts
    postrotate
        systemctl reload app > /dev/null 2>&1 || true
    endscript
}

轮转三条纪律：
● 一定配 rotate，否则日志能吃掉整块盘
● 应用不支持重开文件就加 copytruncate
● 重要日志同时外发（rsyslog 转发或 Filebeat），本机磁盘坏了也不至于丢

10.4 内核与内存：dmesg

dmesg -T | tail -50                  # 带时间戳看最近内核消息
dmesg -T | grep -i -E "oom|kill"     # 有没有被 OOM 杀
dmesg -T | grep -i -E "error|fail|ata"
journalctl -k -b                     # 本次开机的内核日志

看到 Out of memory: Killed process 12345 (java) 就基本结案：不是应用 bug，是内存不够或 Xmx 给太大。此时把 free -h、Xmx、容器 --memory 三组数放一起核对。

10.5 四类高频故障

SSH 连不上

systemctl status sshd
ss -lntp | grep :22
journalctl -u sshd -n 30
tail -30 /var/log/auth.log

八成是 sshd 没起、防火墙没放行、PermitRootLogin 被改、磁盘满导致登录写不了记录。

端口被占用

ss -lntp | grep :8080
lsof -i :8080

常见于旧进程没退干净、上次部署没停服务、容器映射冲突。

磁盘满

df -h; df -i; du -sh /var/* | sort -rh | head
lsof +L1

服务起来又退出

systemctl status app -l
journalctl -u app -n 100 --no-pager

把 ExecStart 的命令复制出来手动跑一遍，错误立刻现形。

10.6 五步排障法

  1. 确认现象：谁、什么时候、什么操作之后、影响面多大
  2. 保住现场：先抓 df -h、free -h、ps aux --sort=-%cpu、相关日志片段，再考虑重启
  3. 缩小范围：从最外层（网络/端口）往里（进程/配置/代码）
  4. 验证假设：每改一处只改一个变量，改完立刻验证
  5. 留档：把命令与输出贴进工单，问题解决了也记下来

第 2 步最容易被跳过，也最贵。重启确实能”解决”八成的偶发问题，但第二天同一个问题会换个时间再来一次。

10.7 清单

  1. 事故先取证再动手，重启是最后手段
  2. 日志必配轮转与外发，别让磁盘替你做决定
  3. dmesg -T | grep -i oom 是内存类故障的第一步
  4. journalctl -u svc -b --since "5 min ago" 是服务类故障的第一步
  5. 排障一次只改一个变量
  6. 结论写进工单，别只留在脑子里
