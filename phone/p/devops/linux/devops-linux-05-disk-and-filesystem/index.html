磁盘与文件系统

“磁盘满了”是线上最常见的故障原因之一：日志写不进去、数据库拒绝连接、容器起不来。而”满了”有六种：数据真多、inode 用光、被删文件仍被占用、挂载点被上层目录盖住、日志没轮转、/tmp 被塞爆。逐个分清才能治本。

磁盘的分区、格式化、挂载与容量

5.1 通俗小故事：仓库分区

磁盘是一栋仓库楼：
● 分区是一间间库房，文件系统是库房里的货架编号规则
● 挂载点是”把一号库房接在仓库二楼”的那个位置
● inode 是每件货的登记卡，卡用完了还有空地也放不进货
● 卷（LVM）是”可伸缩的库房隔断”，能在线加面积

排障的顺序永远是：先看哪个挂载点满，再看是数据多还是 inode 多，最后看谁在占着已删的文件。

5.2 两条基础命令

df -h                            # 每个挂载点的容量与使用率
df -i                            # inode 使用率（小文件多时会先满）
du -sh /var/log                  # 目录总大小
du -sh * | sort -rh | head -10    # 当前目录下体积前十

df 看”挂载点”，du 看”目录”。两者数字不一致，八成是”文件已删但进程还开着”。

5.3 块设备与分区

lsblk                            # 块设备树，一眼看清盘与分区
lsblk -f                         # 带文件系统类型与 UUID
blkid                            # UUID 列表（写 fstab 要用）
fdisk -l                         # 磁盘容量与分区表
parted -l                        # GPT 盘更适用

新盘上手的顺序是固定的：分区 → 建文件系统 → 挂载 → 写 fstab。

fdisk /dev/sdb                   # n 新建 → w 写入
mkfs.xfs /dev/sdb1               # 或 mkfs.ext4
mkdir -p /data
mount /dev/sdb1 /data

5.4 挂载与开机生效

mount | grep /data              # 当前挂载
umount /data                     # 卸载（有进程占用会失败）
lsof +D /data                    # 找谁占着

/etc/fstab 写错会让机器起不来，所以：

UUID=xxxx-xxxx  /data  xfs  defaults,noatime  0 0

● 用 UUID，不用 /dev/sdb1（设备名可能变）
● 写完先 mount -a 验证，能挂上再重启
● 加 nofail 可以避免单块盘坏掉导致整机卡在启动

5.5 LVM：可伸缩的分区

pvs / vgs / lvs                          # 看三层结构
lvextend -L +10G /dev/vg0/lv_data         # 加 10G
xfs_growfs /data                          # XFS 扩容（在线）
resize2fs /dev/vg0/lv_data                # ext4 扩容

LVM 的价值在”事后能加”：当初只给了 20G，业务涨了直接 lvextend + growfs，不用停机迁数据。

5.6 inode 用光

df -i
# Filesystem  Inodes  IUsed  IFree IUse% Mounted on
# /dev/sdb1  2621440 2621440     0  100% /data

df -h 显示还有空间但写文件报 No space left on device，就是 inode 满了。常见于几十万个 session 文件、邮件、小缓存：

find /data -type f | wc -l
find /data/sessions -type f -mtime +7 -delete

治本是让这类文件按天归档/清理，而不是长期堆在一个目录。

5.7 “删了但空间没释放”

现象：rm 了大日志，du 变小了，df 还是 100%。

lsof +L1                         # 列出被删除但仍被占用的文件
# 输出里有 PID，重启/重载那个进程即可释放

原因是有进程还开着文件句柄（典型是 Nginx、Java 应用）。正确处理是 truncate 而不是 rm：

: > /var/log/app.log             # 原地清空，句柄不变
truncate -s 0 /var/log/app.log

5.8 日志治理

logrotate -d /etc/logrotate.d/nginx   # 干跑，看策略对不对
logrotate -f /etc/logrotate.d/nginx   # 立即轮转一次
/var/log/app/*.log {
    daily
    rotate 14
    compress
    missingok
    notifempty
    copytruncate
}

copytruncate 给不支持重开文件的程序兜底，代价是轮转瞬间可能丢几十行。支持的用 postrotate 发信号重开，最干净。

5.9 清单

  1. df -h 与 df -i 一起看，先分清空间满还是 inode 满
  2. du -sh * | sort -rh 定位大户，别全盘 du
  3. 大日志用 truncate 清，不用 rm
  4. dd 之前先 lsblk，确认写的是哪块盘
  5. fstab 用 UUID 并加 nofail，改完 mount -a 验证
  6. 该轮转的日志一定配 logrotate，别指望手动清
