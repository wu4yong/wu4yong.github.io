systemd 与服务托管

现代 Linux 的 1 号进程是 systemd。它管开机顺序、托管服务、重启崩溃的进程、收集日志、跑定时任务。不会用 systemd，就等于把服务交给了 nohup 和运气。

systemd 单元依赖树与启动顺序

9.1 通俗小故事：值班表

systemd 是机房的排班表：
● unit 文件是每项工作的一张排班卡：谁、干什么、依赖谁、挂了怎么办
● enable 是把卡片贴进”每天开工”那一栏，start 是现在就叫人来
● After / Requires 是”先等网络起来，再拉我这个”
● Restart=always 是”挂了立刻补位”
● journald 是打卡记录，出事查这里

关键区别记牢：enable 管开机自启，start 管现在运行。两个都要做才有”开机自启并立即运行”。

9.2 unit 有哪几种

后缀
用途
.service
常驻服务
.timer
定时任务（替代 cron）
.socket
按连接触发启动服务
.target
一组 unit 的集合（类似运行级别）
.mount
挂载点管理

9.3 写一个 service

# /etc/systemd/system/app.service
[Unit]
Description=App Service
After=network.target
Wants=network-online.target

[Service]
Type=simple
User=app
Group=app
WorkingDirectory=/data/app/current
Environment="SPRING_PROFILES_ACTIVE=prod"
ExecStart=/usr/bin/java -Xms512m -Xmx1g -jar app.jar
ExecReload=/bin/kill -HUP $MAINPID
SuccessExitStatus=143
Restart=always
RestartSec=5
LimitNOFILE=65535
StandardOutput=journal
StandardError=journal
KillSignal=SIGTERM
TimeoutStopSec=30

[Install]
WantedBy=multi-user.target

几个参数值得单独记：
● Restart=always 保活；on-failure 只在非 0 退出时重启
● SuccessExitStatus=143 把”被 SIGTERM 正常停”当成成功，避免日志里一堆误报
● LimitNOFILE 不设，文件句柄默认可能只有 1024，高并发直接 Too many open files
● TimeoutStopSec 给应用留出优雅停机时间，超时后强杀

9.4 systemctl 常用命令

systemctl daemon-reload          # 改完 unit 必须执行
systemctl start app
systemctl stop app
systemctl restart app
systemctl reload app             # 不中断地重载配置（需 ExecReload）
systemctl status app -l --no-pager
systemctl enable app             # 开机自启
systemctl enable --now app       # 自启并且现在启动
systemctl disable app
systemctl is-active app          # 脚本里判断状态用这个
systemctl is-enabled app
systemctl list-units --type=service --state=running
systemctl list-units --failed    # 所有失败的服务

systemctl status 里三行最关键：Loaded（unit 路径与是否 enable）、Active（是否 running）、最后 10 行日志（失败原因）。

9.5 用 timer 代替 cron

# /etc/systemd/system/backup.service
[Unit]
Description=Nightly backup

[Service]
Type=oneshot
ExecStart=/data/scripts/backup.sh
# /etc/systemd/system/backup.timer
[Unit]
Description=Run backup at 03:00

[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true

[Install]
WantedBy=timers.target
systemctl enable --now backup.timer
systemctl list-timers --all

Persistent=true 是 cron 没有的能力：机器在 3 点关机，开机后会补跑一次。日志也直接进 journalctl -u backup。

9.6 查日志：journalctl

journalctl -u app -n 100 --no-pager      # 某服务最近 100 行
journalctl -u app -f                     # 实时跟踪
journalctl -u app --since "10 min ago"
journalctl -u app --since "2018-05-08 09:00" --until "2018-05-08 10:00"
journalctl -p err -b                     # 本次开机以来的错误
journalctl -t sudo                       # 按 syslog 标识过滤
journalctl --disk-usage                  # 日志占了多少
journalctl --vacuum-size=200M            # 收缩到 200M

journalctl -u app -b --since "5 min ago" 基本覆盖了”服务刚挂掉，看看为什么”的九成场景。

9.7 服务起不来的排查顺序

  1. systemctl status app -l 看最后几行报错
  2. journalctl -u app -n 50 --no-pager 看完整上下文
  3. 手动跑一遍 ExecStart 的命令，看是不是命令本身有问题
  4. 检查路径与权限：WorkingDirectory、User、文件属主
  5. 检查端口占用：ss -lntp | grep 8080
  6. 检查资源：LimitNOFILE、内存是否被 OOM 杀（dmesg | grep -i oom）

status 里出现 status=203/EXEC 是执行文件找不到或没有执行权限，status=1/FAILURE 是程序自己退出非 0。

9.8 清单

  1. 服务一律写 unit，不用 nohup 顶着
  2. 改 unit 后 daemon-reload，再 restart
  3. enable 与 start 分开理解，需要时用 enable --now
  4. 必配 Restart、LimitNOFILE、TimeoutStopSec
  5. 定时任务优先 timer，能补跑、有日志
  6. 日志排障从 status → journalctl -u → 手跑命令
