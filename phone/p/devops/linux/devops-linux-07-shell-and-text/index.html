Shell 与文本处理

日志在运维手里就是数据。几千行日志里找出某段时间的错误、统计某个接口的调用量、把一行行结果拼成命令——这些事靠 grep、sed、awk 加管道，一条命令顶半小时鼠标操作。

管道与文本处理：过滤 → 切割 → 排序 → 统计

7.1 通俗小故事：流水线

Shell 是一条流水线，每个命令是一个工位。
● | 是把上一个工位的成品递给下一个
● > 是”装进箱子”，>> 是”往同一只箱子里继续装”
● 2>&1 是”把抱怨（错误输出）也一起装箱”
● xargs 是”把箱子里的东西一件件拿出来喂给下一个工位”

流水线的威力不是单个工具多强，而是能把三段式（过滤 → 转换 → 统计）接起来。

7.2 重定向与管道

cmd > out.txt                    # 覆盖写
cmd >> out.txt                   # 追加
cmd 2> err.txt                   # 只收错误
cmd > all.txt 2>&1               # 标准与错误一起收
cmd 2>&1 | tee all.log           # 既落盘又显示
cmd &> /dev/null                 # 全部丢弃

顺序很关键：> all.txt 2>&1 正确，2>&1 > all.txt 会把错误丢到终端。记法是”先接好目的地，再让错误跟上”。

7.3 grep：找

grep "ERROR" app.log
grep -i "error" app.log                  # 忽略大小写
grep -c "ERROR" app.log                  # 计数
grep -n -C 3 "Exception" app.log         # 行号 + 前后 3 行
grep -v "DEBUG" app.log                  # 反向：排除
grep -E "ERROR|WARN" app.log             # 正则多选
grep -r --include="*.log" "timeout" /var/log
grep -oP 'cost=\K[0-9]+' app.log         # 只取捕获部分（-P 需要 PCRE）

-C 是排障神器：光看错误行看不出上下文，带前后三行往往就能定位到具体请求与参数。

7.4 sed：改

sed -n '100,120p' app.log                          # 打印指定行
sed 's/old/new/' file                              # 每行替换第一个
sed 's/old/new/g' file                             # 全部替换
sed -i 's/8080/9090/g' app.conf                    # 原地改（-i 危险）
sed -i.bak 's/8080/9090/g' app.conf                # 先备份再改，推荐
sed '/^#/d' app.conf | grep -v '^$'                # 去注释与空行
sed -i '/oldblock/,/endblock/d' app.conf           # 删一段

-i.bak 是最省事的保护：改错了把 .bak 挪回来。生产改配置前先 cp 一份，再用 sed -i，规范一样有效。

7.5 awk：按列算

awk '{print $1, $7}' access.log                    # 取第一列和第七列
awk -F: '{print $1}' /etc/passwd                   # 指定分隔符
awk '$9 == 500 {print $7}' access.log | sort | uniq -c | sort -rn
awk '{sum+=$10} END {print sum}' access.log        # 求和
awk 'length($0) > 200' app.log                     # 按行长度过滤

awk 的模型是”按行读、按字段切、最后 END 汇总”。统计类需求（求和、计数、平均）用它最顺手。

7.6 排序与统计组合拳

sort file | uniq -c | sort -rn | head -10          # 出现最多的十项
cut -d' ' -f1,2 file                                # 取列
wc -l file                                          # 行数
tr -s ' ' '\n' < file | sort | uniq -c              # 空格切分成词再统计

最常见的三件事，记住这三条就够：
● 谁最多：sort | uniq -c | sort -rn | head
● 有几条：grep -c 或 wc -l
● 什么时间段发生：grep "2018-05-07 1[0-1]:" 或 awk 比对时间列

7.7 把结果变成命令：xargs

find /data -name "*.log" -mtime +7 | xargs rm -f
grep -l "ERROR" /var/log/*.log | xargs -I{} echo "检查 {}"
pgrep -f java | xargs -r kill -15

-r 表示”输入为空就不执行”，-I{} 允许把参数放在中间。不加 -r 时空输入可能让命令按默认参数跑一次，很危险。

7.8 变量、引号与脚本骨架

#!/usr/bin/env bash
set -euo pipefail          # 出错即停、未定义变量报错、管道错误也算失败
set -x                     # 调试时打印执行命令

APP=/data/app/current
LOG=/var/log/deploy/$(date +%F).log
mkdir -p "$(dirname "$LOG")"

echo "deploy start $(date '+%F %T')" | tee -a "$LOG"

● 单引号内一切原样，双引号内变量会展开 → 路径与变量一律加双引号
● $? 是上一条命令退出码，0 成功
● $(...) 优于反引号，可嵌套
● 脚本开头 set -euo pipefail 能挡掉大量”静默失败”

7.9 定时任务

crontab -l                # 当前用户的任务
crontab -e                # 编辑
# 分 时 日 月 周
0 3 * * *  /data/scripts/backup.sh >> /var/log/backup.log 2>&1
*/5 * * * * /usr/bin/curl -s http://localhost:8080/health > /dev/null

cron 常见坑：环境变量极少（用绝对路径）、不记录输出（务必重定向）、% 需转义。更现代的做法是 systemd timer，日志直接进 journalctl。

7.10 清单

  1. 三段式：过滤（grep）→ 转换（sed/awk）→ 统计（sort/uniq/wc）
  2. 2>&1 放最后，tee 同时落盘与显示
  3. sed -i.bak 改配置，先备份
  4. xargs 加 -r，防空输入误执行
  5. 脚本开头 set -euo pipefail，变量一律双引号
  6. 定时任务用绝对路径并重定向输出
