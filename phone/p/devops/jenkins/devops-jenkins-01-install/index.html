基础运行环境快速安装部署

Jenkins 本质是一个 Java Web 应用：一个 war 包、一个工作目录、一个内置的 Jetty 容器。所谓”安装”，就是让这个 war 跑起来、给它一个能持久写入的家目录。真正容易踩坑的不是安装本身，而是 JDK 版本、端口、时区和数据目录这四件事。

三条安装路径与 JENKINS_HOME 数据目录

1.1 通俗小故事：开一间印刷厂

把 Jenkins 想成印刷厂：

● war 包是印刷机本体，插电（JVM）就能转
● JENKINS_HOME 是厂房仓库，所有活字模（任务）、印版（构建记录）、订单（配置）都存在这里
● 8080 端口是门牌号，别人要下单得能找到门
● 初始密码是仓库钥匙，第一次进门必须出示
● 插件是后装的专用字模，装错了机器照样转，只是印不出那种版式

搬厂（迁移服务器）时只搬机器不搬仓库，结果就是”任务全没了”——厂房仓库才是全部家当。

1.2 前置：JDK 与版本红线

Jenkins 只跑在 JDK 上，现代 LTS 版本要求 JDK 17 或 21（旧版 2.3xx 尚可 JDK 11）。版本对不上，启动时直接抛 UnsupportedClassVersionError，跟配置无关。

# Ubuntu / Debian
apt install -y openjdk-17-jdk
java -version

# RHEL 系
dnf install -y java-17-openjdk-devel

# 多版本共存时指定（Jenkins 用哪个看的是启动它的那个 java）
update-alternatives --config java
# 验证
java -version 2>&1 | head -1
# openjdk version "17.0.9" ...

war 包方式的最小可用启动：

mkdir -p /opt/jenkins && cd /opt/jenkins
wget https://get.jenkins.io/war-stable/latest/jenkins.war
nohup java -Xms512m -Xmx1024m -jar jenkins.war \
  --httpPort=8080 \
  --jenkins-home=/opt/jenkins/home > jenkins.log 2>&1 &

-Xmx 别给太小：Pipeline 多任务并发时 512M 很容易 OOM，生产一般 2–4G 起步。

1.4 Docker 方式（最省事）

docker volume create jenkins_home
docker run -d --name jenkins \
  -p 8080:8080 -p 50000:50000 \
  -v jenkins_home:/var/jenkins_home \
  -v /etc/localtime:/etc/localtime:ro \
  -e JAVA_OPTS="-Duser.timezone=Asia/Shanghai -Xmx2048m" \
  --restart unless-stopped \
  jenkins/jenkins:lts-jdk17

● 50000 是 agent 通信端口，以后加构建节点要用
● 挂 /etc/localtime 或设 user.timezone，否则定时构建会按 UTC 触发，看起来”晚了八小时”
● 数据卷必须落在宿主机持久目录，docker rm 后任务才不会丢

1.5 初始化向导

# 解锁密码位置
cat /var/lib/jenkins/secrets/initialAdminPassword      # 包安装
docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword   # 容器

向导四步：

  1. 粘贴初始密码解锁
  2. 选”安装推荐的插件”（Git、Pipeline、Maven、SSH、Email 等一次到位）
  3. 建第一个管理员账号，别用 admin/弱密码
  4. 填 Jenkins URL（写公网/内网真实地址，邮件里的链接和 webhook 回调用它）

首次装插件经常卡在 Installing plugin，多是连 updates.jenkins.io 慢。

1.6 换源与代理

国内环境把更新中心换到镜像站，能省掉大量等待：

# 方式一：改配置文件
cat > /var/lib/jenkins/hudson.model.UpdateCenter.xml <<'EOF'
<?xml version='1.1' encoding='UTF-8'?>
<sites>
  <site>
    <id>default</id>
    <url>https://mirrors.tuna.tsinghua.edu.cn/jenkins/updates/update-center.json</url>
  </site>
</sites>
EOF
systemctl restart jenkins
# 方式二：图形界面 系统管理 → 插件管理 → 高级 → 升级站点 URL
# 方式三：JVM 参数走代理
-Dhttp.proxyHost=10.0.0.1 -http.proxyPort=3128 -Dhttp.nonProxyHosts="localhost"

镜像站的 update-center 里插件下载地址仍指向官方 CDN，若插件仍慢，需要在”高级”里把插件下载地址一并替换或让服务器出网走代理。

1.8 清单

  1. 先确认 JDK 17/21，再谈安装
  2. 三种装法按场景选，生产优先包管理或容器
  3. JENKINS_HOME 必须持久化，容器要挂卷
  4. 时区一定设成 Asia/Shanghai
  5. 初始密码在 secrets/initialAdminPassword
  6. Jenkins URL 填真实地址，否则邮件与 webhook 全歪
  7. 首次装插件慢就换更新中心镜像
  8. 备份 jobs users credentials.xml secrets config.xml
