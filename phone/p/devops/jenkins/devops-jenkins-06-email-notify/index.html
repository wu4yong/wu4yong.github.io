邮件通知任务执行结果

构建失败不该等人去翻界面。邮件通知是最便宜的”出事了有人知道”手段，但它也是最容易配出”垃圾邮件”的地方：端口选错、授权码当密码、成功也发全员，最后所有人都把通知规则丢进垃圾箱。

构建结果经 SMTP 加密投递：成功与失败两条路径

6.1 通俗小故事：挂号信

● SMTP 服务器是邮局，smtp.example.com:465 是邮局的窗口
● 用户名密码是寄件人身份，很多邮箱不接受”密码”，只认授权码/应用专用密码
● SSL/TLS 是信封加密，465 是”一上来就加密”，587 是”先打招呼再升级加密”
● 收件人是信封地址，抄送是”让领导也知道”
● 触发器是”什么时候寄”：只有失败寄，还是每次都寄

邮局窗口认错（465 配成 587）的典型报错是 Could not connect to SMTP host 或 Handshake failed，和账号密码无关。

6.3 授权码怎么拿

以 QQ 邮箱为例：设置 → 账号 → 开启 POP3/SMTP 服务 → 生成授权码（16 位）。163 类似，Gmail 要在”应用专用密码”里生成。企业邮箱一般是直接给密码，但可能需要先在管理员侧开 SMTP。

用授权码而非密码还有个好处：泄露了可以单独吊销，不影响邮箱登录。

6.5 项目里配收件人与触发器

Project Recipient List:      dev-team@example.com, oncall@example.com
Reply-To:                    no-reply@example.com
Content Type:                text/html
Default Subject:             [${PROJECT_NAME}] 构建 #${BUILD_NUMBER} - ${BUILD_STATUS}
Default Content:             见下方模板
Triggers:
  Failure - Any            → 立即发（收件人：dev-team + oncall）
  Unstable - Any           → 发（测试有失败）
  Fixed                    → 发（恢复了，让大家松口气）
  Success                  → 不发或每天汇总
  Aborted                  → 不发

模板写法（Groovy 变量可直接插值）：

<html><body>
<h3>${PROJECT_NAME} #${BUILD_NUMBER} <b>${BUILD_STATUS}</b></h3>
<ul>
  <li>分支：${BRANCH_NAME}</li>
  <li>提交：${GIT_COMMIT}</li>
  <li>耗时：${BUILD_DURATION}</li>
  <li>日志：<a href="${BUILD_URL}console">${BUILD_URL}console</a></li>
</ul>
<p>最近 5 次结果：</p>
${CHANGES_SINCE_LAST_SUCCESS, reverse=true, format="%c %d %m %p"}
</body></html>

CHANGES_SINCE_LAST_SUCCESS 很有用：直接告诉收件人”这次失败是哪个 commit 引起的、谁提交的”。

6.6 Pipeline 里发邮件

post {
  failure {
    emailext(
      to: 'dev-team@example.com, oncall@example.com',
      subject: "[失败] ${env.JOB_NAME} #${env.BUILD_NUMBER}",
      body: """构建失败
分支: ${env.BRANCH_NAME}
提交: ${env.GIT_COMMIT}
日志: ${env.BUILD_URL}console""",
      mimeType: 'text/html'
    )
  }
  fixed {
    emailext(
      to: 'dev-team@example.com',
      subject: "[恢复] ${env.JOB_NAME} 构建通过",
      body: '上一次失败已修复，可继续合并。'
    )
  }
  success {
    // 成功默认不发，避免噪音；需要日报就单独建一个汇总 Job
  }
}

只发失败 + 修复，是最不惹人烦的组合。全量成功通知请改成一个每天 H 9 * * 1-5 的汇总 Job，一封信说清所有 Job 昨天怎么样。

6.8 清单

  1. 465 配 SSL、587 配 TLS，别混
  2. 密码位置填授权码/应用专用密码
  3. 装 Email Extension，用触发器矩阵而不是”啥都发”
  4. 只发失败与修复，成功走日报汇总
  5. 正文带 BUILD_URL 与 GIT_COMMIT，别让人回登录界面翻日志
  6. Charset 设 UTF-8，杜绝中文乱码
  7. 配好 Jenkins URL，否则邮件里所有链接都是 localhost
