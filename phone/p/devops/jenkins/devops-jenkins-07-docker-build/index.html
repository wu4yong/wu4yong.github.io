DevOps Jenkins 构建运行在 Docker 容器中

分类：devops · jenkins ｜ 标签：jenkins

Jenkins 构建项目自动化运行在 Docker 容器中

CI 最经典的抱怨是”我本地能跑，构建机上不行”——构建机的 JDK 8 和你本地 17 打架。把构建环境装进镜像、每次构建起一个新容器，环境就变成代码的一部分，随时可复现、随时可丢弃。

容器化 CI：Jenkins 容器通过 docker.sock 调度宿主机资源

7.1 通俗小故事：标准化集装箱

● 镜像 = 装满工具的标准集装箱，里面 JDK、Maven、Node 全都定死
● 容器 = 临时拉来的一个箱子，跑完就扔，不留油污
● docker.sock = 宿主机码头的出入口，容器想造船（起新容器）必须从这里过
● Dockerfile = 装箱单，写给码头工人看的
● DinD（Docker in Docker）= 在箱子里再开一个码头，重且慢，通常不需要

宿主机码头越多，越要小心：把 docker.sock 挂进容器，等于给了它 root 级的权限。

绝大多数团队用第二种：Jenkins 容器化，挂 socket，构建在临时容器里跑。

7.3 Jenkins 容器化并挂 socket

docker run -d --name jenkins \
  -p 8080:8080 -p 50000:50000 \
  -v jenkins_home:/var/jenkins_home \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /usr/bin/docker:/usr/bin/docker \
  -e JAVA_OPTS="-Duser.timezone=Asia/Shanghai" \
  --restart unless-stopped \
  jenkins/jenkins:lts-jdk17
# 进入容器验证 docker 可用
docker exec -it -u root jenkins bash -c "docker version"

挂载方式有个坑：jenkins/jenkins 镜像里没有 docker 客户端。要么把宿主机的 /usr/bin/docker 挂进去（如上，简单但版本耦合），要么进容器装：

docker exec -u root -it jenkins bash
apt-get update && apt-get install -y docker.io

还需要权限：容器内用户 jenkins 要能读写 socket，否则报 permission denied while trying to connect to the Docker daemon socket。

# 查 socket 的属组 GID，再在容器里建同名组
stat -c '%g' /var/run/docker.sock          # 宿主机上执行
docker exec -u root jenkins groupadd -g 999 docker || true
docker exec -u root jenkins usermod -aG docker jenkins
docker restart jenkins

7.4 自由风格任务里用 docker

在”执行 shell”里直接起构建容器，把工作区挂进去：

docker run --rm \
  -v "$WORKSPACE":/src \
  -v "$HOME/.m2":/root/.m2 \
  -w /src \
  maven:3.9-eclipse-temurin-17 \
  mvn -B clean package -DskipTests

环境变量要显式传，别指望容器继承：

docker run --rm \
  -e BUILD_ENV="$BUILD_ENV" -e BUILD_NUMBER="$BUILD_NUMBER" \
  -v "$WORKSPACE":/src -w /src \
  maven:3.9-eclipse-temurin-17 \
  bash -c 'mvn -B clean package && cp target/*.jar /src/'

-v "$HOME/.m2" 会共享依赖缓存，第一次下载慢、后面快；但要注意容器内路径是 /root/.m2，用户不同就失效。

7.5 Pipeline 用 docker agent（推荐）

装了 Docker Pipeline 插件后，整段 stage 都能跑在镜像里，无需自己 docker run：

pipeline {
  agent any
  stages {
    stage('Build in Maven') {
      agent {
        docker { image 'maven:3.9-eclipse-temurin-17' }
      }
      steps {
        sh 'mvn -B clean package -DskipTests'
      }
    }
    stage('Test in JDK 21') {
      agent { docker { image 'maven:3.9-eclipse-temurin-21' } }
      steps { sh 'mvn -B test' }
    }
  }
}

插件会自动做三件事：起容器、把 workspace 挂到容器工作目录、结束后销毁。

缓存与固定参数：

agent {
  docker {
    image 'maven:3.9-eclipse-temurin-17'
    args '-v $HOME/.m2:/root/.m2 -u root'
    reuseNode true
  }
}

reuseNode true 让容器复用当前节点的工作区，配合 -v $HOME/.m2 缓存依赖。-u root 常见于容器内与挂载目录的 UID 冲突导致写不进 workspace。

7.6 构建镜像并推送仓库

stage('Docker Build') {
  steps {
    script {
      def img = "registry.example.com/team/order-api:${env.BUILD_NUMBER}"
      docker.withRegistry('https://registry.example.com', 'registry-creds') {
        def image = docker.build(img, '.')
        image.push()
        image.push('latest')
      }
    }
  }
}

对应 Dockerfile：

FROM eclipse-temurin:17-jre
WORKDIR /app
COPY target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "/app/app.jar"]

registry-creds 是 Jenkins 凭据 ID（用户名密码类型），withRegistry 会自动登录和登出。

7.7 在测试机跑容器

docker rm -f order-api || true
docker run -d --name order-api \
  --restart unless-stopped \
  -p 8080:8080 \
  -e SPRING_PROFILES_ACTIVE=test \
  -v /opt/apps/order-api/logs:/app/logs \
  registry.example.com/team/order-api:${BUILD_NUMBER}
# 健康检查，失败让构建红掉
for i in $(seq 1 20); do
  curl -fsS http://127.0.0.1:8080/actuator/health && exit 0
  sleep 3
done
docker logs --tail 50 order-api
exit 1

发布用镜像比 scp jar 更好：版本不可变、回滚就是 docker run 一个旧 tag。

7.8 安全与清理

● 挂 docker.sock 的 Jenkins 容器天然是 root 权限，别把它暴露到公网
● 定期清悬空镜像：docker image prune -f --filter "until=168h"
● 每个构建都要有 --rm 或 docker rm，否则容器会越堆越多
● 镜像 tag 禁止只用 latest，用构建号或 commit SHA
● 私有仓库凭据用 Jenkins Credential，别写在脚本里

7.9 清单

  1. 优先”Jenkins 容器 + 挂 docker.sock”，不要盲目 DinD
  2. 容器内装 docker 客户端、加 socket 属组，否则 permission denied
  3. Pipeline 用 agent { docker { image ... } }，比手写 docker run 干净
  4. 挂 .m2 缓存依赖，配合 reuseNode true
  5. 镜像 tag 用构建号或 commit，latest 只当别名
  6. 容器发布配合健康检查，失败 exit 1
  7. 定期 prune 镜像与容器，防止磁盘爆
