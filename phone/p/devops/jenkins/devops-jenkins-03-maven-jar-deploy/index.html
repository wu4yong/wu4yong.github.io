DevOps Jenkins Maven 构建 jar 并发布到测试机

分类：devops · jenkins ｜ 标签：jenkins

一键 Maven 拉取 Git 代码构建 jar 并提交到测试服务器自动运行

这是 Jenkins 最经典的一条链路：Git 拉代码 → Maven 打包 → 把 jar 传到测试机 → 停旧进程 → 起新进程。手工做一遍要十分钟，还容易漏步骤；做成任务后，点一次按钮就完成，日志还能追溯。

一条链路：拉代码 → 构建打包 → 传 jar → 发布 → 健康检查

3.1 通俗小故事：一条装配线

● Git 是原料仓库，git clone 是把原料拉到车间
● Maven 是机床，clean package 是按图纸加工成 jar
● scp 是货运车，把成品送到客户厂房
● 启动脚本是开机钥匙，停旧、起新、留日志
● Jenkins 是车间主任，负责按顺序喊”下一步”

主任最怕的是货运车送错门、或新机床还在加工就把旧机床拆了。所以链路里必须加”构建成功才发货”的闸门。

3.3 新建 Maven 项目

新建任务 → 输入 order-api-test-deploy → 选 构建一个 maven 项目。

源码管理：

Git
  Repository URL: git@gitlab.example.com:team/order-api.git
  Credentials:    gitlab-deploy-key（SSH 私钥凭据）
  Branch Specifier: */develop
  Additional Behaviours: 浅克隆 shallow clone（depth 1，加快大仓库）

SSH 凭据要先把 Jenkins 的公钥加到 GitLab 的 Deploy Key，否则报 Permission denied (publickey)。

构建触发器：先不勾，等第四章再接 webhook。

Build：

Root POM:            pom.xml
Goals and options:   clean package -DskipTests -U -Plocal

● -DskipTests 只跳过执行、仍编译测试代码；要连编译都跳用 -Dmaven.test.skip=true
● -U 强制更新 SNAPSHOT 依赖，避免用到本地缓存里的旧包
● -Plocal 指定环境 profile，把配置从代码里剥离

构建后操作：

归档成品：**/target/*.jar

归档后每次构建结果页能直接下 jar，回滚时不用重新打包。

3.4 把 jar 送到测试机

最省事的做法是 Publish Over SSH 插件：

系统管理 → 系统设置 → Publish over SSH
  Passphrase / Path to key:  Jenkins 自己的私钥
  SSH Servers:
    Name: test-server
    Hostname: 10.0.1.20
    Username: deploy
    Remote Directory: /opt/apps/order-api

不想装插件也有两条路：

# 方式二：scp + ssh，写在 Execute shell 里（需把私钥配成 Jenkins 凭据）
scp -i "$KEY" target/*.jar deploy@10.0.1.20:/opt/apps/order-api/app.jar
ssh -i "$KEY" deploy@10.0.1.20 'bash /opt/apps/order-api/deploy.sh'

# 方式三：rsync，只传变化部分，大包更快
rsync -az --delete -e "ssh -i $KEY" target/*.jar deploy@10.0.1.20:/opt/apps/order-api/

3.5 测试机上的启动脚本

/opt/apps/order-api/deploy.sh：

#!/bin/bash
set -euo pipefail
APP=/opt/apps/order-api
JAR=$APP/app.jar
PID_FILE=$APP/app.pid
LOG=$APP/app.log

# 1. 停旧进程：先 TERM 再等，超时才 KILL
if [ -f "$PID_FILE" ]; then
  PID=$(cat "$PID_FILE")
  if kill -0 "$PID" 2>/dev/null; then
    kill "$PID"
    for i in $(seq 1 20); do
      kill -0 "$PID" 2>/dev/null || break
      sleep 1
    done
    kill -9 "$PID" 2>/dev/null || true
  fi
fi

# 2. 备份新包，保留最近 5 个
mkdir -p "$APP/backup"
cp "$JAR" "$APP/backup/app-$(date +%Y%m%d-%H%M%S).jar"
ls -1t "$APP"/backup/*.jar | tail -n +6 | xargs -r rm -f

# 3. 起新进程
nohup java -jar "$JAR" \
  --spring.profiles.active=test \
  -Xms512m -Xmx1024m > "$LOG" 2>&1 &
echo $! > "$PID_FILE"

# 4. 健康检查，失败就回滚
for i in $(seq 1 30); do
  if curl -fsS http://127.0.0.1:8080/actuator/health >/dev/null; then
    echo "started ok"
    exit 0
  fi
  sleep 2
done
echo "health check failed, see $LOG"
exit 1

关键点：

● set -euo pipefail + 结尾 exit 1，让 Jenkins 能判定失败（否则脚本永远”成功”）
● 停进程要优雅，直接 kill -9 会让正在处理的请求全断
● 备份 + 健康检查，才是”可回滚”的部署
● nohup 必须重定向输出，否则 SSH 断开后进程可能被 SIGHUP 带走

3.8 清单

  1. 全局工具配置里锁死 JDK 与 Maven 路径
  2. Git 用 Deploy Key 凭据，分支显式写 */develop
  3. 构建用 clean package -DskipTests -U，产物务必归档
  4. 传包优先 Publish over SSH，路径三段（Source / Remove prefix / Remote）要对齐
  5. 启动脚本必须优雅停机 + 备份 + 健康检查 + 失败退出非零
  6. 参数化构建把环境、分支做成参数，别改代码来换环境
