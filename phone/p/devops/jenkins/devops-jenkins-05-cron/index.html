分类：devops · jenkins ｜ 标签：jenkins

定时构建发布任务

Jenkins 的定时表达式是带 H 的 cron：五段、空格分隔，和 Linux crontab 几乎一样，但多了一个 H 用来做哈希散列。所有”每天凌晨两点”的坑，几乎都出在对 H 与并发策略的误解上。

H 散列把定时任务摊在整点之间，避免全公司一起打卡

5.1 通俗小故事：一群人的闹钟

如果全公司都在 02:00 打卡，打卡机必然卡死。Jenkins 的 H 就是”按你的名字算一个随机分钟”，把 200 个 Job 摊在 02:00–02:59 之间：

● H 2 * * * 是”凌晨两点这一小时内、某个固定分钟”
● H/10 * * * * 是”每 10 分钟一次，但起点按 Job 名散开”
● 每个 Job 的 H 值一旦算出就固定不变，不会今天 17 分、明天 42 分

所以看到”为什么我的任务不是整点跑”——那不是 bug，是 H 在干活。

5.2 五段语法

MINUTE HOUR DOM MONTH DOW
  0-59  0-23 1-31 1-12 0-7（0 和 7 都是周日）
H 2 * * *        每天 02:00–02:59 之间某个固定分钟

5.3 时区：最容易错的地方

Jenkins 用的是 Jenkins 进程的时区，不是浏览器的时区。

# 宿主机层面
timedatectl set-timezone Asia/Shanghai
date

# JVM 层面（war / systemd 启动）
JAVA_OPTS="$JAVA_OPTS -Duser.timezone=Asia/Shanghai"

# 容器
docker run ... -e JAVA_OPTS="-Duser.timezone=Asia/Shanghai" -v /etc/localtime:/etc/localtime:ro

改完重启服务，再进”系统信息”看 user.timezone。判断是否生效的小技巧：建一个 H * * * * 的测试 Job，看它触发时间与本地时间差几小时。

5.4 定时 + 发布的正确组合

定时本身只管”什么时候开始”，发布的安全要靠下面几条：

一个”每天凌晨构建 + 发布到测试”的任务，构建步骤可以这样写：

#!/bin/bash
set -euo pipefail

echo "开始时间: $(date '+%F %T')"
git log -1 --pretty='commit: %h %s'

mvn -B clean package -DskipTests -U

# 只在构建成功后传包，脚本非 0 就中断
scp -i "$KEY" target/*.jar deploy@10.0.1.20:/opt/apps/order-api/app.jar
ssh -i "$KEY" deploy@10.0.1.20 'bash /opt/apps/order-api/deploy.sh'

5.5 与其他系统的错峰

夜间窗口通常还有数据库备份、日志切割、报表导出。错峰靠”车次表”：

时间
任务
00:30
数据库全量备份
01:30
日志切割 + 归档上传
02:00–02:59
Jenkins H 2 构建（多个 Job 自动散列）
04:00
报表导出
06:00
制品清理（保留 N 个版本）

Jenkins 里对应的清理任务用 H 6 * * *，配合”丢弃旧构建”策略，避免磁盘被历史产物吃满。

5.6 让定时任务可观测

定时任务失败最尴尬的是”没人发现”。三个必做动作：

● 构建描述写关键信息：currentBuild.description = "nightly ${env.BUILD_NUMBER} @ ${env.BRANCH_NAME}"
● 结果通知：邮件或 IM（第 6 章），失败必发、成功可只发摘要
● 趋势图看耗时：构建趋势里耗时突然翻倍，通常是依赖仓库变慢或磁盘 IO 抖动

Pipeline 写法：

pipeline {
  agent any
  triggers { cron('H 2 * * *') }
  options {
    timeout(time: 60, unit: 'MINUTES')
    disableConcurrentBuilds()
    buildDiscarder(logRotator(numToKeepStr: '50', daysToKeepStr: '30'))
  }
  stages {
    stage('Build') {
      steps { sh 'mvn -B clean package -DskipTests' }
    }
    stage('Deploy') {
      steps { sh './scripts/deploy.sh' }
    }
  }
}

5.7 清单

  1. 定时用 H 打头，别写 0 2 * * * 让全公司一起打卡
  2. 先确认 Jenkins 进程时区是 Asia/Shanghai
  3. 一律开”禁止并发构建”
  4. Pipeline 加 timeout，防止卡住占资源
  5. 配”丢弃旧构建”，控制日志与产物体积
  6. 与备份、报表等夜间任务错峰
  7. 失败必须有人收到通知，否则定时等于没做
