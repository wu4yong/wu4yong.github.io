Pipeline 脚本与 Jenkinsfile 使用

自由风格任务是”点出来的”，Pipeline 是”写出来的”。写出来的好处很直接：流程能进 Git、能 review、能改一行就跑，不用登录界面一步步点。代价是必须懂一点 Groovy。

Jenkinsfile 结构：pipeline → stage → steps → post

8.1 通俗小故事：剧本与现场指挥

● 自由风格 = 导演在现场喊”灯光、收音、开拍”，靠记忆和默契
● Jenkinsfile = 剧本，谁演、第几场上、出错怎么救，全写在纸上
● Declarative（声明式）= 标准剧本格式，有固定章节（pipeline / stages / post）
● Scripted（脚本式）= 自由写作，想怎么写就怎么写，也更难维护
● 共享库（Shared Library）= 全集通用的桥段，抽出来给大家复用

剧本进仓库后，改流程就是一次 commit，”谁把发布步骤改了”有迹可循。

8.2 声明式最小骨架

pipeline {
  agent any

  environment {
    APP_NAME = 'order-api'
    JAVA_OPTS = '-Xmx1024m'
  }

  options {
    timeout(time: 30, unit: 'MINUTES')
    disableConcurrentBuilds()
    buildDiscarder(logRotator(numToKeepStr: '30'))
    timestamps()
  }

  stages {
    stage('Checkout') {
      steps {
        checkout scm
        sh 'git log -1 --pretty="commit %h %s"'
      }
    }
    stage('Build') {
      steps {
        sh 'mvn -B clean package -DskipTests'
      }
    }
    stage('Deploy') {
      steps {
        sh './scripts/deploy.sh'
      }
    }
  }

  post {
    always  { junit 'target/surefire-reports/*.xml' }
    success { echo "构建成功 #${env.BUILD_NUMBER}" }
    failure { echo '构建失败，请看控制台' }
  }
}

写好后把文件放进仓库根（或 ci/Jenkinsfile），任务里选 Pipeline script from SCM，指定仓库与脚本路径。

脚本式对照：

node('linux') {
  stage('Build') {
    checkout scm
    sh 'mvn -B clean package -DskipTests'
  }
  stage('Deploy') {
    try {
      timeout(30) { sh './scripts/deploy.sh' }
    } catch (e) {
      currentBuild.result = 'FAILURE'
      throw e
    }
  }
}

8.5 凭据的正确用法

凭据不该出现在脚本、也不该出现在日志。三种标准写法：

// 1. 用户名密码：注入为环境变量，日志里自动打码
withCredentials([usernamePassword(
  credentialsId: 'gitlab-deploy',
  usernameVariable: 'GIT_USER',
  passwordVariable: 'GIT_PASS')]) {
  sh 'git push http://$GIT_USER:$GIT_PASS@gitlab.example.com/team/repo.git HEAD:develop'
}

// 2. SSH 私钥：文件型凭据
withCredentials([sshUserPrivateKey(
  credentialsId: 'deploy-key',
  keyFileVariable: 'KEY')]) {
  sh 'scp -i $KEY target/*.jar deploy@10.0.1.20:/opt/apps/'
}

// 3. 令牌 / Secret Text
withCredentials([string(credentialsId: 'sonar-token', variable: 'SONAR_TOKEN')]) {
  sh 'sonar-scanner -Dsonar.login=$SONAR_TOKEN'
}

environment { } 里的 credentials() 也能注入，但那会对整段 stage 生效，作用面更大，按需选择。

8.6 并行、条件与重试

stage('Verification') {
  parallel {
    stage('Unit Test')       { steps { sh 'mvn -B test' } }
    stage('Lint')            { steps { sh 'mvn -B checkstyle:check' } }
    stage('Dependency Check'){ steps { sh 'mvn -B dependency:analyze' } }
  }
}

stage('Deploy Prod') {
  when {
    branch 'main'
    expression { currentBuild.result == null || currentBuild.result == 'SUCCESS' }
  }
  steps {
    retry(3) { sh './scripts/deploy.sh prod' }
  }
}

● parallel 内的子 stage 共享 workspace，别让它们同时写同一份 target/
● when 条件不满足时该 stage 显示为灰色 skipped，不算失败
● retry(3) 只包住步骤本身，网络抖动的部署很适用

8.7 共享库（多个项目复用）

仓库 jenkins-shared 结构：

vars/
  mavenBuild.groovy
  deployTo.groovy
src/
  com/example/Utils.groovy

vars/mavenBuild.groovy：

def call(Map cfg = [:]) {
  sh "mvn -B clean package ${cfg.skipTests ? '-DskipTests' : ''}"
  archiveArtifacts artifacts: '**/target/*.jar', fingerprint: true
}

Jenkinsfile 里的用法：

@Library('shared-lib@main') _
pipeline {
  agent any
  stages {
    stage('Build') { steps { mavenBuild(skipTests: true) } }
  }
}

配置位置：系统管理 → 系统设置 → Global Pipeline Libraries（名字 shared-lib、默认版本、SCM 地址）。

8.8 排错与调试技巧

● Declarative 语法校验：任务页”Pipeline Syntax”里可以生成片段（checkout scm、withCredentials 都能一键生成）
● Replay：构建页点 Replay，在页面上改脚本直接重跑，不用提交代码，调试阶段极快
● 打印环境：sh 'env | sort' 一眼看清变量真实值
● 定位慢在哪：timestamps() + 每步 date 打点
● 常见报错 No such DSL method：插件没装或版本不对，按报错里的方法名反查插件

报错
原因
No such DSL method 'xxx'
对应插件未安装
Expected a step
steps 块里写了非法语句（如裸 Groovy 赋值，需 script { }）
java.io.NotSerializableException
在 CPS 流程里用了不可序列化对象，包进 @NonCPS 方法
script returned exit code 1
shell 命令失败，看 console 对应行
Cannot invoke method
变量作用域问题，def 声明别跨 stage 复用

8.9 清单

  1. Jenkinsfile 必须进仓库，别写在页面里
  2. 首选声明式，复杂逻辑用 script { } 局部包
  3. options 里配 timeout + disableConcurrentBuilds + 丢弃旧构建
  4. 凭据一律 withCredentials，绝不明文
  5. 并行 stage 注意 workspace 冲突
  6. 多项目复用抽共享库，别复制粘贴 Jenkinsfile
  7. 调试用 Replay，稳定后再提交
