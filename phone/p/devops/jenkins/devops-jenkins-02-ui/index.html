DevOps Jenkins 传统界面与 Blue Ocean 使用

分类：devops · jenkins ｜ 标签：jenkins

Jenkins 传统 / Blue Ocean UI 使用

Jenkins 有两张脸：一张是 2007 年长出来的传统界面，功能全、入口深；一张是 Blue Ocean，专门为 Pipeline 做的可视化看板，好看、但功能覆盖不全。会用的人两张一起用——日常配置走传统界面，看流水线跑成什么样走 Blue Ocean。

传统界面与 Blue Ocean 的分工：配置 vs 观察

2.1 通俗小故事：老仪表盘与新看板

● 传统界面像工厂的老式仪表盘：几百个按钮、几十个表盘，什么都能调，就是找起来费劲
● Blue Ocean 像车间门口的大屏：只看每条流水线走到哪一步、哪一步红了，点进去能看日志
● 仪表盘能改参数，大屏只能看进度——这就是两套界面的分工

所以结论很简单：配任务用传统，看结果用 Blue Ocean。

2.4 任务详情页的几个动作

● 立即构建（Build Now）：手动触发，左侧出现 #12 这样的构建号
● 控制台输出（Console Output）：最常用的排错入口，等价于 URL 后加 /console
● 工作空间（Workspace）：构建时的当前目录，ls 一下就知道脚本跑在哪
● 构建历史：点时间戳看当次参数、变更集（Changes）、耗时
● 构建趋势：成功/失败/耗时曲线，判断”最近是不是越来越慢”
● 参数化构建：勾选后有 BUILD_ENV 之类的参数，用 $BUILD_ENV 在脚本里取
● 重放 / 重建：按当次参数再跑一次，验证”是不是偶发”

常用 URL 速记
/job/<name>/              任务页
/job/<name>/lastBuild/consoleText   最近一次完整日志（可直接 curl）
/job/<name>/build?delay=0sec        命令行触发构建
/job/<name>/lastBuild/api/json      结果 JSON，便于脚本判定成败

2.5 Blue Ocean 的安装与进入

插件管理 → 可选插件 → 搜 "Blue Ocean" → 安装（会连带装 blueocean-pipeline-editor 等）

入口在左侧菜单”打开 Blue Ocean”，或直接访问：

http://<jenkins>/blue

Blue Ocean 的核心视图：

Blue Ocean 官方已停止大版本演进，但作为”看板”依旧好用。不要把关键配置只放在 Blue Ocean 的编辑器里，它的图形化编辑会把 Jenkinsfile 重写成它认识的形态，容易覆盖手写内容。

2.7 上手顺序建议

  1. 传统界面 → 系统管理 → 全局工具配置，把 JDK / Maven / Git 配好
  2. 传统界面 → 新建一个自由风格 Job，跑通”拉代码 + 构建”
  3. 装 Blue Ocean，从 /blue 看这次构建的阶段图
  4. 把该 Job 换成 Pipeline，用 Jenkinsfile 管理
  5. 之后所有流程改动都改 Jenkinsfile，界面只用来观察和触发

2.8 清单

  1. 配置走传统界面，观察走 Blue Ocean
  2. 任务名用英文，别让 URL 变 %E4%B8%AD
  3. consoleText 是排错第一入口，能直接 curl
  4. 参数化构建统一用 BUILD_ENV 之类的显式参数
  5. 全局工具配置里锁定 JDK/Maven 版本，别依赖系统默认
  6. Blue Ocean 的图形化编辑别用来改手写 Jenkinsfile
  7. 用 lastBuild/api/json 做自动化判定成败，比 grep 日志可靠
