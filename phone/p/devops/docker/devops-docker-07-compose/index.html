DevOps Docker Compose

分类：devops · docker ｜ 标签：Docker

Docker Compose

一个 Java 服务 + MySQL + Redis + Nginx，如果挨个 docker run，光参数就能写错三条。Compose 用一份 YAML 把整套环境描述出来，docker compose up -d 一次拉起，down 一次收走。

Compose 多服务拓扑：一条命令拉起整套依赖

7.1 通俗小故事：剧组通告单

每个容器是一名演员，compose 文件是通告单：谁先上场（depends_on）、穿什么（image/build）、台词（environment）、道具（volumes）、走位（ports/networks）。
导演（docker compose）照着单子点名，缺人自动补，散场统一清场。少写一条，演员就不知道自己该站哪儿——所以 YAML 缩进必须一致。

7.2 最小可用示例

services:
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: rootpass
      MYSQL_DATABASE: app
      TZ: Asia/Shanghai
    volumes:
      - mysql-data:/var/lib/mysql
      - ./sql/init.sql:/docker-entrypoint-initdb.d/init.sql:ro
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "-uroot", "-prootpass"]
      interval: 10s
      timeout: 3s
      retries: 10
    networks: [backend]

  redis:
    image: redis:7-alpine
    command: ["redis-server", "--appendonly", "yes"]
    volumes:
      - redis-data:/data
    networks: [backend]

  api:
    build:
      context: .
      dockerfile: Dockerfile
    image: myapp:1.0
    environment:
      SPRING_PROFILES_ACTIVE: prod
      SPRING_DATASOURCE_URL: jdbc:mysql://mysql:3306/app?useSSL=false
      SPRING_DATA_REDIS_HOST: redis
    ports:
      - "127.0.0.1:8080:8080"
    volumes:
      - ./logs:/app/logs
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_started
    networks: [backend, frontend]

  nginx:
    image: nginx:1.25-alpine
    ports: ["80:80"]
    volumes:
      - ./nginx/default.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on: [api]
    networks: [frontend]

networks:
  backend:
  frontend:

volumes:
  mysql-data:
  redis-data:

注意：depends_on 只保证启动顺序，不保证”服务可用”；要等就绪必须配 healthcheck + condition: service_healthy。

7.3 常用命令

docker compose up -d              # 构建 + 启动
docker compose up -d --build api  # 只重建 api
docker compose ps
docker compose logs -f api
docker compose restart api
docker compose exec api sh
docker compose down               # 停并删容器/网络
docker compose down -v            # 连卷一起删（数据没了，慎重）
docker compose config             # 校验并展开最终配置，排错第一招

docker compose config 会把变量替换后的完整配置打印出来，${VAR} 没读到、缩进写错，一眼就能看出来。

7.4 变量与环境分层

services:
  api:
    image: ${REGISTRY}/myapp:${TAG:-1.0}
    env_file: [.env]
# .env
REGISTRY=harbor.example.com/dev
TAG=1.0

再叠一份覆盖文件做环境差异：

docker compose -f compose.yml -f compose.prod.yml up -d

后一份文件里的同名字段覆盖前一份，ports 这类列表会整体替换而不是合并，别指望”追加端口”。

7.5 健康检查与优雅停机

healthcheck:
  test: ["CMD-SHELL", "curl -fs http://localhost:8080/actuator/health || exit 1"]
  interval: 20s
  timeout: 5s
  retries: 3
  start_period: 40s
stop_grace_period: 30s

● start_period 给冷启动留时间，否则健康检查会在应用还没起来时就把容器判死
● stop_grace_period 必须大于应用的优雅停机时长，否则 Spring 的 SIGTERM 处理完就被直接 kill
● 检查命令要写 127.0.0.1，别写 localhost，某些镜像里它会解析到 IPv6 导致永远失败

7.6 资源限制与日志

deploy:
  resources:
    limits:
      cpus: "1.5"
      memory: 1g
logging:
  driver: json-file
  options:
    max-size: "50m"
    max-file: "3"

deploy.resources 在 compose 单机模式已生效（早期版本需要 --compatibility），日志轮转不配就是等着磁盘满。

7.7 项目隔离与命名

Compose 用目录名作为项目名，容器名形如 project-api-1，网络是 project_backend。同一台机器跑多套环境时：

docker compose -p blog-dev up -d
docker compose -p blog-prod up -d

两套环境的容器、网络、卷完全隔离，端口冲突改 ports 即可。
