常用命令速查

前面十二章讲的是”为什么”，这一篇只讲”怎么敲”。Docker 命令按对象分成几组：镜像、容器、网络、卷、仓库、系统、Compose。记住”动作 + 对象”的结构，docker <对象> <动作>（新语法）和 docker <动作> <对象>（老语法）其实是同一件事，例如 docker image ls 与 docker images。

容器命令的六大族：镜像、容器、网络、存储、编排、日志

13.1 通俗小故事：遥控器

宿主机是机房，Docker 守护进程是机房的总控台，CLI 就是你手里的遥控器。
● docker images 看货架上有什么模板
● docker run 从模板开一台机器出来
● docker ps 看现在哪些机器在转
● docker logs 听机器在说什么
● docker rm / docker rmi 把不要的机器、模板清掉

遥控器按错只会让某台机器停，但 prune 一类”一键清场”的键要看清再按。

13.2 版本与环境自检

docker version            # 客户端与服务端版本
docker info               # 内核、存储驱动、资源、安全选项
docker system df          # 镜像/容器/卷/构建缓存各占多少
docker context ls         # 当前连的是本机还是远程  # 多主机切换

docker info 出现 Cannot connect to the Docker daemon 时，先查服务是否在跑（systemctl status docker），再看 DOCKER_HOST 环境变量是否指向了错误的主机。

13.3 镜像：拉、看、查、删

docker pull nginx:1.25                       # 拉取（不带 tag 默认 latest）
docker images                                # 本地镜像列表
docker image ls --filter dangling=true       # 悬空镜像（<none>:<none>）
docker inspect nginx:1.25                    # 完整 JSON，看 Env/Entrypoint/Cmd
docker history nginx:1.25 --no-trunc         # 分层来源，排查体积与泄露
docker tag myapp:1.0 registry.example.com/team/myapp:1.0
docker push registry.example.com/team/myapp:1.0
docker rmi nginx:1.25                        # 删镜像，被容器占用要先删容器
docker save myapp:1.0 -o myapp.tar           # 导出离线包
docker load -i myapp.tar                     # 离线导入

docker history 是最实用的一条：镜像为什么 1.2G、哪一层把密钥写进去了，一条命令就能定位。

13.4 容器的生命周期

docker run -d --name web -p 8080:80 nginx:1.25   # 后台运行并映射端口
docker run -it --rm alpine sh                    # 交互进入，退出即删
docker ps                                        # 运行中的容器
docker ps -a                                     # 含已退出的
docker start web && docker stop web              # 启停已存在的容器
docker restart web
docker pause web && docker unpause web
docker rm web                                    # 删容器
docker rm -f web                                 # 运行中也强删

run 的常用组合参数：

docker run -d \
  --name api \
  --restart unless-stopped \
  -e SPRING_PROFILES_ACTIVE=prod \
  -v /data/api/logs:/app/logs \
  --network backend \
  --memory 1g --cpus 1.0 \
  myapp:1.0

● -d 后台、-it 交互、--rm 用完即删
● -p 宿主:容器 发布端口，只给本机用就写 127.0.0.1:8080:80
● -v 宿主:容器 挂目录，-v 名字:容器 用命名卷
● --network 指定网络、--restart 定义崩溃自愈策略

13.5 进入容器与看现场

docker exec -it web sh                 # 最常用：在运行中的容器里开个 shell
docker exec -it web env                # 看容器内环境变量
docker attach web                      # 接 pid=1 的标准输入输出，Ctrl+P Ctrl+Q 脱离
docker logs -f --tail 100 web          # 跟踪最近 100 行日志
docker logs --since 10m web            # 只看最近 10 分钟
docker inspect web                     # 配置、IP、挂载、状态
docker stats                           # 实时 CPU/内存/网络/IO
docker top web                         # 容器内进程
docker port web                        # 端口映射
docker diff web                        # 容器内文件系统改了什么

exec 和 attach 的区别要分清：exec 新开一个进程，退出不影响容器；attach 连的是主进程，Ctrl+C 会把容器带走。生产排障一律用 exec。

13.6 拷文件、看健康、改配置

docker cp web:/etc/nginx/nginx.conf ./nginx.conf     # 容器 → 本机
docker cp ./nginx.conf web:/etc/nginx/nginx.conf     # 本机 → 容器
docker rename web web-old                            # 改容器名
docker update --memory 2g --cpus 2 web               # 运行中调资源上限
docker commit web myapp:hotfix                       # 把当前容器存成镜像（临时救急，别当发布）
docker wait web                                      # 阻塞等待容器退出并打印退出码

docker commit 只适合现场抢救：它把整层文件系统打包，产物不可复现、体积不可控，正规发布仍应改 Dockerfile 重建。

13.7 网络与卷

docker network ls
docker network create backend
docker network inspect backend
docker network connect backend web
docker network disconnect backend web

docker volume ls
docker volume create pgdata
docker volume inspect pgdata
docker volume rm pgdata

网络排障常用组合：

docker network inspect backend --format '{{range .Containers}}{{.Name}} {{.IPv4Address}}{{"\n"}}{{end}}'
docker run --rm --network backend nicolaka/netshoot nslookup api

卷的删除是不可逆数据操作：docker volume rm、docker volume prune 前先确认 docker volume inspect 里的 Mountpoint。

13.8 仓库登录与镜像搬运

docker login registry.example.com -u robot -p "$REGISTRY_TOKEN"
docker logout registry.example.com
docker search nginx                    # 只查 Docker Hub，语法简单、结果少
docker manifest inspect nginx:1.25     # 看多架构清单
docker buildx imagetools inspect nginx:1.25

CI 里建议用 --password-stdin 或 token 环境变量，避免密码进 shell 历史：

echo "$REGISTRY_TOKEN" | docker login registry.example.com -u robot --password-stdin

13.9 构建

docker build -t myapp:1.0 .                          # 当前目录为上下文
docker build -t myapp:1.0 -f docker/Dockerfile .      # 指定 Dockerfile
docker build --build-arg JAR_FILE=target/app.jar -t myapp:1.0 .
docker build --secret id=mvn,src=$HOME/.m2/settings.xml -t myapp:1.0 .
docker build --no-cache -t myapp:1.0 .                # 忽略缓存（排查"改了没生效"）
docker buildx build --platform linux/amd64,linux/arm64 -t myapp:1.0 --push .

docker build --progress=plain 能看到每一步的真实输出，构建卡住或缓存命中异常时用它。.dockerignore 没写好会导致上下文几个 G，构建时间全耗在传输上。

13.10 Compose 常用命令

docker compose up -d                 # 按 compose.yml 起全部服务
docker compose up -d --build api      # 只重建并重启 api
docker compose ps                     # 本项目的容器状态
docker compose logs -f --tail 50 api  # 跟随日志
docker compose exec api sh            # 进容器
docker compose restart api
docker compose down                   # 停止并删除容器与网络
docker compose down -v                 # 连卷一起删（数据会没）
docker compose config                 # 展开并校验最终配置

docker compose config 是把心放到肚子里的命令：变量替换、extends、多个 compose 文件叠加之后究竟长什么样，它会打印成一份完整的 YAML。

13.11 清理与磁盘治理

docker system prune              # 删停止的容器、悬空镜像、无用网络
docker system prune -a           # 再删所有未使用镜像（谨慎）
docker container prune           # 只清停止的容器
docker image prune -a --filter "until=168h"   # 只清一周前的镜像
docker builder prune             # 清构建缓存，往往能省最大一块
docker volume prune              # 清未挂载的卷（数据风险）

先看再删是纪律：

docker system df -v | head -20

会列出每个镜像、容器、卷的实际占用。-v 不加只能看到汇总，排不出”到底是谁占了 40G”。

13.12 一页速查

  1. 看现状：docker ps -a、docker images、docker system df -v
  2. 起一台：docker run -d --name x -p 宿主:容器 -v 卷:路径 镜像:tag
  3. 进现场：docker exec -it x sh、docker logs -f --tail 100 x、docker stats
  4. 转移镜像：docker tag → docker push；离线用 save / load
  5. 构建：docker build -t 名字:tag -f Dockerfile .，跨架构加 buildx --platform
  6. 编排：docker compose up -d --build、docker compose config、docker compose down -v（慎）
  7. 清理：docker system prune / docker builder prune，-a、-v 之前先 df -v 核对

命令记不住不用背，docker <对象> --help 与 docker <动作> --help 是最快的文档；docker run --help 里 --restart、-p、-v、--network 四组参数覆盖了八成的日常场景。
