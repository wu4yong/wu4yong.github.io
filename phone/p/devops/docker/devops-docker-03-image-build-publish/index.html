Docker 镜像构建与发布

镜像不是”一个文件”，而是一组按层叠起来的只读快照加一份元数据（启动命令、端口、环境变量、数据卷）。理解分层，才谈得上构建得小、推得快、回滚得住。

镜像分层与仓库的推拉关系：一次构建，随处运行

3.1 通俗小故事：盖楼与楼层

每一层 RUN / COPY 就像给楼加一层，下层是地基，上层只记录”在上面的基础上改了什么”。
● 同一块地基（基础镜像）可以被无数栋楼复用，机器上只存一份
● 只改顶层，重建时下面几层直接从缓存拿，秒级完成
● 层数不是越多越好，但”把易变的东西放上层”是铁律：COPY pom.xml 在 COPY src 之前，依赖层就能长期复用

3.2 拉取、查看、打标签

docker pull openjdk:17-jdk-slim
docker image ls
docker image inspect openjdk:17-jdk-slim
docker history --no-trunc myapp:1.0        # 看每层干了什么、占多大
docker tag myapp:1.0 registry.example.com/team/myapp:1.0
docker tag myapp:1.0 registry.example.com/team/myapp:latest

标签是”指针”，一个镜像可以有多个 tag；latest 只是默认名，不是”最新版本”的语义保证，生产一定用明确版本号或 git commit sha。

3.3 构建：本机与多平台

# 最基础的构建
docker build -t myapp:1.0 .

# 指定 Dockerfile 与上下文
docker build -f docker/Dockerfile.prod -t myapp:1.0 .

# 构建期参数
docker build --build-arg JAR_FILE=target/app.jar -t myapp:1.0 .

# 不在 Dockerfile 里写内网地址，用 secret 传入
docker build --secret id=mavenrc,src=$HOME/.m2/settings.xml -t myapp:1.0 .

# 多架构构建（需要 buildx + QEMU）
docker buildx create --use --name multi
docker buildx build --platform linux/amd64,linux/arm64 -t myapp:1.0 --push .

三条经验：上下文要小（用 .dockerignore 排除 target、.git、node_modules），构建要可复现（基础镜像用 digest 或明确 tag），产物不要带构建缓存（多阶段构建解决）。

3.4 推送与仓库

docker login registry.example.com
docker push registry.example.com/team/myapp:1.0

# 私有 Harbor 常见命名：<harbor>/<项目>/<仓库>:<tag>
docker tag myapp:1.0 harbor.example.com/dev/myapp:1.0
docker push harbor.example.com/dev/myapp:1.0

镜像命名规则：[registry[:port]/]namespace/repository[:tag|@digest]。省略 registry 就是 Docker Hub。推送前先 docker login，自建 Harbor 记得把证书放进 /etc/docker/certs.d/<host>/ca.crt，否则会报 x509: certificate signed by unknown authority。

3.5 导出、导入与离线分发

docker save -o myapp-1.0.tar myapp:1.0
docker load -i myapp-1.0.tar
docker export -o app-rootfs.tar $(docker create myapp:1.0)
docker import app-rootfs.tar myapp:flattened

save/load 保留全部层与元数据，适合内网搬运；export/import 只留一个扁平的文件系统快照，丢历史、丢启动配置，体积略小但不适合当镜像用。docker save | gzip 可以把传输体积再压一半。

3.6 清理与体积治理

docker image prune -a --filter "until=72h"
docker builder prune --filter "until=24h"
docker images --format "{{.Repository}}:{{.Tag}}\t{{.Size}}" | sort -k2 -h | tail -10

体积大的三个常见来源：基础镜像选了 latest 全量版、单阶段构建把编译工具留在镜像里、COPY . 把 .git 和测试数据带进去了。逐条对症即可，通常能省下一半以上空间。

3.7 构建失败排查顺序

  1. docker build --progress=plain --no-cache . 看完整输出，别被折叠日志误导
  2. 报 failed to compute cache key 多半是 .dockerignore 和 COPY 路径不一致
  3. 报 no space left on device 查 /var/lib/docker 所在分区，先 builder prune
  4. 拉基础镜像超时，先 docker pull 单独验证网络与镜像加速是否生效
  5. 构建成功但运行崩，docker run --entrypoint sh -it <image> 进去手工跑一遍入口命令
