Docker 介绍与安装

部署一个 Java 应用，先要装 JDK、配环境变量、调 Tomcat、核对依赖版本……换台机器重来一遍，线上和本地还经常”行为不一致”。Docker 把这套东西和代码一起打包成镜像，机器上只留一个运行时，环境问题被一次性收走。

容器与虚拟机的架构差异：一套内核共享 vs 每台都装完整系统

1.1 通俗小故事：集装箱

把镜像想成一个标准集装箱：里面装好了应用、运行时、依赖、配置和启动脚本，外部只看箱子的规格，不管里面怎么装的。
容器就是这只箱子被吊到某台船上（宿主机）后开始运行的状态；同一只箱子可以同时吊上十条船，每条船上的货物互不影响。港口（宿主机）只需要准备吊机和轨道（Docker Engine），不需要为每票货单独盖一间仓库。

三个关键词先立住：

● 镜像（Image）：只读模板，分层存储，可复用、可分发
● 容器（Container）：镜像的运行实例，多一层可写层，进程隔离
● 仓库（Registry）：镜像的存放与分发点，Docker Hub 是公共的，Harbor 是常见的私有方案

1.2 和虚拟机的差别

两者都能”隔离”，但隔离的层次不同：

● 虚拟机靠 Hypervisor 虚拟出整套硬件，每台虚机跑一个完整内核，启动按分钟算，内存按 GB 占
● 容器只是宿主机上的普通进程，靠 Namespace 做视图隔离、Cgroups 做资源限制，共享宿主机内核，启动按秒甚至毫秒算

所以容器轻、快、密度高；代价是内核共享，隔离强度弱于虚机，对内核版本和安全配置更敏感。这也是后面”容器安全”一章要专门讲的原因。

1.3 安装：三条主流路线

Linux（官方脚本，最快）

curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
docker version

Linux（apt / yum 仓库，可控版本）

sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt-get update && sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Windows / macOS：Docker Desktop

安装包一路下一步即可。Windows 需要 WSL2 后端（或 Hyper-V），macOS 走的是轻量 Linux 虚拟机。国内拉镜像慢，可以在 Docker Desktop 的 Settings → Docker Engine 里配镜像加速地址，写进 registry-mirrors。

1.4 安装后必做的四件事

① 免 sudo 使用 docker（把自己加进 docker 组，重新登录生效）

sudo usermod -aG docker $USER
newgrp docker
docker run --rm hello-world

② 配置镜像加速与日志轮转（/etc/docker/daemon.json）

{
  "registry-mirrors": ["https://your-mirror.example.com"],
  "log-driver": "json-file",
  "log-opts": { "max-size": "50m", "max-file": "3" },
  "data-root": "/data/docker"
}

改完 sudo systemctl reload docker（部分项需要 restart）。日志不轮转是生产上磁盘打满的经典原因，max-size 一定要设。

③ 检查存储驱动与内核能力

docker info | grep -E "Storage Driver|Cgroup|Kernel Version"

xfs 需要 ftype=1 才支持 overlay2；cgroup v2 是新版本默认，老工具链要留意兼容性。

④ 常用自检命令

docker version          # 客户端 + 服务端
docker info             # 引擎全量信息
docker system df        # 磁盘占用分布
docker run --rm alpine uname -a

1.5 一个最小闭环

docker pull nginx:1.25-alpine
docker run -d --name web -p 8080:80 nginx:1.25-alpine
curl -I http://localhost:8080
docker logs -f web
docker stop web && docker rm web

pull 取镜像、run 起容器、-p 做端口映射、logs 看日志、stop/rm 收尾。这五条命令串起来，就是后面所有章节的基本节奏。

1.6 版本与选型建议

● 生产优先用 LTS 发行版（如 Ubuntu 22.04/24.04），内核与 cgroup 支持成熟
● Docker Engine 装官方仓库版本，别用发行版自带的 docker.io（版本旧、功能缺）
● 单机开发 + 桌面用 Docker Desktop；服务器用 Engine + compose plugin；要图形化管理再叠 Portainer
● 国内环境先把镜像加速、私有 Harbor 规划好，否则拉包时间会占掉大半调试时间

装完这一章，环境就算齐了。下一章直接从容器生命周期开始，把 run / exec / cp / commit 这些日常动作走一遍。
