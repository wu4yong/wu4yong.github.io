Docker 与 Podman

Docker 不是唯一的容器运行时。Podman 用同样的 CLI 语义、同样的镜像格式，但不需要常驻守护进程、默认不用 root，在 RHEL 系发行版里已经成了默认选择。这一章按”能不能换、换了差在哪”来讲。

Docker 与 Podman：有守护进程 vs 无守护进程

9.1 通俗小故事：专柜与自助

Docker 像商场里的专柜：所有动作都得经过柜台（dockerd 守护进程），柜台有钥匙（root 权限），顾客多时柜台排队。
Podman 像自助货架：每个容器是你自己起的一个进程（fork/exec），不需要专职柜台，也没有”柜台下班所有货架都停”的问题。

9.2 关键差异

维度
Docker
Podman
架构
客户端 + 常驻 dockerd
无守护进程，直接 fork 容器进程
权限
默认 root，需 docker 组
默认 rootless，普通用户即可
编排
docker compose 插件
podman compose（可调 docker-compose 或 podman-compose）
集群
Swarm
无内置集群，配合 K8s 或 Quadlet
镜像格式
OCI
同 OCI，可互相导入导出
systemd 集成
需手写 unit
podman generate systemd / Quadlet 原生
生态
最广，教程/工具最多
增长快，RHEL/Fedora 默认

一个容易误解的点：podman 与 docker 的镜像存储目录不同，docker images 看不到 podman 的镜像（rootless 下更彻底）。要复用得 podman save / docker load。

9.3 迁移成本

alias docker=podman          # 多数日常命令可直接互换
podman run -d -p 8080:80 nginx:alpine
podman ps
podman pull harbor.example.com/dev/myapp:1.0

直接兼容的部分：run / ps / logs / exec / build / push / save / load / inspect 语义基本一致，Dockerfile 也能直接 podman build。

需要改造的部分：
● compose：podman compose 是转发器，需要本机装 docker-compose 或 podman-compose，少数字段（depends_on 健康条件、deploy 段）行为不同
● 依赖 daemon 的功能：docker events、docker system df 的实时统计、部分 docker stats 指标在 rootless 下有限制
● 网络：rootless 模式端口映射走 slirp4netns/pasta，低端口（<1024）需要额外配置
● CI 工具：一些插件默认调 docker.sock，需要开 podman.socket 提供兼容接口

systemctl --user enable --now podman.socket
export DOCKER_HOST=unix:///run/user/$UID/podman/podman.sock

打开 socket 后，大量按 Docker 写的脚本可以无痛跑在 Podman 上。

9.4 rootless 的真实收益

● 安全性：容器进程就是你的用户权限，逃逸拿到的也只是普通账号
● 多用户共享主机：每人一套自己的容器与镜像，不互相污染
● 无守护进程：升级运行时不用停服务，崩溃不影响其他容器

代价是：网络与存储走用户态路径，吞吐和延迟略差；--privileged 基本不可用；某些需要挂载内核文件系统的镜像跑不起来（如部分监控 agent）。

9.5 该选谁

● 团队已有成熟的 Docker 流程、CI 基于 Docker、需要 Swarm：继续 Docker
● RHEL/CentOS Stream/Fedora、重视 rootless 与 systemd 集成：Podman
● 要跑 K8s：运行时用 containerd/CRI-O，本地开发用 Docker 或 Podman 都行

实际结论：两者不是二选一的对立面。镜像与 Dockerfile 是通用的，换运行时主要是”编排层”和”权限模型”的适配；先把镜像做规范，后面迁移成本自然就低。

9.6 一个互换验证脚本

#!/usr/bin/env bash
set -e
RT=${RT:-docker}
$RT build -t demo:1.0 .
$RT run -d --name demo -p 8080:80 demo:1.0
sleep 3
curl -fsS http://127.0.0.1:8080/ > /dev/null && echo "OK: $RT"
$RT rm -f demo

RT=podman ./check.sh 和 RT=docker ./check.sh 都能过，说明镜像和启动方式没有隐含依赖，迁移就只是换命令。
