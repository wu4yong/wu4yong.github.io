DevOps Docker 多架构支持

分类：devops · docker ｜ 标签：Docker

Docker 的多架构支持（x86 / arm）

开发用 Apple Silicon 或 ARM 云主机、线上是 x86，docker run 一句 exec format error 就卡住了。镜像的架构不是”可选项”，而是镜像身份的一部分。多架构支持的核心是 manifest list：一个 tag 下挂多份不同架构的镜像，拉取时按平台自动选。

多架构镜像：一份清单分发到 x86 与 ARM

10.1 通俗小故事：同一款鞋的多码

myapp:1.0 这个 tag 像”某款鞋”，manifest list 是尺码表：40 码（amd64）、42 码（arm64）各一双。
● 顾客（docker pull）报自己的尺码，店员按表取对应那双
● 表里没这个尺码，就报”没有你的号”（no matching manifest for linux/arm64）
● 你想自己穿，就得先按自己的尺码做一双（buildx 构建对应平台）

10.2 先看清自己在什么平台

docker version --format '{{.Server.Os}}/{{.Server.Arch}}'
docker image inspect nginx:1.25-alpine -f '{{.Os}}/{{.Architecture}}'
uname -m          # x86_64 / aarch64

常见组合：linux/amd64（x86 服务器）、linux/arm64（Apple Silicon、ARM 云主机、树莓派 64 位）、linux/arm/v7（32 位 ARM）。

10.3 检查一个 tag 支持哪些架构

docker manifest inspect nginx:1.25-alpine | grep -E '"architecture"|"variant"'
docker buildx imagetools inspect nginx:1.25-alpine

输出里没有 arm64 就是拉不到，不是网络问题。

10.4 用 buildx 构建多架构镜像

docker buildx create --name multi --driver docker-container --use
docker buildx inspect --bootstrap

docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -t harbor.example.com/dev/myapp:1.0 \
  --push .

要点：
● 必须 --push，多平台结果无法直接 --load 到本地镜像库（本地只能存单架构）
● --driver docker-container 会起一个构建容器，能用 QEMU 模拟其他架构，第一次构建慢是正常的
● 只想要单个平台的 tar 包：--platform linux/arm64 --output type=tar,dest=myapp-arm64.tar

10.5 模拟运行（慢，但能验证）

docker run --rm --platform linux/arm64 arm64v8/alpine uname -m

QEMU 模拟的 CPU 性能大约是原生的十分之一，只适合”能不能起来”的冒烟测试；压测、编译这类重活别在模拟环境里做，会很慢甚至超时。

10.6 基础镜像要选对

多架构构建失败，八成是基础镜像本身没有对应架构：

FROM --platform=$BUILDPLATFORM golang:1.22 AS build
ARG TARGETOS TARGETARCH
RUN GOOS=$TARGETOS GOARCH=$TARGETARCH go build -o /out/app ./cmd/app

FROM alpine:3.20
COPY --from=build /out/app /app
ENTRYPOINT ["/app"]

● --platform=$BUILDPLATFORM 让构建阶段跑在原生架构（快），产物按目标架构交叉编译
● $TARGETOS / $TARGETARCH 是 buildx 自动注入的全局 ARG
● Java 场景更简单：eclipse-temurin、openjdk 官方镜像基本都提供多架构，直接 --platform 构建即可

10.7 CI 里的常见配置

# GitHub Actions 片段
- uses: docker/setup-qemu-action@v3
- uses: docker/setup-buildx-action@v3
- uses: docker/build-push-action@v5
  with:
    platforms: linux/amd64,linux/arm64
    push: true
    tags: harbor.example.com/dev/myapp:1.0
    cache-from: type=registry,ref=harbor.example.com/dev/myapp:buildcache
    cache-to: type=registry,ref=harbor.example.com/dev/myapp:buildcache,mode=max

cache-to mode=max 把中间层也缓存起来，多架构构建从几十分钟降到几分钟。

10.8 排障清单

  1. no matching manifest → 该 tag 不支持目标架构，换基础镜像或自己构建
  2. exec format error → 用了单架构镜像，检查 docker image inspect 的 arch
  3. buildx 构建卡住 → 检查 QEMU 是否注册：docker run --rm --privileged multiarch/qemu-user-static --reset -p yes
  4. 构建成功但运行报 Illegal instruction → 依赖了平台特定指令集（AVX、NEON），换编译参数
  5. 推送后 ARM 机器拉不到 → docker buildx imagetools inspect 确认 manifest list 里真的有 arm64
