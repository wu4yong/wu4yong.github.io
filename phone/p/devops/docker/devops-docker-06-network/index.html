Docker 的网络

容器一多，”怎么互相访问”就成了主要问题：IP 会变、端口要映射、跨主机还要互通。Docker 内置了 bridge、host、none、container、overlay 几种网络模式，选对模式能省掉一半排障时间。

四种网络模式：桥接、主机、无网络、覆盖

6.1 通俗小故事：写字楼与门牌

宿主机是一栋写字楼，Docker 负责在楼里隔出房间并分配内线分机号：
● bridge（默认）：每层楼一个独立内网，房间之间用内线互拨，外面只能通过前台转接（端口映射）
● host：房间不隔墙，直接用大楼的分机号（容器与宿主机共享网络栈）
● none：房间没电话，完全断网
● container：蹭别人房间的电话线（与另一个容器共享网络命名空间）
● overlay：跨栋楼的总机系统，把不同宿主机上的房间接进同一张内网（Swarm 用）

6.2 默认 bridge 的三个事实

docker network ls
docker network inspect bridge -f '{{json .IPAM.Config}}'
docker run --rm alpine ip route

● 默认 bridge 上的容器只能用 IP 互访，没有 DNS 名字解析
● 默认 bridge 的网段常是 172.17.0.0/16，和公司内网冲突是高频事故
● 容器重启后 IP 可能变，靠 IP 写死连接等于埋雷

所以生产上第一件事：别用默认 bridge，自己建自定义网络。

6.3 自定义 bridge：自带 DNS

docker network create --subnet 172.28.0.0/16 appnet
docker run -d --name mysql --network appnet -e MYSQL_ROOT_PASSWORD=*** mysql:8
docker run -d --name api --network appnet -p 8080:8080 myapp:1.0
docker exec -it api ping -c 2 mysql        # 直接用容器名解析

自定义网络里，Docker 内置 DNS 会把容器名和网络别名解析成容器 IP；同网络内所有端口直接可达，不需要 -p。-p 只是”给宿主机开一个入口”。

同一容器可以接多个网络，做前后端隔离：

docker network connect backend api
docker run -d --name web --network frontend -p 80:80 nginx:alpine
docker network connect frontend web

6.4 host 与 none 的适用场景

docker run --rm --network host nginx:alpine     # 直接占用宿主机 80 端口
docker run --rm --network none alpine ping 8.8.8.8   # 必然失败，验证断网

host 模式省掉 NAT，性能略好，适合高频网络 IO 的采集器、代理；代价是端口冲突直接暴露、失去端口隔离。Linux 上可用，Docker Desktop 上语义受限（在虚拟机的 host 里）。

6.5 端口映射的坑

docker run -d -p 8080:80 nginx:alpine
docker port <container>            # 查看实际映射

● 只写 -p 80 时，宿主机端口随机，多副本部署常用
● -p 127.0.0.1:8080:80 只绑本机回环，配合反向代理最安全
● -p 8080:80/udp 才映射 UDP，默认是 TCP
● 宿主机端口被占时报 port is already allocated，ss -lntp | grep 8080 查占用者

6.6 跨主机：overlay 与 macvlan

单机之外有两条路：
● overlay：需要 Swarm 或外部 KV 存储，跨主机容器进同一虚拟网络，配置简单但封包有开销
● macvlan：给容器分配与物理网络同网段的 MAC/IP，像一台真实主机接入交换机；性能好，但需要交换机允许混杂模式，IP 规划要提前做

docker network create -d overlay --attachable appnet_overlay
docker network create -d macvlan --subnet 192.168.10.0/24 --gateway 192.168.10.1 -o parent=eth0 macnet

6.7 DNS 与排查顺序

容器内解析走的是 Docker 内置 DNS（127.0.0.11），/etc/resolv.conf 里能看到。排查按这个顺序：

  1. docker network inspect appnet 确认两个容器在同一个网络、别名是否拼错
  2. docker exec -it api getent hosts mysql 看名字能否解析
  3. docker exec -it api nc -zv mysql 3306 看端口通不通
  4. docker exec -it api ip route 看默认路由是否指向网关
  5. 宿主机 iptables -t nat -L -n | grep 8080 看 DNAT 规则是否生成
  6. 还不对就 tcpdump -i docker0 port 3306，用抓包定责

故障 90% 落在前三步：不同网络、名字拼错、端口没监听在 0.0.0.0 而是 127.0.0.1。
