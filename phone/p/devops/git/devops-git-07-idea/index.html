在 IDEA 中使用

IDEA 的 Git 面板不是另一套系统，它只是把命令包成按钮。看清每个按钮背后执行的是哪条命令，出问题才能回到命令行处理。

IDEA 里的 Git 面板：变更、提交、推送、历史

7.1 通俗小故事：遥控器与面板

IDEA 是一块把 Git 命令做成按钮的控制面板。
● 点”Commit”其实是 git add + git commit
● 点”Push”是 git push <remote> <branch>
● 点”Update Project”是 git pull
● 点分支名是 git checkout

面板按错能撤销，但它不告诉你”实际执行了什么”。所以排障时仍要会看命令行输出。

7.2 配置 Git 路径

IDEA 用的是本机安装的 Git，先装 Git 再配路径。

Settings → Version Control → Git 里填 git.exe 路径：

装在默认目录（C:\Program Files\Git）时通常无需手动指定。点 Test 显示版本号即连通。

7.4 .gitignore

.gitignore 决定哪些文件不进版本库，是最值得先配好的文件。

一份可用的 Java 项目模板：

.git
logs
target/
!.mvn/wrapper/maven-wrapper.jar
*.class
*.log

### IntelliJ IDEA ###
.idea
*.iws
*.iml
*.ipr

三条纪律：
● 文件名固定 .gitignore，不能改
● 已提交过的文件加进 .gitignore 不会自动失效，需 git rm --cached 文件
● target/、node_modules/、日志这类生成物一律忽略，否则仓库越滚越大

实际命令
查看分支

git branch <name>

7.8 面板背后的命令

git status                                  # 面板顶部未提交改动列表
git diff                                    # 双击文件看差异
git log --oneline -10                       # History 面板
git remote -v                               # Manage Remotes

遇到”面板显示已推送但远程没有”这类怪象，先到 Terminal 窗口跑 git status 与 git log --oneline github/develop，用命令行核对真实状态，再回面板操作。

7.9 清单

  1. 先装 Git 再配路径，Test 通过才算配好
  2. 建仓先写 .gitignore，生成物一律不入库
  3. 提交粒度按功能划分，message 写清做了什么
  4. 推送前 Update Project，避免非快进被拒
  5. 面板怪象回命令行核对，别在界面上反复点
