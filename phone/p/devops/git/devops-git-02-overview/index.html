核心结构与安装配置

Git 只有四样东西：对象（提交、树、文件内容）、引用（分支与标签指针）、索引（暂存区）、配置。搞清这四样，git 的每个命令就不再是”记住的咒语”。

三区模型：工作区 → 暂存区 → 本地仓库 → 远端

2.1 通俗小故事：仓库前厅

Git 仓库是一座带前厅的仓库。
● 工作区是前厅，货摆在这里，你随手改
● 暂存区（.git/index）是待发货清单，git add 就是把货搬上清单
● 版本库（.git/objects）是真正的库房，git commit 才把货入库并拍一张照片
● 远程仓库是异地分仓，git push 是发车，git pull 是收货

只有”入库”的东西才会被记录，add 只是登记。这个差别是所有”改了半天没提交，一切白干”场景的根源。

2.2 Git 的两类仓库

仓库类型
位置
作用
本地仓库
开发者自己的电脑
日常提交、分支、回退，全部在这里发生
远程仓库
GitHub / Gitee / GitLab 等服务器
备份、协作、CI/CD 触发

三个动作把它们连起来：
● commit：把本地文件与版本信息写入本地仓库
● push：把本地仓库的提交上传到远程仓库
● pull：把远程仓库的新提交取回并合入本地

2.3 下载与安装

Windows 从 git-scm.com 下载安装包，双击安装即可，安装选项保持默认最省事。装完之后在任意目录右键，出现这两项就说明装好了：

● Git GUI Here：打开图形界面
● Git Bash Here：打开命令行（推荐，命令与 Linux 一致）

2.4 最小可用配置

git config --global user.name "your-name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch master
git config --global core.autocrlf false      # Windows 下避免换行符来回改
git config --list                            # 核对

三处配置的层级与覆盖顺序：

user.name / user.email 与代码托管平台的账号无关，它只写进提交记录，随便填但要一致——否则历史里会出现同一人多个身份。

2.5 生成 SSH 密钥

ssh-keygen -t ed25519 -C "you@example.com"     # 一路回车
cat ~/.ssh/id_ed25519.pub                      # 复制公钥
ssh -T git@github.com                          # 验证是否连通
ssh -T git@gitee.com

公钥贴到平台的 SSH Keys 页面，私钥永远留在本机。用 SSH 地址克隆（git@host:owner/repo.git）比 HTTPS 省掉每次输密码，也避开 token 过期问题。
