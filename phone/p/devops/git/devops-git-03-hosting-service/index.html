代码托管服务

本地仓库只在自己电脑上，硬盘一坏历史就没了。远程仓库解决的是”备份 + 协作 + 触发流水线”三件事。选平台时看的不是界面好不好看，而是访问速度、权限模型、CI 能力。

托管平台协作流：拉取、推送、合并请求

3.1 通俗小故事：异地分仓

远程仓库是一座异地分仓。
● GitHub 是国际大仓，货最全、伙伴最多，但国内取货慢
● Gitee 是本地分仓，取货快，适合团队日常推拉
● GitLab 是自建仓库，整栋楼自己管，权限与网络全可控
● 成员权限 是谁能搬货、谁能改清单、谁只能看

双远程（同时推 GitHub 与 Gitee）就是”两地各存一份”，任意一边挂掉都不影响。

选择建议：
● 个人博客、开源项目：GitHub 做门面，Gitee 做镜像（国内访问快）
● 公司内部：GitLab 自建，代码不出内网
● 团队小、预算低：Gitee 私有仓库即可满足

3.3 在 Gitee 上创建远程仓库

流程是固定的五步：注册 → 登录 → 建仓库 → 拿地址 → 邀请成员。

新建仓库页面要填四项：

● 仓库名称：必填，同一账号下不能重复
● 路径：参与访问 URL，一般与名称一致，无需手改
● 开源 / 私有：开源所有人可见，私有仅成员可见
● 初始化选项：是否生成 README、.gitignore、许可证

建完仓库最要紧的是复制克隆地址：

git clone git@gitee.com:your-name/repo.git

邀请方式有三种：链接邀请、直接添加、从组织内邀请。被邀请人必须是平台注册用户，否则邀请链接点开也没法接受。

3.5 双远程：一份代码两处备份

git remote add github git@github.com:owner/repo.git
git remote add gitee  git@gitee.com:owner/repo.git
git remote -v

推送时两边各推一次：

git push github develop
git push gitee develop

更省事的写法是给一个远程配两个推送地址：

git remote set-url --add --push origin git@github.com:owner/repo.git
git remote set-url --add --push origin git@gitee.com:owner/repo.git
git push origin develop        # 一次推两边

注意 set-url --add --push 只影响推送，拉取仍走原地址，避免”从 A 拉、推到 B”的错位。

3.6 清单

  1. 远程仓库按”速度 + 权限 + CI”选，不按界面选
  2. 建仓后先复制 SSH 地址，不要手敲
  3. 成员按角色分配，观察者不要给开发者权限
  4. 双远程用两个 remote，或给 origin 追加 push URL
  5. 定期 git remote -v 核对，防止推拉指向不同仓库
