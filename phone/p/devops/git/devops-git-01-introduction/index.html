版本控制入门

代码从来不是一次写成的。一个类改十遍、配置换三套、两个人同时动同一个文件——这些事没有版本控制就是灾难。Git 是分布式版本控制工具，管的是”每一次改动”这件事本身。

版本控制演进：本地版本 → 集中式 → 分布式

1.1 通俗小故事：时间机器

Git 是一台给代码装的时间机器。
● 快照：每次提交都是给整个仓库拍一张照片，不是记录”改了哪几行”
● 分支：在同一条时间线上开出一根旁支，随便折腾，主线不受影响
● 回滚：想回到任何一张照片，一条 git reset 就够
● 远程仓库：把照片备份到云端，本地硬盘挂了还能从远处取回

理解”照片 + 旁支 + 备份”这三件事，后面所有命令都只是操作这三样东西的不同手法。

1.2 什么是 Git

Git 是一个分布式版本控制工具，主要用于管理开发过程中的源代码文件（Java 类、XML 配置、HTML 页面等）。所谓分布式，是指每个开发者本地都有一份完整仓库（含全部历史），不依赖中央服务器也能提交、查看历史、切分支。

在实际开发里它解决四类问题：

● 代码回溯：记录每次改动，随时回退到任意历史版本
● 版本切换：分支即版本，主线与实验分支可任意切换
● 多人协作：每人负责一部分代码，通过分支与合并协调
● 远程备份：仓库可推到 GitHub / Gitee / GitLab，本地丢了还能拉回来

1.3 和其他版本控制工具的区别

工具
架构
典型问题
SVN
集中式，只有服务器有完整历史
服务器挂了就全员停工；分支是目录拷贝，重
CVS
集中式，比 SVN 更老
不支持原子提交，改名会丢历史
VSS
集中式，微软早期方案
库文件易损坏，锁文件机制冲突频繁
Git
分布式，每人一份完整仓库
概念多，学会了才用得顺

集中式与分布式的关键差别不在”能不能提交”，而在离线可用性与合并能力：Git 的合并基于三路内容比对，SVN 更多依赖文件级冲突标记，长期分支维护成本高一个量级。

1.5 上手清单

  1. 先装 Git，配好 user.name 与 user.email，提交记录才有归属
  2. 记住三个区：工作区（改文件的地方）、暂存区（准备提交的清单）、版本库（.git）
  3. 一个功能一个提交，message 写”做了什么”，不写”改了文件”
  4. 每天至少 git status + git log --oneline 各一次，知道自己在哪
  5. 远程仓库当作备份，不是唯一副本；本地历史同样重要
