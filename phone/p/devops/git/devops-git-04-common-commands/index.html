DevOps Git 常用命令

分类：devops · git ｜ 标签：git

常用命令

前面三章讲”是什么”，这一章只讲”怎么敲”。命令按场景分组：配置、拿仓库、暂存提交、远程、分支、标签、排错。后半段是本博客的双远程工作流，可直接对照执行。

Git 命令地图：提交、分支、合并、回滚、远端、标签

4.1 通俗小故事：发货流程

提交代码像发货。
● git status 是查库存：哪些货改了、哪些已经上了发货单
● git add 是把货搬上发货单（暂存区）
● git commit 是封箱装车，给这一车拍张照片（提交）
● git push 是把车开到异地分仓
● git pull 是把异地的新货拉回来再点一遍

漏了拍照（没 commit）、拍错车（推到别的分支）、货没上车就开车（忘 add），就是日常九成问题的来源。

4.2 全局配置

git config --global user.name "itcast"
git config --global user.email "itcast@itcast.cn"
git config --list

user.name / user.email 只写进提交记录，与托管平台账号无关，但必须前后一致，否则历史里同一个人会变成多个人。

4.3 获取仓库

git init                     # 本地初始化（不常用）
git clone git@github.com:wu4yong/starry-blog.git   # 从远程克隆（常用）

git init 后目录里出现 .git 隐藏文件夹即成功。克隆会连同全部历史一起下来，不是只拿当前文件。

4.4 三个区与文件状态

概念
说明
版本库
.git 隐藏文件夹，存配置、日志与全部文件版本
工作区
含 .git 的目录，日常改代码的地方
暂存区
.git/index，也称 stage，临时存放待提交的改动

文件状态两级四态：

● 未跟踪 untracked → 还没纳入版本控制
● 已跟踪 tracked → 已纳入，再分三种：

  • Unmodified 未修改
  • Modified 已修改（工作区变了，未 add）
  • Staged 已暂存（add 过，等 commit）

状态会随命令变化，git status 随时能看。

4.5 本地仓库操作

命令
作用
git status
查看文件状态
git add
把修改加入暂存区
git reset
取消暂存，或切换到指定版本
git commit
把暂存区内容提交到版本库
git log
查看提交日志
git status                       # 看状态
git add fileName                 # 加单个文件
git add .                        # 加全部改动
git commit -m "feat: 新增xxx功能"  # 提交
git log --oneline -5             # 最近 5 条
git log --graph --oneline --all -20   # 图形化分支历史

git reset 有两个用法，别混：

git reset 文件名                 # 取消暂存（工作区改动保留）
git reset --hard 版本号          # 硬回退（工作区改动一起丢，谨慎）

--hard 会直接丢掉未提交的修改，执行前先 git stash 或确认确实不要了。

4.6 远程仓库操作

本博客源码仓库配置了双远程：github 与 gitee。

git remote                       # 别名
git remote -v                    # 详细地址（必查）
git remote add gitee git@gitee.com:wu4yong/starry-blog.git
# 推送
git push github develop
git push gitee develop
git push github master
git push gitee master

# 变基后安全强推（单人仓库可用，多人禁止）
git push github develop --force-with-lease
# 拉取
git pull github develop
git pull gitee master

fetch 与 push 指向不同仓库会出现”拉错仓库、状态错乱”，git remote -v 里两侧必须一致。

本地建的仓库拉远程会撞 fatal: refusing to merge unrelated histories，加参数即可：

git pull github master --allow-unrelated-histories

清理远程追踪缓存：

git fetch --prune                          # 清掉已删除远程分支的本地引用
git branch -r -d github/develop            # 删失效的远程追踪分支
git push github --delete develop           # 删远程分支（慎）

4.7 分支操作

git init 默认创建 master。分支的意义是”把工作从主线上分出来”，互不干扰。

git branch                 # 本地分支
git branch -r              # 远程分支
git branch -a              # 全部

git branch develop              # 建分支
git checkout -b develop         # 建并切
git switch develop              # 新版本语法，切分支
git push github develop         # 推到远程

合并：

git merge develop                            # 快进合并（无冲突时）
git merge develop --no-ff -m "merge: develop -> master"   # 保留合并节点

冲突处理的四步：

  1. git status 看冲突文件
  2. 编辑文件，删掉 <<<<<<< / ======= / >>>>>>> 标记
  3. git add 冲突文件 后 git commit
  4. 想放弃这次合并：git merge --abort

变基（单人项目保持线性历史）：

git checkout develop
git rebase master
# 冲突：解决 → git add → git rebase --continue
# 放弃：git rebase --abort

4.8 本项目工作流：develop 合并到 master

业务全部在 develop 开发，验证稳定后合回 master，两边远程同步。

develop 提交 → 同步远程 develop → 切 master 同步 → 切回 develop rebase master
→ 切 master 快进合并 → 推送双端 master → 安全强推 develop → 切回 develop
# 1. 提交并同步 develop
git status && git add . && git commit -m "feat: 改动描述"
git pull github develop && git pull gitee develop
git push github develop && git push gitee develop

# 2. 切 master 同步最新
git checkout master
git pull github master && git pull gitee master

# 3. 变基
git checkout develop
git rebase master

# 4. 快进合并
git checkout master
git merge develop

# 5. 推双端
git push github master && git push gitee master

# 6. 变基改写了历史，安全强推
git push github develop --force-with-lease
git push gitee develop --force-with-lease

git checkout develop

多人协作的备选是 merge --no-ff，保留合并节点、历史可追溯：

git checkout master && git pull github master
git merge develop --no-ff -m "merge: develop -> master"
git push github master && git push gitee master
git checkout develop

4.9 标签

标签用于标记发布点（v1.0、v1.2）。

git tag                          # 查看
git tag -a v1.0 -m "版本说明"     # 带说明的标签（推荐）
git push github v1.0             # 推到远程
git push gitee v1.0
git checkout -b hotfix v1.0      # 检出标签需新建分支

4.10 常见报错排查

报错现象
排查 / 处理
non-fast-forward 推送被拒绝
先 git pull github 分支名 同步，不要盲目强推
推送被 Ctrl+C 中断，状态混乱
git fetch --prune 清理引用，再 git log --oneline github/develop 核对真实 hash
提示 Everything up-to-date 但本地有提交
指定提交推送：git push github <commit>:develop
返回报错但不确定是否成功
git ls-remote github refs/heads/develop 查服务器真实引用
撤销已 commit 且未 push的提交
git reset --hard HEAD~1（已 push 禁止）
本地与远程引用错乱
git fetch --prune 后重新核对分支状态

原则：推送报错先核对远程真实状态，不要反复强推。有些命令报错但对象实际已写入，盲推会造成重复提交或历史错位。
