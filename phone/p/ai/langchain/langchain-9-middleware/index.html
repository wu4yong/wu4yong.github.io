09 内置中间件

不必自己写钩子：官方的预置件覆盖了「重试、摘要、人工确认、脱敏、限流」这些高频需求｜依据官方 Prebuilt middleware 页自绘

版本不一致提示

  • 本篇基线是 LangChain v1（1.x）+ Python 3.13，官方示例环境是 Python 3.11，仅解释器版本不同；
  • ModelRefusalMiddleware 需要 langchain>=1.4.9；PII 的流式脱敏需要 langchain>=1.3.2；摘要按比例的条件需要 >=1.1 的 profile data；
  • 官方示例模型名随 provider 更新，配置项名称不受影响。

一、学习目标

学完这一讲，你要能做到三件事：

  1. 记住官方预置中间件的清单，知道哪些是「几乎必装」；
  2. 会配三件最常用的：SummarizationMiddleware（历史压缩）、HumanInTheLoopMiddleware（写操作确认）、PIIMiddleware（脱敏）；
  3. 会用 ModelCallLimitMiddleware / ToolCallLimitMiddleware 给成本兜底，并说清它们和「循环终止」的关系。

二、前置知识

  • 读完 LC08（create_agent 与循环、checkpointer）；
  • 知道中间件是「加在循环里的钩子」（LC07 用过 wrap_tool_call）；
  • 手上有一个能跑通的 Agent 示例。

三、理论讲解（官方定义）

1. 官方清单（provider 无关的部分）

官方 Prebuilt middleware 页按「与 provider 无关」列出这些：

装法统一：create_agent(..., middleware=[...])，顺序会影响执行先后（见 LC10 的执行顺序）。

2. SummarizationMiddleware：历史压缩

官方示例：

from langchain.agents.middleware import SummarizationMiddleware

agent = create_agent(
    model="...",
    tools=[...],
    middleware=[SummarizationMiddleware(model="...", trigger=("tokens", 4000), keep=("messages", 20))],
)

关键参数与官方口径：

  • model 必填：用来生成摘要的模型（可以和主模型不同，官方示例就是用便宜的小模型做摘要）；
  • trigger：什么时候触发，示例是「token 到 4000」；
  • keep：保留什么，示例是「最近 20 条消息」。

官方明确两点限制：摘要只压缩文本，不压缩图片/音视频负载；keep 保留的近期消息仍带原始多模态块，被摘要的旧消息只留文本摘要。所以图片类应用应把媒体放对象存储、消息里只放 URL。

fraction 类条件依赖模型的 profile data（langchain>=1.1），拿不到就手工给 profile。

3. HumanInTheLoopMiddleware：写操作先点确认

官方示例（配合 checkpointer）：

agent = create_agent(
    model="...",
    tools=[your_read_email_tool, your_send_email_tool],
    checkpointer=InMemorySaver(),
    middleware=[HumanInTheLoopMiddleware(interrupt_on={
        "your_send_email_tool": {"allowed_decisions": ["approve", "edit", "reject"]},
        "your_read_email_tool": False,
    })],
)

要点：

  • interrupt_on 的键是工具名（Python 里 @tool 的函数名）；
  • 值是 False 表示「这个工具不用确认」，给字典则能配允许的决策；
  • 必须配 checkpointer，否则中断后无法恢复；
  • 恢复方式见官方 HITL 章节：把决策按顺序回传（LC04 的流式示例里就是收 __interrupt__ 再 Command(resume=...)）。

4. PIIMiddleware：脱敏

middleware=[PIIMiddleware("email", strategy="redact", apply_to_input=True),
            PIIMiddleware("credit_card", strategy="mask", apply_to_input=True)]

官方参数表里几个关键点：

  • pii_type：内置类型有 email、credit_card、ip、mac_address、url，也可自定义；
  • strategy：block（命中即抛异常）、redact（替换为 [REDACTED_TYPE]）、mask（部分打码）、hash（确定性哈希），默认 redact；
  • apply_to_input 默认 True，apply_to_output 默认 False，apply_to_tool_results 默认 False；
  • 自 langchain>=1.3.2 起，apply_to_output=True 还会通过流式转换器改写流给客户端的输出，官方提醒：转换器会扣住每段文本最后 128 字符，自定义检测的匹配串不要超过 128 字符。

自定义检测器有三种：正则字符串、编译后的正则、自定义函数（返回 PIIMatch 列表）。自定义函数可以带校验逻辑（官方给了 SSN 首三位合法性校验的例子）。

5. 成本兜底：调用上限

ModelCallLimitMiddleware / ToolCallLimitMiddleware 是 LC08 说的「安全带」：循环终止条件仍是「模型不给 tool_call」，但真实业务需要硬上限，防止模型空转把账单刷爆。配合 ModelFallbackMiddleware 还能在主模型故障时降级。

四、原理拆解

选中间件的顺序应该是「先想清楚怕什么」，再对照清单找对应件｜自绘

四类问题对应四类件：

  • 怕崩：Tool error、Tool retry、Model retry、Model fallback、Model refusal；
  • 怕撑爆上下文：Summarization、LLM tool selector（先挑工具，少塞无关定义）；
  • 怕出事：Human-in-the-loop、PII detection；
  • 怕花钱：Model call limit、Tool call limit。

装之前先答一个问题：这件中间件在循环的哪一步介入？ 介入点错了，行为就不是你预期的——比如把「摘要」装在最外层、把「脱敏」装在内层，先用后脱，等于没脱。

五、场景说明

  1. 客服长会话：Summarization（trigger 按 token、keep 按条数）+ PII（输入脱敏）；
  2. 发邮件 / 改库 / 下单：HumanInTheLoop + checkpointer，决策走 approve / edit / reject；
  3. 多模型灰度：ModelFallback 主备切换，配合日志记录实际走了谁；
  4. 对外 API：Model call limit + Tool call limit，把「单次请求最多几轮」变成可配置项。

步骤 4：最小可运行代码

存成 middleware_demo.py，uv run middleware_demo.py。

from dotenv import load_dotenv
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware, PIIMiddleware, HumanInTheLoopMiddleware
from langchain.tools import tool
from langgraph.checkpoint.memory import InMemorySaver

@tool
def send_email(to: str, body: str) -> str:
    """发送一封邮件。写操作，必须人工确认后才能执行。"""
    return f"已发送给 {to}"

@tool
def get_order(order_id: str) -> str:
    """查询订单状态，订单号形如 SO-2026-0001。"""
    return "已发货"

load_dotenv()
agent = create_agent(
    model="openai:gpt-5-nano",
    tools=[send_email, get_order],
    system_prompt="你是客服助手。查单直接调 get_order；发邮件前要说清收件人与正文。",
    checkpointer=InMemorySaver(),                        # HITL 需要它才能恢复
    middleware=[
        PIIMiddleware("email", strategy="redact", apply_to_input=True),      # 先把邮箱脱敏
        HumanInTheLoopMiddleware(interrupt_on={"send_email": True}),         # 写操作挂起等确认
        SummarizationMiddleware(model="openai:gpt-5-nano",
                                trigger=("tokens", 6000),
                                keep=("messages", 20)),                       # 历史压缩
    ],
)

config = {"configurable": {"thread_id": "demo-1"}}
result = agent.invoke(
    {"messages": [{"role": "user", "content": "给 zhang@example.com 发邮件问他对账有没有问题"}]},
    config=config,
)
print("是否有中断:", bool(result.get("__interrupt__")))
if result.get("__interrupt__"):
    print("待确认的工具调用:", result["__interrupt__"][0].value["action_requests"])

步骤 5：预期输出

是否有中断: True
待确认的工具调用: [{'name': 'send_email', 'args': {'to': '[REDACTED_EMAIL]', 'body': '...'}, 'id': 'call_xxx'}]

注意 to 已经被 PII 中间件替换成 [REDACTED_EMAIL]——这就是「顺序」的意义：脱敏装在人工确认前面，人看到的是脱敏后的参数。若想让人看到真实邮箱，就得把两个中间件的位置对调，并接受「真实 PII 会出现在确认界面」。

步骤 6：验证是否成功

  • 收到中断且 action_requests 里只有 send_email，说明 HITL 命中且没有误伤只读工具；
  • 参数里出现 [REDACTED_EMAIL]，说明 PII 中间件生效；
  • 用 agent.invoke(Command(resume={"decisions": [{"type": "approve"}]}), config=config) 恢复后能拿到「已发送」，说明中断—恢复闭环完整。

写法 A · 统一入口：同一份代码换成 DeepSeek

内置中间件是框架侧实现，换 provider 只需改 create_agent 的 model 与摘要中间件自己的 model：

uv add langchain-deepseek
# 09 内置中间件
import os
from dotenv import load_dotenv
from langchain.agents import create_agent
from langchain.agents.middleware import PIIMiddleware, HumanInTheLoopMiddleware, SummarizationMiddleware
from langchain.tools import tool
from langgraph.checkpoint.memory import InMemorySaver

@tool
def send_email(to: str, body: str) -> str:
    """发送一封邮件。写操作，必须人工确认后才能执行。"""
    return f"已发送给 {to}"

load_dotenv()
assert os.environ.get("DEEPSEEK_API_KEY")

agent = create_agent(
    model="deepseek:deepseek-chat",
    tools=[send_email],
    checkpointer=InMemorySaver(),
    middleware=[
        PIIMiddleware("email", strategy="redact", apply_to_input=True),
        HumanInTheLoopMiddleware(interrupt_on={"send_email": True}),
        # 摘要用的模型也换成 DeepSeek，整条链路只用一把 key
        SummarizationMiddleware(model="deepseek:deepseek-chat",
                                trigger=("tokens", 6000),
                                keep=("messages", 20)),
    ],
)

r = agent.invoke({"messages": [{"role": "user", "content": "给 zhang@example.com 发邮件问他对账有没有问题"}]},
                 config={"configurable": {"thread_id": "ds-1"}})
print("是否有中断:", bool(r.get("__interrupt__")))
if r.get("__interrupt__"):
    print("待确认的工具调用:", r["__interrupt__"][0].value["action_requests"])

SummarizationMiddleware 内部会再起一次模型调用做压缩，它的 model= 参数是独立配置——这点最容易被漏掉：只改了主模型，摘要还在偷偷调 OpenAI。DeepSeek 上填 "deepseek:deepseek-chat" 即可，别填 reasoner（摘要不需要推理档，也更贵）。

差异集中在「模型怎么初始化」这一层，往下 invoke / stream / bind_tools 的链路基本不变：

  • 智谱、通义不进统一入口。init_chat_model 认不出 zhipuai / tongyi 这两个 provider 名，要直接实例化 ChatZhipuAI、ChatTongyi（两个类都在 langchain-community 里）；两家也都提供 OpenAI 兼容端点（智谱 https://open.bigmodel.cn/api/paas/v4、通义 https://dashscope.aliyuncs.com/compatible-mode/v1），用 ChatOpenAI(base_url=...) 也能打通，但 provider 专有字段可能不被提取或保留。
  • Claude 走统一入口，写法和 DeepSeek 一样是换个字符串；但要盯 max_tokens——官方迁移指南的 Breaking changes 里写了 langchain-anthropic 的默认值变化，结论是显式传，别依赖默认；logprobs 也不支持。
  • 通义的类默认走流式，ChatTongyi(model="qwen-plus") 之后拿到的就是流式结果；要做视觉用 qwen-vl-max。
  • 能力面各不同：工具调用、结构化输出、图像/音频输入的支持情况在这几家之间并不一致，换之前按各自官方集成页的能力表核一遍，别照抄 DeepSeek 的「一律 deepseek-chat」经验。

七、常见坑（官方明确限制/版本差异）

  1. HITL 不配 checkpointer。中断后无处保存状态，无法恢复；官方示例一律带 InMemorySaver()。
  2. interrupt_on 的键写成函数显示名。键是工具名（@tool 下就是函数名），写错则静默不生效。
  3. 以为摘要会压缩图片。官方明确摘要只压文本，多模态内容要么落对象存储、要么接受「旧图只剩摘要文本」。
  4. 脱敏装在最内层却要求「对外输出也脱敏」。要覆盖输出与工具结果，得开 apply_to_output / apply_to_tool_results，且流式脱敏需要 langchain>=1.3.2。
  5. 只装上限不看上限。ModelCallLimitMiddleware 命中后是「中止并返回」，不是「自动继续」；文案与兜底策略要自己设计。

八、课后小结

  • 官方预置中间件覆盖可靠性、上下文、安全、成本四类，装法都是 middleware=[...]；
  • 摘要只压文本，trigger / keep 各管「何时压、留多少」；
  • HITL 的 interrupt_on 按工具名配置，必须配 checkpointer；
  • PII 有四种策略（block / redact / mask / hash），默认只处理输入；
  • 调用上限是「终止条件」之外的安全带。

九、思考题

1、为什么 HumanInTheLoopMiddleware 必须配 checkpointer？

参考回答：中断意味着执行停在半途，需要把当时的状态持久化，恢复时才能从断点继续；没有 checkpointer，中断即是结束，resume 无从谈起。

2、摘要中间件的 model 为什么不建议用主模型？

参考回答：摘要是一次独立的、低难度的文本压缩调用，用便宜的小模型即可；官方示例就用更小的模型做摘要，主模型留给真正需要推理的步骤，成本更可控。

3、PII 的 redact 与 mask 该选哪个？

参考回答：redact 完全替换，适合日志与对外展示、不需要保留任何可识别信息；mask 保留尾部（如卡号后四位），适合需要人工核对但又不能全文暴露的场景。合规要求「不可复原」时只能用 redact 或 hash。

4、中间件顺序为什么会影响安全效果？

参考回答：钩子是嵌套执行，外层的 before_* 先跑、内层的 after_* 先跑。把脱敏放外层、确认放内层，人看到的就是脱敏后参数；反过来，脱敏在人之后执行，人已经在界面上看到了原始 PII。
