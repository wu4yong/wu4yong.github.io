16 综合实战：工单审批 Agent

状态、工具、中断、持久化、记忆、流式、可靠性各就各位；缺一件，这台机器就跑不稳｜本篇自绘

版本不一致提示

  • 本篇基线是 LangGraph 1.2.x + Python 3.13，主路径不调模型，没 key 也能完整跑通；
  • 接模型的位置集中在两个节点（classify / draft_reply），写法 A 给出替换点；
  • 审批用 interrupt()，必须挂 checkpointer；本篇用 InMemorySaver 演示，生产换 PostgresSaver（LG15）；
  • 表格与代码都在 1.2 口径；create_react_agent 不在本篇出现，已是弃用件。

一、学习目标

学完这一讲，你要能做到三件事：

  1. 把「状态 + 子图 + 工具 + 中断 + 记忆 + 流式 + 可靠性」装进一张图；
  2. 给出可交付的三件套：图、测试、部署清单；
  3. 说清每个能力缺了会出什么事——这是评审时最常被问的。

四、原理拆解：这张图的「三条边界」

  1. 状态边界：主图只管「流程字段」（ticket_id / risk / decision），工单原文与检索结果放子图或工具返回，避免主 state 膨胀；
  2. 人的边界：interrupt() 只放在 approve 一个节点，且只调一次——恢复语义清晰（LG06）；
  3. 失败边界：execute 带 RetryPolicy 与 error_handler，失败走补偿节点回滚库存/标记（LG11）。

五、场景说明

工单系统里最典型的三种单：退款、改地址、补发。它们的共同点是「查得到、改得动、但要人点头」。

步骤 4：最小可运行代码

存成 ticket_agent.py，uv run ticket_agent.py。

import asyncio
from typing import Literal, Optional
from typing_extensions import TypedDict, NotRequired
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import Command, interrupt, RetryPolicy

# ---------- 1. 状态 ----------
class Ticket(TypedDict):
    ticket_id: str
    text: str
    kind: NotRequired[str]
    risk: NotRequired[str]
    decision: NotRequired[Optional[str]]
    approver: NotRequired[str]
    steps: list[str]

# ---------- 2. 分类子图（可单独测） ----------
class Kind(TypedDict):
    text: str
    kind: str

def rule_classify(state: Kind):
    t = state["text"]
    if "退" in t: return {"kind": "refund"}
    if "地址" in t: return {"kind": "address"}
    return {"kind": "reship"}

kind_builder = StateGraph(Kind)
kind_builder.add_node("rule_classify", rule_classify)
kind_builder.add_edge(START, "rule_classify")
kind_builder.add_edge("rule_classify", END)
classify = kind_builder.compile()

# ---------- 3. 主图节点 ----------
def intake(state: Ticket):
    return {"steps": state.get("steps", []) + ["intake"]}

def do_classify(state: Ticket):
    out = classify.invoke({"text": state["text"], "kind": ""}, version="v2")
    kind = out.value["kind"]
    risk = "high" if kind == "refund" and "大额" in state["text"] else "normal"
    return {"kind": kind, "risk": risk, "steps": state["steps"] + ["classify"]}

def investigate(state: Ticket):
    # 真实项目在这里调工具查历史工单；本篇用确定性结果保证可跑
    history = {"refund": "历史同类单 3 件，均通过", "address": "地址可改", "reship": "仓库有货"}
    return {"steps": state["steps"] + [f"investigate:{history[state['kind']]}"]}

def approve(state: Ticket):
    if state.get("risk") != "high":
        return {"decision": "auto", "steps": state["steps"] + ["approve:auto"]}
    ask = {"question": "这笔大额退款要批吗？", "ticket_id": state["ticket_id"]}
    ans = interrupt(ask)
    return {"decision": "yes" if ans else "no", "approver": "human", "steps": state["steps"] + ["approve:human"]}

async def execute(state: Ticket):
    return {"steps": state["steps"] + [f"execute:{state['kind']}"]}

def report(state: Ticket):
    return {"steps": state["steps"] + ["report"]}

def after_approve(state: Ticket) -> Literal["execute", "report"]:
    return "execute" if state.get("decision") in ("yes", "auto") else "report"

# ---------- 4. 组装 ----------
builder = StateGraph(Ticket)
builder.add_node("intake", intake)
builder.add_node("classify", do_classify)
builder.add_node("investigate", investigate)
builder.add_node("approve", approve)
builder.add_node("execute", execute, retry_policy=RetryPolicy(max_attempts=3))
builder.add_node("report", report)
builder.add_edge(START, "intake")
builder.add_edge("intake", "classify")
builder.add_edge("classify", "investigate")
builder.add_edge("investigate", "approve")
builder.add_conditional_edges("approve", after_approve)
builder.add_edge("execute", "report")
builder.add_edge("report", END)

graph = builder.compile(checkpointer=InMemorySaver())

async def main():
    cfg = {"configurable": {"thread_id": "T-1001"}}
    r1 = await graph.ainvoke({"ticket_id": "T-1001", "text": "客户要求大额退款 2 万", "steps": []}, cfg, version="v2")
    print("第一轮：", r1.value["risk"], r1.interrupts)

    r2 = await graph.ainvoke(Command(resume=True), cfg, version="v2")
    print("批准后：", r2.value["decision"], r2.value["steps"])

    # 低风险单：同一张图，不用人批
    cfg2 = {"configurable": {"thread_id": "T-1002"}}
    r3 = await graph.ainvoke({"ticket_id": "T-1002", "text": "改一下收货地址", "steps": []}, cfg2, version="v2")
    print("低风险：", r3.value["decision"], r3.value["steps"])

asyncio.run(main())

步骤 5：预期输出

第一轮： high (Interrupt(value={'question': '这笔大额退款要批吗？', 'ticket_id': 'T-1001'}, ...),)
批准后： yes ['intake', 'classify', 'investigate:历史同类单 3 件，均通过', 'approve:human', 'execute:refund', 'report']
低风险： auto ['intake', 'classify', 'investigate:地址可改', 'approve:auto', 'execute:address', 'report']

读法：高风险单停在 approve，interrupts 里有待批问题；resume=True 后走 execute → report。低风险单直接 auto，全程无人介入——同一张图，两种节奏。

步骤 6：验证是否成功

  • resume=False：decision 变 no，条件边把流程直接导向 report，execute 不执行（steps 里没有 execute:*）；
  • 把 approve 里的 if risk != "high" 删掉：低风险单也会停，说明「动态断点」是按业务条件生效的；
  • 把 execute 的 retry_policy 去掉，在里面 raise ConnectionError：整条 run 失败；加回后自动重试——这就是 LG11 的价值；
  • 换新 thread_id 跑同一单：状态全新，说明 checkpointer 按线程隔离。

七、常见坑（官方明确限制/版本差异）

  1. 把 interrupt 放在条件分支里（if high: interrupt() 与「跳过」混在一节点）。恢复时下标错位，答案会串（LG06）。
  2. execute 没配重试。一次网络抖动整单失败，用户重提，重复建单。
  3. 审批结果直接写库。interrupt 后的写操作要幂等，恢复会重跑该节点。
  4. 主 state 塞工单原文。每轮检查点都存一份长文本，存储与延迟一起涨。
  5. 测试只测 happy path。高风险、拒绝、重试三条路径才是回归重灾区。
  6. 上线仍用 InMemorySaver。重启后所有在途审批丢失，等于审批链断在半空。

八、课后小结

  • 七件套各管一段：状态、子图、工具、中断、持久化与记忆、流式、可靠性；
  • 一个是主图两条节奏：高风险必须人批，低风险自动通过；
  • 人批只在一个节点、只调一次 interrupt，恢复语义才干净；
  • 失败边界在 execute：重试 + 补偿，而不是让整条 run 崩；
  • 交付三件套：图、测试（三条路径）、部署清单（LG15 五题）。

九、思考题

1、为什么分类做成子图而不是一个函数？

参考回答：分类逻辑会长（规则 + 模型 + 兜底），独立成子图能单独测、单独换实现，主图只关心「拿到 kind」这个契约。

2、低风险自动通过，会不会让 interrupt 变成「有时有时无」？

参考回答：不会。interrupt 在同一节点里只在特定条件下调用，但两次执行的条件都由同一份 state 决定，所以个数稳定；真正危险的是「同一节点里按数据长度调多次」。

3、execute 的重试会不会造成重复退款？

参考回答：会，如果不做幂等。正确做法是用 ticket_id 当幂等键，先查「这笔是否已执行」再写；重试只重跑逻辑，不重复扣款。

4、这套图要上线，你最先补哪一件？

参考回答：持久化。InMemorySaver → PostgresSaver（加 store 也一样），否则重启即在途单全丢，其它能力都白搭。
