LangGraph 01 · 安装与最小图

分类：ai · langgraph ｜ 标签：系统课 · AI · LangGraph

01 安装与最小图

StateGraph 只是图纸，compile() 才把它变成可执行对象｜依据官方 Graph API overview 自绘

版本不一致提示

  • 本篇基线是 LangGraph 1.2.x + Python 3.13；官方要求 Python ≥ 3.10，本系列统一 3.13，仅解释器版本不同；
  • 官方示例的 invoke() 默认返回 version="v1" 的 dict；1.1 起可传 version="v2" 拿 GraphOutput（.value / .interrupts），本系列统一显式传 v2；
  • 旧教程常见 from langgraph.prebuilt import create_react_agent，该函数在 v1 已弃用；本篇不用任何预置件，从 StateGraph 手搭；
  • 官方 Quickstart 的模型名随 provider 更新，本篇用 openai:gpt-5-nano，换模型只改这一行。

一、学习目标

学完这一讲，你要能做到三件事：

  1. 说清 LangGraph 的三件套（state / node / edge）各自负责什么，为什么「节点返回整份 state」是错的；
  2. 用 uv 起一个能跑的最小工程，从 StateGraph 到 compile() 到 invoke() 全链路跑通；
  3. 看到 AttributeError: 'StateGraph' object has no attribute 'invoke'、KeyError: 'answer' 这类报错时，知道问题在「没编译」还是「状态里没这个 key」。

二、前置知识

  • 会 Python 类型注解，见过 TypedDict（没见过也行，本篇会解释）；
  • 装过 uv（没有就 pip install uv），能在命令行起项目；
  • 读过 LangChain 系列的 LC01–LC03 更好：那套讲「模型怎么调、消息长什么样」，这套讲「调用之外的那层编排」，不冲突。

三、理论讲解（官方定义）

官方 Overview 对 LangGraph 的定位很明确：它是一个面向长时运行、有状态 Agent 的底层编排框架与运行时。你把手写的确定性步骤和模型驱动的步骤画进同一张图，图的形状就是流程的形状。

顺序照官方 Graph API 页：Graphs → StateGraph → Compiling → State → Nodes → Edges。

1. 图的三个部分

官方的定义只有三句：

  1. State：应用的共享快照，通常是一个带类型的 schema；
  2. Nodes：读 state、干活、返回更新的函数；
  3. Edges：固定或条件的转移，决定下一个跑谁。

一句话版本：节点干活，边决定下一步，状态是它们之间唯一的传递媒介。

2. StateGraph 是图纸

StateGraph 是主构建器，参数是你的 state schema。它本身不可执行——你往里加节点、加边，加完还是一张图纸。

3. compile() 才变成可执行对象

官方的原话是：编译会检查图结构（例如是否存在孤立节点），同时把运行时选项（checkpointer、断点）挂上去；必须先编译，才能 invoke / stream。

编译返回的对象才有 invoke / stream / get_state 这些方法。对 StateGraph 本体重直接调 invoke，拿到的是 AttributeError，不是「图跑不起来」的业务错误。

4. 状态是「通道的集合」

官方把 state 拆成两层：schema 声明有哪些 channel，reducer 决定更新怎么合并。默认行为是「后写覆盖」，所以节点正确做法是只返回要改的 key，而不是把整份 state 返回去。

这一条先记住结论，LG02 会把它讲透。

5. 节点是普通函数

节点可以是同步函数，也可以是 async 函数，参数可以是 state、config、runtime 三种组合。加了节点不写名字时，LangGraph 用函数名当节点名——所以下面代码里 add_node(answer_node) 和 add_node("answer", answer_node) 等价。

6. invoke 的入参与返回

入参是输入 state 的 dict（只给 schema 里声明过的 key）；返回在 version="v2" 下是 GraphOutput：

result = graph.invoke({"question": "..."}, version="v2")
result.value        # 最终 state（dict 形态）
result.interrupts   # 本次运行遇到的 interrupt 列表，没中断就是空

四、原理拆解

把一张图想成工厂的装配线图纸：

  • state 是在传送带上流动的那块工件，每个工位都能在它身上加东西；
  • node 是一个工位，只做自己那一道工序，做完把「新增/修改」贴回工件；
  • edge 是传送带的走向，决定下一件工件去哪个工位；
  • compile 是把图纸装成真机器——装好之前，图纸不会动。

三个关键判断：

  1. 图纸 ≠ 机器：StateGraph 上没有 invoke，这不是 bug，是设计；
  2. 工件是共享的：两个工位同时改同一个字段会打架，所以需要 reducer（LG02）；
  3. 工位不该复制整块工件：返回整份 state 会把别人的修改抹掉，也是最常见的「莫名其妙丢数据」。

五、场景说明

  1. 单节点问答图：验证环境用，本篇就是这一种；
  2. 确定性 + 模型混合的流程：比如「先查库 → 再让模型总结」，查库这段不需要模型，适合画进图；
  3. 需要暂停/续跑的流程：审批、长任务、可恢复批处理——这是 LangGraph 相对 create_agent 的核心增量（M2）；
  4. 不该用的场景：一句话就能起 Agent 的需求，直接用 LC08 的 create_agent，不必自己画图。

六、示例代码

步骤 1：环境准备

# 01 安装与最小图
uv python pin 3.13
uv init lg-demo
cd lg-demo
uv add langgraph "langchain[openai]" python-dotenv

uv add langgraph 装的是运行时本体；langchain[openai] 只为拿到 init_chat_model 和 OpenAI 集成。想用 pip，等价写法是 pip install -U langgraph "langchain[openai]" python-dotenv，区别只在谁管锁文件。

步骤 2：凭证配置

.env 里放 OPENAI_API_KEY=sk-...，代码里 load_dotenv() 读进来。官方 Quickstart 的「Set up API keys」一节也是这个做法。

步骤 3：导入

from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END
from langchain.chat_models import init_chat_model

三个来源要分清：TypedDict 是 schema，StateGraph / START / END 是图，init_chat_model 是模型入口。

步骤 4：最小可运行代码

存成 min_graph.py，uv run min_graph.py。

from dotenv import load_dotenv
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END
from langchain.chat_models import init_chat_model

load_dotenv()

class State(TypedDict):
    question: str      # 输入
    answer: str        # 输出

model = init_chat_model("openai:gpt-5-nano")

def answer_node(state: State):
    msg = model.invoke(state["question"])
    return {"answer": msg.text}          # 只返回要改的 key

builder = StateGraph(State)
builder.add_node("answer", answer_node)
builder.add_edge(START, "answer")
builder.add_edge("answer", END)

graph = builder.compile()                # 图纸 → 机器

result = graph.invoke(
    {"question": "用一句话解释什么是状态机"},
    version="v2",
)
print(type(result).__name__)
print(result.value["answer"])

步骤 5：预期输出

GraphOutput
状态机是一组状态和触发状态转移的规则组成的系统，任意时刻只处于一个状态。

第一行是类型，证明你拿到的是 v2 的 GraphOutput；第二行是模型的回答，措辞会随模型变化。

步骤 6：验证是否成功

  • 把 builder.compile() 注释掉，直接 builder.invoke(...)：应看到 AttributeError，而不是业务报错；
  • 把 return {"answer": msg.text} 改成 return state：单节点图看不出问题，但这是坏习惯，LG02 会演示它怎么吃掉别人的写入；
  • 删掉 add_edge(START, "answer") 再编译运行：图没有入口，跑不出结果——官方说的「结构校验」拦的就是这类图纸错误。

写法 A · 统一入口：同一份代码换成 DeepSeek

# 01 安装与最小图
uv add langchain-deepseek
from dotenv import load_dotenv
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END
from langchain.chat_models import init_chat_model

load_dotenv()

class State(TypedDict):
    question: str
    answer: str

model = init_chat_model("deepseek:deepseek-chat")

def answer_node(state: State):
    return {"answer": model.invoke(state["question"]).text}

builder = StateGraph(State)
builder.add_node("answer", answer_node)
builder.add_edge(START, "answer")
builder.add_edge("answer", END)
graph = builder.compile()

print(graph.invoke({"question": "用一句话解释什么是状态机"}, version="v2").value["answer"])

图的形状一行没变——换的只是 init_chat_model 里那个 provider 串。这也是本系列的固定写法：图是框架的事，模型是 provider 的事。

七、常见坑（官方明确限制/版本差异）

  1. 拿 StateGraph 直接 invoke。官方要求先 compile()；没编译就没有 invoke 方法。
  2. 节点返回整份 state。return state 看起来「稳妥」，实际会覆盖并行分支写入的 key；只返回要改的 key。
  3. schema 里没声明的 key 硬写。写进不存在的 channel 不会报错得很清楚，通常是运行时才发现读不到。
  4. 入参多给了 key。invoke 的输入只按 schema 收，多给的字段不会进 state。
  5. 把 result 当 dict 用。传了 version="v2" 就拿到 GraphOutput，要 .value；混用 v1 / v2 的返回结构，是升级期最常见的错。

八、课后小结

  • LangGraph = 状态 + 节点 + 边，三者缺一不可；
  • StateGraph 是图纸，compile() 之后才是可执行对象；
  • 节点返回的是「部分更新」，不是整份 state；
  • invoke 的输入是 schema 的 dict，version="v2" 返回 GraphOutput；
  • 图的结构与模型无关，换 provider 只改模型那一行。

九、思考题

1、为什么 compile() 是必需的一步，而不是 StateGraph 构造时自动完成？

参考回答：编译期要做结构校验（孤立节点、入口缺失等），并把运行时选项（checkpointer、断点）挂到执行对象上。把「画图」和「装配」分开，才能在同一份图纸上反复编译出不同配置的机器。

2、节点为什么不能返回整份 state？

参考回答：state 的每个 key 都按自己的 reducer 合并。返回整份 state 等于把当前读到的旧值重新写一遍，并行分支的写入会被覆盖；只返回要改的 key 才能让合并规则生效。LG02 会用两个并行节点演示这个事故。

3、version="v2" 和不传有什么区别？

参考回答：1.x 默认是 v1，invoke 直接返回 state dict；传 v2 返回 GraphOutput，状态在 .value，中断信息在 .interrupts。官方建议新代码显式传 v2，本系列从第一篇就统一。

4、这张最小图里，哪一部分换成 DeepSeek 会变？

参考回答：只有 init_chat_model 的参数、装包与凭证三处。StateGraph 的 schema、节点签名、边、compile、invoke 都是框架侧能力，与 provider 无关。
