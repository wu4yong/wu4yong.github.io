11 Playground 与 Context

试完就转实验，别在 Playground 里「感觉不错」就上线｜依据官方 Playground 页自绘

版本不一致提示

  • 本篇基线是 LangSmith 平台（2026-11 文档）+ langsmith 0.16.2 + Python 3.13；
  • 本篇以平台操作为主，必须有真实 key 与已配置的模型连接；SDK 只承担「把 Playground 里定稿的 prompt 拉下来复现实验」这一步；
  • Playground 里的 prompt 与模型配置是草稿态，不提交就没有 commit；关页面即丢；
  • Context Hub（context-hub）在 2026 年并入 prompt 体系（prompt-context-hub），版本与晋升语义与 prompt 一致：commit 不可变、tag 可变；
  • 官方在 Playground 侧的模型连接叫「model providers」，与 LS10 的 prompt 模型配置分开管理，别以为改一处两处都变。

一、学习目标

学完这一讲，你要能做到三件事：

  1. 在 Playground 里换模型、改 prompt、跑对比，并把定稿一键转成 dataset 上的实验；
  2. 说清 Playground 配置与线上配置不一致会导致什么，以及怎么对齐；
  3. 用 Context Hub 给「agent 的上下文」做版本与晋升，避免把上下文当配置文件随手改。

二、前置知识

  • 读完 10 Prompt 与版本，理解 commit 与 tag；
  • 有一个 dataset（06）可用于转实验。

三、理论讲解（官方定义）

1. Playground 是什么

一个「不写代码就能试」的工作台：选 prompt（可以是平台上的某个 commit，也可以是临时草稿）、选模型连接、填变量、跑一次看输出；支持并排对比两个配置。

它不是评测工具：单次输出好看不代表批量好。官方的用法是「在 Playground 里定方向，转到 dataset 上跑实验定结论」。

2. 从 Playground 到实验

官方提供 run-evaluation-from-playground：把当前 Playground 的 prompt + 模型配置直接作为一个 experiment 的 target，在选定 dataset 上跑一遍评测器。这样「试出来的感觉」就有了分数背书。

3. Context Hub 管什么

Agent 的「上下文」不只是 system prompt：还包括技能说明、工具描述、少样本示例、检索到的文档片段模板。Context Hub 把这些作为可版本化的资源管理：提交成 commit、打 tag、按环境晋升（dev → staging → prod）。

4. 晋升顺序

与 prompt 一样：先在 Playground / 实验里验证 → 打不可变 tag → 再把可变的 prod 指过去。反了就是「拿线上做实验」。

四、原理拆解：为什么「本地好线上差」

三个变量经常被混为一谈：

  1. prompt 内容（平台 commit）；
  2. 模型连接与参数（Playground 的 provider 配置 / prompt 里的模型配置 / 线上代码里的参数）；
  3. 运行时上下文（检索到的文档、注入的工具描述、历史消息裁剪策略）。

只要其中一项与线上不一致，Playground 的结果就不能代表线上。所以官方把「prompt + 模型配置」一起版本化——但运行时上下文仍要你自己对齐，这部分靠 Context Hub 或代码侧统一读取。

五、场景说明

要决定「退款 FAQ 用大模型还是小模型」。做法：在 Playground 里同一 prompt 并排跑两个模型连接，看 5 条典型问题的输出；觉得小模型够用，点「转实验」，在 refund-faq 上跑同一批评测器；分数达标后把 prompt 的 prod 指过去，并同步线上模型连接配置。

如果只在 Playground 里看了 5 条就切线上，等于用 5 个样本做了一次没有分母的决策。

六、示例代码

本篇主体是平台操作，下面按「先平台、后代码」的顺序走。

步骤 1：确认模型连接

平台 Settings → Model providers 里确认至少有一个可用连接（OpenAI / DeepSeek / 智谱 / 通义 / Anthropic 任选）。没有连接时 Playground 无法跑。

步骤 2：在 Playground 里组配置

选 prompt refund-reply:prod → 选两个模型连接 → 填 question → 并排跑。观察：哪个模型的回答更贴约束（给出到账时间、不承诺立即到账）。

步骤 3：转成实验

点「Evaluate」→ 选 dataset refund-faq → 选评测器（json_ok + has_sla）→ 起实验名 pg-small-vs-large。跑完在 Experiment 页看两列分数。

步骤 4：SDK 侧复现这一步

Playground 定稿后，代码里要能复现同一个配置：

import os
from dotenv import load_dotenv
from langsmith import Client, evaluate

load_dotenv()
client = Client()

# 拉平台上的 prompt（含模型配置，若该 commit 存了）
prompt = client.pull_prompt("refund-reply:prod", include_model=True)

def target(inputs: dict) -> dict:
    msgs = prompt.format_prompt(question=inputs["question"]).to_messages()
    # 这里换成你的线上调用；Playground 与线上必须用同一个模型连接
    return {"answer": "3 个工作日到账"}

evaluate(target, data="refund-faq", evaluators=[], experiment_prefix="pg-repro")

步骤 5：预期输出

View the evaluation results for experiment: 'pg-repro-...' at:
https://smith.langchain.com/...

步骤 6：验证是否成功

  • Playground 那次实验与 SDK 这次实验，在同一个 dataset 上的分数差不超过容差（说明配置对齐了）；
  • 若 SDK 侧分数明显更低：先查模型连接是否一致，再查 include_model 有没有带出温度等参数；
  • 在 Context Hub 里建一个 context 版本，改一段工具描述，打 staging tag，再在 Playground 里选它跑一遍——确认「换 context 也会改变输出」。

写法 A · Context 的版本与晋升

# Context Hub 的资源同样走 commit + tag 语义
ctx_staging = client.pull_prompt("ticket-agent-context:staging")
ctx_prod = client.pull_prompt("ticket-agent-context:prod")

晋升动作 = 把 prod 指到已验证的 commit；回滚 = 指回上一个。不要在代码里按 name 直接拉最新，那等于放弃晋升流程。

写法 B · Playground 草稿的保存纪律

  • 草稿只在页面存活，改完先「提交为 commit」再关；
  • 提交时写清 commit 说明（改了什么、为什么），后面回滚时才看得懂；
  • 需要长期对比的两个配置，各提交一个 commit 并打不同 tag，别靠「再改回来」。

七、常见坑（官方明确限制/版本差异）

  1. 草稿没提交就关页面。Playground 的临时修改不落库。
  2. Playground 与线上模型配置不一致。温度、max_tokens 差一点，输出差很多。
  3. Context 晋升顺序搞反（先指 prod 再验证）。线上直接吃到未验证的上下文。
  4. 把 Context 当配置文件随手改。没有 commit 说明，出问题无法定位哪一版坏的。
  5. 只跑 5 条就下结论。样本量不足，结论不可信；转实验才有分母。
  6. pull_prompt 不带 include_model。以为拉到了完整配置，其实只有模板。

八、课后小结

  • Playground 定方向、实验定结论，两步不能合并；
  • 三个变量要对齐：prompt 内容、模型连接与参数、运行时上下文；
  • Context Hub 与 prompt 同一套 commit/tag 语义，晋升即移动指针；
  • 草稿要提交，否则关页面即丢；
  • SDK 复现实验时记得 include_model=True。

九、思考题

1、为什么 Playground 里「感觉不错」不能直接上线？

参考回答：单条输出受采样随机性与挑选偏差影响，没有分母；只有在 dataset 上跑评测器，才有可比的分数与退化清单。

2、Context Hub 与 prompt 版本化的区别在哪？

参考回答：机制相同（commit + tag），管理对象不同：prompt 是「指令文本」，context 是「agent 运行时要读的全套上下文资源」，后者变更的影响面更隐蔽。

3、线上「本地好线上差」先查哪一项？

参考回答：先查模型连接与参数（最常见），再查运行时上下文（检索内容、消息裁剪），最后才怀疑 prompt 本身。

4、为什么要给 context 打 staging 再晋升？

参考回答：staging 提供一个「已验证但未上线」的稳定指针，方便预发环境与灰度流量指向它；直接指 prod 就没有中间态。
