10 Prompt 与版本

代码里写 name:tag，换 tag 指向就等于换版本，不用改代码｜依据官方 Prompt engineering 页自绘

版本不一致提示

  • 本篇基线是 LangSmith 平台（2026-11 文档）+ langsmith 0.16.2 + langchain-core 1.x + Python 3.13；
  • 本篇必须有真实 key；prompt 的提交、拉取全部走 API；
  • 每次 push_prompt 生成一个 commit hash（不可变），commit_tags 给该 commit 打不可变标签，tags 给 prompt 打可变指针（如 prod）；
  • 拉取语法是 "<name>:<tag>" 或 "<name>:<commit-hash>"；只写 name 默认取最新 commit，这会让线上跟着最新走，慎用；
  • pull_prompt 的 include_model=True 才会把模型配置一起带回来；默认只回 prompt 本身。

一、学习目标

学完这一讲，你要能做到三件事：

  1. 说清 prompt 的构成（模板 + 变量 + 模型配置 + 结构化输出）与「commit 不可变、tag 可变」的区别；
  2. 用 SDK 建 prompt、提交两版、打 prod 与不可变 tag，并在代码里按 name:tag 拉取；
  3. 用 webhook / 拉取失败兜底把「线上依赖平台」这件事的爆炸半径压住。

二、前置知识

  • 读完 09 在线评测与标注，闭环里已经会出现「改 prompt」这个动作；
  • 用过 format 风格的模板字符串。

三、理论讲解（官方定义）

1. prompt 不只是字符串

平台上的 prompt 可以带：

  • 模板与变量（{question} 这种占位）；
  • 模型配置（model、temperature 等，可选）；
  • 工具与结构化输出（把 output schema 一起版本化）；
  • metadata：owner、说明、readme。

把模型配置一起存的价值是：同一个 prompt 版本在 Playground、实验、线上用的是同一套参数，不会出现「本地 temp 0.2、线上 0.7」。

2. commit 与 tag

  • 每次提交 = 一个 commit（hash 唯一、内容不可变）；
  • tag 是指针：prod 今天指向 commit A，明天可以被指到 commit B；
  • commit_tags 是给某个 commit 打的固定标记（如 v1、approved-2027-01），不会移动；
  • 所以「线上跟 prod 走」= 我允许平台改我的线上行为；「线上跟 v1 走」= 换版本要发版。

这两种都是合理选择，但必须明确选一个，不能混着用。

3. 公开 Hub 与私有空间

公开 Hub 的 prompt 任何人可见可拉（dangerously_pull_public_prompt 才允许拉公共源），私有空间只有本 workspace 可见。不要把内部 prompt 发到公开 Hub，那等于把业务规则公开。

四、原理拆解：拉取时发生了什么

  1. 代码按 name:tag 请求 → 平台解析 tag 到具体 commit hash；
  2. 返回模板对象（include_model=True 时附模型配置）；
  3. SDK 本地有缓存：同一进程内重复拉取不会重复请求；skip_cache=True 可强制刷新；
  4. 模板对象在本地 format 成消息列表，再喂给模型。

最后一条决定了运行时的耦合：线上每一次请求都依赖平台可用性。所以生产上必须做两件事：启动时预拉一次并缓存到进程内、拉取失败时回退到内置的兜底 prompt。

五、场景说明

客服回复 prompt 现在写在代码里，改一句话要走一次发版。搬到平台后：

  • prompt 有 commit 历史，谁改的、改了什么一目了然；
  • 用「A/B 两个 tag」在线上按比例切换，验证后再把 prod 指过去；
  • 出问题回滚 = 把 prod 指回上一个 commit，秒级生效。

代价是：平台故障会直接影响线上。所以兜底必须有。

六、示例代码

步骤 1：环境准备

uv init ls10-prompt
cd ls10-prompt
uv add langsmith langchain-core python-dotenv

步骤 2：凭证配置

.env：LANGSMITH_API_KEY=...、LANGSMITH_PROJECT=ticket-agent-prod。

步骤 3：导入

from langsmith import Client
from langchain_core.prompts import ChatPromptTemplate

步骤 4：最小可运行代码

存成 prompt.py，uv run prompt.py。

import os
from dotenv import load_dotenv
from langsmith import Client
from langchain_core.prompts import ChatPromptTemplate

load_dotenv()
client = Client()
NAME = "refund-reply"

v1 = ChatPromptTemplate.from_messages([
    ("system", "你是退款客服，回答简洁。"),
    ("human", "{question}"),
])

v2 = ChatPromptTemplate.from_messages([
    ("system", "你是退款客服。给出明确到账时间；不能承诺立即到账；无法处理时转人工。"),
    ("human", "{question}"),
])

if client.get_prompt(NAME) is None:          # 没有 has_prompt，用 get_prompt 判空
    client.create_prompt(NAME, description="退款客服回复模板")

c1 = client.push_prompt(NAME, object=v1, commit_tags=["v1"])
c2 = client.push_prompt(NAME, object=v2, tags=["prod"], commit_tags=["v2"])
print("commits:", c1, c2)

# 代码侧只认 tag，不认具体版本
p = client.pull_prompt(f"{NAME}:prod")
print(p.format_prompt(question="退款多久到账？").to_string())

# 想钉死版本用 commit tag
pinned = client.pull_prompt(f"{NAME}:v1")
print(pinned.format_prompt(question="退款多久到账？").to_string())

步骤 5：预期输出

commits: <PromptCommit ...> <PromptCommit ...>
System: 你是退款客服。给出明确到账时间；不能承诺立即到账；无法处理时转人工。
Human: 退款多久到账？
System: 你是退款客服，回答简洁。
Human: 退款多久到账？

（format_prompt(...).to_string() 的输出格式随 langchain-core 版本略有差异，重点看两段 system 是否不同。）

步骤 6：验证是否成功

  • 平台 Prompts 页打开 refund-reply：两个 commit，prod 指向第二个；
  • 把 tags=["prod"] 的那次提交的 tag 手动改指到第一个 commit 再跑：pull_prompt("refund-reply:prod") 会拿到 v1 的内容——代码没改，行为变了，这就是「tag 是指针」；
  • 用 pull_prompt("refund-reply:v1") 再跑：永远是 v1，不受 tag 移动影响；
  • client.get_prompt 返回 Optional，用它判空（SDK 没有 has_prompt）；list_prompt_commits(NAME) 能列出两个 hash，证明 commit 不可变。

写法 A · 预拉 + 兜底（生产必须）

import logging
from langchain_core.prompts import ChatPromptTemplate

FALLBACK = ChatPromptTemplate.from_messages([
    ("system", "你是退款客服。"),
    ("human", "{question}"),
])

def load_prompt(client, name_tag: str):
    try:
        return client.pull_prompt(name_tag)      # 启动时拉一次，缓存在进程内
    except Exception as e:
        logging.error("prompt pull failed: %s", e)
        return FALLBACK                          # 平台不可用时降级，不阻断线上

要点：在启动阶段拉、失败降级，不要在每次请求里拉。

七、常见坑（官方明确限制/版本差异）

  1. 把 key / 密码写进 prompt 变量。prompt 可被共享、可被导出，泄漏面比代码大。
  2. prod tag 直接覆盖。线上行为跟着变而没人审查；要么走评审，要么用不可变 commit tag。
  3. 只写 name 不带 tag。默认取最新 commit，等于「谁提交谁上线」。
  4. prompt 里有变量但 inputs 没给值。format 时直接 KeyError。
  5. 每次请求都 pull_prompt。多一次网络往返，还放大平台故障的影响面。
  6. 把内部 prompt 发到公开 Hub。业务规则就公开了。
  7. 以为 pull_prompt 会带模型配置。默认不带，要 include_model=True。

八、课后小结

  • prompt = 模板 + 变量 + 可选模型配置 + 可选结构化输出；
  • commit 不可变、tag 可变；prod 是移动指针，v1 是固定标记；
  • 拉取写 name:tag，只写 name 会跟最新；
  • 生产上启动预拉 + 失败降级，别在请求路径里拉；
  • 内部 prompt 不进公开 Hub。

九、思考题

1、「线上跟 prod」与「线上跟 v1」各自的代价是什么？

参考回答：跟 prod 能秒级改行为、也秒级出事，需要评审与回滚纪律；跟 v1 稳，但每次换版本都要发版，紧急修复变慢。

2、为什么 commit 不可变，而 tag 可变？

参考回答：commit 是内容快照，可变就失去「可复现」的意义；tag 是部署指针，本来就该能移动。两者分工对应「证据」与「发布」。

3、prompt 里存模型配置的好处与风险？

参考回答：好处是 Playground、实验、线上共享同一套参数，消除「本地好线上差」；风险是模型配置变更也被当成 prompt 变更，评审时要一起看。

4、兜底 prompt 应该写得多完整？

参考回答：够用即可——保持核心约束（不承诺、转人工），不追求与线上同质量；它的目标是不让平台故障变成线上事故。
