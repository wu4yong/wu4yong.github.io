08 离线实验与门禁

实验是「量一次」，门禁是「量和基线比」｜依据官方 Compare experiments / Experiment configuration 页自绘

版本不一致提示

  • 本篇基线是 LangSmith 平台（2026-11 文档）+ langsmith 0.16.2 + Python 3.13；
  • 本篇必须有真实 key：evaluate() 会在平台上创建 experiment 并写回结果；
  • evaluate() 的关键参数是 experiment_prefix（实验名前缀，平台会补时间戳）、repetitions、max_concurrency、blocking；SDK 里的「缓存」是 LANGSMITH_TEST_CACHE，那是 pytest 录制回放用的 cassette，和实验页的缓存不是一回事，别把两者混成一个旋钮；
  • ExperimentResults 上的方法只有 wait() / to_pandas() / url / comparison_url 这几个，没有 compare()；
  • 教科书式的「改完 dataset 再比历史实验」不成立：分母变了，均值不可比。

一、学习目标

学完这一讲，你要能做到三件事：

  1. 跑一次可复现的离线实验，说清 repetitions / concurrency / blocking 三个旋钮各影响什么，以及「测试回放缓存」与「实验缓存」的区别；
  2. 拿两次实验的逐条差值，列出「退化的那几条」而不是只看均值；
  3. 把「分数不低于基线」写成 CI 里的退出码判断，让坏改动进不了主干。

二、前置知识

  • 读完 07 评测器，有至少一列可用分数；
  • 有一条能跑通的 dataset（06）；
  • 知道均值会掩盖单条退化。

三、理论讲解（官方定义）

1. 三个旋钮

旋钮
管什么
调大的代价
什么时候必须调
repetitions
一条题重复跑几次
时间与 token 线性增长
输出有随机性时要 ≥2
max_concurrency
同时跑几条
触发限流、结果乱序
题库大、target 是 IO 型
blocking
是否等实验跑完再返回
脚本挂得久
CI 里要拿结果做判断时必须为 True

2. 实验与运行的关系

一次 experiment 本质是「在某个 dataset 上，用某个 target + 一组评测器，产出 N 条 run」。所以：

  • 同一实验内，每条 example 对应一条 run（repetitions > 1 时是多条）；
  • 跨实验，只有 example 相同才可比；新增/删除 example 都会破坏可比性；
  • 实验名带前缀 + 时间戳，方便按前缀筛。

3. 三种用法

  • regression test：拿历史坑题跑，确认「修好的没复发」；
  • unit test：单条 example + 硬断言（格式、字段），等价于会调模型的单元测试；
  • backtesting：用新 prompt 回放旧流量，估「如果当时用新版本会怎样」。

四、原理拆解：均值为什么会骗人

假设 10 条题，9 条从 1.0 掉到 0.9，1 条从 0 涨到 1.0：均值从 0.9 变成 0.91，「提升」了。但实际是九条集体退步。

所以门禁要看两个量：均值（宏观趋势）与退化条数（微观风险）。官方对比页给的就是逐条差值表，不是只给一个总分。

另一个细节：repetitions=1 时，单条分数本身带随机性；拿单次结果和单次结果比，差值里混着噪声。要么 repetitions ≥ 2 取均值，要么给门禁留容差。

五、场景说明

把退款 FAQ 的 prompt 从 v1 改到 v2，想确认「没有变差」。你跑两次实验，得到两份逐条结果。均值 0.91 vs 0.88，看着像退步；但逐条看，退步集中在 3 条「退款失败怎么办」的题上——原因是 v2 把「转人工」的措辞删了。门禁的价值就在这里：拦住「均值还行、但某类题全崩」的改动。

步骤 3：导入

from langsmith import evaluate

步骤 4：最小可运行代码

存成 gate.py，uv run gate.py。

import json, os, sys
from dotenv import load_dotenv
from langsmith import evaluate
import pandas as pd

load_dotenv()

def target(inputs: dict) -> dict:
    return {"answer": json.dumps({"answer": "3 个工作日到账"}, ensure_ascii=False)}

def json_ok(run, example) -> dict:
    try:
        json.loads(run.outputs["answer"]); return {"key": "json_ok", "score": 1}
    except Exception:
        return {"key": "json_ok", "score": 0}

res = evaluate(
    target,
    data="refund-faq",
    evaluators=[json_ok],
    experiment_prefix="gate-candidate",
    repetitions=2,          # 有随机性的 target 才需要
    max_concurrency=4,
    blocking=True,
)
res.wait()
df = res.to_pandas()
print("columns:", list(df.columns)[:10])

# 逐条聚合：先确认列名形如 feedback.json_ok（不同版本可能带前缀）
col = [c for c in df.columns if str(c).endswith("json_ok")][0]
per_ex = df.groupby("example_id")[col].mean() if "example_id" in df.columns else df[col]

baseline = json.load(open("baseline.json", encoding="utf-8"))
mean_now = float(per_ex.mean())
print(f"mean={mean_now:.3f} baseline={baseline['mean']:.3f}")

# 门禁：均值不低于基线 - 容差，且退化条数不超过阈值
tol, max_regress = 0.02, 1
bad = int((per_ex < baseline["mean"] - tol).sum())
print(f"regressed examples: {bad}")

if mean_now < baseline["mean"] - tol or bad > max_regress:
    print("GATE FAILED")
    sys.exit(1)
print("GATE PASSED")

步骤 5：预期输出

columns: ['run_id', 'example_id', 'feedback.json_ok', ...]
mean=0.950 baseline=0.950
regressed examples: 0
GATE PASSED

baseline.json 是上一次发版时的快照：{"mean": 0.95}。第一次跑先人工确认结果合格，再把它写成快照。

步骤 6：验证是否成功

  • Experiment 页能看到 gate-candidate-<时间戳> 这次实验，json_ok 一列均值与脚本打印一致；
  • 把 target 故意改成返回纯文本（非 JSON），重跑：GATE FAILED，退出码 1；
  • echo $LASTEXITCODE（PowerShell）确认 CI 能读到失败信号；
  • 打开 res.url，逐条看「哪几条从 1 变 0」，这才是门禁要拦的东西。

写法 A · 对比两次历史实验

from langsmith import Client
client = Client()

runs = list(client.list_runs(project_name="gate-candidate-202701101200", limit=100))
# feedback 在 run.feedback_stats 里；列表接口默认可能不返回，需要在 select 里显式要
for r in runs[:3]:
    print(r.id, r.feedback_stats)

不追求复刻 UI 的对比表时，直接按 experiment 名拉 run 逐条比最快；要完整表格与图表，用 res.comparison_url 打开对比页。

写法 B · 缓存：两种「缓存」别混

  • 测试回放：LANGSMITH_TEST_CACHE=tests/cassettes，把模型响应录成 cassette，单测离线重放，省 token 且结果确定；
  • 实验页的缓存：指平台复用了之前相同输入的结果，判断方法是看实验页的 cached 标记比例；
  • 错误用法：prompt 改了，但实验命中了旧结果 → 分数是上一版 prompt 的，改动静默失效。改 prompt 的实验务必确认没有复用旧输出。

七、常见坑（官方明确限制/版本差异）

  1. repetitions=1 就下结论。有随机性的 target，单次差值里全是噪声。
  2. 改完 dataset 再比历史。分母变了，均值不可比；要改题库就重跑基线。
  3. prompt 改了还开缓存。分数是旧版本的，白高兴一场。
  4. 只看均值。九条退步一条进步，均值还能涨。
  5. 门禁容差设 0。任何抖动都红，最后所有人都学会「重跑一次直到绿」。
  6. 把 evaluate() 当无副作用。它会在平台上建 experiment、写 feedback，跑多了会占配额。
  7. to_pandas() 的列名按记忆写。不同版本前缀不一，先 print(df.columns) 再取列。

八、课后小结

  • 三个旋钮：repetitions 管噪声、concurrency 管吞吐、blocking 决定脚本要不要等结果；
  • 实验可与历史比的前提是 dataset 没变；
  • 门禁要同时看均值与退化条数，容差不为 0；
  • ExperimentResults 只有 wait / to_pandas / url / comparison_url，没有 compare；
  • 改 prompt 的实验不要开缓存。

九、思考题

1、为什么门禁要留容差？

参考回答：模型输出有随机性，即使代码没改，分数也会小幅波动；容差为 0 的门禁会被噪声反复触发，最终失去约束力。

2、repetitions 从 1 提到 2，代价与收益各是什么？

参考回答：时间与 token 翻倍；收益是把「单次运气」摊平，差值才有意义。题库大时可以对 hard 层提 repetitions、smoke 层保持 1。

3、backtesting 与 regression test 的区别？

参考回答：regression 是「已知坑题不许复发」，题来自历史失败；backtesting 是「用旧流量估新版本」，题来自线上分布，目的在估影响面而不是守住底线。

4、CI 里该跑哪个 split？

参考回答：日常提交跑 smoke（快、必跑），合并到主干或发版跑 regression + hard；全都跑会让每次提交都等十分钟。
