06 数据集

dataset 是题库，example 是题目；split 是题库里的分层标签｜依据官方 Manage datasets 页自绘

版本不一致提示

  • 本篇基线是 LangSmith 平台（2026-11 文档）+ langsmith 0.16.2 + Python 3.13；
  • 本篇必须有真实 key：读写 dataset 全部走 API，无 key 直接 401；
  • 批量写用 create_examples(examples=[...])，字段名是 outputs（不是 reference_outputs）；单条写 create_example 才是 reference_outputs，两个接口的字段名不一致，是官方历史包袱；
  • split 是自由字符串，没有 create_dataset_split；改分层用 update_dataset_splits(dataset_name=, split_name=, example_ids=, remove=False)；
  • dataset 支持 inputs_schema / outputs_schema，但官方不强制校验；schema 与 app 入参不一致时，实验会直接报错。

一、学习目标

学完这一讲，你要能做到三件事：

  1. 说清 dataset 与 example 的组成，以及 example 的三个必填语义（输入、参考输出、metadata）；
  2. 从三种来源（手写 / trace 回流 / 合成）各建一批 example，并批量写入；
  3. 用 split 做出 smoke / regression 分层，并用 update_dataset_splits 重新分层。

二、前置知识

  • 读完 05 筛选与数据集，知道 example 与 trace 的寿命差别；
  • 知道 reference_outputs 不能抄当时的模型输出。

三、理论讲解（官方定义）

1. 一个 example 由什么组成

  • inputs：喂给被测程序的入参，通常就是 {"question": "..."} 这种形态；
  • reference_outputs：期望结果，可以是一个字段，也可以是结构化对象（JSON）；
  • metadata：这条题的附加信息（难度、来源、租户、标签）；
  • split：分层标签，一个 example 可以只属于一个 split。

3. split 的意义

官方建议按用途分层，而不是按数量切分：smoke（几条快的，改完必跑）、regression（历史踩过的坑）、hard（难例）。这样「日常提交跑 smoke、发版跑 regression」才有意义——按 80/20 随机切分，两边的难度分布是一样的，起不到分层作用。

4. 版本意识

dataset 的内容可以被改（example 增删改），而实验是「拿某一时刻的题库跑出来的」。所以改题库之前先想清楚：这次改动会让历史实验的分数失去可比性吗？官方提供 list_dataset_versions / diff_dataset_versions 做版本对比，但不会阻止你直接改。

四、原理拆解：为什么 schema 要对齐

实验的执行路径是「example.inputs → 你的 target 函数 → 返回值 → 评测器」。所以 inputs 的键必须正好是 target 的入参名：

  • target 是 def answer(question: str)，example 的 inputs 就必须是 {"question": ...}；
  • 如果 example 里写的是 {"q": ...}，实验会直接抛 KeyError，而不是「跳过」；
  • 反过来，多出来的键会被忽略——这会让你误以为「字段对齐了」，其实跑的是别的值。

inputs_schema 只是元数据声明，不替你做校验；真正的约束来自 target 的签名。

五、场景说明

退款客服上线两个月，攒了三种素材：产品同学写的 40 条标准问答、线上筛出的 12 条差评案例、模型合成的 60 条问法变体。你要做的是把它们放进同一个 dataset，但分层存放：40 条标准问答进 smoke，12 条差评进 regression，60 条变体进 hard。同一份题，三种跑法。

六、示例代码

步骤 1：环境准备

uv init ls06-dataset
cd ls06-dataset
uv add langsmith python-dotenv

步骤 2：凭证配置

.env：LANGSMITH_API_KEY=...、LANGSMITH_PROJECT=ticket-agent-dev。本篇不需要 LANGSMITH_TRACING，因为不产生 trace。

步骤 3：导入

from langsmith import Client

步骤 4：最小可运行代码

存成 dataset.py，uv run dataset.py。

import os
from dotenv import load_dotenv
from langsmith import Client

load_dotenv()
client = Client()
DS = "refund-faq"

if not client.has_dataset(dataset_name=DS):
    client.create_dataset(
        dataset_name=DS,
        description="退款客服题库：smoke / regression / hard 三层",
        inputs_schema={"question": "str"},
        outputs_schema={"answer": "str"},
    )

# 1) 批量写：注意字段是 outputs，不是 reference_outputs
client.create_examples(
    dataset_name=DS,
    examples=[
        {"inputs": {"question": "退款多久到账？"}, "outputs": {"answer": "3 个工作日"}, "split": "smoke"},
        {"inputs": {"question": "能退到原卡吗？"},   "outputs": {"answer": "默认退回原支付渠道"}, "split": "smoke"},
        {"inputs": {"question": "退款失败怎么办？"}, "outputs": {"answer": "转人工并登记工单"}, "split": "regression"},
        {"inputs": {"question": "钱什么时候回来"},   "outputs": {"answer": "3 个工作日"}, "split": "hard"},
    ],
)

# 2) 重新分层：把最后一条从 hard 挪到 regression
ex = [e for e in client.list_examples(dataset_name=DS) if e.inputs["question"] == "钱什么时候回来"]
client.update_dataset_splits(
    dataset_name=DS,
    split_name="regression",
    example_ids=[e.id for e in ex],
)

# 3) 盘账
print("examples:", len(list(client.list_examples(dataset_name=DS))))
print("splits:", list(client.list_dataset_splits(DS)))

步骤 5：预期输出

examples: 4
splits: ['hard', 'regression', 'smoke']

splits 来自 list_dataset_splits，取的是当前 dataset 下实际出现过的分层名；把某层的题全部移走后，该层是否还出现在列表里由平台侧决定，别把它当成「层还在、只是空」。要判断某层有没有题，用 list_examples(dataset_name=DS, splits=["regression"]) 数条数。

步骤 6：验证是否成功

  • UI 的 Datasets 里打开 refund-faq：4 条 example，3 个 split；
  • 鼠标悬停最后一条：split 从 hard 变成了 regression；
  • 用 client.read_dataset(dataset_name=DS) 看 inputs_schema 确实是 {"question": "str"}；
  • 故意写一条 {"q": "..."} 的 example，然后拿它跑实验（LS08）：会直接 KeyError: 'question'——这就是「schema 声明不校验」的实证。

写法 A · 单条写 + 带 metadata

client.create_example(
    inputs={"question": "发票抬头写错了能改吗"},
    dataset_name=DS,
    reference_outputs={"answer": "作废重开，3 个工作日内"},
    metadata={"source": "manual", "difficulty": "easy"},
    split="smoke",
)

单条接口的参数名是 reference_outputs，批量是 outputs；混用会报 unexpected keyword，不要照着记忆写。

写法 B · 从 CSV 导入

官方支持在 UI 里上传 CSV 建 dataset（首行是字段名）。脚本侧更稳的做法是读 CSV 后转成 create_examples 的列表，一次性写入——比一条条调 create_example 快一个数量级。

七、常见坑（官方明确限制/版本差异）

  1. 批量接口写成 reference_outputs。create_examples 要 outputs，静默写入空值的情况在 SDK 里会出现，务必跑一遍验证。
  2. inputs 键名与 target 入参不一致。实验直接 KeyError，不是「跳过」。
  3. 按数量 80/20 切 split。两边难度一样，分层没意义。
  4. dataset 只加不删。跑一次实验十分钟，改一次 prompt 等半天。官方提供 delete_examples(hard_delete=False) 软删。
  5. 改了题库再和历史实验比分数。分母变了，结论不成立。
  6. 把密钥塞进 example 的 metadata。dataset 可被共享，泄漏面比想象中大。

八、课后小结

  • example = inputs + reference_outputs + metadata + split；
  • 批量写用 outputs，单条写用 reference_outputs，字段名不一致；
  • split 按用途分层（smoke / regression / hard），不按比例切；
  • inputs_schema 只是声明，真正的约束是 target 签名；
  • 题库改动会让历史实验失去可比性，改前先想清楚。

九、思考题

1、为什么 split 建议按用途而不是按比例？

参考回答：按比例切，两边难度分布相同，smoke 就只是「小号的全量」，起不到快而准的作用；按用途切才能让日常提交与发版各跑该跑的题。

2、batch 与 single 两个接口字段名不一致，说明什么？

参考回答：两个接口是不同时期加的，SDK 没有做统一层；写代码前查签名比凭记忆可靠，这也是本系列反复强调「先 probe 再写」的原因。

3、reference_outputs 用结构化对象有什么好处？

参考回答：评测器可以做字段级比对（例如只比 answer 不比 citations），也能让 LLM-judge 拿到「应该包含哪些要点」而不是一句标准话术。

4、dataset 该多久清理一次？

参考回答：按实验耗时决定——单次实验超过可接受时长（比如 10 分钟）就该清；同时保留 regression 层的全部，只清 hard 里长期跑不动、也没人看的题。
