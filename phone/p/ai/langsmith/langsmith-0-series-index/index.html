00 系列目录

按需求选路径：线上排障、回归门禁、要上线，三条路各读一半｜本篇自绘

版本与口径

  • 本系列基线是 LangSmith 平台（2026-11 官方文档）+ langsmith 0.16.2 + Python 3.13；
  • 平台 UI 迭代快，正文只讲结构性概念（run / trace / thread / dataset / experiment），按钮位置以官方截图为准；
  • 部署相关能力有套餐门槛：Cloud 上的 Agent Server 需 Plus 及以上，自建 / BYOC / Hybrid 需 Enterprise；
  • 示例统一用 LANGSMITH_TRACING + LANGSMITH_API_KEY 显式开关，没有 key 时给出「本地断言照跑、只跳过上报」的降级写法。

一、这套课解决什么

LangChain 系列讲「怎么把 Agent 搭出来」，LangGraph 系列讲「底下那台运行时怎么自己搭」。两个系列跑完，你手上有一张能跑的图，但还缺三个问题的答案：

  1. 线上这一步为什么慢、为什么错，去哪儿看？
  2. 改完 prompt，怎么证明没把别的用例改坏？
  3. 这套东西上线之后，谁在跑、花了多少钱、出了问题谁修？

LangSmith 就是回答这三件事的平台。这套课按「看得见 → 量得出 → 改得动 → 上得了线」的顺序，把它拆成 16 讲。

三条边界：

  • 只讲 LangSmith 侧，不复述图与 Agent 的原语，需要时一句「见 LGxx」带过；
  • 重心在评测闭环，不是「界面导览」：trace 只占 3 讲，评测占 4 讲；
  • 部署只到「一个能上线的拓扑 + 一张检查表」，K8s 与 license 的运维细节指回官方。

二、四个对象先记住

整套平台的数据模型只有四个粒度，后面每一讲都在复用它们：

对象
一句话
典型用途
run
一次最小工作单元（模型调用、工具、检索），等价于 OTel 的 span
定位单步的输入输出与耗时
trace
一次操作的全部 run 组成的树，上限 25,000 run
查「这一次为什么错」
thread
用 metadata.thread_id 串起来的多条 trace，一次多轮会话
查「跨轮到底发生了什么」
trajectory
thread 拍平成有序消息列表，去掉嵌套
把会话当一段对话读

再加两类富化手段：feedback（tag + score，打分）、tags / metadata（分类与过滤键）。评测、筛选、告警都建在这两样上。

四、三条阅读路径

不是每个人都要从头读到尾。按你的当前问题选：

  • 线上有故障：03 埋点 → 04 读 trace → 05 筛选 → 09 在线评测。目标是把一次事故变成一条能复跑的用例；
  • 要做回归门禁：06 数据集 → 07 评测器 → 08 离线实验。目标是 CI 里有一道「分数不许掉」的闸；
  • 准备上线：12 Agent Server → 13 平台治理 → 14 发现修复 → 15 网关与注册 → 16 实战。目标是选对拓扑、算清成本、出问题有人接。

16 讲按模块顺序读最顺，但不必按顺序读完全部。

五、环境与前置

  • Python 3.13，uv 管依赖；uv add langsmith 即可，不需要装 LangChain；
  • 一个 LangSmith 账号（Google / GitHub / 邮箱登录）；免费层够跑完 M0–M3 的示例；
  • 编辑器里配 .env：LANGSMITH_API_KEY、LANGSMITH_TRACING=true、LANGSMITH_PROJECT、LANGSMITH_ENDPOINT；
  • 想跟着看 UI 的，建议开两个窗口：一边跑脚本，一边刷 Runs 列表。
