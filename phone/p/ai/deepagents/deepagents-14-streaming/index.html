14 事件流与前端

主代理与子代理各说各话；前端要回答的永远是「谁的、哪一步、说了什么」｜依据官方 streaming / event-streaming 页自绘

版本不一致提示

  • 本篇基线是 deepagents 0.7.42 + langgraph 1.2.24 + Python 3.13；
  • 经典写法是 agent.stream(..., stream_mode=..., subgraphs=True, version="v2")：单模式也返回 dict，键是 type / ns / data；
  • 子代理事件的命名空间长这样：("tools:<tool_call_id>",)，主代理是空元组 ()——用 ns 判断来源，不要用节点名猜；
  • 0.6 起新增类型化投影 agent.stream_events(input, version="v3")，可直接遍历 stream.messages / stream.tool_calls / stream.subagents；
  • 实测 v3 协议会打 LangChainBetaWarning: The v3 streaming protocol on Pregel is experimental，按 beta 对待，生产前先锁版本；
  • 不传 subgraphs=True 时：单模式给 (chunk, metadata) 元组，多模式给 (mode, data)，与 v2 dict 形状不同。

一、学习目标

学完这一讲，你要能做到三件事：

  1. 说清 messages / updates / custom 三条流各装什么，什么时候该订哪条；
  2. 用命名空间把「主代理说的」和「子代理说的」分开，前端不再把子代理的话塞进主气泡；
  3. 知道审批中断、待办进度、子代理状态分别从哪条流里拿。

二、前置知识

  • 读完 DA12 异步子代理（子代理有独立生命周期）；
  • 有 LangGraph 流式基础（LG09 流式 级别即可）；
  • 知道 LangGraph 的 updates 是「每个节点跑完后的增量」。

三、理论讲解（官方定义）

1. 三条经典投影

stream_mode
装什么
前端拿它做
messages
模型逐 token 增量 + 元数据
打字机、气泡
updates
每个节点跑完的增量与审批中断
步骤进度、审批弹窗
custom
工具里 get_stream_writer() 写的信号
百分比、阶段条

values 是全量状态，每步一份完整快照——适合调试，不适合直接做前端 diff（会把整页重渲染）。

2. 命名空间：谁在说话

开 subgraphs=True 后，每个事件带 ns：

ns
来源
()
主代理
("tools:abc123",)
主代理 task 调用 abc123 拉起的子代理
("tools:abc123", "model_request:def456")
子代理内部的模型节点

3. 类型化投影（0.6+）

stream_events 把「按 mode 分支」换成「按投影遍历」：

stream = agent.stream_events(input, version="v3")
for message in stream.messages:        # 主代理消息
    print(message.text)
for sub in stream.subagents:           # 每个 task 调用一个句柄
    print(sub.name, sub.status)        # started / completed / failed / interrupted
    for message in sub.messages:
        print(f"[{sub.name}]", message.text)

子代理句柄还带 .tool_calls / .values / .output / .path，以及嵌套的 .subagents。官方明确：stream.subgraphs 是图结构，stream.subagents 是产品级派活；面向 UI 用后者。

4. 中断也在流里

审批中断会作为 __interrupt__ 出现在 updates 流；子代理里的中断也会冒到父流，不需要为了收中断额外开 subgraphs=True（开它是为了子代理的 token 与进度）。

四、原理拆解：为什么不能只订 messages

只订 messages，前端能显示「正在说话」，但答不了三个问题：

  1. 谁在说：主代理和子代理的 token 混在一条流里，不按 ns 分开就会串台；
  2. 说到哪一步：messages 没有节点边界，工具调用开始/结束看不到；
  3. 什么时候要人：审批是状态事件，不是文本，只订 token 永远等不到弹窗。

所以一个能用的前端至少订两条：messages 给文本、updates 给结构与中断；自定义进度再加 custom。三条流合起来才是「一场运行」的完整投影。

另一个容易忽略的点：投影是同一份执行的三个视角，不是三次执行。同时订 ["messages","updates"] 时，chunk 变成 (mode, data) 二元组，别把它当成两次运行。

五、场景说明

  • 聊天式 UI：messages + updates，主气泡只吃 ns=()；
  • 任务面板 / 多子代理：stream.subagents，每个句柄一张卡，状态从 status 读；
  • 长任务进度：工具里写 custom 信号（处理到第几条、百分比），比猜 token 靠谱；
  • 审批工作台：updates 里的 __interrupt__ + action_requests 渲染表单；
  • 不适合：把 values 当 diff 源、把子代理 token 直接拼进主回答。

步骤 3：导入

from langchain.tools import tool
from langgraph.config import get_stream_writer
from langchain_core.language_models.fake_chat_models import GenericFakeChatModel
from langchain_core.messages import AIMessage, HumanMessage
from deepagents import create_deep_agent

步骤 4：最小可运行代码（工具自己发进度信号）

存成 stream_custom.py，uv run stream_custom.py。假模型调一次 scan，scan 内部写两条进度。

from langchain.tools import tool
from langgraph.config import get_stream_writer
from langchain_core.language_models.fake_chat_models import GenericFakeChatModel
from langchain_core.messages import AIMessage, HumanMessage
from deepagents import create_deep_agent

@tool
def scan(topic: str) -> str:
    """扫描一个主题并回报进度。"""
    w = get_stream_writer()
    w({"stage": "start", "pct": 0})
    w({"stage": "done", "pct": 100})
    return f"scan {topic}: 12 条"

class Fake(GenericFakeChatModel):
    def bind_tools(self, tools, **kw):
        return self

call = AIMessage(content="", tool_calls=[{"name": "scan", "args": {"topic": "工单"}, "id": "s1"}])
agent = create_deep_agent(
    model=Fake(messages=iter([call, AIMessage(content="fin")])),
    tools=[scan],
)

for chunk in agent.stream(
    {"messages": [HumanMessage(content="扫描")]},
    stream_mode="custom",
    subgraphs=True,
    version="v2",
):
    print(chunk["ns"], chunk["data"])

步骤 5：预期输出

() {'stage': 'start', 'pct': 0}
() {'stage': 'done', 'pct': 100}

步骤 6：验证是否成功

  • 两条 chunk 的 type 都是 custom，ns 是 ()（主代理里的工具）；
  • 把 stream_mode 换成 updates，会看到 model / tools 等节点名；
  • 把 stream_mode 换成 messages 且不传 subgraphs，形状变成 (AIMessageChunk, metadata) 元组。

写法 A · 主代理与子代理分开：按 ns 路由

for chunk in agent.stream(
    {"messages": [{"role": "user", "content": "查 1024 并给结论"}]},
    stream_mode="updates",
    subgraphs=True,
    version="v2",
):
    if chunk["type"] != "updates":
        continue
    if not chunk["ns"]:
        print("[主]", list(chunk["data"].keys()))
    else:
        print(f"[子 {chunk['ns'][0]}]", list(chunk["data"].keys()))

实测一个主代理 + 一个 researcher 子代理的运行，ns 序列是：

() ['PatchToolCallsMiddleware.before_agent']
() ['model']
('tools:b3e4e26e-1cbb-5f78-bc1e-60746d0f906a',) ['PatchToolCallsMiddleware.before_agent']
('tools:b3e4e26e-1cbb-5f78-bc1e-60746d0f906a',) ['model']
() ['tools']
() ['model']
() ['_ParentNotifierMiddleware.after_agent']

tools: 后面就是主代理那次 task 调用的 id——前端用它把子代理卡片和主对话里的「派活」条目对上。

写法 B · 类型化投影：一张卡一个句柄

stream = agent.stream_events(
    {"messages": [{"role": "user", "content": "查 1024 并给结论"}]},
    version="v3",
)
for sub in stream.subagents:
    print(f"{sub.name}: {sub.status}")      # researcher: started
    for call in sub.tool_calls:
        print("  工具:", call.tool_name, call.input)
    for msg in sub.messages:
        print("  说:", msg.text)

需要并发消费（主对话与子代理同时刷）时，同步代码用 stream.interleave("messages", "subagents")，异步代码用 asyncio.gather + astream_events。

七、常见坑（官方明确限制/版本差异）

  1. 只订 messages。看不到子代理进度，也收不到审批中断。
  2. 没开 subgraphs=True 却按 ns 取。单模式给元组、多模式给二元组，直接 chunk["ns"] 会报 TypeError。
  3. 把 values 当 diff。每轮都是全量状态，前端会整页重绘。
  4. 用节点名判断来源。节点名在中间件里会重复出现，唯一可靠的是 ns。
  5. 子代理 token 拼进主回答。父子气泡会串；按 ns 或 sub.name 分流。
  6. v3 当稳定协议。实测会打 LangChainBetaWarning，升级前先回归一遍。
  7. 中断去子代理流里找。审批中断在父 updates 流里，子代理只负责冒泡。
  8. 异步子代理的事件当成同一 trace。它们跑在服务端独立线程，要按 task id 归并。

八、课后小结

  • 三条经典投影：messages 文本、updates 结构 + 中断、custom 自定义进度；
  • ns 是判断「谁在说话」的唯一可靠依据；
  • 0.6+ 的 stream_events 把投影变成可遍历对象，stream.subagents 是面向 UI 的抽象；
  • v3 目前 experimental，锁版本、留回退；
  • 审批、待办、子代理状态分别来自 updates / state["todos"] / subagents。

九、思考题

1、为什么审批中断不需要 subgraphs=True 也能收到？

参考回答：中断写在父图的 updates 流里，子代理只负责把自己的中断冒泡到父流；subgraphs 控制的是子图事件是否外露。

2、ns 里为什么是 tools: 前缀而不是子代理名？

参考回答：命名空间是图结构路径，子代理是挂在 task 工具调用下的子图；产品级名字在 subagents 投影里。

3、什么时候必须用 custom，而不是从 token 里猜进度？

参考回答：工具有明确的阶段与数量时；token 数量与业务进度无关，猜出来的百分比只会骗人。

4、values 适合什么场景？

参考回答：调试、状态快照、断点复盘；不适合直接作为前端增量。
