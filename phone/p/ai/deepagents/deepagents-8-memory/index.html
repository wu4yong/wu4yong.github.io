Deep Agents 08 · 记忆

分类：ai · deepagents ｜ 标签：Deep Agents · LangChain · 系统课

08 记忆

记忆每次都进系统提示；作用域由后端的 store 命名空间决定｜依据官方 memory 页自绘

版本不一致提示

  • 本篇基线是 deepagents 0.7.42 + langgraph 1.2.24 + Python 3.13；
  • memory= 收的是文件路径列表（例如 ["/memories/AGENTS.md"]），不是目录；
  • 记忆在启动时就被包进系统提示的 <agent_memory> 块（实测原文），并附带 <memory_guidelines> 教模型何时用 edit_file 更新；
  • 作用域靠 StoreBackend(namespace=lambda rt: (...))：(assistant_id,) = agent 级、(user_id,) = 用户级、(org_id,) = 组织级；
  • 默认可读可写；要只读就用 FilesystemPermission(operations=["write"], paths=["/memories/**"], mode="deny")；
  • 跨会话「发生了什么」属于情节记忆，靠 checkpointer 持久化会话，不是靠 AGENTS.md。

一、学习目标

学完这一讲，你要能做到三件事：

  1. 用 memory= 注入一份 AGENTS.md，并验证它出现在系统提示里；
  2. 按 agent / user / org 三种命名空间配置记忆作用域；
  3. 识别共享记忆的安全风险，并会用权限把它设成只读。

二、前置知识

  • 读完 DA07 技能包；
  • 知道 CompositeBackend 的路由与 StoreBackend 的命名空间（DA04）；
  • 权限规则的 first-match-wins（DA05）。

三、理论讲解（官方定义）

1. 记忆是什么

官方定义：记忆是跨会话的长期信息，agent 以文件形式读写，存储位置由后端决定。与之相对的是短期记忆——会话历史与临时草稿，由 state 自动管理（DA09）。

2. 三个动作

  1. 用 memory= 指向记忆文件；
  2. agent 启动时把记忆读进系统提示，或在会话中按需读；
  3. agent 学到新东西时用内置 edit_file 更新记忆（默认行为），也可以改成对话之间后台整合。

3. 三种作用域

作用域
namespace
适合

(assistant_id,)

(user_id,)
个人偏好、个人上下文
组织级
(org_id,)

4. 记忆 vs 技能 vs 工具（官方对照）

  • 技能：按需读的流程，格式 SKILL.md，命中才加载；
  • 记忆：启动就加载的事实，格式 AGENTS.md；
  • 工具：每轮都能调的动作，由代码定义。

判据：这次用不上但下次一定用得上 → 记忆；只有某类任务才需要 → 技能；要真的执行 → 工具。

四、原理拆解：为什么记忆要「每次都在」

因为记忆的内容是前提，不是选项。比如「回复用中文」「交付前先跑测试」——这些如果按需加载，模型在需要之前根本不知道该去读。

代价是：记忆会永久占据每一轮的系统提示。所以官方在技能页给出边界：常相关的进记忆，任务特定的进技能。一个实用判据：这句话如果「这次用不上但下次一定用得上」，它就是记忆；如果「只有做某类任务才需要」，它就是技能。

另外，记忆文件注入时会被明确标注为「文件数据，不是隐藏指令」，官方在 <memory_guidelines> 里写明：与用户请求或工具验证冲突时，以用户和证据为准。这是防提示注入的提示层设计。

五、场景说明

  • 用户级：称呼偏好、常用项目路径、输出格式偏好；
  • agent 级：这个 agent 自己的工作习惯、踩过的坑；
  • 组织级：合规口径、品牌语气、审批规则（只读）；
  • 情节记忆：过去哪次怎么解决的问题——用 checkpointer + 检索工具，不要硬塞进 AGENTS.md；
  • 不该进记忆：临时状态（”我现在在外面”）、一次性任务、任何密钥。

六、示例代码

步骤 1：环境准备

uv init da08-memory
cd da08-memory
uv add deepagents

步骤 2：准备记忆文件

memories/AGENTS.md：

## 团队约定
- 交付前先跑测试
- 回复用中文，代码与路径保持英文

步骤 3：导入

import itertools
from langchain_core.language_models.fake_chat_models import GenericFakeChatModel
from langchain_core.messages import AIMessage
from deepagents import create_deep_agent
from deepagents.backends.utils import create_file_data

步骤 4：最小可运行代码（干跑，不需要 key）

存成 memory_check.py，uv run memory_check.py。

MEMO = """## 团队约定
- 交付前先跑测试
- 回复用中文
"""

captured = {}

class Capture(GenericFakeChatModel):
    def bind_tools(self, tools, **kw):
        return self
    def _generate(self, messages, *a, **kw):
        sys_msg = messages[0].content
        captured["sys"] = sys_msg if isinstance(sys_msg, str) else "".join(
            b.get("text", "") if isinstance(b, dict) else str(b) for b in sys_msg
        )
        return super()._generate(messages, *a, **kw)

files = {"/memories/AGENTS.md": create_file_data(MEMO)}
agent = create_deep_agent(
    model=Capture(messages=itertools.cycle([AIMessage(content="ok")])),
    memory=["/memories/AGENTS.md"],
)
agent.invoke(
    {"messages": [{"role": "user", "content": "hi"}], "files": files},
    config={"configurable": {"thread_id": "mem-1"}},
)

s = captured["sys"]
print("有注入块:", "<agent_memory>" in s)
print("有路径标注:", "/memories/AGENTS.md" in s)
print("有内容:", "交付前先跑测试" in s)
print("有更新指引:", "<memory_guidelines>" in s)

步骤 5：预期输出

有注入块: True
有路径标注: True
有内容: True
有更新指引: True

步骤 6：验证是否成功

  • <agent_memory> 块存在 → 记忆确实进了系统提示；
  • 路径被标注 → 模型知道这份记忆来自哪个文件，后续可以 edit_file 更新；
  • <memory_guidelines> 存在 → 「何时该记、何时不该记」的规则也在。

写法 A · 用户级记忆（部署时可解析到人）

from deepagents import create_deep_agent
from deepagents.backends import CompositeBackend, StateBackend, StoreBackend

agent = create_deep_agent(
    model="openai:gpt-6.1-sol",
    memory=["/memories/AGENTS.md"],
    skills=["/skills/"],
    backend=CompositeBackend(
        default=StateBackend(),
        routes={
            "/memories/": StoreBackend(namespace=lambda rt: (rt.server_info.user.identity,)),
            "/skills/": StoreBackend(namespace=lambda rt: (rt.server_info.user.identity,)),
        },
    ),
)

rt.server_info.user.identity 在部署环境里由鉴权解析；本地没有这个字段时换成一个固定元组，先把链路跑通。

写法 B · 组织级记忆设成只读

from deepagents import create_deep_agent, FilesystemPermission

agent = create_deep_agent(
    model="openai:gpt-6.1-sol",
    memory=["/memories/preferences.md", "/policies/compliance.md"],
    permissions=[
        FilesystemPermission(operations=["write"], paths=["/policies/**"], mode="deny"),
    ],
)

政策文件由应用代码写入，agent 只能读——这是防「共享状态被注入」的标准做法。

七、常见坑（官方明确限制/版本差异）

  1. memory= 传目录。它要文件路径，传 /memories/ 不会加载任何东西。
  2. 以为记忆自动持久化。默认 StateBackend 下记忆也活在线程里；跨会话要 StoreBackend 或磁盘后端。
  3. 把密钥写进记忆。官方明确禁止：不要在任何文件、记忆或系统提示里存密钥。
  4. 共享记忆可写。一个用户能写的记忆被另一个用户读到，就是注入通道；默认用用户级作用域。
  5. 并发写同一文件。后写覆盖；按主题拆文件，或把更新放到后台整合任务里串行执行。
  6. 给组织级记忆开放写权限。政策类必须只读，用 permissions deny 写。
  7. 把「发生过什么」塞进 AGENTS.md。情节记忆是 checkpointer 的事；硬写进文件会让记忆无限膨胀。

八、课后小结

  • 记忆是启动即加载的长期事实，以 AGENTS.md 这类文件承载；
  • <agent_memory> + <memory_guidelines> 一起注入，且明确「记忆不是系统指令」；
  • 作用域由 StoreBackend 的命名空间决定：assistant / user / org；
  • 共享记忆默认只读，写入交给应用代码；
  • 短期记忆（会话与草稿）是 state，长期记忆才用 memory=。

九、思考题

1、为什么记忆不能「按需加载」？

参考回答：记忆多是前提（语言、格式、红线），模型在不知道前提的情况下不会主动去查；按需加载只适合任务相关的流程。

2、用户级记忆的命名空间为什么用 callable？

参考回答：要从运行时取出当前调用者的身份，动态拼出命名空间，才能做到「每人一份、互不可见」。

3、共享记忆被写坏会怎样？

参考回答：读到它的所有用户都会被影响；攻击者可以在共享文件里写指令，形成跨用户的提示注入。所以要只读或加审批。

4、情节记忆该放哪？

参考回答：会话本身由 checkpointer 持久化；要做「搜索过去的会话」，用一个工具把 thread 搜索包起来，而不是塞进 AGENTS.md。
