分类：ai · deepagents ｜ 标签：系统课 · Deep Agents · LangChain

02 第一次跑通

模型决定下一步，文件系统负责「记住」，子代理负责「分担」；跑完从三处验收｜依据官方 quickstart 页自绘

版本不一致提示

  • 本篇基线是 deepagents 0.7.42 + langchain 1.5.2 + langgraph 1.2.24 + langsmith 0.16.2 + Python 3.13；
  • create_deep_agent(model=...) 的 model 既可以是 provider:model 字符串（内部走 init_chat_model），也可以是已初始化的模型实例；要调 temperature / max_tokens 就用实例；
  • 默认后端 StateBackend 的文件只活在当前 thread：换 thread_id 就读不到上次写的文件，这不是 bug；
  • 想让 trace 落到指定 agent / 环境，官方新增 LANGSMITH_AGENT_ID + LANGSMITH_AGENT_ENVIRONMENT；只设 LANGSMITH_TRACING + LANGSMITH_API_KEY 会落到默认环境；
  • middleware= 的合并顺序：.name 与内置项相同的替换内置项，其余插在核心栈之后、profile / prompt-caching / memory 之前；
  • 本篇第 4 步是不需要 key 的干跑版（打印工具表），第 6 步给真跑版。

一、学习目标

学完这一讲，你要能做到三件事：

  1. 从零装好 deepagents，写出第一条能跑的 create_deep_agent；
  2. 跑完会从三处验收：回复内容、落盘的文件、LangSmith 里的 trace；
  3. 知道 invoke 与 stream 各自什么时候用，以及 middleware= 是怎么排进栈里的。

二、前置知识

  • 读完 DA01 三层关系与选型，知道 harness 多给了什么；
  • 有任一 provider 的模型 key（OpenAI / Anthropic / DeepSeek / 智谱 / 通义都行，要支持 tool calling）；
  • 想接 trace 的话，有一个 LangSmith key（免费档够用）。

三、理论讲解（官方定义）

1. 装什么

官方 quickstart 的装法是 uv add deepagents（或 pip install deepagents）。它会把 langchain、langgraph、langsmith 一起带上——你不用再单独装这三个。

模型侧的 provider 包要另装，例如 uv add "langchain[openai]"。内置搜索这类 provider 侧工具不需要额外包。

2. 传什么

参数
作用
常见误用
model=
模型字符串或实例
字符串写成 openai/gpt-…（要用冒号）
tools=
你的业务工具
把文件工具也手写一遍（内置已有）
system_prompt=
你的指令
写成和内置指令冲突的条款
backend=
文件存哪
不传就默认线程内内存

system_prompt 之外还有几个参数后面几讲才会用：permissions=（DA05）、skills= / memory=（DA07 / DA08）、subagents=（DA11）、interrupt_on=（DA13）。

3. 跑与看

  • invoke()：一次跑完拿结果，适合脚本与测试；
  • stream()：边跑边拿事件，适合前端与长任务；
  • trace：设 LANGSMITH_TRACING=true + LANGSMITH_API_KEY，每一次工具调用与子代理都会出现在树上。

4. middleware 的合并顺序

官方的规则是：你传的 middleware 里，.name 与内置项相同的原位替换；其余插在「最后一个核心中间件之后、profile / prompt-caching / memory 之前」。这决定了你的中间件看得到什么：排在 memory 之前，就意味着它拿不到 memory 注入后的上下文。

四、原理拆解：一次请求都经过谁

按顺序走一遍（也是 trace 里的顺序）：

  1. 你的脚本把 {"messages": [...]} 交给 agent；
  2. agent 进入 model 节点：系统提示（内置指令 + 你的 system_prompt + memory + skills 索引）与工具表一起发给模型；
  3. 模型要么直接回复，要么发一个 tool call；
  4. 工具节点执行：ls / read_file / write_file / task …；
  5. 文件工具读写的是后端（默认是线程 state），task 会起一个子代理并在 trace 里形成子树；
  6. 回到 model 节点，直到模型不再发 tool call；
  7. 结果回到脚本：out["messages"][-1].content。

三个验收点正好对应这条链的三段：回复看第 7 步，文件看第 5 步，trace看整条链。

五、场景说明

适合这一讲骨架的任务：

  • 「读三份 md，合成一份摘要」：会触发 read_file / write_file，能同时看到文件与工具调用；
  • 「查资料写报告」：会触发搜索工具 + task 子代理，能看到子树；
  • 不适合：一步就能答完的问答（见 DA01 的判据）。

六、示例代码

步骤 1：环境准备

uv init da02-first
cd da02-first
uv add deepagents
uv add "langchain[openai]"     # 换成你用的 provider

步骤 2：凭证配置

.env（真跑时用）：

OPENAI_API_KEY=sk-...
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=lsv2_pt_...
LANGSMITH_AGENT_ID=<agent-id>            # 可选，指定 trace 落到哪个 agent
LANGSMITH_AGENT_ENVIRONMENT=local        # local / development / staging / production

没有 key 也能做第 4 步的干跑。

步骤 3：导入

from deepagents import create_deep_agent

步骤 4：最小可运行代码（干跑，不需要 key）

存成 inspect_tools.py，uv run inspect_tools.py。用假模型把工具表打印出来，确认内置工具与你的工具都绑上了。

from langchain_core.language_models.fake_chat_models import FakeListChatModel
from deepagents import create_deep_agent

seen = {}

def search(q: str) -> str:
    """Search the web for a query."""
    return "ok"

class Recorder(FakeListChatModel):
    def bind_tools(self, tools, **kw):
        seen["tools"] = [
            getattr(t, "name", None) if not isinstance(t, dict) else t.get("name")
            for t in tools
        ]
        return self

agent = create_deep_agent(model=Recorder(responses=["ok"]), tools=[search])
agent.invoke({"messages": [{"role": "user", "content": "hi"}]})
print(seen["tools"])

步骤 5：预期输出

['ls', 'read_file', 'write_file', 'edit_file', 'delete', 'glob', 'grep', 'task', 'search']

步骤 6：验证是否成功

  • 列表里有 7 个文件工具 + task → 内置能力都在；
  • 列表末尾有你的 search → 自定义工具接上了；
  • 真跑版（下面写法 A）再验三件事：回复非空、/workspace 下有文件、LangSmith 里能看到这棵 run 树。

写法 A · 真跑一次（有 key）

from deepagents import create_deep_agent

def search(q: str) -> str:
    """Search the web for a query."""
    return "ok"

agent = create_deep_agent(
    model="openai:gpt-6.1-sol",
    tools=[search],
    system_prompt="你是研究员。长材料先写到 /workspace 再总结，不要整段贴回上下文。",
)

out = agent.invoke(
    {"messages": [{"role": "user", "content": "把三份 md 合成一份摘要"}]},
    config={"configurable": {"thread_id": "t-001"}},
)
print(out["messages"][-1].content)

thread_id 必须给：它是文件（StateBackend）与后续 checkpointer 的归属单位，不给就是一个临时线程。

写法 B · 边跑边看（stream）

for chunk in agent.stream(
    {"messages": [{"role": "user", "content": "把三份 md 合成一份摘要"}]},
    config={"configurable": {"thread_id": "t-001"}},
    stream_mode="updates",
):
    for node, payload in chunk.items():
        print(node, "→", str(payload)[:120])

updates 每步给一次增量，适合脚本里看进度；前端要的更细的投影（消息、工具调用、子代理）见 DA14。

七、常见坑（官方明确限制/版本差异）

  1. model 串用斜杠。provider:model 是冒号，写成 openai/gpt-… 会走错 provider。
  2. 忘了 thread_id。文件活在线程里，不给就是新线程，写完读不到。
  3. 以为内置文件工具要自己装。tools= 里只放业务工具，文件工具是内置的。
  4. system_prompt 和内置指令打架。内置指令先于你的 prompt，冲突条款通常被忽略。
  5. trace 落到默认环境。设了 LANGSMITH_TRACING 但没设 LANGSMITH_AGENT_ID / ENVIRONMENT 时，数据进默认环境，后面按环境筛就找不到。
  6. 一步任务也开 agent。每次 invoke 都有系统提示成本，短任务直接调模型更快。
  7. 模型不支持 tool calling。现象是「一个工具都不调、直接回文本」；先用第 4 步确认工具绑上了，再查模型能力。

八、课后小结

  • uv add deepagents 一把装齐三层依赖，provider 包另装；
  • model 可传字符串或实例，要调参数就传实例；
  • 默认文件后端是线程内 state，thread_id 决定文件归属；
  • 验收看三处：回复、文件、trace；
  • middleware= 同名替换、异名插队，插队位置在 memory 之前。

九、思考题

1、为什么建议一开始就传 thread_id？

参考回答：它同时是「文件归属」和「checkpoint 归属」；不给的话每次都是新线程，文件读不到、也续不上。

2、invoke 和 stream 该在什么场景各用哪个？

参考回答：脚本跑批、跑测试用 invoke；要给用户看进度、或任务可能跑很久时用 stream，按 updates 或更细的投影消费。

3、LANGSMITH_AGENT_ID 不设会怎样？

参考回答：trace 仍会上报，但落到默认环境；按 agent / 环境筛数据时会缺这一批，排查时容易误判「没跑过」。

4、middleware= 里传一个同名的内置中间件会发生什么？

参考回答：原位替换，不新增一层；这也是官方推荐的「改默认行为」的方式（例如换掉默认的 FilesystemMiddleware 配置）。
