06 沙箱与解释器

沙箱是「能跑命令的一块地」，解释器是「agent 循环里的内存工作台」｜依据官方 sandboxes / interpreters 两页自绘

版本不一致提示

  • 本篇基线是 deepagents 0.7.42 + langchain 1.5.2 + Python 3.13；
  • 沙箱后端多给一个 execute 工具，其余 7 个文件工具不变；execute 是否出现取决于后端是否实现 SandboxBackendProtocol（官方 harness 每次模型调用前检查）；
  • BaseSandbox 只需要实现 execute()，其余文件操作都由基类拼脚本走 execute；
  • LocalShellBackend(root_dir=None, *, virtual_mode=True, timeout=120, max_output_bytes=100000, env=None, inherit_env=False) 是本机对照用，不是安全沙箱；
  • 解释器是 beta：CodeInterpreterMiddleware 来自 langchain-quickjs>=0.3.0（Python ≥3.11），默认给 agent 加一个 eval 工具；
  • 解释器默认不能碰文件、网络、shell、装包、时钟；能力要显式桥接（PTC 工具白名单 / task() 子代理）；
  • 权限规则管不到 execute（DA05 已讲过），所以「要跑命令」和「路径白名单」不是一套防线。

一、学习目标

学完这一讲，你要能做到三件事：

  1. 说清沙箱与解释器的分工：一个作用于环境，一个作用于循环内的代码；
  2. 用 LocalShellBackend 在本机跑通 execute，并知道它为什么不能当生产沙箱；
  3. 用 CodeInterpreterMiddleware 给 agent 加 eval，知道三种持久化模式与默认隔离边界。

二、前置知识

  • 读完 DA05 权限规则；
  • 知道 agent 的「工具调用」是「模型发一次、结果回上下文」的同步模式（LC08 级别）；
  • 想接真沙箱的话，要有对应 provider 的账号（LangSmith Sandbox / E2B / Modal / Runloop / Vercel…）。

三、理论讲解（官方定义）

1. 沙箱是什么

官方口径：沙箱就是一类后端，但它额外提供 execute（在隔离环境里跑 shell）。给 agent 的能力因此变成「7 个文件工具 + execute」。

隔离边界：agent 读不到你的本机文件、拿不到你的环境变量、动不了别的进程。但官方明确它不防两件事：上下文注入（它能被诱导在沙箱里跑命令）、网络外泄（除非 provider 关掉网络，例如 Modal 的 blockNetwork）。

2. 架构：只要实现 execute

BaseSandbox 把 read / write / edit / delete / ls / glob / grep 全部基于 execute 拼脚本实现。所以接一个新 provider 只需要实现一个方法。

3. 解释器是什么

官方口径：解释器给 agent 一个进程内的、可编程的内存工作台（QuickJS，编译成 WebAssembly 跑在 wasmtime 里）。作用是让「循环、分支、重试、批量」发生在代码里，而不是靠模型一次次发工具调用。

默认给一个 eval 工具；代码里 console.log 会被捕获，返回最后一个表达式的值。

4. 两者怎么分工

要做的事
用哪个
跑 shell、装包、跑测试、改真实文件
沙箱
循环 / 分支 / 重试 / 数据变换（纯内存）
解释器
一两次简单外部调用
普通工具调用

四、原理拆解：为什么 agent 需要「代码里的循环」

模型一次可以发多个工具调用，但这一批是发出去就固定的：不能根据第一个结果决定第二个、不能重试、也不能把中间结果留在本地。每个结果都要回到上下文。所以「遍历 200 个文件」这种活，模型只会抽样做几十个。

解释器把编排搬进代码：eval 里写一个 for 循环，中间值留在 QuickJS 变量里，只有最终结果回到上下文。这就是官方说的「模型思考做什么，而不是每一步」。

沙箱解决的是另一个问题：副作用与隔离。代码要真的跑、要装包、要碰文件系统，就必须在隔离环境里，且不能带你的凭证。

一句话：解释器省上下文，沙箱保安全。

五、场景说明

  • 数据分析：解释器做聚合（把 500 行压成 5 行结论），沙箱不需要；
  • 代码任务：写代码 → 沙箱里 pytest → 失败回读日志，这是沙箱的主场；
  • 批量检索：解释器里 for 循环调 PTC 工具，并发跑完只回摘要；
  • 验收脚本：要跑本机命令做快速验证，用 LocalShellBackend，但只在受信环境；
  • 不该用解释器：需要读写真实文件、需要真实网络、需要 datetime——默认都不给。

步骤 4：最小可运行代码（干跑，不需要 key）

存成 execute_tool.py，uv run execute_tool.py。同一套写法换后端，看 execute 工具出不出现。

from langchain_core.language_models.fake_chat_models import FakeListChatModel
from deepagents import create_deep_agent
from deepagents.backends import FilesystemBackend, LocalShellBackend

seen = {}

class Recorder(FakeListChatModel):
    def bind_tools(self, tools, **kw):
        seen["tools"] = [getattr(t, "name", None) for t in tools]
        return self

root = r"C:\Windows\Temp\da06-root"
for label, backend in [
    ("filesystem", FilesystemBackend(root_dir=root, virtual_mode=True)),
    ("local_shell", LocalShellBackend(root_dir=root, virtual_mode=True)),
]:
    agent = create_deep_agent(model=Recorder(responses=["ok"]), backend=backend)
    agent.invoke({"messages": [{"role": "user", "content": "hi"}]})
    print(label, "→", seen["tools"])

be = LocalShellBackend(root_dir=root)
print(be.execute("echo hello-da"))

步骤 5：预期输出

filesystem → ['ls', 'read_file', 'write_file', 'edit_file', 'delete', 'glob', 'grep', 'task']
local_shell → ['ls', 'read_file', 'write_file', 'edit_file', 'delete', 'glob', 'grep', 'execute', 'task']
ExecuteResponse(output='hello-da\n', exit_code=0, truncated=False)

步骤 6：验证是否成功

  • 两个后端的工具表只差一个 execute——这就是「沙箱后端才给 shell」的可观测证据；
  • execute 返回 ExecuteResponse，字段是 output / exit_code / truncated；
  • 在 Windows 上 execute("ls") 会失败（默认走 cmd，没有 ls），要写 dir——这是本机对照的常见坑。

写法 A · 生产沙箱（LangSmith Sandbox）

from deepagents import create_deep_agent
from deepagents.backends.langsmith import LangSmithSandbox
from langsmith.sandbox import SandboxClient

client = SandboxClient()
ls_sandbox = client.create_sandbox()
backend = LangSmithSandbox(sandbox=ls_sandbox)

agent = create_deep_agent(
    model="openai:gpt-6.1-sol",
    backend=backend,
    system_prompt="你可以写代码并在沙箱里运行；装依赖前先说明要装什么。",
)
try:
    out = agent.invoke(
        {"messages": [{"role": "user", "content": "写个 hello 脚本并跑一遍"}]},
        config={"configurable": {"thread_id": "sb-1"}},
    )
    print(out["messages"][-1].content)
finally:
    client.delete_sandbox(ls_sandbox.name)

官方支持的其他 provider：E2B、Modal、Runloop、Vercel、AgentCore、Databricks、Daytona、NVIDIA OpenShell——各自一个后端类，写法同构。

写法 B · 解释器：把循环搬进代码

from langchain_quickjs import CodeInterpreterMiddleware
from deepagents import create_deep_agent

agent = create_deep_agent(
    model="openai:gpt-6.1-sol",
    middleware=[CodeInterpreterMiddleware(mode="turn")],
)
out = agent.invoke({
    "messages": [{"role": "user", "content": "把这三组数据按 team 汇总，只回汇总结果"}]
})

关键参数（官方表）：memory_limit 默认 64 MB、timeout 默认 5 秒、tool_name 默认 eval、max_result_chars 默认 4000、mode 默认 thread（跨轮）/ turn（轮内）/ call（每次全新 REPL）。

七、常见坑（官方明确限制/版本差异）

  1. 把 LocalShellBackend 当沙箱。它跑在你本机，等于把 shell 直接交给模型；只适合受信环境做验证。
  2. 以为权限能护住 execute。DA05 的规则只覆盖内置文件工具，shell 能绕过一切路径限制。
  3. 只防了沙箱、没防外泄。上下文注入 + 网络未封 = 数据可以被发出去；要按 provider 关网络。
  4. 沙箱不关。它按使用时长计费，finally 里必须 delete_sandbox。
  5. 解释器里访问 Date / fetch / 文件。默认全禁（无时钟、无网络、无文件系统）；要用就走 PTC 桥接。
  6. mode="thread" 后访问函数变量。快照只留可序列化数据，函数 / 类恢复后不可用，会报「not serializable」。
  7. 以为 PTC 调用也会走审批。官方明确：PTC 的工具调用不经过 interrupt_on 的逐调用审批——桥接的工具要自己选安全的那批。
  8. 解释器当生产沙箱。官方原话是「把它当作受限的解释器运行时，不是完整的生产沙箱」；恶意多租户还要加进程 / 容器隔离。

八、课后小结

  • 沙箱 = 后端 + execute；其余文件工具由 BaseSandbox 基于 execute 实现；
  • execute 工具按 SandboxBackendProtocol 条件出现，实测「fs 少一个 execute」就是证据；
  • 隔离不防上下文注入与网络外泄，要按 provider 配网络策略；
  • 解释器是 beta 的 QuickJS/wasmtime 内存工作台，默认零外部能力；
  • 解释器省上下文（中间值不出循环），沙箱保安全（副作用在隔离环境）。

九、思考题

1、为什么 BaseSandbox 只要求实现 execute？

参考回答：所有文件操作都能用 shell 脚本表达，接口收窄到一个方法，接新 provider 的成本最低，也让「有没有 shell」成为唯一的能力分界线。

2、什么任务你会选解释器而不是沙箱？

参考回答：中间结果多、需要循环/分支/重试、且不需要真实文件与网络的——例如批量聚合、结果校验、递归筛选。

3、沙箱都隔离了，为什么还要担心上下文注入？

参考回答：隔离保护的是你的机器，不是你的数据；被注入的 agent 可以在沙箱内把数据打包并发出去，除非网络被封。

4、mode="call" 适合什么？

参考回答：每次 eval 都要干净环境时——例如要求结果可复现、或防止上一轮的变量污染下一轮。
