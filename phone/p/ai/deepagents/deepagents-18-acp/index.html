18 在编辑器里用：ACP

换一个壳：编辑器出上下文与弹窗，agent 用 JSON-RPC 说话｜依据官方 ACP 文档与 deepagents-acp 0.1.0 源码自绘

版本不一致提示

  • 本篇基线是 deepagents-acp 0.1.0 + agent-client-protocol 1.1.0 + deepagents 0.7.42 + Python 3.13；ACP 集成是独立包，不在 SDK 里；
  • ACP ≠ MCP：ACP 管「agent 与编辑器怎么说话」，MCP 管「agent 怎么调外部工具」，两者方向相反；
  • 服务端默认 stdio：它从 stdin 读请求、往 stdout 写响应，由编辑器作为子进程拉起，不要自己再套一层 HTTP；
  • 面对面审批只走 ACP 的 request_permission，选项固定为 approve / reject /（会话内）always；自由格式的 interrupt() 会被直接拒（-32600）；
  • 需要 checkpointer：多轮会话与 Command(resume=...) 都靠它，InMemorySaver() 只适合本地试；
  • 本机实测只到 握手与建会话（initialize 返回 protocolVersion: 1、session/new 返回 sessionId）；session/prompt 要真模型才有内容，下面给了可复现的最小客户端。

一、学习目标

学完这一讲，你要能做到三件事：

  1. 说清 ACP 的三段结构：编辑器（client）、协议（JSON-RPC over stdio）、agent（server）；
  2. 把 DA16 那个工单 / 编码 agent 包成 ACP server，并在编辑器里跑起来；
  3. 让审批弹窗出现在编辑器里，而不是终端里，并知道哪些中断形式 ACP 表达不了。

二、前置知识

  • DA13 人工审批（interrupt_on 与 __interrupt__ 载荷，ACP 的弹窗就建在这上面）；
  • DA14 事件流（ACP 的 session/update 是它的又一次投影）；
  • DA15 上生产（cwd、会话、检查点这些概念在自托管里出现过）；
  • 知道 JSON-RPC 的 id / method / params 三段式，以及 stdio 是「行分隔」而不是「一问一答必须换行」。

三、理论讲解（官方定义）

1. 它解决什么问题

官方一句话：ACP 标准化「编码 agent 与编辑器 / IDE 之间」的通信。接上之后，你的自定义 deep agent 可以被任何 ACP 兼容客户端使用，编辑器负责提供项目上下文、显示富更新（diff、工具调用、计划），agent 只管干活。

这条链路的价值在「上下文从哪来」：终端里你要手敲 @file；编辑器里它天然知道当前打开的文件、选区、workspace 根目录，并通过 cwd 告诉 agent。

2. 三段结构与包

段
具体是什么
谁实现
client
Zed、JetBrains、VS Code（vscode-acp）、Neovim 插件
编辑器侧
protocol
JSON-RPC 2.0，stdio 行分隔
agent-client-protocol 1.1.0

注意依赖方向：deepagents-acp 依赖 agent-client-protocol 与 deepagents，不反向依赖。所以升级 SDK 不会自动升级 ACP 集成，反之亦然。

3. 服务端怎么构造

AgentServerACP 的构造签名（0.1.0 实测）：

AgentServerACP(agent, *, modes=None, models=None, load_sessions=False)
  • agent 可以是编译好的图，也可以是工厂函数 Callable[[AgentSessionContext], CompiledStateGraph]；
  • AgentSessionContext 只有三个字段：cwd、mode、model——这就是编辑器能告诉你的全部上下文入口；
  • modes 官方标注已废弃，改用 config options；models 用来把可选模型暴露给编辑器的模型选择器；
  • load_sessions=True 才允许客户端「恢复历史会话」。

启动方式就是把它交给 run_agent：

server = AgentServerACP(agent)
await run_agent(server)      # 默认从 stdin/stdout 说话

4. 一条 prompt 在服务端怎么变成编辑器里的画面

读 0.1.0 源码，prompt 的骨架是：

agent.astream(..., stream_mode=["messages", "updates"], subgraphs=True)
  • messages → agent_message_chunk / agent_thought_chunk（气泡与思考）；
  • 工具调用（含流式参数）→ tool_call、tool_call_update（卡片与状态）；
  • write_todos → plan 更新（编辑器侧的计划面板）；
  • updates 里的 __interrupt__ → session/request_permission（弹窗）。

所以 ACP 不是新协议栈，而是把 DA14 的三条投影翻译成编辑器认识的更新类型。

四、原理拆解：一次「改文件」的完整往返

  1. 用户在编辑器里发一句话，client 发 session/prompt，带上 sessionId 与内容块（文本 / 图片 / 资源引用）；
  2. server 把内容块转成 LangChain 消息，用 thread_id = sessionId 的 config 起 astream；
  3. 模型要调 write_file → server 发 tool_call（标题形如 Write `src/a.py` ）；
  4. interrupt_on 命中 → updates 里出现 __interrupt__ → server 发 session/request_permission，选项 approve / reject / always；
  5. 用户在编辑器点「Approve」→ client 回 optionId → server 把它翻成 {"type": "approve"}，用 Command(resume={"decisions": [...]}) 续跑；
  6. 工具落盘 → server 发 tool_call_update（completed）与 diff 内容 → 模型继续 → 最后 PromptResponse 带 stop_reason。

其中第 4 步有两个”坑位”是协议层面的，不是 bug：

  • 只有结构化中断能显示。自由格式 interrupt() 会抛 -32600，官方错误信息写得很清楚：「ACP 只支持固定决策的权限提示（approve/reject/edit）」；
  • write_todos 被特殊对待：初次建计划会弹「Review Plan」，计划进行中的更新则自动放行（否则每改一次 todo 都要人点一次）。

五、场景说明

  • 适合：你已经在用 Zed / JetBrains / VS Code，想让自己的 agent 在编辑器里带着项目上下文干活；
  • 适合：团队里想统一「同一个 agent、不同编辑器」，ACP 是那层公约数；
  • 不适合：只需要终端交互（用 DA17 的 dcode 更省事）；
  • 不适合：跨机器远程调用——stdio 是本地子进程模型，远程要走沙箱或 Agent Server；
  • 调试期：用 Toad 这类 ACP 客户端当「协议层 curl」，比每次开编辑器快。

六、示例代码

步骤 1：安装

uv add deepagents-acp
# 或者
pip install deepagents-acp

步骤 2：写服务端

存成 acp_server.py。这里用假模型，保证不花 token 也能验通协议：

import asyncio

from acp import run_agent
from langchain_core.language_models.fake_chat_models import GenericFakeChatModel
from langchain_core.messages import AIMessage
from langgraph.checkpoint.memory import MemorySaver

from deepagents import create_deep_agent
from deepagents_acp.server import AgentServerACP

model = GenericFakeChatModel(messages=iter([
    AIMessage(content="", tool_calls=[{
        "name": "write_file",
        "args": {"file_path": "/workspace/a.md", "content": "hi"},
        "id": "call_1",
    }]),
    AIMessage(content="done"),
]))

agent = create_deep_agent(
    model=model,
    system_prompt="test",
    checkpointer=MemorySaver(),
    interrupt_on={"write_file": {"allowed_decisions": ["approve", "reject"]}},
)

server = AgentServerACP(agent)
asyncio.run(run_agent(server))

步骤 3：写最小客户端（不装编辑器也能验协议）

ACP 是行分隔 JSON-RPC，所以用子进程 + 三行 JSON 就能握手：

import json, subprocess, threading, queue

p = subprocess.Popen([PY, "-u", "acp_server.py"],
                     stdin=subprocess.PIPE, stdout=subprocess.PIPE,
                     text=True, encoding="utf-8", bufsize=1)
q = queue.Queue()
threading.Thread(target=lambda: [q.put(l.rstrip()) for l in p.stdout], daemon=True).start()

def send(o):
    p.stdin.write(json.dumps(o) + "\n"); p.stdin.flush()

send({"jsonrpc": "2.0", "id": 1, "method": "initialize",
      "params": {"protocolVersion": 1, "clientCapabilities": {}}})
print(q.get(timeout=10))

send({"jsonrpc": "2.0", "id": 2, "method": "session/new",
      "params": {"cwd": r"./workspace", "mcpServers": []}})
print(q.get(timeout=10))

步骤 4：运行

python acp_server.py     # 单独跑会一直等 stdin，正常
python acp_client.py     # 另开一个终端跑客户端，看握手

步骤 5：预期输出（本机实测）

{"jsonrpc":"2.0","id":1,"result":{"protocolVersion":1,
 "agentCapabilities":{"loadSession":false,"promptCapabilities":{"image":true}}}}
{"jsonrpc":"2.0","id":2,"result":{"sessionId":"ef59f268f12b45e5855f00c80521c45f"}}

用不存在的 sessionId 发 session/prompt，会立刻回 -32603 Internal error——说明会话表是按 id 严格查的，不会给你新建一个隐式会话。

步骤 6：验证是否成功

  • initialize 回了 protocolVersion: 1，且 loadSession 与你构造时的 load_sessions 一致；
  • session/new 回了非空 sessionId，且 cwd 就是你传的那个目录；
  • 关掉客户端，服务端进程应随 stdin 关闭而退出（编辑器就是这么管它的）。

写法 A · 工厂 + cwd：让 agent 真的读写当前项目

from deepagents import create_deep_agent
from deepagents.backends import CompositeBackend, FilesystemBackend, StateBackend
from deepagents_acp.server import AgentServerACP, AgentSessionContext

def build_agent(context: AgentSessionContext):
    backend = CompositeBackend(
        default=FilesystemBackend(root_dir=context.cwd, virtual_mode=True),
        routes={
            "/memories/": StateBackend(),
            "/conversation_history/": StateBackend(),
        },
    )
    return create_deep_agent(
        model="anthropic:claude-sonnet-5",
        backend=backend,
        checkpointer=MemorySaver(),
        interrupt_on={"write_file": {"allowed_decisions": ["approve", "reject"]}},
    )

server = AgentServerACP(build_agent, load_sessions=True)

要点：FilesystemBackend(root_dir=context.cwd, virtual_mode=True) 把 agent 的虚拟根钉在编辑器给的目录上；/memories/ 走 StateBackend，避免把长期记忆写进用户仓库。

写法 B · 审批：让弹窗出现在编辑器里

interrupt_on = {
    "write_file": {"allowed_decisions": ["approve", "reject"]},
    "execute": {"allowed_decisions": ["approve", "reject"]},
}
  • 服务端会给 write_file 生成标题 Write `src/a.py` ，给 execute 生成 Execute: `pytest -q` ，编辑器直接显示；
  • 对 execute 会多给一个 Always allow this exact command in this session（按命令粒度记忆，不按工具粒度）；
  • 人点取消（不是拒绝）也按 reject 处理，且不会自动重试。

写法 C · 接编辑器

Zed 的 settings.json：

{
  "agent_servers": {
    "DeepAgents": {
      "type": "custom",
      "command": "/absolute/path/to/uv",
      "args": ["run", "python", "/absolute/path/to/acp_server.py"]
    }
  }
}

调试期用 Toad 更轻：

uv tool install -U batrachian-toad
toad acp "uv run python acp_server.py" .

官方还给了示例编码 agent（带文件系统与 shell），在 deepagents 仓库的 libs/acp 下，run_demo_agent.sh 可以直接注册进 Zed。

七、常见坑（官方明确限制/版本差异）

  1. 把 ACP 当 MCP。ACP 是「编辑器 ↔ agent」，MCP 是「agent ↔ 工具服务器」；方向反了，配置全错。
  2. 忘了 checkpointer。多轮与 resume 都靠它；不传就每次都是新图，审批恢复会报错。
  3. 用自由格式 interrupt()。ACP 直接 -32600 拒掉；必须用 interrupt_on 那种 action_requests / review_configs 结构。
  4. load_sessions 默认 false。想要「恢复上次会话」，构造时显式打开，否则编辑器里的历史按钮是灰的。
  5. 把 modes 当新 API。0.1.0 起它已标废弃，配置项要走 config options。
  6. 工厂里忽略 context.cwd。不把后端钉到 cwd，agent 会读写进程启动目录，编辑器里的「当前项目」形同虚设。
  7. 想远程调用。stdio 是本地子进程；远程要么走沙箱后端，要么走 Agent Server，不是 ACP 的职责。
  8. 只测握手就当跑通。握手只证明协议层通；session/prompt 还依赖模型、后端与审批三件都对。

八、课后小结

  • ACP 是三段结构：编辑器客户端、JSON-RPC over stdio、AgentServerACP；
  • 上下文入口只有 AgentSessionContext 的 cwd / mode / model，工厂函数是你把 cwd 钉进后端的唯一机会；
  • 编辑器里的画面 = DA14 三条投影的再投影：气泡、工具卡、计划面板；
  • 审批只支持固定决策，write_todos 有「进行中自动放行」的特例；
  • 迭代顺序：先 initialize / session/new 验协议，再上真模型验 prompt，最后接编辑器。

九、思考题

1、为什么 ACP 用 stdio 而不是 HTTP？

参考回答：agent 是编辑器拉起的本地子进程，stdio 天然一对一、生命周期跟着编辑器走，不用端口、不用鉴权；跨机器才需要另外的传输。

2、AgentSessionContext 只有三个字段，够用吗？

参考回答：够表达「在哪、什么模式、哪个模型」。其余上下文（打开的文件、选区）由 client 在 prompt 内容块里给，不放在 context 里，避免把协议做成 IDE 状态镜像。

3、为什么 write_todos 的计划更新可以自动放行？

参考回答：计划本身不是副作用，反复弹窗会让人本能点同意；只在「初次建计划」和「计划完成」这两个节点拦，才有审批的意义。

4、同一个 agent，终端和编辑器两个壳，审批逻辑要不要写两份？

参考回答：不用。审批写在 interrupt_on，壳只负责把中断翻译成自己的 UI；这正是 DA13 把审批放在工具层而不是 UI 层的原因。
