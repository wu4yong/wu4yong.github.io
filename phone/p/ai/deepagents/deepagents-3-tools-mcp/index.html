03 工具与 MCP

函数、@tool 对象、provider 内置 dict、MCP server —— 最后都变成同一张表｜依据官方 tools 页自绘

版本不一致提示

  • 本篇基线是 deepagents 0.7.42 + langchain 1.5.2 + Python 3.13；
  • tools= 接受四类东西：普通可调用、@tool 装饰的 BaseTool、provider 原生工具 dict（例如 {"type": "web_search"}）、以及 MCP 拿到的工具列表；
  • 工具 schema 由函数签名 + docstring 推断：docstring 写得糙，模型就不会用；
  • MCP 的连接类在 langchain.mcp 里（MCPAdapter），要装 langchain[mcp]；deepagents 自身不导出 MCP 符号（0.7.42 实测）；
  • 内置工具是 7 个文件工具 + task；沙箱后端才有 execute，普通后端不出现；
  • 白名单用 FilesystemMiddleware(tools=[...])，但 read_file 必须留着，否则创建时报 ValueError: read_file must be included in tools（实测）；
  • 内置工具名不要撞：你传一个叫 read_file 的工具会顶掉内置那个。

一、学习目标

学完这一讲，你要能做到三件事：

  1. 把四种来源的工具接进同一张表，并说清各自的适用场景；
  2. 用 MCPAdapter 接一个 MCP server，知道连接为什么要放在 async with 里；
  3. 工具变多时，用白名单与子代理把工具面收窄，而不是硬塞给模型。

二、前置知识

  • 读完 DA02 第一次跑通；
  • 知道 LangChain 工具的基本形态（LC05 工具）；
  • 本机有 uv；想真接 MCP 的话，手上要有一个 MCP server 地址。

三、理论讲解（官方定义）

1. 四种来源

来源
写法
适合

要自定义名称、描述、返回类型

2. schema 从哪来

官方明说：Deep Agents 从函数签名与 docstring 推断 schema，大多数情况下不用另写 schema。这意味着 docstring 不是注释，是给模型看的说明书——第一行说「做什么」，后面说「什么时候用、参数含义」。

3. 内置工具表（官方原文）

ls、read_file、write_file、edit_file、delete（0.7+）、glob、grep、execute（仅沙箱后端）、task。任务规划的 write_todos 要额外开 TodoListMiddleware（DA10）。

4. MCP 怎么接

官方写法是：

from langchain.mcp import MCPAdapter

config = {"mcpServers": {"my_server": {"url": "http://localhost:8000/mcp"}}}
async with MCPAdapter(config) as adapter:
    tools = await adapter.list_tools()

连接在 async with 里开、退出即断；list_tools() 拿到的是标准 LangChain 工具，直接塞进 tools=。

四、原理拆解：工具表就是模型的「能力边界」

模型看不到你的代码，它只看到一张表：名字 + 一句话描述 + 参数 schema。所以工具设计的三条原则都从这张表来：

  1. 名字要能猜：query_order_by_id 比 q1 好一百倍；
  2. 描述要写「何时用」："查订单状态" 不够，要写「用户问订单到哪了、要物流进度时用」；
  3. 表要短：每个工具都占上下文，也都增加选错概率。

工具表还有一个隐藏作用：它就是权限边界。模型只能用表里的工具，表外的能力它没法「想办法」调用——这也是为什么收窄工具面比写一堆「不要做 X」的提示更有效。

五、场景说明

  • 检索类：web_search（provider 内置最省事）、内部知识库查询（函数）；
  • 事务类：下单、退款、改状态——这类工具建议配审批（DA13），不要裸给；
  • MCP 类：公司已有工具网关、SaaS 官方 server（GitHub / Slack / 数据库）；
  • 不该进表的：一次性的调试脚本、返回巨量数据且不落盘的查询（应该改成「落盘 + 回路径」，见 DA09）。

步骤 4：最小可运行代码（干跑，不需要 key）

存成 tool_table.py，uv run tool_table.py。三段分别验证：自定义工具进表、白名单收窄、漏 read_file 报错。

from langchain_core.language_models.fake_chat_models import FakeListChatModel
from langchain_core.tools import tool
from deepagents import create_deep_agent
from deepagents.middleware import FilesystemMiddleware

seen = {}

class Recorder(FakeListChatModel):
    def bind_tools(self, tools, **kw):
        seen["tools"] = [
            getattr(t, "name", None) if not isinstance(t, dict) else t.get("name")
            for t in tools
        ]
        return self

def query_order(order_id: str) -> str:
    """按订单号查状态。用户问「我的订单到哪了」时使用。"""
    return '{"status": "shipping"}'

@tool
def refund(order_id: str, reason: str) -> str:
    """发起退款。仅在用户明确要求退款、且订单未发货时使用。"""
    return "refund-requested"

def build(middleware=None):
    return create_deep_agent(
        model=Recorder(responses=["ok"]),
        tools=[query_order, refund],
        middleware=middleware or [],
    )

build().invoke({"messages": [{"role": "user", "content": "hi"}]})
print("全量工具表:", seen["tools"])

build([FilesystemMiddleware(tools=["ls", "read_file", "grep"])]).invoke(
    {"messages": [{"role": "user", "content": "hi"}]}
)
print("白名单后:", seen["tools"])

try:
    build([FilesystemMiddleware(tools=["ls"])])
except ValueError as e:
    print("漏 read_file:", e)

步骤 5：预期输出

全量工具表: ['ls', 'read_file', 'write_file', 'edit_file', 'delete', 'glob', 'grep', 'task', 'query_order', 'refund']
白名单后: ['ls', 'read_file', 'grep', 'task', 'query_order', 'refund']
漏 read_file: read_file must be included in tools; it is required by FilesystemMiddleware

步骤 6：验证是否成功

  • 全量表里有 8 个内置 + 你传的 2 个；
  • 白名单后文件工具只剩 3 个，但 task 还在（子代理是独立中间件，不在这个白名单里）；
  • 第三段报的 ValueError 就是官方的硬约束：read_file 不能删。

写法 A · 接一个 MCP server

import asyncio
from deepagents import create_deep_agent
from langchain.mcp import MCPAdapter

async def main():
    config = {"mcpServers": {"kb": {"url": "http://localhost:8000/mcp"}}}
    async with MCPAdapter(config) as adapter:
        tools = await adapter.list_tools()
        agent = create_deep_agent(
            model="openai:gpt-6.1-sol",
            tools=tools,
            system_prompt="先查 kb 再回答，不要凭空猜。",
        )
        await agent.ainvoke(
            {"messages": [{"role": "user", "content": "帮我查一下退款政策"}]},
            config={"configurable": {"thread_id": "mcp-1"}},
        )

asyncio.run(main())

async with 退出后连接关闭，所以 ainvoke 必须在块内。

写法 B · 只给子代理看一部分工具

工具太多时，最有效的收窄方式不是白名单，而是把工具分给子代理（DA11 详讲）：

research = {
    "name": "researcher",
    "description": "只做检索与抓网页，不做写入",
    "system_prompt": "你是检索员，找到资料就落盘到 /workspace/notes，不要总结。",
    "tools": [internet_search, fetch_page],
}
agent = create_deep_agent(
    model="openai:gpt-6.1-sol",
    tools=[write_summary],          # 主代理只留交付工具
    subagents=[research],
)

主代理的工具表因此只剩 write_summary + 内置 8 个，选错率大幅下降。

七、常见坑（官方明确限制/版本差异）

  1. 工具名撞内置。传一个叫 read_file 的工具会覆盖内置实现，路径语义全乱。
  2. docstring 只写一句「查询」。模型不会知道「什么时候该用」，表现为该查的时候不查。
  3. 返回巨大字符串。几万字的工具结果会把上下文打满；应该落盘、只回路径（DA09）。
  4. MCP 连接没关。忘记 async with（或手动 close()），进程里会挂着一堆连接。
  5. 白名单删掉 read_file。创建即报 ValueError（本篇实测）。
  6. 把危险工具裸给主代理。退款、删除、发消息这类工具要么给子代理，要么配 interrupt_on（DA13）。
  7. 一次给 20 个工具。实测经验：单 agent 超过 8–10 个业务工具后，选错工具的概率明显上升【实践补充，非官方文档内容】。
  8. 以为 task 也受白名单约束。FilesystemMiddleware(tools=...) 只管文件工具，task 归子代理中间件。

八、课后小结

  • 四种来源最后都是一张表：函数、@tool、provider dict、MCP；
  • schema 靠签名 + docstring，docstring 是写给模型看的；
  • 内置 7 文件工具 + task，execute 只在沙箱后端出现；
  • MCP 用 langchain.mcp.MCPAdapter，连接在 async with 内；
  • 收窄工具面的优先级：子代理 > 白名单，且 read_file 必须留。

九、思考题

1、为什么说「收窄工具面」比「写一堆不要做 X 的提示」更有效？

参考回答：模型只能调用表里的工具，表外的能力它根本没有通道；而提示是软约束，会被长上下文稀释。

2、MCP 工具和普通函数工具在 agent 眼里有区别吗？

参考回答：没有。list_tools() 返回的就是标准 LangChain 工具，进表后与函数工具同权；区别只在连接生命周期与鉴权。

3、白名单里为什么必须保留 read_file？

参考回答：文件中间件的其他工具（edit_file、grep 后回读等）都依赖它，删掉会让中间件无法工作，所以创建时直接报错。

4、一次任务里工具超过 10 个，你会怎么拆？

参考回答：按阶段拆子代理（检索 / 处理 / 交付），主代理只留调度与交付工具；每个子代理工具 ≤ 3 个。
