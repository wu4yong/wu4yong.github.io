00 系列目录与学习路线

16 讲 · 5 模块：定位 → 执行环境 → 上下文 → 委派 → 控制与交付｜以 Deep Agents 0.7.x 为基线自绘

版本不一致提示

  • 本篇基线是 deepagents 0.7.42 + langchain 1.5.2 + langgraph 1.2.24 + langsmith 0.16.2 + Python 3.13；deepagents 依赖 langchain>=1.5.2，所以 LC 系列的写法在这里同样成立；
  • 0.7 是两个行为的分水岭：任务规划（write_todos）从默认内置改成显式 opt-in（要自己传 TodoListMiddleware）；delete 工具是 0.7 才有的，且后端不支持删除时会对模型自动隐藏；
  • 默认文件后端是 StateBackend：文件活在线程 state 里，换 thread 即消失；要跨线程必须换 StoreBackend，要落本地磁盘换 FilesystemBackend；
  • permissions= 只管内置文件工具，对沙箱后端的 execute 无效；规则按声明顺序 first-match-wins，无命中即放行；
  • 沙箱后端在官方文档里叫 SandboxBackendProtocolV2，0.7.42 代码里的类名是 SandboxBackendProtocol，两者是同一件事；
  • 示例统一 uv add deepagents + uv run；没有模型 key 时给「本地断言照跑、只跳过模型调用」的降级写法，不假装跑通。

一、一句话定位

LangChain 系列讲「怎么用一张装好的 Agent」，LangGraph 系列讲「底下那台运行时怎么自己搭」，LangSmith 系列讲「怎么知道它跑得好不好」。这套讲第四件事：把前三件事打包成一个能干长活的骨架（harness）。

学完的目标不是「知道 create_deep_agent 有多少参数」，而是面对一个真实的长任务，能判断该开哪几层能力、每层的代价是什么、出事时该去哪一层查。

二、三条口径先说清

  1. 只讲 harness 层。create_agent、StateGraph、checkpointer、dataset / evaluator 都不复述，需要时一句「见 LCxx / LGxx / LSxx」带过。
  2. 官方文档是唯一权威。凡是「官方没写、我补的」都标【实践补充，非官方文档内容】；官方文档与 0.7.42 代码对不上时，以代码实测结果为准并注明。
  3. 不写「跑个 demo」的教程。每讲都给判据：这一层什么时候该开、什么时候是纯浪费 token。

三、学习路线

  • M0 定位与起步（2 讲）：先分清框架 / 运行时 / harness 三层，再跑通第一条带文件系统与 task 工具的 agent。前置：无（最好读过 LC05、LG01）。
  • M1 执行环境（4 讲）：工具与 MCP、四种文件后端、权限规则、沙箱与解释器。前置：M0。
  • M2 上下文管理（3 讲）：Skills 按需加载、AGENTS.md 长期记忆、压缩与卸载。前置：M1。这三是「能干长活」的真正原因，别跳。
  • M3 委派与编排（3 讲）：任务清单、子代理、异步与动态子代理。前置：M2。
  • M4 控制与交付（4 讲）：人工审批、事件流、两种上线跑法、综合实战。前置：M3 + LS06–LS08。

顺序 M0 → M4 不跳。理由很实在：M2 的三件能力都建在「虚拟文件系统」上，而 M1 没读，M2 的代码你连落盘都看不到。

一个判断口诀：任务只有一两步、工具不超过三个，就别上 harness。harness 的成本是「每轮多几千 token 的系统提示 + 多几层工具」，小任务付不起。

七、怎么读这套课

  • 先跑通再回头：每讲六步代码都能单独 uv run；没有模型 key 时用第 6 步的干跑脚本看结构；
  • 先看 trace 再改 prompt：子代理、文件工具都会在 trace 里各成一段，链路不对时改 prompt 只是让错得更顺；
  • 不背 API：真正要记的只有四个入口——create_deep_agent、backend、subagents、interrupt_on，其余用到再查；
  • 能力是加法，不是默认：0.7 起规划要手动开，别照着老文章以为它自带。
