07 技能包

启动只进「名字 + 描述」，命中任务才读正文，脚本最后读｜依据官方 skills 页自绘

版本不一致提示

  • 本篇基线是 deepagents 0.7.42 + langchain 1.5.2 + Python 3.13；
  • skills= 接的是源目录（容器），不是技能目录本身：传 /skills/ 才对，传 /skills/pdf-extract/ 会静默发现 0 个技能；
  • 技能目录里必须有 SKILL.md，frontmatter 的 name 必须与目录名一致，否则不加载；
  • 默认 StateBackend 下技能文件要用 create_file_data() 塞进 invoke(files={...})；裸字符串不支持；
  • SKILL.md 超过 10 MB 会被跳过（不是报错）；正文建议 < 5000 token / < 500 行；
  • 系统提示里只出现 name + description（实测原文形如 - **pdf-extract**: … → Read /skills/pdf-extract/SKILL.md），正文靠 read_file 按需读。

一、学习目标

学完这一讲，你要能做到三件事：

  1. 写一个能被正确发现、正确激活的 SKILL.md；
  2. 用 skills= 把技能挂到 agent 上，并验证「系统提示只有元数据」；
  3. 判断一件事该做成技能、记忆还是工具。

二、前置知识

  • 读完 DA06 沙箱与解释器；
  • 会读写 markdown，知道 YAML frontmatter 是什么；
  • 后端概念还记得（DA04）：技能文件放在哪个后端，决定它是否跨线程。

三、理论讲解（官方定义）

1. 技能是什么

官方定义：技能把流程、最佳实践、脚本、参考文档、模板打包成一个目录，agent 启动时只拿到摘要，相关内容时才读全文。

一个技能 = 一个目录 + 一个 SKILL.md（YAML frontmatter + 指令正文），可选 scripts/、references/、assets/。

2. 三层渐进披露

层
加载什么
什么时候
L1 元数据
name + description
启动时，每个技能都进系统提示
L2 指令
SKILL.md 全文
技能被激活时，用 read_file 读
L3 资源
scripts/、references/、assets/
指令引用到时才读

实现在 SkillsMiddleware：它负责第 1、2 层的发现与注入；第 3 层由模型自己按指令去读。

3. frontmatter 字段

必需两个：name（小写字母数字 + 连字符，1–64 字符，必须等于目录名）、description（≤1024 字符，写清「做什么 + 何时用」）。可选：license、compatibility、metadata、allowed-tools（实验）。

四、原理拆解：为什么是「描述」决定一切

第 1 层只把 description 放进系统提示。模型看到的就是这一句话，它据此决定「要不要读这个技能」。所以：

  • 描述写得空（”Helps with PDFs”）→ 模型不知道何时用；
  • 两个技能描述重叠 → 模型在两个之间犹豫，或者选错；
  • 描述写得具体（”提取 PDF 文本与表格、填表单、合并 PDF；用户提到 PDF / 表单 / 文档抽取时使用”）→ 命中率高。

第 2 层之后才是正文，所以正文可以长，但官方仍建议 < 5000 token：激活一次就要占一次上下文。更细的内容挪到 references/，正文只写「什么时候去读哪个文件」。

五、场景说明

  • 适合做成技能：发布流程、报表口径、代码规范检查步骤、某类文档的提取流程；
  • 适合做成记忆（DA08）：每次都要遵守的团队约定、称呼偏好；
  • 适合做成工具：真正要执行的动作（查库、发消息、跑脚本的入口）；
  • 不适合：一次性的临时指令、只有一句话的提示（直接写进 system_prompt 更省事）。

import itertools

from langchain_core.messages import AIMessage
from deepagents import create_deep_agent
from deepagents.backends.utils import create_file_data

步骤 4：最小可运行代码（干跑，不需要 key）

存成 skills_check.py，uv run skills_check.py。用假模型截获系统提示，验证「只有元数据进提示」。

import itertools
from langchain_core.language_models.fake_chat_models import GenericFakeChatModel
from langchain_core.messages import AIMessage
from deepagents import create_deep_agent
from deepagents.backends.utils import create_file_data

SKILL = """---
name: pdf-extract
description: Extract text and tables from PDF files. Use when the user mentions PDF, forms, or document extraction.
---
# pdf-extract
1. 用 read_file 读 PDF 摘要。
2. 表格结果写到 /notes/tables.md。
"""

captured = {}

class Capture(GenericFakeChatModel):
    def bind_tools(self, tools, **kw):
        return self
    def _generate(self, messages, *a, **kw):
        sys_msg = messages[0].content
        captured["sys"] = sys_msg if isinstance(sys_msg, str) else "".join(
            b.get("text", "") if isinstance(b, dict) else str(b) for b in sys_msg
        )
        return super()._generate(messages, *a, **kw)

files = {"/skills/pdf-extract/SKILL.md": create_file_data(SKILL)}
agent = create_deep_agent(
    model=Capture(messages=itertools.cycle([AIMessage(content="ok")])),
    skills=["/skills/"],
)
agent.invoke(
    {"messages": [{"role": "user", "content": "hi"}], "files": files},
    config={"configurable": {"thread_id": "sk-1"}},
)

print("有元数据:", "**pdf-extract**" in captured["sys"])
print("有正文:", "表格结果写到 /notes/tables.md" in captured["sys"])
print("有读取指引:", "/skills/pdf-extract/SKILL.md" in captured["sys"])

步骤 5：预期输出

有元数据: True
有正文: False
有读取指引: True

步骤 6：验证是否成功

  • 元数据在 → 发现成功；
  • 正文不在 → 渐进披露生效（没被激活就不读）；
  • 读取指引在 → 模型知道该 read_file 哪个路径。

写法 A · 接一个真实 agent

agent = create_deep_agent(
    model="openai:gpt-6.1-sol",
    skills=["/skills/"],
    system_prompt="遇到 PDF 类任务先查技能库，按技能步骤执行。",
)
out = agent.invoke(
    {"messages": [{"role": "user", "content": "把这份 PDF 里的表格抽出来"}], "files": files},
    config={"configurable": {"thread_id": "sk-2"}},
)

模型命中描述后会 read_file("/skills/pdf-extract/SKILL.md", limit=1000) 再按步骤执行。

写法 B · 用 FilesystemBackend 放技能（跨线程可用）

from deepagents.backends import FilesystemBackend

# 把 skills/ 目录放到 ./work/skills/ 下（虚拟路径就是 /skills/）
be = FilesystemBackend(root_dir="./work", virtual_mode=True)
agent = create_deep_agent(model="openai:gpt-6.1-sol", backend=be, skills=["/skills/"])

virtual_mode=True 会把 /skills/ 映射到 ./work/skills/，技能目录原样落盘即可。

StateBackend 的技能只活在当前线程；要跨线程就落盘或进 store。

七、常见坑（官方明确限制/版本差异）

  1. skills= 指到技能目录本身。传 /skills/pdf-extract/ 不报错，但发现 0 个技能——因为只扫源目录下的子目录。
  2. name 与目录名不一致。直接不加载，且没有明显报错。
  3. description 写得太虚。这是模型唯一能看到的匹配依据，虚就等于没写。
  4. 正文写超长。官方建议 < 5000 token；超过 10 MB 的 SKILL.md 会被跳过。
  5. 用裸字符串塞技能文件。StateBackend 必须用 create_file_data()，否则格式不对。
  6. 资源引用多层嵌套。官方建议引用只比 SKILL.md 深一层，否则模型要读好几跳才拿到信息。
  7. 技能互斥不清。同类能力合并成一个技能、用章节分；两个描述重叠会让模型选错。
  8. 技能里塞密钥。技能是文本，会被读进上下文；凭证走环境变量。

八、课后小结

  • 技能 = 目录 + SKILL.md；skills= 传的是源目录；
  • 三层：元数据常驻、正文按需、资源最后；
  • description 决定命中率，name 必须等于目录名；
  • 默认后端下技能只活当前线程，要跨线程就落盘 / 进 store；
  • 常驻规则进记忆，按需流程进技能，动作进工具。

九、思考题

1、为什么元数据要常驻，正文不常驻？

参考回答：元数据只有一两行，成本低且能帮模型判断相关性；正文可能几千 token，没命中就白占。

2、一个技能写了 800 行，应该怎么改？

参考回答：主文件压到 500 行内，细节拆到 references/，并在正文里明确「何时读哪个参考文件」。

3、技能和 system_prompt 的边界在哪？

参考回答：每次都要遵守的短规则进 system_prompt / 记忆；分场景、分步骤、可能很长的流程进技能。

4、同一份技能想给多个 agent 用，放哪？

参考回答：放到共享的文件系统或 store 命名空间（例如 ("skills","builtin")），各 agent 用同一个 skills=["/skills/"] 指向它。
