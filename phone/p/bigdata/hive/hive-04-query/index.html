HQL 查询与窗口函数

日常取数绝大多数时间花在 SELECT 上：表怎么连、分组怎么聚合、排名和累计指标怎么算。HQL 语法对齐标准 SQL，但底层是分布式作业，Join 方式、分组限制和窗口帧的语义都和单机数据库有差别。这一篇把查询骨架、Map Join、分组聚合、窗口函数与 lateral view 讲清楚。

算子链条沿光带依次展开，多路数据在连接节点汇合，窗口按分区切片后做排名与累计聚合

1.1 查询骨架与执行顺序

一条典型 HQL 的书写顺序如下，理解时要按底层执行顺序倒过来读：

SELECT user_id, dt, COUNT(*) AS pv, SUM(amount) AS gmv
FROM dwd.order_daily
WHERE dt >= '2022-01-13'
GROUP BY user_id, dt
HAVING COUNT(*) > 10
ORDER BY gmv DESC
LIMIT 100;

一个硬性限制：SELECT 里出现的非聚合列，必须全部出现在 GROUP BY 中。这和部分宽松数据库允许随便选列不同，Hive 会直接报解析错误。

1.2 Join 的几种类型

Hive 支持标准的内连接与外连接：

-- 内连接：只保留两表都匹配的行
SELECT o.order_id, u.user_name
FROM dwd.`order` o
JOIN dim_user u ON o.user_id = u.user_id;

-- 左外连接：左表全保留，右表不匹配补 NULL
SELECT o.order_id, u.user_name
FROM dwd.`order` o
LEFT JOIN dim_user u ON o.user_id = u.user_id;

-- 全外连接：两表全保留，不匹配侧补 NULL
SELECT o.order_id, u.user_name
FROM dwd.`order` o
FULL OUTER JOIN dim_user u ON o.user_id = u.user_id;

1.3 Map Join：小表广播，避免 shuffle

普通 Join 要按连接键做 shuffle，两侧数据都拉到 reducer 上分组连接。如果其中一张是维表、体量很小，可以把小表广播到每个计算节点，本地直接和大表关联，省掉 shuffle，这就是 Map Join（也叫 Broadcast Join）。

开启方式有两种：自动转换与语句级提示：

# 自动 Map Join：小表体积低于阈值时自动广播
hive.auto.convert.join=true
# 广播表的最大体积，单位字节，示例为 25MB
hive.mapjoin.smalltable.filesize=25000000
-- 语句级提示：指定 dim_user 作为被广播的小表
SELECT /*+ MAPJOIN(u) */ o.order_id, u.user_name
FROM dwd.`order` o
JOIN dim_user u ON o.user_id = u.user_id;

判断原则：小表适合广播，大表广播会把内存撑爆甚至拖垮任务。两张都是大表时，老老实实地走 shuffle Join，靠分桶、列裁剪和压缩控制成本。

1.4 分组与聚合

常用聚合函数与标准 SQL 一致：COUNT、SUM、AVG、MAX、MIN，配合 GROUP BY 使用。

SELECT channel,
       COUNT(*)              AS pv,
       COUNT(DISTINCT uid)   AS uv,
       SUM(amount)           AS gmv,
       AVG(amount)           AS avg_order
FROM dwd.order_daily
WHERE dt = '2022-01-13'
GROUP BY channel;

几个分布式场景下的注意点：

  • COUNT(DISTINCT col) 去重需要把同值行聚到一起，高基列上成本很高；必要时先按列去重再 COUNT。
  • GROUP BY 的列尽量低基，分组数过多会造成 reducer 倾斜，这一点在调优篇展开。
  • HAVING 只能过滤聚合结果，行级条件写 WHERE，别把下推过滤提到 Having 里。

1.5 窗口函数：分组内排名与累计

窗口函数在不折叠行的前提下，给每行挂上分组内的聚合或排名结果，是取数里最常用也最容易写错的部分。基本结构：

函数名(参数) OVER (
  [PARTITION BY 分组列]
  [ORDER BY 排序列]
  [窗口帧 ROWS BETWEEN ...]
)
函数
作用
典型场景
ROW_NUMBER()
连续编号，不并列
取每个用户最新一笔订单

并列占名次，后续跳号
比赛排名
DENSE_RANK()
并列占名次，后续不跳号

示例：每个渠道按金额排名，并计算累计 GMV：

SELECT channel,
       order_id,
       amount,
       ROW_NUMBER() OVER (PARTITION BY channel ORDER BY amount DESC) AS rn,
       SUM(amount) OVER (
         PARTITION BY channel
         ORDER BY amount DESC
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS cum_gmv
FROM dwd.order_daily
WHERE dt = '2022-01-13';

窗口帧（Window Frame）决定累计范围：UNBOUNDED PRECEDING 表示从分区第一行开始，CURRENT ROW 表示到当前行；不写 ORDER BY 时，默认帧覆盖整个分区。

取每个用户最新一笔订单的经典写法：

SELECT user_id, order_id, amount, login_ts
FROM (
  SELECT user_id, order_id, amount, login_ts,
         ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_ts DESC) AS rn
  FROM dwd.order_login
) t
WHERE rn = 1;

1.6 lateral view：把数组和列拆开

表里常见数组、Map 类型字段，一行要拆成多行时用 LATERAL VIEW 配合 EXPLODE：

-- tags 是数组字段，炸开后每行一个标签
SELECT user_id, tag
FROM dwd.user_profile
LATERAL VIEW EXPLODE(tags) t AS tag;
写法
输入
输出
EXPLODE(数组)
一行多元素数组
每个元素一行
EXPLODE(Map)
一行键值对 Map
每个键值一行
LATERAL VIEW
原表 + 炸裂结果
列对应展开后的行

一个表可以挂多个 LATERAL VIEW，分别拆开不同字段；字段为 NULL 或空数组时该行不会出现在结果里，下游统计要注意口径。

1.7 容易踩的坑

  • SELECT 列没进 GROUP BY：非聚合列必须出现在分组列里，否则解析报错，这是 Hive 与宽松数据库最常见的差异。
  • 大表被广播成 Map Join：广播表体积超过阈值会撑爆节点内存，自动转换要配合小表阈值使用。
  • ORDER BY 全局排序走单 reducer：大结果集全局排序会集中到一个节点，慢任务优先用 SORT BY 做节点内排序，或分区后再排。
  • lateral view 丢空行：NULL 或空数组被炸裂后不产出行，涉及留存、覆盖类指标时要核对口径。

1.9 清单

  1. HQL 书写顺序是 SELECT→FROM→WHERE→GROUP BY→HAVING→ORDER BY，底层执行按 FROM 起倒序
  2. 非聚合列必须全部进 GROUP BY；行级条件走 WHERE，聚合结果过滤走 HAVING
  3. Map Join 广播小表省 shuffle，大表不能广播；自动转换受 hive.mapjoin.smalltable.filesize 阈值控制
  4. 窗口函数 PARTITION BY 分组、ORDER BY 排序、窗口帧限定累计范围；排名用 ROW_NUMBER/RANK/DENSE_RANK
  5. LATERAL VIEW EXPLODE 把数组、Map 拆成多行，空值与空数组不产出行，统计口径要核对
  6. 全局 ORDER BY 收敛到单 reducer，大结果集先节点内排序；高基去重先拆出去重步骤
