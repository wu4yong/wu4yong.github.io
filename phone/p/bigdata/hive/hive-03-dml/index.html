Hive（三）数据加载与导出

分类：bigdata · hive ｜ 标签：Hive

数据加载与导出

表建好了，数据怎么进去、结果怎么出来，是日常 ETL 最频繁的操作。Hive 没有关系库那种随手 INSERT VALUES 的用法，数据入口主要是 LOAD DATA 和 INSERT，跨表迁移走 EXPORT/IMPORT。这一篇把每条语句的来源、去向和覆盖语义讲清楚，避免一批数据被覆盖或搬错位置。

数据流从本地与分布式存储两侧汇入表目录，结果沿分区树写出，迁移通道单独把元数据与文件打包带走

1.1 数据加载：LOAD DATA

LOAD DATA 是最直接的入库方式，它本身不做格式校验之外的转换，核心是把文件放进表目录。语法上分本地路径与 HDFS 路径两种来源：

-- 从客户端本地文件系统加载，文件被复制到表目录
LOAD DATA LOCAL INPATH '/tmp/access.log'
OVERWRITE INTO TABLE ods.access_log
PARTITION (dt='2022-01-06', channel='app');

-- 从 HDFS 路径加载，原文件被移动到表目录（不是复制）
LOAD DATA INPATH '/staging/access/2022-01-06/'
OVERWRITE INTO TABLE ods.access_log
PARTITION (dt='2022-01-06', channel='app');

OVERWRITE 决定冲突语义：带上它会先清掉目标表或目标分区已有数据再写入；不带则是追加。加载到分区表时，分区在语句里显式指定，属于静态分区。

1.2 结果写出：INSERT OVERWRITE 与 INSERT INTO

INSERT 把查询结果落到表或分区，分覆盖与追加两种语义：

-- 覆盖写入整表：重跑任务时先清空旧结果
INSERT OVERWRITE TABLE dwd.order_daily
SELECT dt, channel, COUNT(*) AS pv, SUM(amount) AS gmv
FROM ods.access_log
GROUP BY dt, channel;

-- 追加写入：保留已有数据，只新增一批
INSERT INTO TABLE dwd.order_daily
SELECT dt, channel, COUNT(*) AS pv, SUM(amount) AS gmv
FROM ods.access_log
WHERE dt = '2022-01-06'
GROUP BY dt, channel;

Hive 还支持一次扫描、多表插入（Multi-Insert），避免同一份源数据被重复读取：

FROM ods.access_log
INSERT OVERWRITE TABLE dwd.login_app
  SELECT user_id, login_ip, device WHERE channel = 'app'
INSERT OVERWRITE TABLE dwd.login_web
  SELECT user_id, login_ip, device WHERE channel = 'web';

1.3 动态分区：按查询结果自动落目录

上一篇的分区在 LOAD 语句里手写死，叫静态分区；如果分区值来自查询结果本身，就需要动态分区。写入时引擎按结果行的分区列值自动创建对应目录。

-- 分区列 dt、channel 来自 SELECT 结果，不在语句里指定固定值
INSERT OVERWRITE TABLE dwd.access_daily
PARTITION (dt, channel)
SELECT ip, url, uid, dt, channel
FROM ods.access_log
WHERE dt >= '2022-01-06';

动态分区必须打开相应配置，否则语句直接报错（hive-site.xml 或会话级 SET）：

# 开启动态分区，默认关闭
hive.exec.dynamic.partition=true
# 分区模式：strict 要求至少一个静态分区，none/nonstrict 才允许全动态
hive.exec.dynamic.partition.mode=nonstrict
# 单语句可创建的最大动态分区数，防止一次任务刷出海量目录
hive.exec.max.dynamic.partitions=2000
# 每个节点可创建的动态分区数
hive.exec.max.dynamic.partitions.pernode=100

两条容易混淆的规则：

  • 默认模式是 strict：只写动态分区、没有任何静态分区列时会被拦下，必须显式改成 nonstrict。
  • 动态分区列必须放在 SELECT 列表最后，顺序与 PARTITION (...) 声明一一对应，位置错位会导致分区值串行。

1.4 跨表迁移：EXPORT 与 IMPORT

EXPORT 把表或分区的数据文件连同元数据一起导出到 HDFS 目录，IMPORT 再还原回来，这是跨集群搬 Hive 表的标准方式：

-- 导出整表：数据与表结构元信息打包到指定目录
EXPORT TABLE dwd.order_daily
TO '/backup/dwd/order_daily';

-- 只导出某个分区
EXPORT TABLE ods.access_log
PARTITION (dt='2022-01-06')
TO '/backup/ods/access_log/dt=2022-01-06';

-- 导入到新集群，表不存在则按元数据重建
IMPORT TABLE dwd.order_daily
FROM '/backup/dwd/order_daily';

注意 EXPORT 出来的目录里除了数据文件，还有一份元数据描述（_metadata），不能只挑数据文件拷走，否则导入时缺少表结构信息。

1.5 导出到外部

查询结果要落到 HDFS 文本或给下游文件消费时，常用两种方式：

-- 导出查询结果到 HDFS 目录，每个 reducer 一个文件
INSERT OVERWRITE DIRECTORY '/export/order_daily'
ROW FORMAT DELIMITED FIELDS TERMINATED BY ','
SELECT dt, channel, pv, gmv FROM dwd.order_daily;

命令行层面还可以用 hive -e "SELECT ..." > result.csv 把标准输出重定向到本地文件，适合小结果集；大结果集走目录导出，避免客户端成为瓶颈。

1.6 容易踩的坑

  • LOAD DATA INPATH 是移动不是复制：原 HDFS 路径会消失，调度重跑时找不到 staging 文件属于正常语义，不要当成丢数据。
  • 漏写 OVERWRITE 导致重复堆积：汇总层重跑任务必须用 INSERT OVERWRITE，否则旧结果和新结果混在同一分区。
  • 动态分区没开配置：默认关闭且为 strict，全动态写入会直接失败；上线前先确认会话与 hive-site.xml 两套配置。
  • 分区列顺序错位：SELECT 末尾的分区列与 PARTITION 声明顺序不一致，会出现分区值串列且不容易一眼看出。
  • 动态分区刷爆目录：高基字段做分区键时，一次任务可能创建上万目录，元数据与 NameNode 都会承压，要限制分区数或改分桶。
  • 只拷数据文件不拷元数据：跨集群迁移只搬 EXPORT 目录里的文件，丢掉 _metadata，IMPORT 无法还原表结构。

1.8 清单

  1. LOAD DATA LOCAL 复制本地文件，LOAD DATA INPATH 移动 HDFS 文件；OVERWRITE 先清目标再写入
  2. INSERT OVERWRITE 用于全量重跑，INSERT INTO 用于增量追加；Multi-Insert 一次扫描分流多张表
  3. 动态分区需要 hive.exec.dynamic.partition=true，模式设为 nonstrict，分区列放在 SELECT 末尾且顺序对应
  4. EXPORT/IMPORT 同时搬运数据文件与元数据，是跨集群迁移的标准方式，不能只拷数据文件
  5. 大结果集导出到 HDFS 目录，小结果集用命令行重定向；分区数量要在参数里设上限
  6. 汇总层重跑务必覆盖写，动态分区避免高基字段，防止目录与小文件失控
