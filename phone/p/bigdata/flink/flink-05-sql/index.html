Flink SQL 与 Table API

DataStream API 写业务灵活，但表结构、关联、聚合都要自己拼代码。Flink 在流之上提供了 Table API 和 SQL：把数据流抽象成动态表，用声明式查询做清洗、关联和聚合，引擎自动翻译成并行作业。这一篇讲表与流的转换、DDL 写法、时态表关联和常用连接器。

悬浮的透明表格网格压在连续流带之上，数据库圆柱与消息立方体通过连接器节点接入表格

1.1 Table 与 DataStream 的关系

Table API 是 DataStream 之上的声明式层，两者可以互转：

方向
做法
适用
DataStream → Table
tableEnv.fromDataStream(stream)
已有流作业，局部改 SQL
Table → DataStream
tableEnv.toDataStream(table)
SQL 结果回流处理或落 Sink
纯 SQL
建表 + 查询 + 插入结果表
实时数仓分层、指标看板

入口环境由流环境创建：

StreamExecutionEnvironment env = StreamExecutionEnvironment.getExecutionEnvironment();
StreamTableEnvironment tableEnv = StreamTableEnvironment.create(env);

Table 本身不存数据，它是一条逻辑查询计划；真正的数据在 Source 连接器里流动，结果写入 Sink 连接器。

1.2 DDL：建表、时间属性与水位线

SQL 作业的第一步是用 DDL 声明表结构，包括字段、时间属性和连接器参数。时间属性分两种：事件时间在字段上挂 WATERMARK，处理时间用 PROCTIME() 声明。

CREATE TABLE order_log (
  order_id    STRING,
  user_id     STRING,
  product_id  STRING,
  amount      DECIMAL(10, 2),
  event_time  TIMESTAMP(3),
  -- 事件时间属性：水位线 = 事件时间减 10 秒乱序容忍
  WATERMARK FOR event_time AS event_time - INTERVAL '10' SECOND,
  PRIMARY KEY (order_id) NOT ENFORCED
) WITH (
  'connector' = 'kafka',
  'topic' = 'order_log',
  'properties.bootstrap.servers' = 'kafka:9092',
  'format' = 'json',
  'scan.startup.mode' = 'latest-offset'
);

连接器参数都写在 WITH 里：Source 决定从哪读，格式决定怎么解析，启动模式决定从最新位点还是最早位点消费。表结构改了要重建表或更新 DDL，已提交作业的状态兼容性仍按上一篇的规则处理。

1.3 动态表与持续查询

批处理里一张表查一次出结果；流处理里表是动态表（Dynamic Table）：新记录持续追加进来，查询结果随之持续更新。一条 SQL 提交后不会结束，它生成一个 changelog 流，下游看到的是不断刷新的结果。

概念
含义
动态表
随数据流持续变化的表，查询结果是 changelog
持续查询
在动态表上长期运行，新数据到达即更新结果
Changelog 模式
追加（Append）、撤回（Retract）、更新（Upsert），由连接器能力决定

聚合结果是更新流而不是追加流：同一个 key 的计数变了，下游要撤回旧值、写入新值。Sink 连接器必须支持对应的 changelog 模式，否则结果写不进去。

1.4 时态表 Join（Temporal Join）

维表数据会随时间变化，订单发生那一刻对应的商品价格、类目，要按当时的版本关联，而不是关联当前最新值。时态表 join 就是解决这个问题：版本化维表由 CDC changelog 维护，关联时按订单事件时间回溯到对应版本。

CREATE TABLE product_dim (
  product_id  STRING,
  price       DECIMAL(10, 2),
  category    STRING,
  update_time TIMESTAMP(3),
  WATERMARK FOR update_time AS update_time,
  PRIMARY KEY (product_id) NOT ENFORCED
) WITH (
  'connector' = 'mysql-cdc',
  'hostname' = 'mysql',
  'database-name' = 'dim',
  'table-name' = 'product_dim',
  'username' = 'flink',
  'password' = '******'
);

-- FOR SYSTEM_TIME AS OF：按订单事件时间关联维表当时版本
SELECT o.order_id, o.product_id, p.price, p.category
FROM order_log o
LEFT JOIN product_dim FOR SYSTEM_TIME AS OF o.event_time AS p
ON o.product_id = p.product_id;

时态表 join 的前提是维表变更流带主键和时间属性，能回溯历史版本；纯外部查询的维表关联走 Lookup Join，是下一篇的内容。

CDC 连接器直接读数据库 binlog，把增删改转成 changelog 流；配置时要保证数据库开启 binlog、账号有复制权限，表必须有主键才能形成 Upsert 流。

1.6 常见易错点

  • 把动态表当静态表写：聚合结果是更新流，Sink 不支持撤回模式就会报错。
  • 事件时间字段没挂 WATERMARK，窗口和时态关联拿不到时间属性。
  • 维表 CDC 没配主键，changelog 退化成追加流，无法做版本回溯。
  • 连接器版本与 Flink 版本不匹配，提交时类找不到或参数不识别。
  • 在 SQL 里做全量遍历式大聚合，没按 key 分组，并行度退化。

1.8 清单

  1. Table API / SQL 是流之上的声明式层，与 DataStream 可双向转换
  2. DDL 声明字段、时间属性与连接器参数；事件时间挂 WATERMARK，处理时间用 PROCTIME()
  3. 动态表上的持续查询产出 changelog，Sink 必须匹配 Append / Retract / Upsert 模式
  4. 时态表 join 按事件时间回溯维表历史版本，前提是维表变更流带主键与时间属性
  5. Kafka 做消息进出，MySQL CDC 捕获库表变更，文件与 ES 做结果落地
  6. 时间属性缺失、维表无主键、连接器版本错配是 SQL 作业最常见的三类报错
