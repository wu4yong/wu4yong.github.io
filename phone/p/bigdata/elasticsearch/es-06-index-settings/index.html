ES06-索引 settings

分类：bigdata · elasticsearch ｜ 标签：Elasticsearch · 系统课

建索引：settings 里真正要紧的四项

新建索引时，settings 能写几十项，但真正一错就要重建索引的只有四项：主分片数、副本数、refresh_interval、analysis。

其余的（熔断、上限、慢日志）都能在线改，这四项里有三项改不了或改了要付代价。

主分片承担写入与存储，副本提供容灾与读扩展；number_of_shards 建索引后不可改，number_of_replicas 可动态调整｜依据 Elasticsearch 官方文档 8.17 自绘

一、学习目标

  1. 说清主分片数为何「只能建索引时定」，副本数为何能随时改；
  2. 给出分片数量与体积的决策依据（官方经验值 + 堆内存约束）；
  3. 知道 refresh_interval 的两个极端取值及其代价；
  4. 会写一个「四项一次配好」的建索引请求，并用 _settings 复核。

三、理论讲解（官方定义）

官方在建索引 API 里给出的两个默认值，是 8.x 的现状，不要照搬 7.x 教程：

为什么主分片数不可改：路由是 hash(routing) % number_of_primary_shards，改了分母，老文档就算不出「原来那个家」，全量数据得重新分布。官方因此把它设计成创建时一次性决定。

副本数为什么能改：副本是主分片的完整拷贝，改数量只触发分片分配，不改变数据归属。

四、原理拆解：分片该给几个

官方《Size your shards》给的是经验区间，不是硬限制，但工程上够用：

维度
官方经验值
含义
单分片体积
10–50 GB
太小则分片过多、开销大；太大则恢复慢、段合并重
单节点分片数
每 1 GB 堆内存不超过 20 个分片
分片元数据常驻堆，超了集群状态更新会变慢
检索长尾
分片越多，等待最慢分片的概率越高
M1-3 的长尾效应

一个 100 GB 的索引，给 3–5 个主分片、1 个副本是比较稳的起点；日增量日志不要「一天一个索引」再配 5 个分片，那是分片爆炸的经典姿势（正确做法是 data stream + ILM，见 M2-8）。

六、实操

curl -X PUT "http://localhost:9200/goods" -H 'Content-Type: application/json' -d '
{
  "settings": {
    "number_of_shards": 3,
    "number_of_replicas": 1,
    "refresh_interval": "1s",
    "analysis": {
      "analyzer": {
        "my_lower": { "type": "custom", "tokenizer": "standard", "filter": ["lowercase", "asciifolding"] }
      }
    }
  },
  "mappings": { "properties": { "title": { "type": "text", "analyzer": "my_lower" } } }
}'

# 复核：以返回值为准，不要凭记忆
curl -s "http://localhost:9200/goods/_settings"
curl -s "http://localhost:9200/goods/_settings?include_defaults=true"   # 连默认值一起看

# 在线改副本与刷新间隔
curl -X PUT "http://localhost:9200/goods/_settings" -H 'Content-Type: application/json' -d '
{ "index": { "number_of_replicas": 2, "refresh_interval": "5s" } }'

第三行那条 include_defaults=true 很值钱：线上排查「这个参数到底生效没」时，能看到真实生效值。

七、常见坑

  1. 照抄 7.x 的默认 5 主分片 1 副本：8.x 默认已改为 1 主分片，别把旧默认当现状。
  2. 指望事后改主分片数：官方不支持直接改，只能 _split（变多）、_shrink（变少）或 reindex。
  3. 导入期也开 refresh_interval: 1s：批量写时每批都生成新段，导入完成后段数巨大、合并压力高。
  4. 副本数设 0 就上线：单节点失联即不可用，读并发也没了。
  5. 分片按「一天一个索引 × 5 分片」堆：分片元数据常驻堆，几千分片后集群状态更新会明显变慢。

八、课后小结

  1. 四项关键设置：主分片数（不可改）、副本数（可改）、refresh_interval（可改）、analysis（改了要重灌）。
  2. 8.x 默认 1 主分片 1 副本，别照搬 7.x。
  3. 分片体积 10–50 GB、每 GB 堆不超过 20 个分片是官方经验区间。
  4. 批量导入：副本先 0、刷新先关，导完再恢复。
  5. _settings?include_defaults=true 是核验真实生效值的标准动作。

九、思考题

  1. 一个 300 GB 的索引，你会给几个主分片？如果查询 P99 偏高，先加分片还是先加副本？
  2. 为什么设定 refresh_interval: -1 之后，_search 需要手动 _refresh 才能看到新数据？把链路串一遍。
  3. 用 _split 把 3 个主分片变 6 个，需要满足什么前置条件？（提示：官方要求源索引只读）
