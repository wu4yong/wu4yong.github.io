安全基础：默认启用、TLS、用户与 API key

8.x 起安全功能默认开启：不配密码你连不上，不配证书集群起不来。

这跟 7.x 时代「可选插件」完全不同，所以照着老教程搭环境的人，第一课往往是「为什么 9200 端口拒绝连接」。

默认启用、TLS、RBAC 与三种凭据｜依据 Elasticsearch 官方文档 8.17 自绘

一、学习目标

  1. 知道 8.x 安全默认开启带来的行为变化；
  2. 说清 transport TLS 与 http TLS 各自保护什么；
  3. 会用 RBAC：建 role、建 user、绑定权限；
  4. 会用 API key 代替账号密码做应用集成。

四、原理拆解：为什么「默认开启」是个设计决策

7.x 时代安全是可选插件，结果大量集群裸奔在公网上，成为数据泄露的主要来源。8.x 把安全做成默认：首次启动生成证书与密码，集群内部强制 TLS + 节点身份校验，客户端也要带凭据。这带来一个副作用——任何「快速搭个 ES 试试」的老脚本都会失败，必须用 discovery.type: single-node + 显式关闭安全（仅开发）或走完整初始化。

两类 TLS 的边界要说清：transport 保护节点之间（9300），防止有人伪装成节点混进集群；http 保护客户端到集群（9200），防止抓包。生产两个都要开，只开一个等于留了半边门。

RBAC 三段式：role 定义权限（对哪些索引、能做什么操作、能访问哪些 API），user 绑定 role，role_mapping 把外部身份（如 LDAP/OIDC 用户）映射到 role。API key 则是「给程序用的凭据」，可以限定权限与有效期，比把账号密码写进配置安全得多。

六、实操

# 开发环境临时关闭安全（仅本地，勿用于生产）
# elasticsearch.yml
# xpack.security.enabled: false
# discovery.type: single-node

# 1) 建 role：只读 goods 索引
curl -s -X POST "http://localhost:9200/_security/role/goods_reader" -u elastic:CHANGE_ME -H 'Content-Type: application/json' -d '
{ "cluster": [], "indices": [ { "names": ["goods*"], "privileges": ["read", "view_index_metadata"] } ] }'

# 2) 建 user 并绑定 role
curl -s -X POST "http://localhost:9200/_security/user/app_reader" -u elastic:CHANGE_ME -H 'Content-Type: application/json' -d '
{ "password": "StrongPass!2024", "roles": ["goods_reader"], "full_name": "App Reader" }'

# 3) 建 API key（给应用用，可设有效期）
curl -s -X POST "http://localhost:9200/_security/api_key" -u elastic:CHANGE_ME -H 'Content-Type: application/json' -d '
{ "name": "goods-search-key", "role_descriptors": {
    "r": { "indices": [ { "names": ["goods*"], "privileges": ["read"] } ] } },
  "expiration": "30d" }'

# 4) 用 key 访问（base64(id:api_key)）
curl -s "http://localhost:9200/goods/_search?size=1" -H "Authorization: ApiKey <base64_id:key>"

返回的 id + api_key 拼成 id:api_key 再做 base64，就是请求头里的值。

七、常见坑

  1. 照抄 7.x 教程：8.x 默认开安全，端口能起来但请求被拒。
  2. 只开 http TLS 不开 transport TLS：节点间明文，集群可被伪造节点混入。
  3. 用 elastic 超级用户跑业务：违反最小权限，泄露即全库沦陷。
  4. API key 不设有效期：泄露后长期有效。
  5. role 权限写成 * 索引：一处失误影响全集群。
  6. 生产直接关 xpack.security.enabled：等于裸奔，只在本地开发可接受。

八、课后小结

  1. 8.x 安全默认开启，transport 与 http 两套 TLS 各管一段。
  2. 开发可临时关闭，生产必须双向 TLS。
  3. RBAC = role（权限）+ user（身份）+ role_mapping（外部身份映射）。
  4. 应用集成用 API key，别用账号密码。
  5. elastic 是引导用超级用户，不是业务账号。

九、思考题

  1. 一个只读看板应用，你会给它什么权限组合？为什么连 view_index_metadata 都要给？
  2. transport TLS 与 http TLS 各自防的是哪类攻击？
  3. API key 泄露与账号密码泄露，处置流程差在哪？
