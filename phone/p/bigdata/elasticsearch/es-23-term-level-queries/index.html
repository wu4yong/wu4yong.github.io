term-level 查询：精确匹配的那一整套

term 系列查询的共同点是不对查询词做分析，直接把词条拿去倒排表比对。

所以它只对 keyword、数值、日期这类「整值索引」的字段有意义；拿它查 text 字段，是新手最常犯的错误之一。

term-level 一族与 text 被切词后的失配｜依据 Elasticsearch 官方文档 8.17 自绘

四、原理拆解：为什么 term 查 text 会失败

写入 Running Dogs 到 text 字段，standard 把它切成 [running, dogs] 两个小写词条。此时：

  • term: "Running Dogs" → 倒排表里没有这个整串，不命中；
  • term: "running" → 命中（但要小心大小写）；
  • term: "Running" → 不命中（词条已小写）。

于是规则很清楚：term 只能打「倒排里真实存在的那个词条」。要么字段是 keyword（整值一个词条），要么你明确知道分析后的形态。

六、实操

# term / terms：注意字段是 keyword
curl -s -X GET "http://localhost:9200/goods/_search" -H 'Content-Type: application/json' -d '
{ "query": { "bool": { "filter": [
  { "term":  { "status": "on_sale" } },
  { "terms": { "tags": ["running", "trail"] } } ] } } }'

# range：数值 + 日期数学
curl -s -X GET "http://localhost:9200/goods/_search" -H 'Content-Type: application/json' -d '
{ "query": { "bool": { "filter": [
  { "range": { "price": { "gte": 10, "lte": 100 } } },
  { "range": { "created": { "gte": "now-7d/d", "lt": "now/d", "time_zone": "+08:00" } } } ] } } }'

# exists：字段存在且有值
curl -s -X GET "http://localhost:9200/goods/_search" -H 'Content-Type: application/json' -d '
{ "query": { "exists": { "field": "promotion" } } }'

# 前缀与通配（前缀放前面，避免前置 *）
curl -s -X GET "http://localhost:9200/goods/_search" -H 'Content-Type: application/json' -d '
{ "query": { "prefix": { "sku": { "value": "NB-2023" } } } }'

now-7d/d 里 /d 是「按天取整」，time_zone 决定取整基准——跨时区的日报统计必须显式指定。

七、常见坑

  1. term 打 text 字段：分析后的词条与整串不一致，必然不命中。
  2. 大小写没对齐：keyword 区分大小写，需要 normalizer 统一（M2-3）。
  3. 前置通配 *abc：倒排表无法按前缀跳转，等于接近全扫。
  4. regexp 不设 max_determinized_states：复杂正则会撞官方上限报错或极慢。
  5. exists 以为能筛出 null：显式 null 与空数组都算「不存在」。
  6. fuzzy 用在中文：一字之差往往语义全变，误召回高。

八、课后小结

  1. term-level 不分析查询词，只适用于整值索引字段。
  2. term/terms 放 filter 最划算；range 支持 date math 时区。
  3. exists 判「有值」，null 与空数组算没有。
  4. wildcard/regexp/fuzzy 都有官方保护参数，别默认拉满。
  5. 查不到时先问：这个词条在倒排里存在吗？
