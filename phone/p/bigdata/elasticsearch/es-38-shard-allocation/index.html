分片分配与再平衡：磁盘水位、分配过滤与手工 reroute

分片去哪里，是 master 算出来的，不是你想放哪就放哪。

但你可以用三组开关影响它：磁盘水位（硬约束）、分配过滤（倾向）、reroute（手工强制）。

配图 38-1｜提示词：三台数据节点的磁盘条并排，分别填充到 60%、88%、96%，对应三条水位线 low 85%（琥珀）、high 90%（橙）、flood_stage 95%（红），96% 那台旁边标注「索引转为 read_only_allow_delete」。下方一排开关：index.routing.allocation.require: rack_id、cluster.routing.rebalance.enable、POST _cluster/reroute。深色星空背景。

一、学习目标

  1. 记住三档磁盘水位的官方默认值与触发后果；
  2. 会用 index.routing.allocation.* 做「指定/排除节点」；
  3. 知道 index.number_of_shards 建索引后不可改；
  4. 会用手工 reroute 处理卡住的分片。

四、原理拆解：为什么水位能「卡住」写入

磁盘写满会让节点崩，所以官方用三档水位做递进防御：85% 只影响「新分片落位」，90% 开始「迁走」，95% 直接把索引置为只读——这是保护性动作，不是故障。此时写入会失败并提示 read_only_allow_delete，正确做法是清磁盘后手工解除：

PUT /goods/_settings
{ "index.blocks.read_only_allow_delete": null }

再平衡的逻辑是「让分片分布尽量均匀」，它会在节点增删、水位变化后自动触发。所以迁移期间不要开自动再平衡做人工干预——两件事同时做会互相打架。

六、实操

# 1) 查磁盘水位默认值
curl -s "http://localhost:9200/_cluster/settings?include_defaults=true&flat_settings=true" | Select-String -Pattern 'disk.watermark'

# 2) 把索引固定在热节点
curl -s -X PUT "http://localhost:9200/goods/_settings" -H 'Content-Type: application/json' -d '
{ "index.routing.allocation.require": { "data_tier": "hot" } }'

# 3) 查为什么有分片没分配
curl -s -X GET "http://localhost:9200/_cluster/allocation/explain?pretty"

# 4) 手工强制分配（仅在确认数据存在时）
curl -s -X POST "http://localhost:9200/_cluster/reroute?pretty" -H 'Content-Type: application/json' -d '
{ "commands": [ { "allocate_stale_primary": {
    "index": "goods", "shard": 0, "node": "data-hot-1", "accept_data_loss": true } } ] }'

accept_data_loss: true 是明确的免责声明——只有在你确认该分片数据可丢弃时才用。

七、常见坑

  1. 想改 number_of_shards：建索引后不可改，只能 reindex / shrink / split。
  2. 95% 只读当成故障：是保护机制，清盘后松开 read_only_allow_delete。
  3. require 写成节点名：写的是 node.attr.* 的属性值，不是节点名（节点名用 include）。
  4. 人工 reroute 与自动再平衡同时进行：结果来回搬，白耗 IO。
  5. total_shards_per_node 设太小：副本无处安放，长期 yellow。
  6. 分配过滤设完忘了清理：后续扩容时新节点永远接不到分片。

八、课后小结

  1. 水位三档：85% 不落新片、90% 迁走、95% 只读。
  2. enable 分集群级与索引级，none 可临时冻结分配。
  3. require/include/exclude 写的是属性值与节点名，别混。
  4. number_of_shards 静态，只能 reindex/shrink/split。
  5. 分片卡住先用 explain 查原因，再决定是否强制分配。

九、思考题

  1. 一台节点磁盘到 91%，集群会发生什么？你的处置顺序是什么？
  2. index.routing.allocation.require 与 include 的语义差别在哪？何时选哪个？
  3. 为什么官方把 number_of_shards 设计为不可改？从路由公式角度解释。
