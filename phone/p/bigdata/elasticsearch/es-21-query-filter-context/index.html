query 上下文与 filter 上下文：打分与不打分的分界线

同一份 bool 查询，把条件从 must 挪到 filter，结果集完全一样，但性能与分数完全不同。

这条分界线是 ES 检索里最值钱的一条常识：能用 filter 表达的，就别放进 must。

query 上下文与 filter 上下文的区别｜依据 Elasticsearch 官方文档 8.17 自绘

一、学习目标

  1. 说清两种上下文的判定方式（写在哪个参数里）；
  2. 记住 filter 结果可被缓存、query 结果不可；
  3. 会写「filter 打底 + must 补相关性」的标准结构；
  4. 知道 constant_score 与 bool.filter 的等价关系。

关键点：must_not 永远在 filter 上下文，它只排除、不打分；这也是为什么「用 must_not 表达负向条件不会影响相关性」。

四、原理拆解：为什么 filter 能缓存而 query 不能

打分依赖索引级统计量（IDF、平均文档长度）与查询词组合，任何一个变了分数就变，缓存没有意义。而 filter 只回答「这个文档在不在集合里」，答案是布尔值，可以用一个 bitset 表示；同一个 filter 在不同查询里反复出现时，直接复用 bitset，成本几乎为零。

所以工程上的标准写法是：

"bool": {
  "filter": [ { "term": { "status": "on_sale" } },
              { "range": { "price": { "gte": 10, "lte": 100 } } } ],
  "must":   [ { "match": { "title": "跑鞋" } } ]
}

先过滤再打分，参与打分的候选集更小，速度更快。

六、实操

# 只过滤：注意到 _score 恒为 0
curl -s -X GET "http://localhost:9200/goods/_search" -H 'Content-Type: application/json' -d '
{ "query": { "bool": { "filter": [ { "term": { "on_sale": true } } ] } } }'

# 过滤 + 相关性
curl -s -X GET "http://localhost:9200/goods/_search" -H 'Content-Type: application/json' -d '
{ "query": { "bool": {
    "filter": [ { "term": { "on_sale": true } },
                { "range": { "price": { "gte": 10, "lte": 100 } } } ],
    "must":   [ { "match": { "title": "跑鞋" } } ] } } }'

# constant_score：过滤后统一给 1.0
curl -s -X GET "http://localhost:9200/goods/_search" -H 'Content-Type: application/json' -d '
{ "query": { "constant_score": { "filter": { "term": { "on_sale": true } }, "boost": 1.0 } } }'

第三条的用途很实际：当你只想「筛出来」并按字段排序，分数毫无意义，用 constant_score 避免无谓计算。

七、常见坑

  1. 把区间、枚举条件放 must：白算分数，还失去缓存。
  2. 指望 query 结果被缓存：官方只对 filter 上下文做结果缓存。
  3. 用 must_not 试图「降低分数」：它只排除，不改变其他文档的分数。
  4. filter 里放 match：match 在 filter 上下文不算分，但分词开销照付，且缓存收益低于 term。
  5. 以为 _score 为 0 是错误：纯 filter 查询本来就无分。

八、课后小结

  1. query、must、should 算分；filter、must_not、constant_score.filter 不算分。
  2. filter 结果可缓存，query 结果不可。
  3. 标准结构：filter 打底 → must 补相关性。
  4. constant_score 适合「只要命中、不要分数」的场景。
  5. must_not 天然属于 filter 上下文。

九、思考题

  1. 一个查询里同一个 range 出现两次（两个不同 bool 子句），官方缓存会命中几次？为什么？
  2. 商品搜索里「价格区间 + 有货 + 关键词」三类条件，分别该放在哪？
  3. 为什么官方不对 query 上下文做结果缓存？从「缓存键包含什么」角度解释。
