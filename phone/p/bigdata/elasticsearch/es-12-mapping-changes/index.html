分类：bigdata · elasticsearch ｜ 标签：Elasticsearch · 系统课

改 mapping 的边界：能在线加的、只能重建的

「能不能在线改 mapping」这个问题，官方答案是分层的：加字段可以，改类型不行。

搞清楚这条线，你才知道什么时候能十分钟搞定，什么时候必须走「新建索引 + reindex + 别名切换」这套完整迁移。

在线加字段 与 新建索引 + reindex 的分界｜依据 Elasticsearch 官方文档 8.17 自绘

一、学习目标

  1. 分清 mapping 里「可在线变更」与「必须重建」的两类内容；
  2. 会写一个安全的 reindex 迁移方案（含别名原子切换）；
  3. 知道 _reindex 不复制 settings 与 mapping 这个坑；
  4. 会说清迁移窗口期如何避免数据丢失。

核心原因只有一句：倒排索引与 doc values 已经按旧结构物理落盘，改「定义」不会重写历史段。所以官方把这套操作归类为「需要重建」。

四、原理拆解：一次安全迁移的四个阶段

  1. 建新索引（v2）：完整 settings + mapping，一次写对；
  2. 灌数据：_reindex 从 v1 到 v2（可带 script 做字段改名/类型转换、source.query 做筛选）；
  3. 切别名：用一个请求原子完成「别名从 v1 指向 v2」，写入侧必须已经用别名而不是物理索引名；
  4. 验证后删 v1：确认检索与写入都正常，保留快照再删。

第 3 步是整套方案的关键：如果应用一直写的是物理索引名，就无法无损切换，只能停机。这也是 M2-8 要讲的「别名是建模的一部分」。

六、实操：完整迁移

# 1) 建 v2（结构一次写对）
curl -X PUT "http://localhost:9200/goods_v2" -H 'Content-Type: application/json' -d '
{ "settings": { "number_of_shards": 3, "number_of_replicas": 1 },
  "mappings": { "properties": {
    "title": { "type": "text", "fields": { "raw": { "type": "keyword" } } },
    "price": { "type": "scaled_float", "scaling_factor": 100 } } } }'

# 2) 灌数据（注意：settings 与 mapping 不会自动带过来）
curl -X POST "http://localhost:9200/_reindex?wait_for_completion=false" -H 'Content-Type: application/json' -d '
{ "source": { "index": "goods_v1" },
  "dest":   { "index": "goods_v2", "op_type": "create" } }'

# 3) 查任务进度
curl -s "http://localhost:9200/_tasks?actions=*reindex*"

# 4) 别名原子切换（一个请求完成，不给中间态）
curl -X POST "http://localhost:9200/_aliases" -H 'Content-Type: application/json' -d '
{ "actions": [
  { "remove": { "index": "goods_v1", "alias": "goods" } },
  { "add":    { "index": "goods_v2", "alias": "goods", "is_write_index": true } } ] }'

第 2 步的 op_type: create 很关键：目标已存在同 ID 文档时不会覆盖，而是记一条冲突，避免「迁移把新数据冲掉」。返回里的 failures 与 version_conflicts 必须为 0 才算迁移成功。

七、常见坑

  1. 以为 reindex 会复制 settings/mapping：官方只搬文档，结构必须你提前建好。
  2. 应用直写物理索引名：切别名时无法无损切换，只能停机。
  3. 迁移期间不清洗并发写入：v1 在迁移后又进新数据，切完别名就丢。要么暂停写、要么迁移完再补一次增量。
  4. _reindex 不带 op_type：默认覆盖，目标侧已有数据可能被旧数据冲掉。
  5. 加子字段后忘了回溯历史文档：fields 新增只对后续文档生效，老文档该子字段为空。
  6. 切完就删 v1：没有回滚余地，官方建议保留快照或至少观察一段时间。

八、课后小结

  1. 可在线改：加字段、改索引级 settings；不可在线改：字段类型、分析器、字段名。
  2. 完整迁移四步：建 v2 → reindex → 别名原子切换 → 删 v1。
  3. _reindex 只搬数据，不搬结构。
  4. 写入侧必须走别名，否则无法无损切换。
  5. 迁移要看 failures 与 version_conflicts，不能只看「完成了」。
