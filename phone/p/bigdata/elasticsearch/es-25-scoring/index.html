分类：bigdata · elasticsearch ｜ 标签：Elasticsearch · 系统课

BM25 与打分调优：boost、function_score 的正确姿势

相关性不是玄学，是公式：BM25 用词频、逆文档频率、字段长度归一把「文本像不像」变成一个数。

想改排序，先得知道自己在改公式里的哪一项，否则调出来的效果无法解释、也无法复现。

BM25 打分与 function_score 的组合｜依据 Elasticsearch 官方文档 8.17 自绘

一、学习目标

  1. 说出 BM25 的两个可调参数 k1、b 的官方默认值；
  2. 会用 boost 做「软权重」，并知道它按乘法作用于分数；
  3. 会用 function_score 的四种函数与 score_mode / boost_mode；
  4. 会用 explain 读分数是怎么算出来的。

function_score 支持的函数：weight（常数权重）、field_value_factor（拿字段值参与，如销量、评分）、random_score（稳定随机，seed 固定则结果稳定）、decay（按距离衰减，gauss/exp/linear 三种曲线，参数 origin、scale、offset、decay）、script_score（自定义脚本，最灵活也最慢）。

四、原理拆解：boost 是乘法，不是排序键

boost 乘在分数上。因为 BM25 分数是无界正数，乘 3 意味着「这个子句的贡献变成三倍」，但它不会把不命中的文档拉进来，也不会压过另一个分数高一个数量级的子句。所以 boost 适合「同类条件间微调权重」，不适合「让某类文档绝对优先」。

要实现「绝对优先」，做法是把优先级放进 filter + 分层排序，或干脆用 function_score 里的大权重 weight（例如 weight: 100），让它数量级上碾压。

field_value_factor 有个坑：字段值为 0 或负数时，乘法会把分数清零或变负。官方建议用 modifier 修正，最常见是 log1p（对 1 取对数），既压缩长尾又保证非负。

六、实操

# 1) explain 看分数构成
curl -s -X GET "http://localhost:9200/goods/_search?explain=true" -H 'Content-Type: application/json' -d '
{ "query": { "match": { "title": "跑鞋" } }, "size": 1 }'

# 2) boost 软权重
curl -s -X GET "http://localhost:9200/goods/_search" -H 'Content-Type: application/json' -d '
{ "query": { "bool": { "should": [
    { "match": { "title": { "query": "跑鞋", "boost": 3 } } },
    { "match": { "body":  { "query": "跑鞋" } } } ] } } }'

# 3) 销量加权：log1p 防 0 值
curl -s -X GET "http://localhost:9200/goods/_search" -H 'Content-Type: application/json' -d '
{ "query": { "function_score": {
    "query": { "match": { "title": "跑鞋" } },
    "functions": [
      { "field_value_factor": { "field": "sales", "modifier": "log1p", "factor": 0.2 } },
      { "weight": 1.5 } ],
    "score_mode": "sum", "boost_mode": "multiply", "max_boost": 10 } } }'

# 4) 距离衰减：附近门店优先
curl -s -X GET "http://localhost:9200/shops/_search" -H 'Content-Type: application/json' -d '
{ "query": { "function_score": {
    "query": { "match": { "name": "咖啡" } },
    "functions": [ { "gauss": { "location": { "origin": "29.55,103.76", "scale": "2km", "offset": "0.5km", "decay": 0.5 } } } ] } } }'

decay: 0.5 表示「距离到 scale 时分数降到一半」，offset 之内不衰减——这三个参数决定曲线形状，必须一起调。

七、常见坑

  1. boost 当开关用：乘法微调，压不过数量级差异。
  2. field_value_factor 直接乘 0 值字段：分数归零，排序全乱。
  3. random_score 不传 seed：同一请求刷新后顺序变化，分页会重复/漏文档。
  4. score_mode: sum 混用不同量纲函数：权重函数与 BM25 分数直接相加，语义不可解释。
  5. script_score 放热点查询：脚本逐文档执行，CPU 与延迟都高。
  6. 改 k1/b 没做 A/B：官方默认值经大量实践验证，改动前先在测试索引上比对。

八、课后小结

  1. BM25 默认 k1=1.2、b=0.75，b=0 关闭长度归一是最常用的一档调整。
  2. boost 是乘法权重，适合同类微调，不适合绝对优先。
  3. function_score 四种函数覆盖权重、字段值、随机、距离；score_mode/boost_mode 决定合并方式。
  4. field_value_factor 务必处理 0 与负值，log1p 是常规解法。
  5. 调分前先 explain，让每一分都有出处。
