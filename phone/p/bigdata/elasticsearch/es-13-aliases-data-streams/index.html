ES13-别名与 data stream

分类：bigdata · elasticsearch ｜ 标签：Elasticsearch · 系统课

别名、data stream 与滚动索引：把「换索引」变成日常操作

M2 收官讲。前面所有「重建索引」的方案，最后都卡在同一个前提上：应用写的必须是一个稳定名字。

这个稳定名字就是别名；而当数据带时间戳、只追加时，官方进一步把它封装成了 data stream。这一讲讲这两种「稳定名字」怎么建、怎么用、哪些坑必须提前埋管子。

alias 指向 v1/v2，data stream 按代滚动｜依据 Elasticsearch 官方文档 8.17 自绘

  4. 知道 rollover 的触发方式，以及为什么它离不开 ILM。

三、理论讲解

别名（alias）：官方定义为一个索引可以拥有的「另一个名字」，一个别名可以同时指向多个索引。它的价值在四个方向：

用途
做法
效果
多索引统一查询
一个别名指向 v1、v2
查询别名 = 跨索引一起搜
读写分离
is_write_index: true 只标在一张上
写走别名，读走别名，切换无感
原子切换
_aliases 一次请求 add+remove
不存在「中间态」
视图裁剪
别名带 filter / routing
同一批数据，不同业务看到不同子集

data stream：官方为「只追加的时间戳数据」设计的抽象。它由一组隐藏的、自动生成的后备索引组成，对外只暴露一个流名。三个前置条件：数据必须有时间字段（ECS 下是 @timestamp）、必须由匹配的索引模板创建、只做追加写。

四、原理拆解：为什么 data stream 必须配 ILM

data stream 本身只解决「写入时自动滚到新索引」，滚动的触发条件要靠 ILM 策略来定：

机制
负责什么
缺了会怎样
data stream
暴露稳定名字、管理后备索引序列
名字不稳定，切换困难
rollover
达到阈值时新建后备索引
单索引无限膨胀
ILM（hot→warm→cold→delete）
决定何时滚、何时降冷、何时删
老数据堆积，磁盘打满

所以官方把这三者写成一条链路：模板（mappings + data_stream: {}）+ ILM 策略（含 rollover action）+ 写入别名。少任何一环都会在几个月后出问题。

六、实操

# 1) 建两个物理索引，用别名对外
curl -X PUT "http://localhost:9200/goods_v1" -H 'Content-Type: application/json' -d '
{ "aliases": { "goods": { "is_write_index": true } }, "mappings": { "properties": { "title": { "type": "text" } } } }'

# 2) 写别名（不要写物理名）
curl -X PUT "http://localhost:9200/goods/_doc/1" -H 'Content-Type: application/json' -d '{ "title": "别名写入" }'

# 3) 读别名
curl -s "http://localhost:9200/goods/_search?pretty"

# 4) data stream：模板 + 流
curl -X PUT "http://localhost:9200/_index_template/logs-template" -H 'Content-Type: application/json' -d '
{ "index_patterns": ["logs-*"], "data_stream": {},
  "template": { "mappings": { "properties": {
      "@timestamp": { "type": "date" }, "message": { "type": "text" },
      "service": { "type": "keyword" } } } } }'

curl -X PUT "http://localhost:9200/_data_stream/logs-app"

# 5) 写入流（不需要指定索引名，也不需要 _id）
curl -X POST "http://localhost:9200/logs-app/_doc" -H 'Content-Type: application/json' -d '
{ "@timestamp": "2023-11-01T09:00:00Z", "message": "started", "service": "api" }'

# 6) 手动滚动后备索引
curl -X POST "http://localhost:9200/logs-app/_rollover"

第 6 步之后，GET /_data_stream/logs-app 会显示两个后备索引，.ds- 前缀是官方自动命名的结果，generation 递增。

七、常见坑

  1. 写入走物理索引名：别名形同虚设，迁移只能停机（M2-7 的坑）。
  2. 别名没标 is_write_index：多索引别名写入会报「no write index」，必须显式指定。
  3. 用 DELETE 逐个删后备索引：官方要求删整个 data stream（DELETE /_data_stream/<name>），逐删会破坏序列。
  4. 缺 @timestamp：data stream 无法定位时间，写入被拒。
  5. 只建 data stream 不配 ILM：不会自动滚动，几个月后单个后备索引巨大。
  6. 别名当索引改名用：别名不改物理名，只提供稳定入口；GET _cat/indices 里看到的还是物理名。

八、课后小结

  1. 别名四用：多索引查询、读写分离、原子切换、带过滤视图。
  2. 写别名必须 is_write_index: true，且应用只能写别名。
  3. data stream = 稳定流名 + 自动后备索引，前置条件是时间字段 + 模板 + 只追加。
  4. rollover 是滚动动作，ILM 是调度者；两者必须同时存在。
  5. 删除 data stream 要整条删，不要动后备索引。
