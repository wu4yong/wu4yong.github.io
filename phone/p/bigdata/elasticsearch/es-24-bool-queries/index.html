bool 四子句与 minimum_should_match：should 为什么不生效

bool 是查询的骨架：must、filter、should、must_not 四个子句。

最常见的困惑是「我写了 should，怎么一点作用都没有」——原因藏在官方默认规则里，而不是你的语法写错了。

bool 的四个子句与 should 生效条件｜依据 Elasticsearch 官方文档 8.17 自绘

一、学习目标

  1. 说清四个子句在「是否算分、是否影响命中」上的差别；
  2. 记住 minimum_should_match 的默认值规则（这是 should 不生效的根因）；
  3. 会写百分比形式的 minimum_should_match 并知道它的取整规则；
  4. 知道 adjust_pure_negative 的作用。

官方默认规则（原文语义）：

bool 里有 must 或 filter 吗
minimum_should_match 默认

这就是「写了 should 却不生效」的全部原因：只要同级的 must/filter 存在，should 就退化成「有则加分、无则不淘汰」。

四、原理拆解：should 的两种角色

  • 加分项（默认，配合 must/filter）：文档命中越多 should，分数越高，排序靠前；
  • 过滤条件（minimum_should_match ≥ 1 或纯 should）：不满足数量要求直接淘汰。

百分比写法按「向下取整」计算，例如 5 个 should 子句 + 75% → 至少 4 个命中；3<75% 这类带负数的表达式表示「超出阈值后的余量」，官方文档有专门说明，复杂表达式建议直接用整数，避免理解偏差。

adjust_pure_negative 默认 true：当 bool 里只有 must_not 时，官方会给它补一个匹配所有文档的子句，保证「纯排除」也能返回结果。这也是为什么「只有 must_not 的 bool」不会返回空集。

六、实操

# 硬过滤 + 相关性 + 加分项
curl -s -X GET "http://localhost:9200/goods/_search" -H 'Content-Type: application/json' -d '
{ "query": { "bool": {
    "filter": [ { "term": { "on_sale": true } } ],
    "must":   [ { "match": { "title": "跑鞋" } } ],
    "should": [ { "term": { "tags": "新品" } }, { "term": { "tags": "热卖" } } ],
    "must_not": [ { "term": { "status": "offline" } } ],
    "minimum_should_match": 1 } } }'

# 纯 should：默认至少命中一个
curl -s -X GET "http://localhost:9200/goods/_search" -H 'Content-Type: application/json' -d '
{ "query": { "bool": { "should": [
    { "match": { "title": "跑鞋" } }, { "match": { "title": "徒步鞋" } } ] } } }'

第一条里把 minimum_should_match 设成 1，should 就从「加分项」变成了「必选项」——这一步差别很大，上线前务必确认业务语义。

七、常见坑

  1. 写了 should 期待过滤效果：同级有 must/filter 时默认 minimum_should_match: 0。
  2. 纯 should 以为能返回全部：默认至少命中 1 个。
  3. 百分比写成小数：minimum_should_match 是字符串表达式，0.75 会被当整数 0。
  4. 把 must_not 当降权手段：它只排除，不改其他文档分数。
  5. should 子句堆几十个：每个都要打分，查询开销显著上升。
  6. 误以为 adjust_pure_negative 要手动开：官方默认 true。

八、课后小结

  1. must 算分、filter 不算分但可缓存、must_not 只排除、should 看最小匹配数。
  2. 同级有 must/filter 时，should 默认只是加分项。
  3. minimum_should_match 用整数最稳，百分比向下取整。
  4. 纯 must_not 的 bool 由 adjust_pure_negative 兜底，不会返回空集。
  5. 硬条件一律 filter，别混进 must。

九、思考题

  1. 一个 bool 里有 1 个 must、1 个 filter、3 个 should，minimum_should_match 不设时，should 起什么作用？
  2. 为什么 filter 的结果可以缓存，而 should 不行？和上下文归属有关还是和语义有关？
  3. 业务要求「至少命中两个标签才展示」，你会怎么配？如果标签有 6 个，写百分比还是整数？
