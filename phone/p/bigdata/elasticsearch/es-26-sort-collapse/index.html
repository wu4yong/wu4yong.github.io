排序与 collapse：按字段排、按分组取头名

sort 决定谁在前，collapse 决定「同组只留一个」。

两者经常一起出现：商品列表按销量排、同一 SPU 只展示一个最低价 SKU。这一篇把参数讲全，也把「为什么文本字段排不了」讲清。

sort 与 collapse 的两种取数方式｜依据 Elasticsearch 官方文档 8.17 自绘

一、学习目标

  1. 会用 _score、字段、_doc 三种排序；
  2. 说清「文本字段为什么不能直接排序」以及 fielddata 的代价；
  3. 会用 missing、mode、numeric_type 处理边界值；
  4. 会用 collapse + inner_hits 实现分组取头名。

四、原理拆解：排序为什么依赖 doc_values 而不是倒排

倒排表是「词条 → 文档列表」，回答的是「哪些文档含这个词」；排序要回答的是「价格 99 和 100 谁小」。用倒排做数值排序等于把整个词典翻一遍，不现实。doc_values 是写入时额外维护的列式正排，按 doc id 顺序存字段值，读取时顺序扫、跳着取都很快，这也是它默认开启的原因。

text 字段没有 doc_values（因为分词后一个字段对应多个词条，无法列存「原值」），所以给 text 排序会报错并提示开启 fielddata。官方对 fielddata 的态度很明确：它把词条加载进堆内存，轻易打爆堆，不建议用于排序。正确做法是加一个 keyword 子字段（M2-2 讲过的 fields）。

六、实操

# 多级排序：先相关性，再销量
curl -s -X GET "http://localhost:9200/goods/_search" -H 'Content-Type: application/json' -d '
{ "query": { "match": { "title": "跑鞋" } },
  "sort": [ "_score", { "sales": { "order": "desc", "missing": "_last" } } ] }'

# collapse：同 spu 取价格最低的一个，并返回组内其余
curl -s -X GET "http://localhost:9200/goods/_search" -H 'Content-Type: application/json' -d '
{ "query": { "match": { "title": "跑鞋" } },
  "sort": [ { "price": "asc" } ],
  "collapse": { "field": "spu_id",
                "inner_hits": { "name": "other_skus", "size": 3, "sort": [ { "price": "asc" } ] } } }'

collapse 与 scroll 不能同用（官方限制），深翻页要换 search_after + PIT，下一篇讲。

七、常见坑

  1. 给 text 排序：报错并建议开 fielddata——别开，加 keyword 子字段。
  2. collapse.field 用了 text：同样因缺 doc_values 失败。
  3. 以为 sort 后 _score 还能用：显式排序后分数默认不再计算，除非把 _score 写进 sort 或 track_scores。
  4. missing 忘了配：默认 _last 在升序时会把空值放末尾，与直觉相反的场景要显式设。
  5. 数组字段不设 mode：默认取最小值，用最大值业务会排错。
  6. collapse 与 scroll 混用：官方明确不支持。

八、课后小结

  1. 字段排序依赖 doc_values，text 需关键字子字段。
  2. fielddata 吃堆内存，官方不建议用于排序。
  3. missing、mode、numeric_type 是边界值三件套。
  4. collapse 按有 doc_values 的单值字段折叠，inner_hits 取回组内明细。
  5. 显式 sort 后分数不参与，需要就写进排序数组。
