UDF 与 Catalog

内置函数覆盖不了的业务逻辑，需要自己写函数注册给 SQL 用，这就是 UDF（User Defined Function）。除了普通逐行 UDF，Spark 还提供基于 Apache Arrow 的 pandas UDF，把批量数据按 pandas Series 处理，Python 侧性能比逐行调用好一个档次。这一篇梳理 UDF 注册路径、临时视图 API 的区别，以及 spark.catalog 提供的元数据操作入口。

自定义函数被注册进会话目录，列值经过函数处理后写入结果列，批量数据以 Arrow 格式在节点间传输

1.1 UDF 注册的两条路径

写好的函数要让 SQL 表达式认到，核心动作是”注册到当前会话的函数目录”。Scala 端两种写法等价：

import org.apache.spark.sql.functions.udf

// 写法一：先包成 UserDefinedFunction，再注册进 SQL 目录
val upperUdf = udf((s: String) => if (s == null) null else s.trim.toUpperCase)
spark.udf.register("to_upper", upperUdf)

// 写法二：直接注册匿名函数
spark.udf.register("str_len", (s: String) => if (s == null) 0 else s.length)

注册之后可以在 SQL 里按名字调用：

SELECT to_upper(name) AS name, str_len(phone) AS phone_len
FROM user_view

UDF 不参与 Catalyst 的表达式内联优化，重计算逻辑放 UDF 里会损失部分优化空间；能用内置函数表达的，优先用内置函数。

df.createOrReplaceTempView("user_view")

1.3 pandas UDF：Arrow 批量序列化

普通 Python UDF 逐行序列化调用，Python 进程与 JVM 之间来回转换开销很大。pandas UDF 借助 Apache Arrow 把列数据批量序列化成 pandas Series，函数一次处理一批，序列化和进程间传输成本大幅下降。

使用前提：

  • 环境装好 pyarrow，版本与 Spark 支持范围匹配
  • 打开 Arrow 批量优化开关 spark.sql.execution.arrow.pyspark.enabled=true
  • 函数输入输出是 pandas Series（或按组的 DataFrame），不是单条记录
from pyspark.sql import SparkSession
from pyspark.sql.functions import pandas_udf
import pandas as pd

spark = SparkSession.builder \
    .appName("pandas-udf") \
    .config("spark.sql.execution.arrow.pyspark.enabled", "true") \
    .getOrCreate()

@pandas_udf("double")
def avg_temperature(series: pd.Series) -> float:
    # 整批传入 pandas Series，内部用向量化计算，避免 Python 逐行循环
    return float(series.mean())

spark.udf.register("avg_temp", avg_temperature)

pandas UDF 适合批量统计、字符串向量化清洗这类一次处理一整列的逻辑；如果函数本身依赖逐条外部调用（RPC、查缓存），换成批量也救不回外部开销。

1.4 Catalog API：操作元数据

spark.catalog 是会话级的元数据入口，查库表、管缓存、注册持久化表都走它：

// 列出当前会话可见的表
spark.catalog.listTables().show()

// 列出指定库下的表
spark.catalog.listTables("default").show()

// 缓存与移除缓存
spark.catalog.cacheTable("user_view")
spark.catalog.uncacheTable("user_view")

// 判断表是否缓存
spark.catalog.isCached("user_view")

// 把 DataFrame 注册为持久化表（写入 Metastore）
df.write.saveAsTable("dwd_user_base")
spark.catalog.dropTempView("user_view")

1.5 容易踩的坑

  • 新代码还在用 registerTempTable，IDE 不报警但版本升级后直接移除
  • 全局视图 SQL 漏写 global_temp. 前缀，反复排查表名拼写
  • Python UDF 不开 Arrow，逐行序列化把作业拖慢，还误以为是数据量大
  • pandas 与 pyarrow 版本不兼容，启动即报序列化类找不到
  • 在 UDF 内部打开文件连接、初始化客户端，每个 Task 重复建连，资源被打满
  • 把重业务逻辑塞进 UDF，绕过 Catalyst 优化，谓词下推和列裁剪都受影响

1.7 清单

  1. UDF 注册进会话函数目录后才能在 SQL 中按名调用；内置函数能解决的不要写 UDF
  2. createOrReplaceTempView 会话级，createOrReplaceGlobalTempView 跨会话且引用要带 global_temp 前缀
  3. registerTempTable 已废弃，新代码禁用
  4. pandas UDF 靠 Arrow 批量序列化，前提是装好兼容版本 pyarrow 并打开 Arrow 开关
  5. Catalog 提供表枚举、缓存管理、视图删除等元数据操作，接 Metastore 后可见持久化表
  6. 常见坑：漏前缀、不开 Arrow、版本不兼容、UDF 内重复建连接
