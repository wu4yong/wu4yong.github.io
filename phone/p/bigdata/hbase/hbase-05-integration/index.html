HBase（五）与 MapReduce/Hive/Spark 集成

分类：bigdata · hbase ｜ 标签：HBase

与 MapReduce/Hive/Spark 集成

HBase 自己擅长随机读写和点查，但批量统计、SQL 分析这类活要交给外围计算框架。这一篇看 HBase 怎么和 MapReduce、Hive、Spark 对接，以及 Phoenix 在 HBase 之上补了哪一层 SQL 能力。重点是每种集成的数据进出方式和并行粒度，而不是把连接器配置背下来。

存储分区向多个计算引擎分别开放读取通道，结果再经 SQL 层统一对外查询

1.1 集成要解决什么问题

HBase 直接对外提供的是 Java 客户端和 Scan 接口，适合在线服务；离线分析场景需要把 HBase 数据批量读出来做聚合，或者把计算结果批量写回 HBase。各框架对接的本质都是同一件事：把 HBase 的 Region 作为并行输入分片，把读写操作封装成框架认识的 InputFormat / 数据源。

1.2 MapReduce：TableInputFormat 按 Region 并行

HBase 官方提供 TableInputFormat，让 MapReduce 作业把 HBase 表当输入源。它的并行粒度是 Region：每个 Region 对应一个 InputSplit，Map 任务就近读取该 Region 的数据，避免单点扫全表。

组件
作用
关键点
TableInputFormat
把 HBase 表包装成 MR 输入
按 Region 切 split，并行度与 Region 数量对齐
TableOutputFormat
把 Reduce 结果写回 HBase
批量 Put 写出，按 Region 分组
RowCounter / Export
官方自带工具类
行数统计、全量导出，可直接复用

典型配置片段（MapReduce 作业的 Job 配置）：

import org.apache.hadoop.hbase.mapreduce.TableInputFormat;
import org.apache.hadoop.hbase.client.Scan;
import org.apache.hadoop.conf.Configuration;

Configuration conf = HBaseConfiguration.create();
conf.set(TableInputFormat.INPUT_TABLE, "user_table");

Scan scan = new Scan();
scan.setCaching(100); // 每次 RPC 拉取行数，平衡 RPC 次数与内存
TableInputFormat.setScan(conf, scan);

job.setInputFormatClass(TableInputFormat.class);

要点：MapReduce 读 HBase 仍然受 RowKey 设计约束，没有前缀的全表扫会分散到所有 Region，但每个 Map 内部仍是顺序遍历。写出到 HBase 走批量 Put，不要在 Map 里逐条 RPC。

1.3 Hive：StorageHandler 映射外表

Hive 不直接存 HBase 数据，而是通过 hive-hbase-handler 里的 HiveStorageHandler 把 HBase 表映射成 Hive 外表。建表时声明列族、列限定符和 RowKey 的对应关系，Hive 查这张表时实际下推到 HBase Scan 读取：

环节
做法
注意点
建表映射
Hive DDL 指定 StorageHandler 与 HBase 表名、列映射
HBase 侧表与列族需已存在
查询执行
Hive 生成扫描计划，经 Handler 读 HBase
不支持跨 HBase 表的高效 Join
写入
从 Hive 结果批量落 HBase
大批量写入注意压缩与版本数

这种集成适合”已经在 Hive 数仓里，需要顺带查一份 HBase 明细”的场景。它不是把 HBase 变成数仓：Hive 层面的聚合仍然要扫描 HBase 数据，点查性能不如直连 HBase 客户端。

1.4 Spark：hbase-spark 连接器

Spark 对接 HBase 有两条路径：一条是复用 Hadoop 的 TableInputFormat 生成 RDD，另一条是使用官方 hbase-spark 模块提供的 DataFrame 接口。前者兼容性好，后者在结构化读写上更顺手：

import org.apache.hadoop.hbase.mapreduce.TableInputFormat
import org.apache.hadoop.hbase.client.Scan
import org.apache.hadoop.conf.Configuration

val conf = new Configuration(conf)
conf.set(TableInputFormat.INPUT_TABLE, "user_table")

// 复用 Hadoop InputFormat，按 Region 并行得到 RDD
val rdd = sc.newAPIHadoopRDD(
  conf,
  classOf[TableInputFormat],
  classOf[org.apache.hadoop.hbase.io.ImmutableBytesWritable],
  classOf[org.apache.hadoop.hbase.client.Result]
)

Spark 侧的经验判断：

  • 批量离线读走 RDD / DataFrame 批处理，按 Region 并行，避免一个任务扫全表
  • 流式写出用批量 Put 攒批，不要每条数据一个 RPC
  • 缓存 RDD 前先确认数据量，HBase 全表数据放进内存很容易把 Executor 撑爆

1.5 Phoenix：在 HBase 之上的 SQL 层

Phoenix 是构建在 HBase 之上的 SQL 层，把 HBase 的列式存储包装成关系表模型，对外提供 JDBC 接口。它解决的是 HBase 原生只能写客户端代码、缺少二级索引和 SQL 查询的问题：

能力
说明
与原生 HBase 的关系
SQL DDL / DML
建表、增删改查用 SQL 表达
底层仍是 HBase 表与 RowKey
二级索引
为非 RowKey 字段建索引
索引以额外 HBase 表维护
JDBC 接入
通用 JDBC 驱动连接
业务侧不必直接写 HBase 客户端

需要注意：Phoenix 的二级索引和物化视图都会落成额外的 HBase 表，写入放大和存储成本要算进去；复杂分析查询仍然受 HBase 存储模型限制，跨大表 Join 不是它的强项。

1.7 容易踩的坑

  • 以为连接器能绕过 RowKey 设计：不管 MR、Hive 还是 Spark，底层扫描路径都受主键分布约束
  • 用 Hive 外表扛在线查询：Hive 是批处理引擎，响应延迟不适合在线点查
  • Spark 里把全表 RDD 缓存：HBase 表数据量通常远超 Executor 内存，缓存前先抽样估算
  • Phoenix 索引随便建：每个索引都是一张额外 HBase 表，写入放大和磁盘占用随索引数增长

1.9 清单

  1. 各框架集成的本质是把 HBase Region 作为并行分片，读写封装成 InputFormat 或数据源
  2. MapReduce 用 TableInputFormat / TableOutputFormat，按 Region 切 split，写出走批量 Put
  3. Hive 通过 HiveStorageHandler 把 HBase 表映射为外表，适合顺带分析，不适合在线点查
  4. Spark 可复用 TableInputFormat 生成 RDD，或用 hbase-spark 的 DataFrame 接口，注意批量写出与内存边界
  5. Phoenix 在 HBase 之上提供 SQL 与 JDBC，支持二级索引；索引落成额外 HBase 表，有写入放大
  6. 连接器替代不了 RowKey 设计，所有扫描路径仍受主键分布约束
  7. 选型按在线点查、批量分析、SQL 查询三类需求分开，批处理引擎不要接在线流量
