Java API 与过滤器

这一篇进入开发视角，把 HBase 官方 Java 客户端的核心用法串一遍：怎么拿 Connection 和 Table，怎么写 Put、做 Get 和 Scan，怎么用 FilterList 组合条件，以及批量操作和协处理器各自解决什么问题。代码按 HBase 1.x / 2.x 通用的客户端模型写，类名和生命周期是重点，参数细节以对应版本 API 文档为准。

客户端通过统一连接通道与数据表句柄交互，条件筛选器在数据返回前逐层收拢结果

1.1 客户端 API 总览

HBase 客户端的核心对象分两层：Connection 是重量级的集群连接，Table 是某张表的轻量级句柄。先把生命周期分清楚，否则容易在连接复用和资源关闭上出问题：

对象
作用
生命周期
Connection
持有集群元数据、RegionServer 连接池
重量级，一个应用共享一个，用完关闭
Table
对应一张表的操作句柄
轻量级，用完即关，不要长期缓存
Put / Get / Scan
一次读写操作的参数载体
单次请求内构造使用
Result / ResultScanner
单行结果 / 扫描迭代器
用完关闭，释放服务端扫描资源

1.2 建立 Connection 与获取 Table

Connection 由 ConnectionFactory 创建，配置从 hbase-site.xml 读取；Table 从 Connection 获取。注意 Connection 线程安全、可复用，Table 实例不建议多线程共享：

import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.hbase.HBaseConfiguration;
import org.apache.hadoop.hbase.client.Connection;
import org.apache.hadoop.hbase.client.ConnectionFactory;
import org.apache.hadoop.hbase.client.Table;

Configuration conf = HBaseConfiguration.create();
// 集群地址通常由 hbase-site.xml 提供，这里不显式硬编码
Connection connection = ConnectionFactory.createConnection(conf);
Table table = connection.getTable(TableName.valueOf("user_table"));
// 使用完毕：先关 Table，再在应用退出时关 Connection
table.close();
connection.close();

一个常见错误是把 Table 当单例缓存起来长期复用，句柄背后的资源不会及时释放；正确做法是每次操作从 Connection 取 Table，用完关闭。

1.3 写入：Put

Put 按 RowKey 定位，再往指定列族、列限定符下写值。Cell 内容是字节数组，序列化由客户端自己负责：

import org.apache.hadoop.hbase.client.Put;
import org.apache.hadoop.hbase.util.Bytes;

byte[] rowKey = Bytes.toBytes("user001");
Put put = new Put(rowKey);
// 列族 info，列名 name，写入最新版本
put.addColumn(Bytes.toBytes("info"), Bytes.toBytes("name"), Bytes.toBytes("Alice"));
// 显式指定时间戳，覆盖默认的当前时间
put.addColumn(Bytes.toBytes("info"), Bytes.toBytes("age"), 1637904000000L, Bytes.toBytes("28"));
table.put(put);

几个要点：

  • 列族必须在建表时定义，列限定符可以动态新增
  • 不显式传时间戳时，服务端取写入时刻作为版本号
  • 同一个 Put 里写多个列，服务端作为一次 Region 写入处理

1.4 读取：Get 与 Scan

Get 按单行主键定点取，Scan 按 RowKey 区间顺序扫。两者都可以裁剪返回的列族、列和版本数，减少网络与磁盘开销：

import org.apache.hadoop.hbase.client.Get;
import org.apache.hadoop.hbase.client.Result;
import org.apache.hadoop.hbase.client.Scan;
import org.apache.hadoop.hbase.client.ResultScanner;

// 单行读取：只取 info:name 一列
Get get = new Get(Bytes.toBytes("user001"));
get.addColumn(Bytes.toBytes("info"), Bytes.toBytes("name"));
Result result = table.get(get);

// 范围扫描：从 user001 到 user099，限制返回版本数
Scan scan = new Scan();
scan.withStartRow(Bytes.toBytes("user001"));
scan.withStopRow(Bytes.toBytes("user099"));
scan.addFamily(Bytes.toBytes("info"));
scan.setMaxVersions(1);

try (ResultScanner scanner = table.getScanner(scan)) {
    for (Result r : scanner) {
        // 逐行处理 r
    }
}

Scan 的 ResultScanner 持有服务端扫描上下文，必须关闭释放资源；大区间扫描建议分批设置缓存行数，避免一次性拉回过多数据。

1.5 过滤器与 FilterList

过滤器在服务端按条件收拢结果，减少回传数据。单条件用具体 Filter，多条件用 FilterList 组合，逻辑分全通过（MUST_PASS_ALL）或任一通过（MUST_PASS_ONE）：

import org.apache.hadoop.hbase.filter.FilterList;
import org.apache.hadoop.hbase.filter.SingleColumnValueFilter;
import org.apache.hadoop.hbase.filter.CompareOperator;
import org.apache.hadoop.hbase.filter.BinaryComparator;

FilterList list = new FilterList(FilterList.Operator.MUST_PASS_ALL);

// 条件一：info:age 大于等于 20
SingleColumnValueFilter ageFilter = new SingleColumnValueFilter(
        Bytes.toBytes("info"), Bytes.toBytes("age"),
        CompareOperator.GREATER_OR_EQUAL, new BinaryComparator(Bytes.toBytes("20")));
list.addFilter(ageFilter);

// 条件二：info:city 等于 "cd"
SingleColumnValueFilter cityFilter = new SingleColumnValueFilter(
        Bytes.toBytes("info"), Bytes.toBytes("city"),
        CompareOperator.EQUAL, new BinaryComparator(Bytes.toBytes("cd")));
list.addFilter(cityFilter);

Scan scan = new Scan();
scan.setFilter(list);

使用过滤器要记住两条边界：

  • 过滤器不能替代 RowKey 设计：不带 RowKey 前缀的条件过滤仍然要大范围扫描，只是在服务端丢弃数据
  • 过滤发生在服务端，但扫描本身要遍历到对应文件；复杂过滤器会增加 RegionServer CPU 开销，重条件下要评估分页与前缀设计

1.6 批量操作

单行逐条写、逐条读会产生大量 RPC 往返。客户端提供按列表提交的批量接口，把多个操作合并到一次网络交互里：

import java.util.ArrayList;
import java.util.List;

List<Put> puts = new ArrayList<>();
for (int i = 0; i < 100; i++) {
    Put p = new Put(Bytes.toBytes("user" + i));
    p.addColumn(Bytes.toBytes("info"), Bytes.toBytes("name"), Bytes.toBytes("name" + i));
    puts.add(p);
}
table.put(puts); // 批量写入，减少 RPC 次数

批量接口内部按 Region 分组发送，部分失败时结果按列表顺序返回，需要逐条检查状态；批量不等于事务，跨 Region 的多行操作不具备原子性。

1.7 协处理器概述

协处理器（Coprocessor）把部分计算推到 RegionServer 侧执行，避免把全量数据拉到客户端再算。官方分两类：

类型
类比
典型用途
Observer
数据库触发器
在 Put / Get / Delete 前后挂钩子，做校验、索引维护、审计
Endpoint
存储过程
在各 Region 上并行执行聚合，再由客户端汇总结果

协处理器的代价是把业务逻辑下沉到存储侧，调试和升级都更复杂。常规需求优先用客户端 Scan + 过滤和批量接口；只有聚合下推、跨大量行的触发逻辑这类场景才考虑协处理器。

1.8 容易踩的坑

  • Connection 用完不关、Table 反复创建：连接要共享复用，句柄随用随关
  • 全表 Scan 加过滤器当查询：没有 RowKey 前缀兜底，过滤只是服务端丢数据，扫的代价一分没少
  • 把批量写入当事务：跨 Region 多行不原子，失败要逐条处理返回结果
  • 直接在客户端缓存 Table 句柄：长生命周期句柄会累积资源占用

1.10 清单

  1. Connection 重量级、线程安全、全局共享；Table 轻量级、用完即关
  2. Put 按 RowKey + 列族 + 列限定符写版本，字节序列化由客户端负责
  3. Get 定点取单行，Scan 按 RowKey 区间顺序扫，ResultScanner 必须关闭
  4. FilterList 用 MUST_PASS_ALL / MUST_PASS_ONE 组合条件，过滤在服务端执行
  5. 过滤器替代不了 RowKey 设计，无前缀条件仍是大范围扫描
  6. 批量接口按 Region 分组发送，减少 RPC，但跨 Region 不具备事务原子性
  7. 协处理器分 Observer（钩子触发）与 Endpoint（并行聚合），把计算下沉到 RegionServer，按需使用
