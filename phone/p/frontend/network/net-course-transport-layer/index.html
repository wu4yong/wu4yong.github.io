计算机网络 运输层

分类：frontend · network ｜ 标签：web

计算机网络

运输层

  • 物理层，数据链路层，网络层他们共同解决了将主机通过异构网络互联起来所面临的的问题，实现了主机到主机的通信
  • 但是实际上在计算机网络中进行通信的真正实体是位于通信两端主机中的进程。
  • 如何为运行在不同主机上的应用进程提供直接的通信服务是运输层的任务，运输层协议又称为端到端协议。

运输层端口号

  • 因为因特网上的计算机 并不是统一的操作系统(windows,Linux,MAC)，不同的操作系统使用不同格式的进程标识符。所以需要使用统一的方法对TCP/IP体系的应用进程进行标识。
  • 常见端口号 FTP：21/20 HTTP: 80 DNS: 53 HTTPS: 443

UDP(用户数据报协议)和TCP(传输控制协议)对比

  • UDP在发送数据时，可以随时发送数据(无连接)
  • TCP在传输数据时，必须使用三报文握手建立连接，使用四报文挥手来释放TCP连接。(面向连接)
  • UDP支持单播，多播和广播。
  • TCP仅仅支持单播
  • UDP是面向报文的，运输层的UDP协议直接在应用层交付的数据上加上首部。不拆分数据。(面向报文的)
  • TCP是面向字节流的，运输层的TCP协议把应用层交付的数据分割成TCP报文段。(面向字节流的)
  • UDP向上层提供的是无连接不可靠的传输服务(适用于IP电话，视频会议等实时应用)
  • TCP向上层提供面向连接的可靠传输服务。(适用于文件传输等)

端口号与套接字

  • 端口号是 16 位整数，范围 0 到 65535，用来标识同一台主机上的不同应用进程
  • IANA 把端口号分成三段：系统端口 0–1023，注册端口 1024–49151，动态/临时端口 49152–65535
  • 系统端口和注册端口由 IANA 登记分配，动态端口留给本地和临时使用，不能作为固定的服务标识
  • 常见服务的默认端口只是约定，服务器也可以监听其他端口，客户端连接时需要显式指定
  • 端口号只在本主机范围内标识进程，跨主机的会话还需要 IP 地址配合
  • 一条 TCP 或 UDP 会话由源 IP 地址、源端口号、目的 IP 地址、目的端口号共同确定
  • TCP 和 UDP 各自维护独立的端口号空间，同一个端口号在 TCP 和 UDP 上可以被不同进程同时使用
  • 应用进程通过操作系统提供的套接字接口收发数据，套接字可以理解为 IP 地址加端口号的组合
  • 同一主机上的不同进程绑定不同端口，操作系统根据端口号把收到的报文交给对应进程

UDP 首部与适用场景

  • UDP 首部只有四个字段：源端口、目的端口、长度、校验和，最小首部长度是 8 个字节
  • UDP 长度字段同时覆盖首部和数据部分，校验和用于发现首部和数据在传输中被改动的情况
  • UDP 校验和为全零表示发送方没有计算校验和
  • UDP 不保证数据报一定送达，也不保证送达顺序，重复的数据报也可能出现
  • 应用需要有序、可靠的字节流交付时应当使用 TCP，而不是在 UDP 之上自己补一套确认机制
  • 对时延敏感、允许少量丢包的实时业务（语音、视频、在线会议）常选择 UDP
  • DNS、NTP 等基于 UDP 的应用层协议也直接使用 UDP 数据报传输
  • UDP 是面向报文的：应用层交下来的报文整体加上首部后发出，UDP 不做拆分也不做合并

TCP 提供的服务

  • TCP 面向连接，通信双方在收发数据之前先经过连接建立阶段，结束之后再经过连接释放阶段
  • TCP 面向字节流，应用层交下来的数据被看作一串无结构的字节，由 TCP 自行决定如何划分报文段
  • TCP 在不可靠的 IP 层之上提供可靠交付：通过序号、确认应答、超时重传、校验和等机制保证字节按序到达
  • IP 层不保证顺序、不保证不重复，这些缺口由 TCP 的编号和确认机制补齐
  • TCP 保证字节流不丢失、不重复、按序到达，但不保证应用层消息的边界
  • TCP 通过滑动窗口做流量控制，避免发送方把接收方的缓冲区塞满
  • TCP 提供全双工通信，一条连接上两个方向独立，可以同时收发数据
  • TCP 只支持一对一的单播通信，不支持广播和多播

UDP 与 TCP 的对比要点

  • 连接方式：UDP 无连接，发送前不需要握手；TCP 面向连接，收发数据前先建立连接
  • 交付保证：UDP 不保证可靠交付；TCP 通过确认、重传、编号保证按序可靠交付
  • 报文形式：UDP 面向报文，保留应用交付的报文边界；TCP 面向字节流，不保留报文边界
  • 通信范围：UDP 支持单播、多播、广播；TCP 只支持单播
  • 协议开销：UDP 首部固定 8 字节；TCP 首部至少 20 字节，还可以携带选项字段
  • 适用业务：UDP 用于语音、视频、会议等实时业务；TCP 用于文件传输、网页浏览、邮件等需要可靠交付的业务
  • 运输层协议号：UDP 在 IP 首部协议字段中对应 17，TCP 对应 6
  • 差错恢复：UDP 报文丢失由应用自行处理；TCP 由协议栈完成超时重传和重复去除

运输层与下层协议的关系

  • 运输层运行在网络层之上，把网络层提供的主机到主机服务，扩展为进程到进程的服务
  • TCP 报文段和 UDP 数据报都被封装进 IP 数据报，交给网络层路由转发
  • 运输层不关心底层网络是以太网、Wi-Fi 还是广域网，这些差异由下层协议屏蔽
  • 运输层复用网络层的路由能力，不自己决定数据报经过哪些路径

端口与连接的识别

  • 四元组（源 IP、源端口、目的 IP、目的端口）完全相同的报文属于同一条连接，任一地址或端口不同就是另一条连接
  • 服务器进程绑定知名端口等待客户端接入，客户端临时分配动态端口作为自己的端点
  • 运输层报文向下交给 IP 层时，协议字段标明承载的是 TCP 还是 UDP
  • 同一台主机上 TCP 服务和 UDP 服务可以共用同一个端口号而互不干扰
  • UDP 通信双方没有连接状态，发送和接收之间不需要维持上下文
  • TCP 连接建立后双方各自维护发送窗口、接收窗口和重传队列等状态
  • 应用层选择 UDP 时需要自己处理丢包、重复和乱序带来的问题
  • 运输层把进程间通信复用在网络层的一条 IP 通路上，多个应用可以同时使用同一台主机的网络
