计算机网络 输入URL到展示页面的全过程

分类：frontend · network ｜ 标签：web

计算机网络

输入 URL 到展示页面的全过程

一、检查缓存

  • 先检查缓存，如果强缓存成功，浏览器不会发出网络请求直接使用本地缓存的内容。如果强缓存失败检查协商缓存。服务器返回304代表着协商缓存生效，服务器返回200代表着协商缓存失败。

二、DNS解析

  • 通过域名得到IP地址，DNS协议运行在UDP协议之上

  • 先搜索浏览器本身的DNS缓存，如果没有的话，本地DNS服务器发起迭代的DNS解析请求。最终本地服务器得到外部服务器返回的域名的对应IP地址。获取到IP地址之后，可以准备向这个IP地址发送请求。

  • HTTP报文封装成 TCP数据报封装成 IP数据报封装成 帧然后通过以太网进行转发

四、TCP连接

4.1 三次握手建立连接

  • 客户端主动打开，服务器端被动打开。
  • TCP建立连接成功之后，客户端开始向服务器端发送HTTP请求

4.2 四次挥手断开连接

  • 服务器响应完客户端的请求之后，解除TCP连接。
  • 客户端主动关闭，服务器端被动关闭。

五、发送 HTTP 请求并且获得 HTTP 响应

  • HTTP连接是基于TCP连接
  • https 协议就是http +ssl协议

六、浏览器渲染解析页面

  • 浏览器解析 html 文档，生成 DOM 树。
  • 浏览器解析 css 文档，生成 CSSOM 树。
  • 浏览器将 DOM 树和 CSSOM 树合并，生成渲染树。
  • 浏览器根据渲染树进行布局，生成布局树。
  • 浏览器根据布局树进行绘制，生成绘制树。
  • 浏览器根据绘制树进行渲染，生成渲染结果。

七、DNS 解析的层次

  • 浏览器先查自身的 DNS 缓存，未命中再查操作系统缓存和本机 hosts 文件
  • hosts 文件中的条目在普通 DNS 查询之前被操作系统优先使用
  • 本地 DNS 服务器收到查询后，按迭代方式依次向根域名服务器、顶级域服务器、权威域名服务器查询，直到拿到域名对应的 IP 地址
  • 迭代查询中本地 DNS 每一步向下一跳域名服务器询问，由对方返回下一跳地址
  • DNS 查询报文运行在 UDP 之上，使用 53 端口
  • 解析得到 IP 地址后，浏览器才开始与目标主机建立运输层连接

八、URL 的组成与解析

  • 浏览器按 URL 规范把输入的地址拆成协议、主机、端口、路径、查询串、片段等组成部分
  • 协议部分决定后续使用的传输方式，例如 http、https、ws、wss
  • 主机部分可以是域名或 IP 地址，端口部分缺省时由协议使用默认端口，http 默认 80，https 默认 443
  • 路径和查询串定位服务器上的具体资源，片段只在浏览器内部使用，不会随请求发送给服务器
  • URL 解析逐字符识别各组成部分，解析失败的地址会按规范返回错误
const url = new URL('https://example.com:8080/docs/page?id=1#section');
url.protocol; // https:
url.hostname; // example.com
url.port;     // 8080
url.pathname; // /docs/page
url.search;   // ?id=1
url.hash;     // #section

九、从 DOM 到屏幕的渲染流程

  • 浏览器解析 HTML 生成 DOM 树，解析 CSS 生成 CSSOM 树
  • DOM 与 CSSOM 合并成渲染树，渲染树只包含页面可见的内容，display: none 的元素不在渲染树中
  • 布局步骤确定每个元素在页面上的位置和尺寸，依赖屏幕视口大小
  • 布局完成后浏览器把内容绘制到屏幕上；加载完成后的更新只重绘受影响的区域
  • 元素增删改或窗口缩放都会重新触发布局，样式变化只影响需要重绘的区域
  • CSS 规则级联和继承在 CSSOM 构建阶段处理，渲染树只计算最终生效的样式
  • CSS 默认阻塞渲染，浏览器要等 CSSOM 构建完成才生成渲染树；脚本在解析 HTML 时可能修改 DOM，会影响后续解析流程

十、解析与渲染的补充要点

  • 域名解析失败或超时前，浏览器不会发起运输层连接
  • 本地 DNS 缓存和 hosts 文件是本机链路，公网权威链路只在前两级未命中时才走
  • URL 片段（hash）用于页面内定位，服务器日志里通常看不到片段内容
  • 渲染树跳过不可见元素，这些元素既不参与布局也不参与绘制
  • 布局依赖视口尺寸，窗口旋转或缩放会重新计算元素位置
  • 脚本同步执行会阻塞 HTML 解析，资源加载顺序会影响首次渲染时间
