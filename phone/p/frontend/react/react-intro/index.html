React 入门

分类：frontend · react ｜ 标签：web

React

React

  • React 是 跨平台 的 UI 框架，React 应用程序同样可以渲染到移动设备或者桌面平台，这些平台可能使用不同的 UI 原语

React 组件

  • React 是由被称为 组件 的独立 UI 片段构建而成
  • React 组件本质上是可以任意添加标签的 JavaScript 函数。组件名必须以大写字母开头
  • React 相比于 Vue 的优势之一是一个文件内能声明多个组件，拆分组件的代价更小
  • 组件可以渲染其他组件，但是不要嵌套他们的定义。仅在顶层声明组件

纯函数组件

  • 保持组件的纯粹性，使用纯函数来定义 React 组件来避免一些令人困惑的错误和不可预料的行为
  • 只负责自己的任务：不会更改在该函数调用前就已经存在的对象或者变量，不会更改函数作用域外的变量
  • 输入相同，输入相同：给定相同的输入，纯函数总是返回相同的输出
  • 一般来说，你不应该期待你的组件以任何特定的顺序被渲染。每个组件应该独立
  • 使用严格模式检测不纯的计算：严格模式下开发，它将会调用每个组件函数两次，严格模式有助于找到这些违反规则的组件
  • 但某些事物在特定情况下不得不发生变化，被称为副作用，与渲染过程无关。在 React 中副作用通常属于事件处理程序，因此事件处理程序无需是纯函数
  • 如果你用尽一切办法，仍无法为副作用找到合适的事件处理程序，你还可以调用组件中的 useEffect 方法将其附加到返回的 JSX 中。这会告诉 React 在渲染结束后执行它。然而，这种方法应该是你最后的手段。

纯函数的好处

  1. 你的组件可以在不同的环境下运行 — 例如，在服务器上！由于它们针对相同的输入，总是返回相同的结果，因此一个组件可以满足多个用户请求。
  2. 你可以为那些输入未更改的组件来 跳过渲染，以提高性能。这是安全的做法，因为纯函数总是返回相同的结果，所以可以安全地缓存它们。
  3. 如果在渲染深层组件树的过程中，某些数据发生了变化，React 可以重新开始渲染，而不会浪费时间完成过时的渲染。纯粹性使得它随时可以安全地停止计算。

组件的 props

  • 父组件传给子组件的属性都放在 props 对象里，子组件可以直接解构出具体属性使用
  • props 是只读的：组件不能修改收到的 props，需要交互状态时应该在组件内部使用 state
  • 每次渲染子组件都会收到一份新的 props 时间快照，而不是一直沿用初次的值
  • 即使是 className 这种 DOM 元素上固有的 prop，也不会自动应用到内部元素上，需要手动指定

组件定义的约定

  • 组件名必须以大写字母开头，用来和内置 DOM 标签区分
  • 组件可以渲染其他组件，但不要在组件定义内部嵌套另一个组件的定义，只在顶层声明组件
  • 组件之间通过 props 传值，组件内部不修改收到的 props
  • 一个文件内可以声明多个组件，拆分组件的代价更小

渲染过程的纯粹性

  • 组件函数只读取 props、state、context，不应该修改调用前就已存在的对象或变量，也不应该改动函数作用域外的变量
  • 给定相同的输入，纯函数总是返回相同的输出；两次渲染之间，组件创建的对象和数组不应被当作固定不变的引用
  • 组件不应该依赖特定的渲染顺序，每个组件独立读取自己的 props、state 和 context
  • 纯组件针对相同输入总是返回相同结果，因此可以在服务器、测试等多个环境下被调用
  • 输入未变化时，纯组件可以被安全地跳过渲染或缓存；渲染中途数据过时，React 可以中断过时计算重新开始

事件处理函数

  • 事件处理函数定义在组件内部，命名习惯以 handle 开头后跟事件名，例如 handleClick
  • 传给 JSX 的是函数本身，而不是函数调用结果；onClick={handleClick} 把函数交给 React 在交互发生时调用
  • 处理函数接收事件对象作为参数，stopPropagation() 阻止向上冒泡，preventDefault() 阻止浏览器默认行为，两者互不替代
  • 事件处理程序只在交互发生时运行，不参与渲染输出的计算，因此不需要保持纯函数约束

副作用与 Effect

  • 订阅、定时器、手动操作 DOM、发请求这类渲染输出之外的操作属于副作用，不写在渲染表达式里
  • 副作用优先放在事件处理程序；只有找不到对应事件可以绑定时，才用 useEffect 在渲染结束后执行，这是最后手段
  • 如果在渲染深层组件树时某些数据已经过时，纯粹性让 React 可以安全地丢弃过时渲染结果，不必等整棵树渲染完

严格模式

  • 开发环境开启严格模式后，React 会把组件函数调用两次，用来找出违反纯粹性的写法
  • 这个双倍调用只发生在开发环境，不影响生产环境；如果组件逻辑是纯的，重复调用不会改变结果
  • 严格模式同样会把 state 初始化函数、更新函数、Effect 的 setup 和 cleanup 多跑一遍，用来校验副作用是否成对可撤销
function Profile({ name, age }) {
  return (
    <section>
      <h2>{name}</h2>
      <p>{age}</p>
    </section>
  );
}
function handleClick(e) {
  e.preventDefault();
  alert('clicked');
}

<button onClick={handleClick}>Send</button>
