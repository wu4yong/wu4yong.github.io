七、组合式 API 的组成与写法

  • 组合式 API 是一组函数式 API 的集合，包括响应式 API（ref、reactive、computed、watch）、生命周期钩子（onMounted 等）和依赖注入（provide、inject）
  • 在 Vue 3 中通常配合 <script setup> 使用；选项式组件也可以通过 setup() 选项接入组合式写法
  • <script setup> 中的代码会在每次组件实例被创建时执行，顶层绑定可以直接在模板中使用
  • 组合式 API 基于函数组合，不等同于函数式编程；Vue 仍然使用可变的、细粒度的响应式系统
<script setup>
import { ref, onMounted } from 'vue'

const count = ref(0)

function increment() {
  count.value++
}

onMounted(() => {
  console.log(`The initial count is ${count.value}.`)
})
</script>

<template>
  <button @click="increment">Count is: {{ count }}</button>
</template>

八、响应式状态的注意点

  • ref() 包装基本类型，访问和修改需要走 .value；在模板中使用时会自动解包
  • reactive() 只能用于对象类型（对象、数组、Map、Set 等），不能持有字符串、数字、布尔值等原始类型
  • 直接解构 reactive 对象会丢失响应式连接；需要保持引用时可以用 toRefs 把属性转为 ref
  • reactive 对象不能整体替换为另一个对象，否则响应式连接会断开
  • 计算属性 computed() 接收 getter 函数，返回计算属性 ref，值会基于其响应式依赖被缓存
  • 侦听器 watch() 在响应式状态变化时执行回调，用于处理副作用
  • ref 可以持有对象、数组、Map 等复杂类型，内部对非原始值使用响应式代理
  • 把 ref 传给函数后，仍然保留对最新值的访问和响应式连接，便于在组合函数间传递状态

九、组合函数的组织方式

  • 同一逻辑关注点相关的代码归到一个组合函数里，可以抽到外部文件复用，函数内部不依赖组件实例的 this
  • 组合函数命名以 use 开头，接收参数、返回状态与方法，多个组合函数之间可以互相调用
  • 抽取逻辑时先在组件内整理好分组，再移动到外部文件，避免边搬边改造成职责混乱
  • 组合函数内部使用的响应式状态和钩子都来自 Vue 的 API，不依赖某个具体组件实例
  • 一个组合函数只负责一个关注点，跨函数共享的状态通过参数返回值或依赖注入传递
  • 生命周期钩子需要在 setup() 内同步注册，不能放在普通异步回调里调用
  • 组合函数内部使用的响应式状态和钩子都来自 Vue 的 API，抽取到外部文件后仍然生效
  • 显式的 setup() 函数接收 props 与上下文对象，上下文提供 attrs、slots、emit、expose
  • setup() 内部访问不到组件实例的 this，逻辑通过参数与返回值组织，而不是依赖实例上下文

十、类型推导与打包体积

  • 组合式 API 基于普通变量和函数，类型友好，配合 TypeScript 可以获得完整的类型推导
  • <script setup> 的模板会编译为同一作用域内的内联函数，本地变量名可以被压缩，对生产包体积更友好
  • 选项式 API 不会被废弃，中小规模项目仍然适用；组合式 API 更适合逻辑复杂、需要长期维护的组件
  • 仅使用组合式 API 及少量必需选项的组件，可以通过编译时标记去掉运行时中针对选项式 API 的支持代码
  • 与 React Hooks 相比，setup() 代码只执行一次，不限制调用顺序，可以条件调用；依赖由响应式系统自动收集，无需手写依赖数组
  • 同一项目里选项式与组合式可以共存，迁移阶段按组件逐步切换，不需要一次性重写全部代码
  • 逻辑关注点归组之后，重构时不需要在各个选项块之间来回查找同一组代码
  • 组合函数返回的状态与方法可以直接在模板或其他组合函数中使用，不需要经过实例代理
  • 抽取复用逻辑时，先在组件内把相关代码整理成组，再移动到外部文件保持职责单一
  • 响应式状态的变更由系统追踪依赖并触发更新，组件侧不需要手动订阅状态变化
  • 组合函数内部不直接访问组件实例，便于在组件外独立复用与测试
  • 响应式状态在组合函数间通过返回值传递，保持依赖关系清晰
  • 抽取的组合函数按关注点命名，与组件内的代码分组对应
  • 钩子与状态在 setup 作用域内注册和使用，脱离该作用域不生效
  • 组合函数抽取后可以在多个组件间复用，不需要复制同一组逻辑代码
  • 响应式依赖由系统自动追踪，组件侧不需要手动维护订阅关系
  • 类型标注集中在状态与函数签名上，模板部分保持简洁
