跨端开发

ReactNative

  • React Native 的设计哲学并非强迫你所有东西都用 JS 写，而是提供一个高效率的基准线，并赋予你随时能“穿透”这层天花板、触及原生性能的能力。

一、页面渲染

  • RN 会将 JavaScript 代码中描述的界面组件转化为原生的 UI 组件，比如在 iOS 上转换为 UIKit 组件，在 Android 上转换为 View 体系的组件，利用原生组件的性能和特性来显示界面
  • 在这一过程中，逻辑代码仍然在 JavaScript 环境中运行，通过 桥接机制 与原生组件进行通信和交互
  • 依赖于 React 的虚拟 DOM 机制，每次页面发生变化时，都会通过 Bridge 来传递 diff, 然后原生平台根据 diff 来更新、创建、删除 UI 组件

二、逻辑执行

  • RN 使用 JS 来编写逻辑和界面代码，运行时代码在 JavaScriptCore(IOS) 或 Hermes(Android) 中执行。
  • Hermes 是专门用来在 Android 上运行 JavaScript 代码的引擎，因为它专门针对移动端进行大量优化，所以性能比 V8 更好

三、优势点

  1. JS 的庞大生态
  2. 对于已经掌握 JS、React 的前端开发人员来说，学习成本低、门槛低。有丰富的人员储备
  3. 混合开发：RN 允许原生应用嵌入 RN 组件，RN 应用也可以嵌入原生组件
  4. 代码热重载，无需编译即可看到效果
  5. 应用热更新、解决问题、发布活动无需发布新版本
  6. 虽然并不完善，但是有适配鸿蒙的方案

四、缺点

  1. 仍然使用 JS 来编写逻辑代码，导致性能还是 JS 脚本语言的水平
  2. JSX 转化为 原生 UI 组件，并且通过 Bridge 来传递 diff，相比于原生 UI 来说有一定的性能损耗

五、新旧架构

5.1 旧架构

  • 它是一个异步、可序列化的消息传递系统

5.2 新架构

  • JSI 不是一个消息传递系统，而是一个用 C++ 编写的轻量级通用层。它允许 JavaScript 和 Native 代码直接、同步地相互调用方法。

六、JSX -> native UI 组件

  • 单纯的 JSX 语法本身，是不足以完全表现出 Native 平台组件所有能力的。

七、Hermes 引擎

  • Hermes 是一个为 React Native 优化的开源 JavaScript 引擎，React Native 默认使用 Hermes，无需额外配置开启
  • 相比 JavaScriptCore，Hermes 在启动时间、内存占用和应用体积方面有针对性的优化，具体表现随应用和构建方式不同而变化
  • 构建发布包时，JavaScript 代码会被编译为 Hermes 字节码，从而改善设备上的启动速度
  • React Native 也支持切回 JavaScriptCore，引擎并不是只能二选一的硬绑定

八、跨语言调用的两种方式

  • 旧架构的桥接是一个异步、可序列化的消息传递系统，JavaScript 与原生之间通过消息队列中转界面更新和方法调用
  • JSI 是用 C++ 编写的轻量级通用层，不再走消息队列，允许 JavaScript 和原生代码直接、同步地相互调用方法
  • 旧架构下跨语言调用需要经过序列化和消息中转，高频界面更新时这部分开销会累积
  • 新架构的目标是减少跨语言通信的中转环节，但具体接入仍要按新架构的组件和模块体系改造

九、界面更新的流程

  • React 侧维护界面的虚拟描述，页面变化时把差异传递给原生平台
  • 原生平台根据收到的差异创建、更新或删除对应的原生 UI 组件
  • JavaScript 逻辑仍运行在 JS 引擎环境中，界面的最终绘制落在各平台原生视图体系上
  • 组件层级较深时，视图层级和跨端通信次数都会影响界面刷新的流畅程度

十、混合嵌入

  • RN 允许原生应用嵌入 RN 组件，也允许 RN 应用嵌入原生组件，适合按模块逐步迁移既有原生项目
  • 嵌入的 RN 页面需要随应用一起打包对应的 JavaScript 产物和运行时依赖
  • 混用原生组件时，原生侧能力仍按各平台方式实现，框架只负责在 RN 视图树中接入这些组件

十一、开发时的刷新机制

  • Fast Refresh 在修改代码后尽量保留组件状态并刷新界面，用于开发期快速查看改动效果
  • 刷新机制作用于调试环境，不改变发布包内 JS 产物由引擎加载执行的方式
  • 调试时可以通过运行视图上的引擎标识确认当前使用的是 Hermes 还是 JavaScriptCore

组件到原生视图的映射

  • JSX 描述的基础组件在各端映射为对应的原生视图，例如 iOS 上对应 UIKit 组件，Android 上对应 View 体系组件
  • React 侧的组件树经过差异计算后，由原生平台落到具体视图上，复杂列表和深层嵌套需要关注视图层级带来的开销
  • 原生平台特有的控件无法靠 JSX 语法直接完整表达时，需要通过原生封装再接入 RN 视图树

运行产物与调试

  • 发布包内的 JavaScript 产物由对应 JS 引擎加载执行，开发期通过刷新机制快速查看改动
  • 调试时可以在运行视图确认当前使用的 JS 引擎，按引擎特性排查启动和性能问题
  • 混合嵌入场景下，RN 页面的 JS 产物和引擎依赖需要随宿主应用一起打包
