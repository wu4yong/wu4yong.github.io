跨端 uni-app x

分类：frontend · cross ｜ 标签：web

跨端开发

uni-appX

渲染层面

  • 使用 nuve 渲染，nuve 的渲染性能高于 webview，但是可能存在兼容性问题或者隐藏的BUG

逻辑层面

  • 使用 UTS 进行开发
  • 在 Android 平台上，UTS 代码会被编译为 Kotlin。
  • 在 iOS 平台上，UTS 代码会被编译为 Swift。
  • 在 Web 和 小程序 平台上，UTS 代码会被编译为 JavaScript。

优点

  • 有接近于原生的性能

缺点

  • 目前不支持小程序、鸿蒙
  • uni-appX 技术较新，生态还不完善
  • nuve 的坑和性能，待商榷
  • 这种完全依赖编译的形式，稳定性和可靠性存疑

UTS 语言的编译目标

  • UTS 是一种跨平台强类型语言，用于编写 uni-app x 的业务逻辑和原生插件
  • 在 VDOM 模式下，Android 平台的 UTS 代码编译为 Kotlin，iOS 平台编译为 Swift，鸿蒙 Next 平台编译为 ArkTS，Web 和小程序平台编译为 JavaScript
  • 编译目标不同，意味着同一套 UTS 语法最终落到各端对应的原生语言或脚本运行时上
  • 当写成 UTS 的部分运行在 JS 引擎环境时，仍然通过对应的编译转换执行，而不是直接在浏览器里运行原始 UTS 源码

原生渲染与样式子集

  • App 平台使用原生渲染，界面由原生视图体系绘制，渲染路径不经过 WebView 内核
  • 因为渲染方式不同，App 平台支持的 CSS 是 Web CSS 的子集，部分 Web 样式特性不会被原生渲染器支持
  • 内置组件与 API 沿袭自老 uni-app 和小程序规范，组件命名和调用方式与既有前端习惯保持一致

各端混编与 SDK 接入

  • Android 端可以混编 Kotlin、Java 源码，接入适配 Android 的 SDK、so 库和对应的仓储管理方式
  • iOS 端可以混编 Swift 源码，接入适配 iOS 的动态库、静态库以及对应的包管理方案
  • 鸿蒙端可以混编 ArkTS，接入适配鸿蒙的 SDK 和 ohpm 库管理
  • Web 和小程序平台则可以调用浏览器或小程序提供的 API，并复用对应的 npm 生态库

插件体系

  • uts 插件通过统一的 interface 约束各平台 API 的输入输出乃至错误码，保障跨平台调用的一致性
  • 一个插件模型在不同子平台可以分别引入各自的库依赖，例如 npm 库、Android 仓储、iOS 的 CocoaPods 或 Swift PM、鸿蒙 ohpm
  • 原生 SDK 的 UI 能力可以以原生组件插件的方式嵌入跨端界面，插件生态与既有 uni-app 插件体系相互复用

与老 uni-app 的关系

  • uni-app x 的组件和 API 命名沿袭自老 uni-app 及小程序规范，从老项目迁移时语法和调用习惯上有延续性
  • 老 uni-app 的插件生态在一定程度上被 uni-app x 复用，但原生组件插件在两代方案之间不能直接混用
  • 业务页面和 uvue 页面在方案内部按约定组织，不同渲染模式的页面不能随意混写

开发与适配的注意点

  • 由于 App 端走原生渲染，编写样式时需要以 CSS 子集为准，不能默认所有 Web 样式都被支持
  • 跨端接口在各平台的输入输出由插件 interface 统一约束，平台特有能力仍要按各端方式封装
  • 技术方案较新时，需要关注官方文档对各端最低系统版本和支持范围的说明，再决定落地平台

组件与响应式写法

  • 内置基础组件与 uni-app 和小程序保持一致，例如 view、text、image、scroll-view、input 等
  • 页面采用 Vue 风格的组件组织和状态写法，组件与 API 命名沿袭既有规范，便于前端开发者上手
  • 自定义 uvue 组件可以基于内置组件和 Vue 组件技术封装，并通过 easycom 方式自动接入

跨端 API 与平台能力

  • uni.* 系列接口在各端由对应的编译目标实现，业务代码通过统一接口调用常见能力
  • 平台独有的系统能力不直接暴露在通用接口上，需要通过 uts 插件按各端方式封装
  • 插件 interface 统一了跨端调用的输入输出，平台差异被收敛在插件内部实现

渲染模式与代码形态

  • App 平台走原生渲染，页面样式以 CSS 子集为准，编写界面时不能默认所有 Web 样式特性都被支持
  • 业务代码在 VDOM 模式下由 UTS 编译到各端目标语言或脚本运行时，插件部分保留向原生语言编译的能力
  • 不同渲染模式的页面在方案内部按约定组织，不能在同一个界面中随意混写

落地前需要核对的事项

  • 各端最低系统版本和支持范围以官方文档说明为准，选择落地平台前需要核对对应要求
  • 平台专有能力通过 uts 插件封装，插件 interface 约束了跨端调用的一致性
  • 方案生态和周边完善程度会随版本演进，引入生产项目前需要评估插件覆盖度和文档支持情况
