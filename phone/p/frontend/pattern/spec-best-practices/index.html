编程规范 JS 代码最佳实践

分类：frontend · pattern ｜ 标签：web

编程规范

基础

  1. 使用空行来分割函数中的逻辑
  2. 减少无意义的注释

命名与声明

  • 声明变量优先使用 const，需要重新赋值时再用 let，避免使用 var
  • const 声明的绑定不能被重新赋值，但如果值是对象，对象内部的属性仍然可以修改
  • 变量和函数命名要能表达含义，避免 a、tmp、data1 这类看不出用途的名字
  • 同一个作用域内不要重复声明同名变量，减少变量名之间的冲突
  • 函数名用动词或动词短语，数据对象名用名词，读代码时能从名字看出用途
  • 变量在第一次使用的地方附近声明，避免把所有声明堆在函数开头
  • 布尔值变量用 is、has、can 这类前缀，读名字就能判断是真假值
  • 集合类变量用复数形式，和单个对象区分开
  • 不要使用保留字和拼写相近的名字，避免阅读时混淆

分支与判断

  • 相等判断使用 === 和 !==，避免 == 带来的隐式类型转换
  • 条件分支尽量提前返回，减少 if else 的嵌套层数
  • 遍历数组优先使用 map、filter、forEach 这类数组方法，不要用 for in 遍历数组下标
  • 复杂的条件判断可以提取成命名清晰的布尔变量或小函数，让主流程更容易读懂
  • 分支覆盖不到的边界情况要显式处理，不要默认所有输入都落在预期范围内
  • 条件表达式只做判断，不在判断条件里写改变外部状态的操作
  • 同一判断条件在多处出现时，提取成公共函数避免各处写法不一致
  • 条件分支保持对称，if 处理的情况和 else 处理的情况都要明确

函数书写

  • 单个函数只做一件事，函数过长时按职责拆分成小函数
  • 函数参数不宜过多，参数含义不明确时考虑用对象参数组织
  • 函数内部尽量不修改传入的参数，需要改动时先复制一份再处理
  • 回调嵌套过深时考虑改用 Promise 或 async await 组织异步流程
  • 函数有明确返回值时保持返回类型一致，不要在不同分支返回不同类型的值
  • 副作用集中在少数几个函数里，纯计算逻辑和外部读写分开，便于排查问题
  • 函数内部的临时变量只在当前作用域使用，不要把中间结果挂到外层对象上
  • 函数只返回自己职责范围内的结果，不顺带修改全局状态
  • 函数参数有默认值时显式写出，不依赖调用方传入兜底值

数组与对象处理

  • 遍历数组时不要在原数组上直接增删元素，按需要生成新数组
  • 拷贝对象或数组使用展开运算符或对应复制方法，避免直接引用赋值造成多处改动同一份数据
  • 读取可能为空的对象属性时先判断层级，避免在 undefined 上继续取属性报错
  • 对象的属性名保持统一风格，不要同一文件里混用驼峰和下划线命名
  • 新增属性前先确认对象结构，不在已有对象上随意挂临时字段
  • 遍历复制得到新数组后，后续操作只作用于新数组

作用域与声明

  • let 和 const 有块级作用域，声明之前访问会进入暂时性死区并抛出错误
  • var 声明会被提升到函数顶部，循环里用 var 声明的计数器会在循环外残留
  • 尽量不在条件语句或循环内部声明函数，避免不同分支下函数互相覆盖
  • 声明集中在作用域顶部，便于一眼看清当前作用域用到了哪些变量

错误与异步

  • 可能失败的操作显式捕获错误，不要让异常静默吞掉
  • Promise 链末尾保留错误处理，未捕获的拒绝会中断后续流程
  • 异步流程中保持上下文清晰，不在回调里改动外层已经确定的状态
  • 异步返回的数据在使用前确认结构，不把未完成的 Promise 当成最终值传给后续逻辑
  • 捕获错误后给出可定位的信息，不要只打印一个笼统的报错
  • 异步任务的超时和取消路径要有处理，避免任务一直挂起

资源与清理

  • 订阅事件、开启定时器、建立连接后，在不再需要的位置对应移除或关闭
  • 用完的引用主动断开，避免对象被长期持有无法被回收
  • 临时生成的 DOM 节点和监听器随页面或组件销毁一并清理
  • 长时间运行的定时器和订阅要在退出路径上统一注销
  • 清理顺序与创建顺序相反，先注销后释放持有的对象

注释与格式

  • 注释用来解释为什么这样写，而不是复述代码表面做了什么
  • 公共函数、复杂算法和不易理解的边界条件需要写注释，一目了然的代码不必额外注释
  • 同一文件内的缩进、引号、分号风格保持一致，不混用两套写法
  • 函数内部用空行分隔不同逻辑块，但不要连续留多个空行
  • 删除不再使用的变量和函数，注释掉的旧代码确认无用后一并清理
  • 注释随代码一起维护，代码改了对应的注释要同步更新
  • 格式争议交给统一的风格约定，不在代码里保留个人习惯
