编程规范

编程范式

一、命令式编程

  • 命令式编程中，程序执行的步骤和顺序是特别重要的
  • 命令式编程中，使用赋值，循环，条件和函数

二、函数式编程

  • 函数和数据集合是函数式编程的核心
  • 主要目标是描述数据以及要对数据应用的转换
  • 函数式编程中程序的执行循序重要性很低
  • 函数式编程中可以滥用递归和函数
  • 在函数式编程中，要避免副作用和可变数据，意味着我们不会修改传入函数的数据。如果需要基于输入返回一个解决方案，可以制作一个副本并返回数据修改后的副本
  • 使用 JavaScript 的函数式编程，需要善于使用 map, filter, reduce 等函数

三、声明式编程

  • 在使用 Vue 等框架时，只需要声明数据，而不需要关注数据如何被渲染成DOM

四、面向对象编程

4.1 基于类的面向对象编程

  • Java 等语言通过 new 一个类来生成新的对象

4.2 基于原型的面向对象编程

  • JS 通过复制原型的方式来快速的创建一个对象
  • 重点描述基于原型的面向对象编程和基于类的面向对象编程有哪些区别，使用 JS 来实现面向对象不是使用了 class 这个关键字就可以了。需要更深入的理解面向对象的概念，由于 JS 的鸭子类型，所以 Java 中的很多复杂操作都是可以简化的

五、命令式与声明式的关系

  • 命令式描述「怎么做」，一步步写出执行的语句、循环和条件
  • 声明式描述「要什么」，把具体执行过程交给底层框架或运行时处理
  • 两者描述的层次不同，声明式代码内部通常仍然由命令式实现，并不是非此即彼的对立关系
  • 同一个程序里可以混用不同范式，按模块或按函数选择合适的写法
  • 描述界面结构和数据关系时偏向声明式，描述逐步计算过程时偏向命令式

六、函数式编程的常用方法

  • 函数式编程围绕函数和数据集合展开，常用 map 对每个元素做转换，filter 筛出符合条件的元素，reduce 把集合归并成一个值
  • 纯函数同样的输入永远得到同样的输出，不依赖外部可变状态，也不产生外部副作用
  • 处理数据时倾向于返回副本而不是修改原数据，避免在多个调用方之间共享被改动的状态
  • 函数可以作为参数传入其他函数，也可以作为返回值返回，组合多个小函数得到新的处理流程
  • 高阶函数接收函数作为参数或返回函数，是函数式组合的基础
  • 避免在数组方法的回调里做外部副作用，保持回调只处理当前元素

七、面向对象的三个特征

  • 封装把数据和操作数据的方法放在一起，对外只暴露必要的接口，内部实现细节隐藏起来
  • 继承让新对象复用已有对象的属性和方法，在 JavaScript 中这种复用通过原型链上的委托完成
  • 多态指同一操作作用于不同对象可以有不同的解释，JavaScript 的鸭子类型让不同对象只要具备同名方法就可以被统一调用
  • 封装隐藏内部状态，暴露的接口保持稳定后，内部实现可以单独调整
  • 继承复用的是属性和行为定义，具体实例仍然持有自己的状态

八、基于类与基于原型的区别

  • 基于类的语言先定义类的结构，再通过类实例化出对象，对象的类型由所属类决定
  • JavaScript 没有传统类的实例化体系，对象之间通过原型互相委托，class 语法最终仍然落在原型机制上
  • 鸭子类型下不需要显式声明接口，一个对象有没有某个能力，看它是否具备对应的属性和方法即可
  • 原型链上的方法会被所有实例共享，修改原型会影响已经创建的对象
  • 基于原型的语言里，对象之间共享的是查找路径，不是直接复制一份方法副本

九、范式与语言特性

  • JavaScript 的函数是一等公民，天然支持函数式风格的写法
  • 原型委托是 JavaScript 面向对象的底层机制，类和实例的概念都建立在这层机制之上
  • 框架封装了渲染和状态更新流程，使用框架时写的是声明式描述，框架内部再按命令式执行
  • 同一语言可以支持多种范式，选择依据是模块要解决的问题，而不是语言标签
  • 范式会随着语言和框架的发展互相渗透，边界并非固定不变

十、范式选择的参考

  • 流程步骤明确、需要逐步控制执行顺序的代码，用命令式写法更直接
  • 主要工作是对数据集合做转换和筛选时，函数式的数组方法组合更清晰
  • 状态和行为联系紧密、需要围绕对象组织职责时，面向对象的写法更合适
  • 范式是组织代码的思路，具体项目里按模块的职责选择，不必强求全篇只用一种
  • 范式之间可以互相借用思路，例如用纯函数的方式写面向对象里的工具方法
  • 判断范式是否合适，看代码是否更容易读懂和维护，而不是追逐概念
  • 选择写法时优先考虑当前团队的维护习惯，概念上的纯粹性让位于可读性
