客户端与图形化工具：会用一个就够了

命令行验证、Shell 运维、GUI 看结构，各有不可替代的地方｜依据 MySQL 8.4 Client Programs 章节自绘

一、学习目标

  1. 用 mysql CLI 完成连接、看版本、批量导入、导出四件事；
  2. 知道 mysqlsh（MySQL Shell）能补 CLI 的哪块短板，尤其是升级检查与 JSON；
  3. 在 Workbench、DataGrip、Navicat 之间做选择时，清楚各自的代价。

二、前置知识

上一讲装好的实例。会用终端和配置文件即可。

三、理论讲解（官方定义）

官方把客户端分成两类：命令行工具（mysql、mysqladmin、mysqlbinlog、mysqldump 等）与交互式工具（MySQL Shell）。图形化里官方只维护 MySQL Workbench，其余都是第三方。

几个常被忽略的官方事实：

  • mysql 客户端默认会自动提交（autocommit=1），与 GUI 一致，只是 GUI 把它藏进了设置项；
  • \s（或 status）会打印当前连接的服务端版本、字符集、SSL 状态、连接 ID——排查「连的到底是哪个实例」最快的手段；
  • mysqladmin 的 ping/status 是探活的标准命令，容器健康检查就用它；
  • MySQL Shell 的 util 系列是运维工具集，不参与 SQL 执行路径，例如 util check-for-server-upgrade。

四、原理拆解

命令行、Shell、GUI 各管一段，选型看场景而非偏好｜依据 MySQL 8.4 Client Programs 章节自绘

1. CLI 的优势：可脚本化

mysql 的价值不在交互体验，而在「参数即脚本」：

mysql -h10.0.0.11 -P3306 -uapp_rw -p --defaults-extra-file=/etc/my.app.cnf -D demo \
  -e "SELECT COUNT(*) FROM t_order" --batch --raw

--batch 让输出变成制表符分隔、无表格线，直接喂给下游脚本；--raw 关掉转义，避免反斜杠被二次处理。

2. 账号配置与密码别写进命令行

-p 后面不跟密码时会交互输入；写在命令行里会进 history 与进程列表（ps 可见）。生产用 --defaults-extra-file 指定 600 权限的配置文件：

[client]
host=10.0.0.11
port=3306
user=app_rw
password=App_1234

3. 导入导出走 CLI

# 导出结构与数据（单库）
mysqldump --single-transaction --quick --routines --triggers demo > demo.sql

# 导入
mysql -uapp_rw -p demo < demo.sql

--single-transaction 让 InnoDB 在不加全局锁的情况下拿到一致快照，是生产导出的默认姿势（备份细节见 MQ49）。

4. GUI 真正的用处

图形化不可替代的地方只有两个：看表结构与依赖关系、可视化执行计划。它不适合做的事同样明确：批量导入大文件、在生产上跑 SELECT *、把 GUI 的连接配置当唯一记录。

五、场景说明

  1. 容器内排障：镜像里通常只有 mysql 客户端，docker exec -it mysql84 mysql -uroot -p 最快；
  2. 批量导入：永远 CLI + source，GUI 会把整个文件读进内存；
  3. 升级前体检：mysqlsh -- util check-for-server-upgrade，见 MQ02；
  4. 看执行计划树：Workbench 的 Visual Explain 比纯文本 EXPLAIN 直观，适合给非 DBA 讲解；
  5. 日常改表：GUI 的建表向导会生成 DDL，但最终仍要肉眼审一遍字符集、引擎、索引。

六、示例代码/实操步骤

1. 连接与自检

mysql -h127.0.0.1 -P3306 -uroot -p
\s                                  -- 连接信息：版本、字符集、SSL、连接 ID
SELECT VERSION(), CURRENT_USER(), @@port, @@datadir;
SHOW DATABASES;

2. 常用交互命令

SOURCE /tmp/demo.sql;                -- 批量执行脚本
\T /tmp/session.log                  -- 开始记录本次会话输出
\t                                   -- 停止记录
\e                                   -- 用 $EDITOR 编辑上一条语句

SOURCE 出错默认继续执行，排障时加 --force 之外还要看返回码，别以为「没报错就是全成功」。

3. 探活与状态

mysqladmin -h127.0.0.1 -uroot -p ping        # 返回 mysqld is alive
mysqladmin -h127.0.0.1 -uroot -p status      # 简版 QPS / 连接数
mysqladmin -h127.0.0.1 -uroot -p processlist # 当前连接

容器健康检查就用 mysqladmin ping，不要用 mysql -e "SELECT 1"（后者每次都要建连、走完整认证）。

4. MySQL Shell 的三种模式

mysqlsh root@127.0.0.1:3306 --sql           # 纯 SQL，交互体验比 mysql 好
mysqlsh root@127.0.0.1:3306 --js            # JavaScript，适合写脚本
mysqlsh -- util check-for-server-upgrade root@127.0.0.1:3306

Java 侧怎么落地：把客户端能力搬进应用

  1. 探活用连接池而非新建连接：Hikari 的 connection-test-query: SELECT 1 或 JDBC4 的 isValid()，避免每次健康检查都走认证；
  2. 脚本化导入用 LOAD DATA 而不是逐条 INSERT：LOAD DATA LOCAL INFILE 需要连接串加 allowLoadLocalInfile=true，否则驱动会拒绝；
  3. 别在代码里拼 mysql 命令行：运维动作交给运维脚本，应用只做读写；
  4. 本地开发用 CLI 复现线上 SQL：--batch 输出便于贴进工单与对比。

七、常见坑

  1. 密码写在命令行：history、ps、审计日志三处都可能留痕；
  2. GUI 里 SELECT * 拉全表：几十万行直接把客户端内存打满；
  3. 把 Workbench 当服务端：它只是客户端，连不上要先查服务端与网络；
  4. SOURCE 中途报错却以为成功：默认不断开，务必看最后的错误计数；
  5. mysqldump 不加 --single-transaction：非 InnoDB 表或混合引擎会拿到不一致快照；
  6. 用 mysqladmin shutdown 当常规停机：生产要走正常停库流程，避免打断进行中的事务。

八、课后小结

  • CLI 的价值是可脚本化，\s 是确认「连的是哪个实例」的最快方式；
  • 密码走 --defaults-extra-file，不要出现在命令行；
  • 导入导出用 mysqldump + mysql，生产导出加 --single-transaction；
  • mysqlsh 补的是运维工具集与脚本能力，升级检查就用它；
  • GUI 只用来看结构与讲计划，不承担批量操作。

九、思考题

  1. 为什么容器健康检查推荐 mysqladmin ping 而不是 mysql -e "SELECT 1"？

    参考回答：mysqladmin ping 走的是轻量协议交互，握手后即可返回存活状态；mysql -e 每次都要完整建连、认证、执行、退出，开销更大，且在高并发探活时会额外占用连接数。探活只判断「进程与端口是否可用」就够了。

  2. mysqldump 导出的数据在导入时报字符集错误，你会先查什么？

    参考回答：先看导出文件头部的 SET NAMES 与建表语句里的字符集，再对比目标库 character_set_server。常见原因是源库 utf8mb3、目标 utf8mb4，或导出时未带 --default-character-set=utf8mb4。

  3. 为什么说「GUI 建表向导生成的 DDL 仍要人工审」？

    参考回答：向导只保证语法正确，不保证设计合理：字符集、排序规则、引擎、索引与主键类型都可能沿用默认值，比如把主键给成 VARCHAR(255) 或漏掉联合索引顺序，这些错要到数据量上来才暴露。

  4. \s 输出里你最关心哪几项，为什么？

    参考回答：服务端版本（确认没连错实例）、当前用户（确认权限身份）、字符集（排查乱码）、SSL 状态（确认是否加密传输）、连接 ID（与 SHOW PROCESSLIST 对齐定位会话）。
