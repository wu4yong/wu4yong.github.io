窗口函数与 CTE：不聚合也能排序排名

窗口函数在不减少行数的前提下做排名与累计，CTE 把复杂查询拆成可读的几步｜依据 MySQL 8.4 Window Functions 与 CTE 章节自绘

一、学习目标

  1. 讲清 PARTITION BY、ORDER BY、窗口帧三件套，知道默认帧是什么；
  2. 用窗口函数做排名、Top N、环比、累计，并能把结果再过滤；
  3. 会用普通 CTE 拆复杂查询、用递归 CTE 展开层级结构。

二、前置知识

分组聚合与 JOIN。知道 GROUP BY 会减少行数，而窗口函数不会。

三、理论讲解（官方定义）

窗口函数在「一组行」上计算，但保留原行数。语法是 函数() OVER (PARTITION BY ... ORDER BY ... 帧)。

官方要点：

  • PARTITION BY 决定分组，ORDER BY 决定组内顺序，帧决定「当前行参与计算的范围」；
  • 带 ORDER BY 时默认帧是 RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW（累计语义）；
  • 窗口函数不能直接出现在 WHERE / HAVING 里，要套一层子查询或 CTE；
  • CTE 用 WITH name AS (...) 定义，可被后续查询多次引用；WITH RECURSIVE 支持自引用，默认递归深度上限 cte_max_recursion_depth=1000。

四、原理拆解

帧决定「当前行看多远」，CTE 决定「查询分几步」｜依据 MySQL 8.4 Window Functions 与 WITH 章节自绘

1. 三件套各管什么

SELECT id, user_id, amount,
       ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY id DESC) AS rn,
       SUM(amount)  OVER (PARTITION BY user_id ORDER BY id)      AS running_total
FROM t_order;
  • 去掉 PARTITION BY：全表一个窗口；
  • 去掉 ORDER BY：组内无序，ROW_NUMBER 的结果不稳定；
  • 帧不同：ROWS 按行数算，RANGE 按值范围算（同值行会一起进窗口）。

2. 排名三兄弟的差别

函数 并列处理 结果示例（1,1,3）
ROW_NUMBER 不并列，强制唯一 1,2,3
RANK 并列跳号 1,1,3
DENSE_RANK 并列不跳号 1,1,2

「取 Top N」用 ROW_NUMBER 去重更稳；「并列都算第一」用 RANK。

3. 累计与环比

SELECT id, amount,
       SUM(amount) OVER (ORDER BY id)                                   AS total_so_far,
       LAG(amount, 1) OVER (ORDER BY id)                                AS prev_amount,
       ROUND((amount - LAG(amount, 1) OVER (ORDER BY id))
             / LAG(amount, 1) OVER (ORDER BY id) * 100, 2)               AS mom_pct
FROM t_order;

LAG / LEAD 取前后行，环比、同比都用它；首行 LAG 返回 NULL，注意分母为 0 或 NULL。

4. 窗口帧

SELECT id, amount,
       SUM(amount) OVER (ORDER BY id ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS ma3
FROM t_order;

移动平均、滑动窗口靠帧；ROWS 是物理行数，RANGE 是值区间（处理时间序列时更符合直觉，但要求 ORDER BY 列可比较）。

5. CTE：把查询拆成几步

WITH paid AS (
  SELECT id, user_id, amount FROM t_order WHERE status = 2
), agg AS (
  SELECT user_id, SUM(amount) AS gmv FROM paid GROUP BY user_id
)
SELECT * FROM agg WHERE gmv > 1000 ORDER BY gmv DESC;

CTE 的好处是可读 + 可复用：agg 可以被后面多条语句引用。但它不是物化缓存，优化器可能把 CTE 展开或物化，不能指望它「只算一次」。

6. 递归 CTE：层级与树

WITH RECURSIVE tree AS (
  SELECT id, parent_id, name, 1 AS lvl
  FROM t_category WHERE parent_id = 0
  UNION ALL
  SELECT c.id, c.parent_id, c.name, t.lvl + 1
  FROM t_category c JOIN tree t ON c.parent_id = t.id
  WHERE t.lvl < 10
)
SELECT * FROM tree ORDER BY lvl, id;

锚点查询 + 递归成员 + UNION ALL，必须有终止条件（lvl < 10 或 parent_id IS NULL），否则撞上 cte_max_recursion_depth 报错。

五、场景说明

  1. 排行榜：ROW_NUMBER() OVER (ORDER BY gmv DESC) 取前 100；
  2. 每组取最新一条：PARTITION BY user_id ORDER BY created_at DESC + rn = 1；
  3. 累计报表：SUM() OVER (ORDER BY day) 出累计曲线；
  4. 环比同比：LAG(1) / LAG(12)；
  5. 组织架构、分类树：递归 CTE；
  6. 复杂报表拆解：CTE 把「过滤 → 聚合 → 排名 → 过滤」写成四步。

六、示例代码/实操步骤

1. 每个用户最近一单

WITH ranked AS (
  SELECT id, user_id, amount, created_at,
         ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY created_at DESC, id DESC) AS rn
  FROM t_order
)
SELECT * FROM ranked WHERE rn = 1;

窗口函数不能直接写在 WHERE，必须套 CTE 或子查询。

2. 每个城市 GMV 前三的用户

WITH s AS (
  SELECT city, user_id, SUM(amount) AS gmv
  FROM t_order WHERE status = 2
  GROUP BY city, user_id
), r AS (
  SELECT city, user_id, gmv,
         ROW_NUMBER() OVER (PARTITION BY city ORDER BY gmv DESC) AS rn
  FROM s
)
SELECT city, user_id, gmv FROM r WHERE rn <= 3 ORDER BY city, rn;

3. 移动平均与累计

SELECT created_day,
       SUM(gmv) OVER (ORDER BY created_day) AS cum_gmv,
       ROUND(AVG(gmv) OVER (ORDER BY created_day ROWS BETWEEN 6 PRECEDING AND CURRENT ROW), 2) AS ma7
FROM t_daily_gmv;

4. 检查窗口与递归

SELECT @@cte_max_recursion_depth;
EXPLAIN FORMAT=TREE WITH RECURSIVE t AS (SELECT 1 n UNION ALL SELECT n+1 FROM t WHERE n < 5) SELECT * FROM t;

Java 侧怎么落地：窗口结果怎么用

  1. 窗口函数结果必须有稳定排序：ROW_NUMBER 的 ORDER BY 里加上主键兜底，否则并列时结果随机，rn = 1 取到哪条不可控；
  2. 不要用窗口函数替代分页：rn <= 3 是全量算完再过滤，列表分页仍应走索引 + LIMIT；
  3. CTE 拆查询要控制层数：3 层以内可读性最好，超过 5 层常被物化多次；
  4. 递归 CTE 加终止条件：应用侧也要限制深度，防止脏数据形成环导致死循环；
  5. 结果映射：窗口列只是普通数值列，rn 用 long，累计金额用 BigDecimal。

七、常见坑

  1. 窗口函数写进 WHERE：语法直接报错，必须套子查询；
  2. ROW_NUMBER 没写稳定排序：并列时结果不确定；
  3. 默认帧误解：以为 SUM() OVER (ORDER BY x) 是整组求和，其实是累计；
  4. RANGE 帧遇重复值：同值行会一起进窗口，ROWS 不会；
  5. 递归无终止条件：撞 cte_max_recursion_depth 报错或死循环；
  6. CTE 当物化缓存：重复引用可能被多次计算；
  7. 大表上全量窗口：排序 + 分组代价高，先过滤再开窗。

八、版本差异

  • 5.7：无窗口函数、无 CTE，只能用自连接 + 变量模拟，语义和性能都难保证；
  • 8.0：窗口函数与 CTE 均可用（含 RECURSIVE）；WINDOW 子句可定义命名窗口；
  • 8.4：语法与行为延续 8.0，无破坏性变化。

九、课后小结

  • 窗口函数保留行数，GROUP BY 减少行数；
  • 三件套：PARTITION BY 分组、ORDER BY 组内顺序、帧决定范围；
  • ROW_NUMBER / RANK / DENSE_RANK 差别在并列处理；
  • 窗口函数不能进 WHERE，套 CTE 再过滤；
  • CTE 拆步骤，递归 CTE 必须有终止条件。

十、思考题

  1. 为什么 SUM(amount) OVER (ORDER BY id) 得到的是累计值而不是总和？

    参考回答：带 ORDER BY 时默认帧是 RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW，只累加当前行及之前的行；要整组总和就去掉 ORDER BY，或显式写 ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING。

  2. ROW_NUMBER、RANK、DENSE_RANK 在并列时分别怎么排？

    参考回答：ROW_NUMBER 强制唯一序号（1,2,3）；RANK 并列同名次且跳号（1,1,3）；DENSE_RANK 并列同名次不跳号（1,1,2）。

  3. 窗口函数为什么不能直接写在 WHERE 里？

    参考回答：WHERE 在窗口计算之前执行，此时窗口结果还不存在；必须先在子查询/CTE 里算出窗口列，再在外层用 WHERE 过滤。

  4. 递归 CTE 必须满足哪两个条件才不会失控？

    参考回答：一是要有锚点（非递归的初始查询）；二是递归成员必须有终止条件（层级上限或父子关系到底），否则会一直递归到 cte_max_recursion_depth 报错，脏数据成环还会提前死循环。

  5. 「每组取最新一条」用窗口函数和用 LATERAL 有什么区别？

    参考回答：窗口函数一次扫描并按组排序，适合大结果集；LATERAL 是逐行执行相关子查询，行数多时代价线性增长，但写法直观、子查询能走索引时也不慢。
