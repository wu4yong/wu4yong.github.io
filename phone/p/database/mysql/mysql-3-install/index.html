安装与初始化：Linux、Docker、Windows、macOS

Linux 包管理、Docker、Windows MSI、macOS，最终都落到同一次初始化｜依据 MySQL 8.4 Installation 章节自绘

一、学习目标

  1. 在 Linux、Docker（含 macOS 与 Windows）、Windows 原生、macOS 四条路径里装上 8.4；
  2. 说清 --initialize 到底创建了什么，知道临时密码去哪找；
  3. 装完能用五件事验收，不把「能启动」当成「装好了」。

二、前置知识

会用一个 Linux shell、装过 Docker 即可。生产环境还要会用 systemd。

三、理论讲解（官方定义）

官方把安装分成两条路：包管理器安装与二进制/压缩包安装，加上容器方式。三条路的差别只在「文件放哪、服务谁管」，初始化逻辑是同一套：

  • mysqld --initialize 会创建数据目录、系统库（mysql、sys、information_schema）、ibdata1、redo 与 undo，并生成一个随机 root 密码写进错误日志；
  • mysqld --initialize-insecure 同流程但 root 无密码，只建议临时环境，因为首次连接前任何能连到端口的人都能拿到 root；
  • 初始化时必须保证数据目录为空，否则直接失败——这是最常见的报错原因。

8.4 的默认值要提前知道：字符集 utf8mb4、排序规则 utf8mb4_0900_ai_ci、认证插件 caching_sha2_password、mysql_native_password 默认不加载。

2. 初始化的内部动作

初始化不是「建个空库」，它做了四件事：建系统表空间与 mysql.ibd（数据字典）、建 mysql/sys 等系统库、写入 root 账号与默认权限、生成 server 证书（若未指定 --ssl 相关参数）。数据字典从 8.0 起统一存放在 InnoDB 表里，所以初始化完成后 mysql.ibd 不能随便删。

3. Docker 方式的四个关键参数

端口、密码、数据卷、配置挂载｜依据官方镜像文档自绘

  • -p 3306:3306：端口映射，只在本机用可写 -p 127.0.0.1:3306:3306；
  • -e MYSQL_ROOT_PASSWORD：只在数据目录为空时生效，改密码必须进库 ALTER USER；
  • -v <volume>:/var/lib/mysql：数据卷，容器重建后数据还在；
  • -v <conf>:/etc/mysql/conf.d：配置目录，字符集、max_connections 等都从这里进。

五、场景说明

  1. 公司内网生产：二进制 tar.gz + 独立数据盘 + systemd，路径固定，方便备份与迁移；
  2. 本地开发（Mac/Windows）：Docker 一条命令，用完即删，不污染宿主；
  3. Windows 服务器：MSI 安装器装成服务，注意服务名随版本变化（8.4 通常是 MySQL84），用 Get-Service *MySQL* 确认；
  4. CI 流水线：mysql:8.4 服务容器 + 健康检查 mysqladmin ping。

六、示例代码/实操步骤

1. Linux 二进制安装 + 初始化

# 1) 建用户与目录（不要用 root 跑 mysqld）
groupadd mysql && useradd -r -g mysql -s /bin/false mysql
mkdir -p /data/mysql/{data,logs,run} && chown -R mysql:mysql /data/mysql

# 2) 解压官方 8.4 压缩包
tar xf mysql-8.4.*-linux-glibc2.28-x86_64.tar.xz -C /usr/local/
ln -s /usr/local/mysql-8.4.* /usr/local/mysql

# 3) 初始化（数据目录必须为空）
/usr/local/mysql/bin/mysqld --initialize \
  --user=mysql --basedir=/usr/local/mysql --datadir=/data/mysql/data

# 4) 临时密码在错误日志里
grep 'temporary password' /data/mysql/logs/error.log

拿到临时密码后第一件事就是改密码并建业务账号：

ALTER USER 'root'@'localhost' IDENTIFIED BY 'Root_Str0ng!';
CREATE USER 'app_rw'@'10.%' IDENTIFIED BY 'App_1234' REQUIRE SSL;
GRANT SELECT, INSERT, UPDATE, DELETE ON demo.* TO 'app_rw'@'10.%';

2. Docker：macOS 与 Windows 都能直接跑

# macOS / Linux（Docker Desktop 已启动）
docker run -d --name mysql84 \
  -p 127.0.0.1:3306:3306 \
  -e MYSQL_ROOT_PASSWORD=Root_1234 \
  -e MYSQL_DATABASE=demo \
  -e TZ=Asia/Shanghai \
  -v mysql84-data:/var/lib/mysql \
  --restart unless-stopped \
  mysql:8.4
# Windows（PowerShell，Docker Desktop + WSL2 后端）
docker run -d --name mysql84 `
  -p 127.0.0.1:3306:3306 `
  -e MYSQL_ROOT_PASSWORD=Root_1234 `
  -e MYSQL_DATABASE=demo `
  -e TZ=Asia/Shanghai `
  -v mysql84-data:/var/lib/mysql `
  --restart unless-stopped `
  mysql:8.4

Apple Silicon 与 Windows ARM 机器上，官方镜像是多架构的，直接 mysql:8.4 即可；如果拉不到，检查 Docker Desktop 的架构设置，而不是随便加 --platform。

官方文档给的是 Oracle 容器仓库镜像 container-registry.oracle.com/mysql/community-server:8.4，Docker Hub 的 mysql:8.4 是社区常用镜像，两者都是官方发行版，差别在拉取渠道与标签策略。若要在容器内使用 RESTART 语句，官方要求启动参数用 --restart on-failure。

3. Windows 原生安装

用官方 MSI 安装器，勾选「Server only」即可；安装过程中会要求设置 root 密码与端口。装完验证：

Get-Service *MySQL*                 # 确认服务名与状态
& "C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe" -uroot -p -e "SELECT VERSION();"

服务名、安装路径都带版本号，脚本里不要写死，改用 Get-Service 查。

4. macOS

两条路：官方 DMG（推荐，版本确定）或 Homebrew。Homebrew 的 mysql formula 会跟随较新主线，如需 8.4 请用官方 DMG，或用 Docker 方式。

brew install mysql          # 版本随 formula，安装后 mysql.server start
mysql -uroot -e "SELECT VERSION();"

5. 装完必须验的五件事

SELECT VERSION();                                  -- 1) 版本对
SHOW VARIABLES LIKE 'character_set_server';        -- 2) utf8mb4
SHOW VARIABLES LIKE 'collation_server';            -- 3) utf8mb4_0900_ai_ci
SHOW VARIABLES LIKE 'port';                        -- 4) 端口与规划一致
SHOW VARIABLES LIKE 'datadir';                     -- 5) 落在规划盘上

再加一条系统级检查：重启机器或容器，确认能自动拉起（systemd enable 或 --restart 策略）。

Java 侧怎么落地：连接自检与三个必配项

  1. 依赖：spring-boot-starter-jdbc 或 mybatis-spring-boot-starter，驱动 com.mysql:mysql-connector-j 由 BOM 管理；
  2. 连接串：jdbc:mysql://127.0.0.1:3306/demo?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai&characterEncoding=utf8——三个参数分别解决认证、时区、中文乱码；
  3. 连接池：Hikari 的 maximum-pool-size 先按「实例数 × 单实例连接上限」倒推，connection-timeout 设 3s 左右，让拿不到连接快速失败；
  4. 自检接口：启动时执行一次 SELECT 1 与 SELECT @@version，把版本打进日志——升级后能立刻看出连的是哪个实例。

七、常见坑

  1. 数据目录非空就初始化：报 data directory has files，先确认目录是否真的空；
  2. 拿不到临时密码：它只写在错误日志里，不在控制台；容器方式看 docker logs mysql84；
  3. Docker 没挂卷：docker rm 一下数据就没了，开发环境也建议挂；
  4. MYSQL_ROOT_PASSWORD 改不动密码：它只在首次初始化生效，之后必须 ALTER USER；
  5. bind-address 默认只监听本地：远程连不上不是防火墙的错，先看这个参数；
  6. 用 root 跑业务：一旦注入就是整库失守，业务必须用最小权限账号；
  7. Windows 上把安装路径写进脚本：路径与服务名随版本变化，用查询代替硬编码；
  8. 装完不验字符集：utf8mb3 与 utf8mb4 在 emoji 上表现完全不同。

版本差异（8.0 / 5.7 标注）

  • 5.7 的 mysql_install_db 脚本在 8.0 起被 mysqld --initialize 取代，网上老教程照抄会直接失败。
  • 8.4 的 --initialize 依旧生成临时密码，但默认认证插件已是 caching_sha2_password，老客户端需升级。
  • Windows 服务名从 MySQL57、MySQL80 到 MySQL84 逐代变化，脚本必须查而不是猜。

依据：https://dev.mysql.com/doc/refman/8.4/en/data-directory-initialization.html

八、课后小结

  • 四条安装路径的差别只在文件布局与进程管理，初始化逻辑相同；
  • --initialize 生成临时密码进错误日志，--initialize-insecure 只用于临时环境；
  • Docker 四参数：端口、密码、数据卷、配置挂载，缺一不可；
  • 装完验五件事：版本、字符集、排序规则、端口、数据目录，外加自启；
  • 业务账号永远不用 root，权限从最小集开始。

九、思考题

  1. mysqld --initialize 报 data directory has files in it，你会怎么处理？

    参考回答：先确认这个目录是不是真的该清空：如果是从旧实例迁来的数据，绝不能删；正确做法是指定一个新的空目录。只有确认是废弃目录时，才清空后重新初始化，且清空前先备份。

  2. 为什么生产环境不推荐 Docker 跑 MySQL 主库，但开发环境推荐？

    参考回答：主库对 IO 延迟、内存独占、崩溃恢复、内核参数（如 vm.swappiness）敏感，容器共享内核且资源隔离有限，出问题时排查面更大；开发环境追求一键起停与可丢弃，容器最合适。折中做法是生产用容器但绑核绑内存、数据卷落本地 SSD。

  3. 临时密码丢了怎么办？

    参考回答：--initialize 的临时密码只存在错误日志中。丢了不必重装：可以停库后用 --skip-grant-tables 启动改密码，或直接重新初始化空目录（会丢数据，仅限新装）。重装前先确认数据目录没有业务数据。

  4. 装完 SELECT VERSION() 显示 8.0 而不是 8.4，最可能的原因是什么？

    参考回答：PATH 或服务指向了旧版本二进制，或多实例环境下连错端口/socket。用 which mysql、SHOW VARIABLES LIKE 'basedir'、SHOW VARIABLES LIKE 'port' 三处对齐，确认客户端与服务端都是 8.4。
