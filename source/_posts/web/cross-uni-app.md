# 跨端开发

## uni-app

## 跨端原理

- uni-app 基于 Vue.js 开发，使用统一的开发规范和语法
- uni-app 的跨端实现依赖于编译器和运行时的协同工作。编译器将开发者的代码编译为不同平台的输出物，而每个平台（如 Web、Android、iOS、小程序）都有各自的运行时（runtime）来解析这些输出。运行时内置了大量跨端的 API（如 uni.request、uni.getStorage 等），同时允许开发者调用平台专有 API。
- 为了处理不同平台之间的差异，uni-app 提供了条件编译功能

## 打包产物

- 逻辑层的 JS 代码依旧保留，只不过在执行上相比于传统 WEB 技术有一定的优化
- 渲染层有两种渲染方式 1. Webview 渲染 2. 原生渲染(nvue)
- 一些较底层的操作，通过 uni.* 方法，来调用对应平台的 API

## 优点

1. JS 的庞大生态
2. 对于已经掌握 JS、Vue 的前端开发人员来说，学习成本低、门槛低。有丰富的人员储备
3. 代码热重载，无需编译即可看到效果
4. 应用热更新、解决问题、发布活动无需发布新版本
5. 能够支持各个平台的小程序（！核心优势）
6. 支持鸿蒙平台的开发

## 缺点

1. 受限于 WEB 技术栈性能，页面渲染性能和逻辑执行性能，仍是 WEB 的水平

## 条件编译

- 不同平台之间存在能力和 API 差异，uni-app 提供条件编译功能，让开发者只为特定平台编写个性化代码
- 被条件编译包裹的代码在编译期按目标端裁剪，不会影响其他平台的产物
- 跨端封装覆盖不到的平台专有能力，可以借助条件编译单独接入，再在通用代码里走统一的调用入口
- 条件编译与平台特有 API 调用配合使用，既保留一套代码的主体结构，又能在必要处保留平台特色

## 各端的运行方式

- H5 平台的产物在浏览器内核中解析和渲染，遵循 Web 技术栈的运行方式
- App 端支持 WebView 渲染和原生渲染两种方式，原生渲染对应的页面形态为 nvue
- 小程序端的代码由对应小程序平台的运行时解析，再由小程序视图层更新界面
- 同一套业务代码经过编译器和各端运行时的协同，分别输出到 Web、App 和各个小程序平台

## 跨端 API 与原生接入

- `uni.*` 系列 API 把常用的组件和接口做了跨平台封装，覆盖大部分常规业务需求
- 封装不足时，App 端可以进行原生代码混写，也可以集成原生 SDK 来补足平台能力
- 原生插件和 SDK 通常通过插件市场或统一的插件方案接入，跨端接口的输入输出由封装层对齐

## 小程序端的运行约束

- 小程序页面运行在各小程序平台自己的运行时和视图体系内，接口和组件能力受平台规范约束
- 同一套框架代码发布到不同小程序时，需要分别适配各家平台的专有 API 和组件限制
- 小程序端的网络、存储、界面跳转等能力，都要遵循对应平台的开放规则

## 产物与性能的边界

- 逻辑层 JavaScript 代码在各端之间复用，渲染表现受对应端运行时和内核水平约束
- 受 Web 技术栈本身的限制，复杂页面的渲染和逻辑执行性能不会脱离所运行端的基础水平
- 对性能要求高的页面可以选择原生渲染方式，进一步逼近原生界面的流畅度

## 生态与插件

- uni-app 兼容 npm 库，前端既有的 JS 逻辑库可以在项目中直接复用
- 插件市场提供大量跨端组件、SDK 和业务模板，常见能力不必从零封装
- 微信小程序的自定义组件和第三方 SDK 也可以在对应端通过适配方式接入

## 条件编译的组织方式

- 条件编译按目标平台区分代码块，通用逻辑放在条件编译之外，某一端专有的实现隔离在对应块内
- 同一能力在不同端有不同实现时，通过条件编译分别给出，通用入口保持调用方式一致
- 平台专有 API 只在对应端的编译块内调用，避免在其他端产物中引用不存在的接口

## 工程组织与跨端约定

- 页面、组件和接口按统一目录组织，框架内置组件和 `uni.*` API 在各端提供一致的调用入口
- 前端既有的 Vue 语法和小程序风格 API 在项目中沿用，降低前端团队的切换成本
- 引入第三方能力时优先选用跨端插件，平台独有的功能再通过条件编译和原生混写补足

## 跨端能力的边界

- 框架封装的是各端都具备通用实现的能力，某一端独有的系统功能不在通用接口范围内
- 页面性能受所运行端的运行时和内核水平约束，复杂页面的体验需要在目标端实际验证
- 跨端方案提高了代码复用比例，但不能替代各端对平台规范、分发限制和原生能力的适配工作

## 端能力调用的层次

- 最上层是框架内置组件和 `uni.*` 封装 API，在各端提供一致的调用方式
- 封装不足时进入条件编译层，为特定平台单独调用专有接口
- 再往下是原生混写和原生 SDK 集成，处理框架和条件编译都覆盖不到的系统能力
