# 跨端开发

## 跨端技术中涉及到的概念

## 字节码（Bytecode）

字节码是一种`中间代码`，它是由编译器将高级语言编译成的一种中间表示形式。字节码是一种抽象的代码，它可以在`不同的平台上运行`，而不需要重新编译。

### 字节码特点

- `较高的可移植性`，字节码不依赖于特定的硬件平台，只需要有相应的`解释器或虚拟机`即可运行。
- 执行效率相对较低。字节码需要虚拟机`解释执行`或者`即时编译 (JIT)`

## 机器码（Machine code）

机器码是`计算机中央处理器 (CPU)` 能够`直接理解和执行`的`指令`集合，它是由`二进制代码`组成的。机器码是由硬件直接执行的，因此它的执行速度非常快。

### 机器码特点

- `可移植性较差`。不同的 CPU 架构有不同的`机器码指令集`，因此为一种 CPU 架构生成的机器码通常不能在另一种 CPU 架构上直接运行

## 提前编译 AOT（Ahead-of-Time Compilation）

- AOT 是一种编译技术，它在程序`运行之前`将源代码编译成`机器码`，而不是在运行时动态编译。
- AOT 通常用于嵌入式系统和移动设备等资源受限的环境中，因为它可以减少运行时的编译时间和内存占用。
- 例如，C、C++、Java 的 GraalVM 虚拟机(早期 JAVA 虚拟机)

## 即时编译 JIT（Just-in-Time Compilation）

- JIT 是一种编译技术，它在程序`运行时`将源代码编译成`机器码`。
- JIT 通常用于解释型语言和动态语言中，因为它可以在`运行时根据程序的需要进行优化和调整`。当发现某些代码段（如热点代码，即被频繁执行的代码）时，JIT 编译器会将这些代码段动态地编译成机器码，之后再执行这些代码时就可以直接运行编译好的机器码
- 例如，JavaScript、Python、Java 的 HotSpot 虚拟机(现代 JAVA 虚拟机)

## AOT 与 JIT 对比

### 启动速度

- AOT 编译的程序在启动时速度更快，因为它不需要在运行时进行动态编译。
- JIT 编译的程序在启动时速度相对较慢，因为它需要在运行时进行动态编译。

### 运行速度

- AOT 编译时无法获取程序运行时的具体信息，只能基于一些通用的假设进行优化，因此生成的机器码可能不是针对特定运行环境的最优代码。在`某些情况`下，AOT 编译的程序运行速度可能不如 JIT 编译的程序。
- JIT 可以根据程序运行时的实际情况进行优化，例如根据实际的输入数据、函数调用频率等信息生成更高效的机器码。对于热点代码，JIT 编译可以显著提高其执行速度，因此在程序长时间运行后，JIT 编译的程序往往能获得更好的性能

## 代码热更新

- 热更新指的是在不重新发布应用安装包、无需用户重新下载安装应用的情况下，对应用的代码、资源等进行更新的技术

## 应用热重载

- 热重载是一种允许开发者在不重新启动应用的前提下，将代码的更改快速应用到正在运行的应用中的技术。当开发者修改了代码后，只需触发热重载操作，应用就能在保持当前状态（如界面展示、用户输入内容、变量值等）的情况下，更新界面和功能，让开发者立即看到代码修改后的效果

## 跨端方案的渲染路线

- 原生控件渲染：把框架描述的界面映射为各平台原生 UI 组件，由原生视图体系负责绘制和交互
- 自绘引擎：框架自带图形渲染引擎，不依赖系统提供的 UI 组件，直接在画布上完成界面绘制
- WebView 渲染：页面以 HTML、CSS、JavaScript 形式在 WebView 内解析展示，运行表现受浏览器内核约束
- 小程序渲染：逻辑层与渲染层分离，由各小程序平台的运行时解析框架代码，再把变更反映到界面上
- 不同路线在一致性、性能、原生能力调用深度上各有取舍，没有单一方案同时占优

## 解释执行与编译执行

- 解释执行：源码在运行时由解释器逐行翻译并执行，启动快，但运行过程中持续存在翻译开销
- 编译执行：源码在运行之前编译为目标平台可直接执行的指令，启动后执行效率更高，但需要一次编译环节
- 字节码是两者之间的折中：先把源码编译为与具体平台无关的中间表示，再由对应虚拟机解释执行或即时编译
- 同一份源码在不同阶段可以采用不同的执行方式，例如开发期用虚拟机配合调试能力，发布期编译为机器码

## 代码复用的层次

- 视图层复用：界面描述和样式在各平台之间共享，差异部分由框架的运行时适配
- 逻辑层复用：业务流程、数据处理等 JavaScript 或 Dart 代码在多端之间重复使用
- 原生能力层：定位、推送、相机等系统能力无法跨端统一抽象时，仍需要各端分别接入原生实现
- 跨端框架能提高前两层的复用比例，但不能完全抹平各平台系统能力之间的差异

## 热重载与热更新的区别

- 热重载面向开发期：改完代码后把变更应用到正在运行的应用，尽量保留当前界面和输入状态，用于快速查看修改效果
- 热更新面向发布期：在不重新安装应用安装包的前提下更新线上代码或资源，用于修复线上问题和下发活动
- 热重载是开发工具链提供的能力，改动只作用于本机调试环境
- 热更新涉及线上包体和平台分发策略，不同应用商店对代码动态下发的限制并不相同

## 跨端框架的选择权衡

- 界面一致性要求高、需要多端保持同一套视觉时，自绘引擎类方案更容易控制表现
- 团队已有前端技术栈积累时，基于 JavaScript 或 Vue 语法的方案学习成本更低
- 对底层系统能力和原生性能要求高的部分，通常仍要预留各端原生开发的空间
- 选择方案时需要同时评估渲染路线、运行时引擎、生态成熟度和平台分发限制，而不只看代码复用比例
