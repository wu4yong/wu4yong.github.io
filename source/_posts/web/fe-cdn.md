# 前端工程化

## CDN

> CDN 的全称是 Content Delivery Network，即内容分发网络。
> 是一种用于加速网络内容传输的技术和架构。它通过将内容分布到全球各地的服务器节点，使得用户可以从离他们更近的服务器上获取所需的内容，从而减少了网络延迟和提高了内容的传输速度。

## CDN 优点

1. 显著提升用户访问速度
2. CDN 起到了分流作用，减轻了源站的负载。

## CDN 如何查找最优的节点

1. 根据用户的 IP 地址，查看与用户最近的节点
2. 考虑各个节点的负载情况，依据最小连接数、最快响应时间等指标来选择最优的节点

## 项目中使用 CDN 的最佳实践

1. 只外链“体积大、稳定、命名全局清晰”的依赖，临时性或者变化快的包继续本地打包
2. 避免混用同一依赖的 “本地ESM 和 CDN 全局” 两套实例(尤其是 Vue/React)，确保全局单例

### 多外链的书写顺序

1. 框架全局（Vue、React）
2. 依赖该框架的库（Element-UI、Ant-Design-Vue、Vue Router、Pinia）
3. 工具库（axios、lodash、moment）
4. 应用入口（index.js）

## 外链资源的完整性校验

- SRI（Subresource Integrity）让浏览器校验从 CDN 等第三方来源拉取的资源是否被篡改
- 在 `<script>` 或 `<link>` 的 `integrity` 属性上填写资源的 base64 哈希，浏览器执行脚本或应用样式表之前先比对哈希
- 适用的元素包括 `<script>`、带 `rel="stylesheet"` 的 `<link>`，以及 `rel="preload"`、`rel="modulepreload"` 的链接
- 支持的哈希算法前缀是 `sha256`、`sha384`、`sha512`，格式为 `算法-` 加 base64 摘要
- 哈希不匹配时浏览器拒绝执行脚本或应用样式表，并返回网络错误
- 跨源资源做 SRI 校验时，浏览器还会检查 CORS，资源需要带允许共享的 `Access-Control-Allow-Origin` 响应头
- `integrity` 可以写多个用空白分隔的哈希，资源匹配其中一个即可加载
- 外链框架文件升级版本后，要同步更新对应的 integrity 值，否则浏览器会拦截
- SRI 只校验资源内容在传输和缓存过程中未被改动，不能替代对第三方来源本身的信任评估
- 第三方主机被控制后可以注入或替换文件，SRI 正是用来缓解这类风险：哈希对不上就拒绝加载

## 静态资源的缓存配合

- 内容哈希文件名是 cache-busting 的基础：内容不变则 URL 不变，内容一变 URL 跟着变
- 哈希命名的静态资源可以配很长的 `max-age`，并加上 `immutable`，刷新页面时不再发条件请求校验
- `immutable` 表示资源在新鲜期内不会更新，避免浏览器重复发 `If-None-Match` 这类校验请求
- HTML 入口本身不要长缓存，一般用 `no-cache`，每次复用前回源校验，保证用户拿到新的资源链接
- `no-cache` 不是不缓存：响应可以存，但复用前必须回源校验；`no-store` 才是完全不存储
- `max-age=N` 表示响应从源站生成时刻起，N 秒内保持新鲜；缓存已存的时间由 `Age` 响应头记录，会从新鲜度寿命里扣除
- `must-revalidate` 表示资源变陈旧后，复用前必须回源校验，通常和 `max-age` 搭配
- 缓存头和文件名哈希要配套：只加长缓存而文件名不带哈希，更新后用户仍会命中旧文件
- 动态内容或更新频繁的资源，不适合套用长缓存加 immutable 的组合
- 共享缓存（代理、CDN）和浏览器缓存可以通过 `public`、`private`、`s-maxage` 分别控制

## CDN 使用上的补充

- CDN 节点缓存的是可公开访问的静态资源；带个性化内容的接口响应不适合走 CDN 缓存
- 外链依赖要保证全局单例：同一框架不要既走 CDN 全局变量又被本地打包再引入一份
- 外链脚本按依赖顺序排列：框架本体先加载，依赖框架的库随后，工具库和业务入口最后
- CDN 减轻源站压力的前提是资源可缓存；不可缓存的请求仍会回源
- 选择 CDN 资源时优先选版本固定、文件路径稳定的地址，避免指向会被覆盖的 latest 链接
- 资源更新时新内容使用新 URL，旧 URL 的文件在缓存有效期内继续服务老用户
- 多外链场景下，某个 CDN 节点不可用时页面加载会受影响，必要时需要考虑备用地址或回源方案

## 缓存指令补充

- `public` 表示响应可被共享缓存存储；`private` 表示只给单个用户缓存，共享缓存不得存储
- `s-maxage` 控制共享缓存的新鲜度寿命，优先级高于 `max-age`
- `max-age=0` 常被用作 `no-cache` 的兼容写法，因为早期 HTTP/1.0 缓存实现不认识 `no-cache`
- 资源陈旧后，`stale-if-error` 允许在源站出错时继续使用陈旧响应
- 没有显式设置缓存头时，缓存可能按启发式规则自行存储，动态内容应明确写出缓存策略

## SRI 使用补充

- 摘要由资源文件内容计算得到，文件哪怕改一个字节，算出的哈希就对不上
- 生成 SRI 哈希可以用 OpenSSL 或 shasum 命令行工具，再拼成 `算法-摘要` 的形式
- 跨源脚本要带 `crossorigin` 属性，浏览器才会以 CORS 模式读取资源并参与完整性校验
- 多个哈希写在同一个 integrity 属性里，按空白分隔，命中其一即可
- 预加载（preload、modulepreload）的链接同样可以带 integrity 做校验

## CDN 与回源

- CDN 节点未命中缓存时会回源站拉取资源，回源次数和源站带宽相关
- 缓存命中率越高，源站分担的请求越少；命中率低通常是缓存键或缓存时间配置不当
- 静态资源带哈希文件名后，可以放心在 CDN 和浏览器两侧都设长缓存
- HTML 不缓存，保证发布后新链接能被及时拿到；静态资源长缓存，保证复用率
- 接口、个性化页面、未登录状态下的页面，按不可缓存处理
- 资源在 CDN 上的版本与源站一致时，节点直接返回缓存副本
- 框架 CDN 文件通常体积大、版本稳定，适合外链；频繁变动的业务代码继续本地打包
- 同一依赖多实例会破坏框架内部状态（如响应式订阅、单例 store），外链前先确认全局唯一
- 外链地址建议锁定具体版本号，不要用浮动版本链接
- 缓存键一般包含请求 URL；查询参数不同会被当成不同资源
