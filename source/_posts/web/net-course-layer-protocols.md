# 计算机网络

## 计算机网络中每层的协议以及协议的主要作用

## 应用层(报文)

* 直接为用户的的应用进程提供服务(电子邮件，文件传输等)

### HTTP协议

* 无连接，无状态，可靠连接(HTTP可靠是因为TCP是可靠的)

### FTP协议

### DNS协议

## 运输层(报文段/用户数据报)

* 定义了一些传输数据的协议和端口号
* 负责向两个主机中的进程之间的通信提供服务

### TCP协议(报文段)

* 面向连接的，报文段，可靠传输。只支持单播

### UDP协议(用户数据报)

* 无连接的，用户数据报，不可靠传输，支持单播多播广播

## 网络层(IP数据报)

* 在位于不同地理位置的网络中的两个主机系统之间提供连接和路径选择。
* 负责网上不同主机之间提供通信服务
* 选择合适的路由，使得数据能通过网络中的路由器找到目的主机。

### IP协议

* 提供面向无连接，无状态，不可靠传输服务。

## 数据链路层(帧)

* 定义了如何让格式化数据以进行传输，以及如何对控制对物理介质的访问。这一层通常还提供错误检测和纠正，以确保数据的可靠传输。、
* 链路 就是从一个结点到相邻结点的一段物理线路，中间没有任何交换结点(没有路由器)

## 物理层(比特)

* 主要定义物理设备标准，如网线的接口类型、光纤的接口类型、各种传输介质的传输速率等。它的主要作用是传输比特流（就是由1、0转化为电流强弱来进行传输,到达目的地后在转化为1、0，也就是我们常说的数模转换与模数转换）。这一层的数据叫做比特。
* 为了解决在各种传输媒体上传输比特0和1的问题。

## 应用层协议的分工

- HTTP 用于网页浏览，基于 TCP 提供可靠传输；HTTP 本身被设计为无状态，状态保持由 Cookie、会话或令牌等上层机制补充
- FTP 用于文件传送，控制连接与数据连接分开；DNS 把域名解析为 IP 地址；SMTP、POP3、IMAP 分别承担邮件发送、下载和服务器侧邮件管理
- 常见熟知端口：FTP 控制 21、FTP 数据 20、SMTP 25、DNS 53、POP3 110、IMAP 143；端口号由 IANA 统一分配
- 端口号范围分为系统端口（0–1023）、用户端口（1024–49151）、动态或私有端口（49152–65535）

## 运输层协议的分工

- 运输层负责两个主机中进程之间的通信，用端口号区分同一主机上的不同应用进程
- TCP 面向连接，传输报文段，保证可靠交付、按序到达和流量控制，只支持单播
- UDP 无连接，传输用户数据报，不保证可靠交付和顺序，支持单播、多播和广播，报文首部开销小、响应快
- 对可靠性要求高的场景（网页、文件、邮件）使用 TCP；对延迟敏感、允许少量丢失的场景（语音、视频、查询应答）常用 UDP

## 网络层协议的分工

- 网络层在不同地理位置的网络之间提供连通和路由选择，让数据报通过路由器找到目的主机
- IP 协议面向无连接、无状态，提供不可靠的数据报交付；是否可靠由运输层 TCP 负责保证
- ICMP 在 IP 数据报中封装传输，用于报告转发过程中的差错和诊断信息；ARP 根据 IP 地址解析同一链路相邻结点的 MAC 地址
- 主机想和其他网络中的主机通信，必须指定本网络中的出口路由器，即默认网关；子网掩码用于区分 IP 地址中的网络编号和主机编号
- 路由器把收到的数据报目的地址与路由表逐项比对，按匹配条目转发，这个过程叫查表转发

## 数据链路层与物理层的分工

- 数据链路层把网络层交下来的数据封装成帧，在相邻结点之间传送，并通过差错检测处理传输误码
- 链路是相邻结点之间的一段物理线路，中间没有交换结点；数据链路是在链路上加上通信协议的硬件和软件后形成的传输通道
- 差错检测在帧尾携带检测码，接收方据此检查误码；不可靠传输服务直接丢弃有误码的帧，可靠传输服务通过确认、重传等机制保证发送什么收到什么
- 物理层解决在具体传输媒体上传输比特 0 和 1 的问题，屏蔽双绞线、光纤、无线等媒体的差异，使数据链路层不必关心具体媒体是什么

## 各层协议数据单元的封装关系

- 应用层产生的报文向下交给运输层，封装为 TCP 报文段或 UDP 用户数据报
- 运输层数据交给网络层，封装为 IP 数据报；网络层再交给数据链路层，封装成帧，最后由物理层以比特形式传输
- 每层把下层提供的服务当作透明通道，只与相邻层交换协议数据单元，不必关心下层的具体实现
- 运输层复用同一 IP 地址上的多个应用进程，靠端口号区分不同进程
- IP 数据报独立路由，可能失序或丢失；端到端的可靠交付由运输层 TCP 在 IP 服务之上弥补
