## 客户服务器方式(C/S) 对等方式(P2P)

* 客户服务器方式(C/S)所描述的是进程之间服务与被服务的关系
* 对等方式(P2P)中没有固定的服务请求者和服务提供者 ，对等方互相之间直接通信。

## 动态主机配置协议DHCP

* 个人PC机，开机自动启动DHCP程序，自动的获取该PC机的网络配置信息。(IP地址，子网掩码等)
* 应用层DHCP协议使用运输层的UDP协议提供的服务。

## DHCP 的工作过程与端口

- DHCP 在应用层工作，运输层使用 UDP，为客户端自动分配 IP 地址、子网掩码、默认网关、DNS 服务器等网络配置
- 客户端到服务器的报文发往 UDP 67 端口，服务器到客户端的报文发往 UDP 68 端口
- 新客户端启动时还不知道自己的地址，先在本地子网广播 DHCPDISCOVER 报文，寻找可用的 DHCP 服务器
- 收到请求的服务器回复 DHCPOFFER，在 yiaddr 字段给出一个可用地址，并在选项中携带其他配置参数；服务器在分配新地址前可以用 ICMP Echo Request 探测该地址是否已被占用
- 客户端从多份报价中选择一份，发送 DHCPREQUEST 请求该配置，并隐含拒绝其他报价；服务器以 DHCPACK 确认，提交分配的地址
- DHCPNAK 表示客户端记录的地址不正确（例如换了子网）或租约已过期；DHCPDECLINE 表示客户端检测到地址已被占用；DHCPRELEASE 用于主动释放地址并取消剩余租约；DHCPINFORM 用于客户端已有外部配置、只向服务器索取本地参数
- 地址分配带有租约期限，客户端在租约到期前需要续租，租约过期后地址可以被分配给其他主机
- 跨子网时，报文可以由 BOOTP 中继代理转发到不在同一物理子网的 DHCP 服务器

## DNS 的报文与记录类型

- DNS 服务器使用 53 端口，UDP 用于普通查询，TCP 用于区域传送等报文较长的场景
- 本地程序不直接查询域名服务器，而是通过操作系统中的解析器（resolver）发起请求；解析器先查本地缓存，缓存未命中再向外部域名服务器查询
- 资源记录按 TYPE 区分用途：A 记录指向主机的 IPv4 地址，AAAA 记录指向主机的 IPv6 地址，NS 记录指向权威域名服务器，CNAME 记录指向别名的规范域名，SOA 标记一个区的授权起点，PTR 是域名指针，MX 指向邮件交换服务器，TXT 存放文本字符串
- 查询报文中 RD（递归期望）位置 1 时，要求域名服务器递归完成查询；响应报文中 RA（递归可用）位表示该服务器支持递归查询
- TC 位表示报文因长度超过传输通道限制而被截断；响应码 RCODE 区分无错误、格式错误、服务器失败、域名不存在、不支持该查询类型、策略拒绝等情况

## DNS 报文的组成

- DNS 查询和响应报文由问题段、回答段、授权段和附加段组成；解析器先查本地缓存，缓存未命中再向外部域名服务器查询
- AAAA 查询返回该域名关联的全部 AAAA 记录，每条记录存放一个 128 比特的 IPv6 地址
- 域名服务器在回答 NS、MX 等查询时，会在附加段中带上相关主机的 A 和 AAAA 地址

## 电子邮件协议与端口

- SMTP（简单邮件传送协议）负责邮件的发送与服务器之间的中转，默认使用 TCP 25 端口
- 发件人把邮件提交给自己的邮件服务器，邮件服务器之间通过 SMTP 把邮件投递到收件人所在的服务器
- POP3（邮局协议第 3 版）默认 TCP 110 端口，客户端登录后把邮件下载到本地，典型用法是邮件从服务器移除
- IMAP4rev1 默认 TCP 143 端口，邮件保留在服务器上；客户端可以创建、删除、重命名邮箱文件夹，搜索消息并按选择获取消息内容，也可以在离线后与服务器重新同步
- IMAP 中的消息用消息序号和唯一标识符编号，客户端按编号访问和操作邮件
- POP3 把邮件从服务器下载到本地，典型用法是下载后邮件从服务器移除
- FTP 控制连接使用 TCP 21 端口，默认数据连接使用 TCP 20 端口

## 应用层协议与运输层对照

- DNS：UDP 53，完成域名到 IP 地址的解析
- DHCP：UDP 67/68，为客户端自动分配 IP 地址和其他网络配置
- HTTP：TCP，承载网页浏览请求与响应
- FTP：TCP 21/20，完成文件传送
- SMTP：TCP 25，完成邮件的发送和服务器之间的中转
- POP3：TCP 110，把邮件从服务器下载到客户端
- IMAP：TCP 143，在服务器侧管理邮件文件夹和消息

## 应用层与运输层的配合

- 应用层直接为应用进程提供服务，不规定底层用哪种传输方式；具体走 TCP 还是 UDP，由应用协议的需求决定
- DNS、DHCP 这类短报文、强调响应速度的服务使用 UDP；文件传输、邮件、网页这类要求可靠送达的服务使用 TCP
- TCP 是面向连接的可靠传输，提供端到端可靠性、报文重排和流量控制；UDP 是无连接的数据报传输，不保证可靠交付和顺序
- C/S 方式中，客户端进程主动发起连接和请求，服务器进程被动等待请求并提供服务，双方角色固定
- P2P 对等方式中各对等方地位相同，既是请求者也是提供者，对等方之间直接通信，没有中心服务器区分角色
