# JavaScript

## 预编译

当 JS 执行到一段可执行代码时(全局代码，函数代码)就会创建执行上下文，执行上下文中有三个重要的属性

1. 变量对象: 分为全局变量对象和函数变量对象
2. this
3. 作用域链

## 一、JS 执行三部曲

1. 语法分析，通篇扫描
2. 预编译 // 1.函数声明 整体提升     2.变量声明 提升
3. 解释执行

## 二、预编译: 函数 & 全局

### 2.1 函数内实现预编译: 四部曲（预编译发生在函数执行前一刻）

1. 创建 AO（执行期上下文）对象
2. 找形参和变量声明，将变量和形参作为 AO 属性名，值为 undefined。（变量 只有声明提升）
3. 将形参和实参值统一
4. 在函数体里面找函数声明(函数声明和函数表达式是完全不同的)，将函数名作为 AO 属性名，值为函数体。（函数声明整体提升）

### 2.2 全局内实现预编译

1. 创建 GO 对象 ```GO === window```
2. 找变量声明，将变量作为 GO 属性名，值为 undefined。（变量 只有声明提升）
3. 在函数体里面找函数声明，将函数名作为 GO 属性名，值为函数体。（函数声明整体提升）

## 三、函数声明与函数表达式的提升差异

- 函数声明（function 语句）在预编译阶段整体提升，函数体被放进变量对象，声明前调用不会报错
- 函数表达式只提升变量名，赋值留在执行阶段；声明前访问得到 undefined，此时调用会报错
- var 声明只提升声明本身，初始化为 undefined，赋的值不会跟着提升
- let、const、class 属于词法声明，进入块作用域后先处于暂时性死区，声明前访问抛 ReferenceError
- 规范中"提升"并非一个官方术语，不同声明的提升表现并不一致
- 函数声明整体提升后，AO/GO 上同名属性的值是函数体；形参和变量声明属性先置 undefined，再与实参值统一

## 四、作用域链

- 嵌套函数可以访问外层作用域声明的变量，外层作用域再向外层形成链条，即作用域链
- 变量解析时沿作用域链由内向外查找，找到即停止；整条链上都找不到才报 ReferenceError
- 作用域链在函数创建时按词法作用域确定，函数在哪里被调用不改变它能访问的作用域
- 词法作用域由函数定义在源码中的位置决定，而不是由调用位置决定

## 五、闭包

- 闭包是函数与其声明时所在词法环境的组合，内部函数因此可以访问外层函数的变量
- 闭包在函数被创建时就生成；即使外层函数执行完毕，其词法环境仍被内部函数引用而保留
- 多个闭包可以共享同一个词法环境；用 var 在循环中创建的回调会共享同一个循环变量，回调执行时读到的是最后一轮的值，改用 let/const 可让每次迭代形成独立绑定
- 闭包常用于数据隐藏和封装，外部只能通过返回的函数读写内部变量
- 不必要的闭包会占用内存，实例方法应挂到原型上，而不是在构造函数里为每个实例重复创建

```js
function makeAdder(x) {
  return function (y) {
    return x + y;
  };
}
const add5 = makeAdder(5);
add5(3); // 8
```

## 六、执行上下文与变量对象

- 一段可执行代码（全局代码、函数代码）执行前会创建对应的执行上下文，上下文包含变量对象、this、作用域链
- 全局代码的变量对象是 GO（全局对象），函数代码的变量对象是 AO（活动对象）
- 函数被调用时创建函数执行上下文，调用结束后上下文出栈；闭包引用的词法环境使外层变量对象不被回收
- 形参先作为 AO 属性置为 undefined，再用实参值统一；函数声明在形参实参统一之后整体写入 AO
- 每次函数调用生成独立的 AO，互不干扰

## 七、提升中的常见现象

- 同名函数声明会覆盖先提升的同名变量或形参；var 重复声明不覆盖已有函数值
- 函数表达式赋值前引用得到 undefined，把它当函数调用会抛 TypeError
- 条件分支内的函数声明行为在不同历史环境中不一致，现代代码中条件内优先用函数表达式或箭头函数

```js
var x = 1;
function fn() {
  console.log(x);
  var x = 2;
}
fn(); // undefined
```

- 这个例子里函数内的 var x 提升到函数顶部，遮蔽外层全局 x，赋值前读取为 undefined
- 作用域链上的解析结果由声明位置决定，与函数在何处调用无关
