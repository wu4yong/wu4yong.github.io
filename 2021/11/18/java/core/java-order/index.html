    Java 排序算法

    📅 2021-11-18

    十大排序算法：从平方级的暴力，到线性级的巧劲

    Java排序算法 从 O(n²) 到 O(n)

    1. 先建立坐标系

    排序算法看起来只是「把数组排好」，但面试和工程里真正被问的，永远是那四件事：平均/最好/最坏时间复杂度、空间复杂度、稳定性、适用场景。先把坐标系立起来，后面十个算法才不是散落的技巧，而是同一条坐标轴上的点。

    1.1 三种复杂度

    • 平均复杂度：随机数据下的期望表现，工程里最常被引用
    • 最坏复杂度：最恶劣输入下的上界，决定会不会被打爆（快排的 O(n²) 就是这么来的）
    • 空间复杂度：额外内存，归并要开 O(n) 的临时数组，快排靠递归栈 O(log n)

    1.2 稳定性到底影响什么

    • 稳定排序：值相等的元素，排序后相对顺序不变
    • 不稳定排序：同值元素的相对顺序可能被打乱

    稳定性的价值只有一句话：多字段排序时，第二次排序不会推翻第一次的结果。

    以扑克牌为例，先按花色排（♠♥♣♦），再按数字排（A K Q J …）：

    System.out.println("=================不稳定================");
Card[] cards = getStaticCards();
System.out.println(Arrays.toString(cards));
selection(cards, Comparator.comparingInt((Card a) -> a.sharpOrder).reversed());
System.out.println(Arrays.toString(cards));
selection(cards, Comparator.comparingInt((Card a) -> a.numberOrder).reversed());
System.out.println(Arrays.toString(cards));

System.out.println("=================稳定=================");
cards = getStaticCards();
System.out.println(Arrays.toString(cards));
bubble(cards, Comparator.comparingInt((Card a) -> a.sharpOrder).reversed());
System.out.println(Arrays.toString(cards));
bubble(cards, Comparator.comparingInt((Card a) -> a.numberOrder).reversed());
System.out.println(Arrays.toString(cards));

    • 不稳定排序按数字排序时，会打乱原本同值的花色顺序

      [[♠7], [♠2], [♠4], [♠5], [♥2], [♥5]]
[[♠7], [♠5], [♥5], [♠4], [♥2], [♠2]]

      原来 ♠2 在前 ♥2 在后，按数字再排后，它俩的位置变了

    • 稳定排序按数字排序时，会保留原本同值的花色顺序，♠2 与 ♥2 的相对位置不变

      [[♠7], [♠2], [♠4], [♠5], [♥2], [♥5]]
[[♠7], [♠5], [♥5], [♠4], [♠2], [♥2]]

    1.3 十种排序总表

    算法 平均 最好 最坏 空间 稳定性
    冒泡排序 O(n²) O(n) O(n²) O(1) 稳定
    选择排序 O(n²) O(n²) O(n²) O(1) 不稳定
    插入排序 O(n²) O(n) O(n²) O(1) 稳定
    希尔排序 O(n^1.3) O(n) O(n²) O(1) 不稳定
    归并排序 O(n log n) O(n log n) O(n log n) O(n) 稳定
    快速排序 O(n log n) O(n log n) O(n²) O(log n) 不稳定
    堆排序 O(n log n) O(n log n) O(n log n) O(1) 不稳定
    计数排序 O(n+k) O(n+k) O(n+k) O(k) 稳定
    基数排序 O(d(n+k)) O(d(n+k)) O(d(n+k)) O(n+k) 稳定
    桶排序 O(n+k) O(n) O(n²) O(n+k) 稳定

    k 为数据范围（或桶数），d 为最大值的位数。

    一条记忆线：前五个是「比较 + 交换/搬移」的平方级思路，希尔把它加速；归并和堆把复杂度压到 n log n；最后三个干脆绕开比较，用「值域」换时间。

    2. 冒泡排序

    要求

    • 能够用自己语言描述冒泡排序算法
    • 能够手写冒泡排序代码
    • 了解一些冒泡排序的优化手段

    算法描述

    1. 依次比较数组中相邻两个元素大小，若 a[j] > a[j+1]，则交换两个元素，两两都比较一遍称为一轮冒泡，结果是让最大的元素排至最后
    2. 重复以上步骤，直到整个数组有序

    算法实现

    public static void bubble(int[] a) {
    for (int j = 0; j < a.length - 1; j++) {
        // 一轮冒泡
        boolean swapped = false; // 这一轮是否发生过交换
        for (int i = 0; i < a.length - 1 - j; i++) {
            if (a[i] > a[i + 1]) {
                swap(a, i, i + 1);
                swapped = true;
            }
        }
        System.out.println("第" + j + "轮冒泡" + Arrays.toString(a));
        if (!swapped) {
            break;
        }
    }
}
    • 优化点1：每经过一轮冒泡，内层循环就可以减少一次
    • 优化点2：如果某一轮冒泡没有发生交换，则表示所有数据有序，可以结束外层循环

    进一步优化：记录最后一次交换的位置

    public static void bubbleV2(int[] a) {
    int n = a.length - 1;
    while (true) {
        int last = 0; // 本轮最后一次交换的索引
        for (int i = 0; i < n; i++) {
            if (a[i] > a[i + 1]) {
                swap(a, i, i + 1);
                last = i;
            }
        }
        n = last; // 后面的元素已经有序，下一轮只比较到这里
        System.out.println(Arrays.toString(a));
        if (n == 0) {
            break;
        }
    }
}
    • 每轮冒泡时，最后一次交换索引可以作为下一轮冒泡的比较边界，如果这个值为零，表示整个数组有序，直接退出外层循环即可

    复杂度与特点

    • 平均/最坏 O(n²)，最好 O(n)（数组已有序 + 加了 swapped 判断）
    • 空间 O(1)，稳定
    • 交换次数多，实际性能最差，只在教学和「短数组」里出现

    3. 选择排序

    要求

    • 能够用自己语言描述选择排序算法
    • 能够比较选择排序与冒泡排序
    • 理解非稳定排序与稳定排序

    算法描述

    1. 将数组分为两个子集，排序的和未排序的，每一轮从未排序的子集中选出最小的元素，放入排序子集
    2. 重复以上步骤，直到整个数组有序

    算法实现

    public static void selection(int[] a) {
    for (int i = 0; i < a.length - 1; i++) {
        // i 代表每轮选择最小元素要交换到的目标索引
        int s = i; // 代表最小元素的索引
        for (int j = s + 1; j < a.length; j++) {
            if (a[s] > a[j]) { // j 元素比 s 元素还要小, 更新 s
                s = j;
            }
        }
        if (s != i) {
            swap(a, s, i);
        }
        System.out.println(Arrays.toString(a));
    }
}
    • 优化点：为减少交换次数，每一轮先找最小的索引，在每轮最后再交换元素（一轮最多交换一次）

    与冒泡排序比较

    1. 二者平均时间复杂度都是 O(n²)
    2. 选择排序一般要快于冒泡，因为其交换次数少
    3. 但如果集合有序度高，冒泡优于选择
    4. 冒泡属于稳定排序算法，而选择属于不稳定排序

    为什么先找索引再交换还不够稳

    选择排序的一轮交换，是拿「当前位」和「最小值位」直接换。假如最小值位与当前位之间，还存在与当前位相等的元素，那么当前位那个元素会被甩到后面去，稳定性就断在这里了。

    // 5, 5, 2  ->  第一轮：最小是 2，与第一个 5 交换
// 结果 2, 5, 5 看起来没事
// 5(a), 5(b), 2, 5(c) -> 换完是 2, 5(b), 5(a), 5(c)
// 两个 5 的相对顺序变了，这就是不稳定

    4. 插入排序

    要求

    • 能够用自己语言描述插入排序算法
    • 能够比较插入排序与选择排序

    算法描述

    1. 将数组分为两个区域，排序区域和未排序区域，每一轮从未排序区域中取出第一个元素，插入到排序区域（需保证顺序）
    2. 重复以上步骤，直到整个数组有序

    算法实现

    public static void insert(int[] a) {
    // i 代表待插入元素的索引
    for (int i = 1; i < a.length; i++) {
        int t = a[i]; // 代表待插入的元素值
        int j = i;
        while (j >= 1) {
            if (t < a[j - 1]) { // j-1 是上一个元素索引，如果 > t，后移
                a[j] = a[j - 1];
                j--;
            } else { // 如果 j-1 已经 <= t, 则 j 就是插入位置
                break;
            }
        }
        a[j] = t;
        System.out.println(Arrays.toString(a) + " " + j);
    }
}

    注意这里的写法是「先挪位、后落子」，不是「边比较边交换」。移动比交换便宜一半，这也是插入排序在短数组上最快的原因。

    与选择排序比较

    1. 二者平均时间复杂度都是 O(n²)
    2. 大部分情况下，插入都略优于选择
    3. 有序集合插入的时间复杂度为 O(n)
    4. 插入属于稳定排序算法，而选择属于不稳定排序

    进阶：二分插入

    public static void binaryInsert(int[] a) {
    for (int i = 1; i < a.length; i++) {
        int t = a[i];
        // 在 [0, i) 这段有序区间里找插入点，找第一个 >= t 的位置
        int l = 0, r = i - 1;
        while (l <= r) {
            int m = l + (r - l) / 2;
            if (a[m] <= t) l = m + 1;
            else r = m - 1;
        }
        // 这里必须用 <= 比较，否则两个相等元素的相对顺序会被打乱
        System.arraycopy(a, l, a, l + 1, i - l);
        a[l] = t;
    }
}
    • 比较次数从 O(n) 降到 O(log n)，但搬移还是 O(n)，总复杂度仍 O(n²)
    • 搬移是连续的，靠 CPU 缓存帮忙，实际小数组上收益明显

    提示

    插入排序通常被同学们所轻视，其实它的地位非常重要。小数据量排序，都会优先选择插入排序，JDK 的 Arrays.sort 在长度小于阈值时也是切到插入排序

    5. 希尔排序

    要求

    • 能够用自己语言描述希尔排序算法

    算法描述

    1. 首先选取一个间隙序列，如 (n/2, n/4 … 1)，n 为数组长度
    2. 每一轮将间隙相等的元素视为一组，对组内元素进行插入排序，目的有二
      1. 少量元素插入排序速度很快
      2. 让组内值较大的元素更快地移动到后方
    3. 当间隙逐渐减少，直至为 1 时，即可完成排序

    算法实现

    private static void shell(int[] a) {
    int n = a.length;
    for (int gap = n / 2; gap > 0; gap /= 2) {
        // i 代表待插入元素的索引
        for (int i = gap; i < n; i++) {
            int t = a[i]; // 代表待插入的元素值
            int j = i;
            while (j >= gap) {
                // 每次与上一个间隙为 gap 的元素进行插入排序
                if (t < a[j - gap]) { // j-gap 是上一个元素索引，如果 > t，后移
                    a[j] = a[j - gap];
                    j -= gap;
                } else { // 如果 j-gap 已经 <= t, 则 j 就是插入位置
                    break;
                }
            }
            a[j] = t;
            System.out.println(Arrays.toString(a) + " gap:" + gap);
        }
    }
}

    要点

    • gap 序列是希尔排序的灵魂。n/2, n/4 … 1 是最朴素的一版，最坏仍是 O(n²)
    • 换成 Knuth 序列 (1, 4, 13, 40, 121 …)（即 h = 3h + 1）实测更快，最坏可压到 O(n^1.5)
    • 希尔排序是不稳定的：同一组内的跳跃式插入会跨过分组边界，同值元素相对顺序不保证

    参考资料

    • Shellsort 的 gap 序列与复杂度证明，可查阅维基百科 Shellsort 词条

    6. 归并排序

    要求

    • 能够用自己语言描述归并排序算法
    • 掌握递归与非递归两种写法
    • 理解它为什么是稳定的，为什么是 O(n log n)

    算法描述

    1. 把数组从中间切成两半，左右两半各自排好序（递归）
    2. 把两个有序数组合并成一个有序数组（merge）
    3. 只剩一个元素时天然有序，递归到底

    这就是「分而治之」最标准的样子：分是把问题对半砍，治是合并两个有序序列。

    算法实现（递归 + 临时数组）

    public static void mergeSort(int[] a) {
    int[] temp = new int[a.length]; // 只用一次，不用每次递归都 new
    mergeSort(a, 0, a.length - 1, temp);
}

private static void mergeSort(int[] a, int l, int r, int[] temp) {
    if (l >= r) {
        return;
    }
    int m = l + (r - l) / 2;
    mergeSort(a, l, m, temp);
    mergeSort(a, m + 1, r, temp);
    merge(a, l, m, r, temp);
}

private static void merge(int[] a, int l, int m, int r, int[] temp) {
    int i = l, j = m + 1, k = l;
    while (i <= m && j <= r) {
        // 这里的 <= 是稳定性的关键：左边相等时优先取左边
        temp[k++] = a[i] <= a[j] ? a[i++] : a[j++];
    }
    while (i <= m) temp[k++] = a[i++];
    while (j <= r) temp[k++] = a[j++];
    System.arraycopy(temp, l, a, l, r - l + 1);
}

    算法实现（非递归，自底向上）

    public static void mergeSortIter(int[] a) {
    int n = a.length;
    int[] temp = new int[n];
    for (int width = 1; width < n; width *= 2) {
        for (int l = 0; l < n; l += 2 * width) {
            int m = Math.min(l + width - 1, n - 1);
            int r = Math.min(l + 2 * width - 1, n - 1);
            if (m < r) {
                merge(a, l, m, r, temp);
            }
        }
    }
}
    • 非递归版没有递归栈开销，适合内存紧张或对栈深度敏感的场景

    复杂度与特点

    • 最好/平均/最坏都是 O(n log n)，是「稳定且最坏有保证」的少数派
    • 递推式写出来只有一行，却决定了两个算法的分野：

    T(n)=2T(n/2)+O(n)⇒T(n)=O(nlog⁡n)T(n) = 2T(n/2) + O(n) \Rightarrow T(n) = O(n\log n)T(n)=2T(n/2)+O(n)⇒T(n)=O(nlogn)

    • 空间 O(n)，这是它唯一的代价
    • 稳定，前提是 merge 里相等时先取左边
    • 外部排序（大文件排序）几乎只用归并：天然适合分块 + 多路合并

    工程优化点

    • 小数组（如长度 < 16）切换成插入排序，减少递归开销
    • 先判断 a[m] <= a[m+1]，若已经有序直接跳过 merge（对近似有序数据提速很大）
    • 这两个优化加上 run 检测，就是 TimSort 的雏形

    7. 快速排序

    要求

    • 能够用自己语言描述快速排序算法
    • 掌握手写单边循环、双边循环代码之一
    • 能够说明快排特点
    • 了解洛穆托与霍尔两种分区方案的性能比较

    算法描述

    1. 每一轮排序选择一个基准点（pivot）进行分区
      1. 让小于基准点的元素进入一个分区，大于基准点的元素进入另一个分区
      2. 当分区完成时，基准点元素的位置就是其最终位置
    2. 在子分区内重复以上过程，直至子分区元素个数少于等于 1，这体现的是分而治之的思想
    3. 关键在于分区算法，常见的有洛穆托分区方案、双边循环分区方案、霍尔分区方案

    单边循环快排（Lomuto 洛穆托分区方案）

    1. 选择最右元素作为基准点元素
    2. j 指针负责找到比基准点小的元素，一旦找到则与 i 进行交换
    3. i 指针维护小于基准点元素的边界，也是每次交换的目标索引
    4. 最后基准点与 i 交换，i 即为分区位置
    public static void quick(int[] a, int l, int h) {
    if (l >= h) {
        return;
    }
    int p = partition(a, l, h); // p 索引值
    quick(a, l, p - 1); // 左边分区的范围确定
    quick(a, p + 1, h); // 右边分区的范围确定
}

private static int partition(int[] a, int l, int h) {
    int pv = a[h]; // 基准点元素
    int i = l;
    for (int j = l; j < h; j++) {
        if (a[j] < pv) {
            if (i != j) {
                swap(a, i, j);
            }
            i++;
        }
    }
    if (i != h) {
        swap(a, h, i);
    }
    System.out.println(Arrays.toString(a) + " i=" + i);
    // 返回值代表基准点元素所在的正确索引，用它确定下一轮分区的边界
    return i;
}

    双边循环快排（不完全等价于 Hoare 霍尔分区方案）

    1. 选择最左元素作为基准点元素
    2. j 指针负责从右向左找比基准点小的元素，i 指针负责从左向右找比基准点大的元素，一旦找到二者交换，直至 i、j 相交
    3. 最后基准点与 i（此时 i 与 j 相等）交换，i 即为分区位置

    要点：

    1. 基准点在左边，并且要先 j 后 i
    2. while (i < j && a[j] > pv) j--
    3. while (i < j && a[i] <= pv) i++
    public static void quick2(int[] a, int l, int h) {
    if (l >= h) {
        return;
    }
    int p = partition2(a, l, h);
    quick2(a, l, p - 1);
    quick2(a, p + 1, h);
}

private static int partition2(int[] a, int l, int h) {
    int pv = a[l];
    int i = l;
    int j = h;
    while (i < j) {
        // j 从右找小的
        while (i < j && a[j] > pv) {
            j--;
        }
        // i 从左找大的
        while (i < j && a[i] <= pv) {
            i++;
        }
        swap(a, i, j);
    }
    swap(a, l, j);
    System.out.println(Arrays.toString(a) + " j=" + j);
    return j;
}

    三路分区（大量重复元素时才见真章）

    public static void quick3(int[] a, int l, int h) {
    if (l >= h) {
        return;
    }
    int pv = a[l];
    int lt = l, gt = h, i = l + 1; // [l, lt) < pv, [gt, h] > pv
    while (i <= gt) {
        if (a[i] < pv) {
            swap(a, lt++, i++);
        } else if (a[i] > pv) {
            swap(a, i, gt--);
        } else {
            i++;
        }
    }
    quick3(a, l, lt - 1);
    quick3(a, gt + 1, h);
}
    • 与基准相等的元素一次性归位，不再参与递归，重复率高的数组能少掉大量无谓比较

    快排特点

    1. 平均时间复杂度是 O(n log n)，最坏时间复杂度 O(n²)
    2. 数据量较大时，优势非常明显
    3. 属于不稳定排序
    4. 空间开销来自递归栈，平均 O(log n)，最坏 O(n)

    最坏情况是怎么出现的

    • 固定取最右/最左为基准 + 数组本身有序（或逆序），每次分区都退化成「一边零个、一边 n-1 个」
    • 递归深度达到 n，既慢又会栈溢出
    • 治法：随机基准、三数取中、小区间切插入排序、尾递归优化（只递归较短一侧）
    // 随机基准，把最右位置和一个随机位置的元素先换一下即可
int r = l + (int) (Math.random() * (h - l + 1));
swap(a, r, h);

    洛穆托分区方案 vs 霍尔分区方案

    • 霍尔的移动次数平均来讲比洛穆托少 3 倍
    • 洛穆托对「已有序」和「大量重复」的数据更敏感，性能衰减明显
    • JDK 里的双轴快排（DualPivotQuicksort）本质上是双基准的双边分区，比单基准更快

    补充代码说明

    • day01.sort.QuickSort3 演示了空穴法改进的双边快排，比较次数更少
    • day01.sort.QuickSortHoare 演示了霍尔分区的实现
    • day01.sort.LomutoVsHoare 对四种分区实现的移动次数进行比较

    8. 堆排序

    要求

    • 能够用自己语言描述堆排序算法
    • 掌握建堆与下沉两个动作
    • 理解为什么它是原地且 O(n log n) 的

    算法描述

    1. 把数组看成一棵完全二叉树（下标 i 的孩子是 2i+1、2i+2）
    2. 从最后一个非叶子节点开始，逐个向下调整（下沉），建成大顶堆——这一步是 O(n)，不是 O(n log n)
    3. 每次把堆顶（当前最大值）与末尾交换，堆范围减一，再对新堆顶下沉，重复到堆只剩一个元素

    算法实现

    public static void heapSort(int[] a) {
    int n = a.length;
    // 1. 建大顶堆
    for (int i = n / 2 - 1; i >= 0; i--) {
        siftDown(a, i, n);
    }
    // 2. 依次把堆顶换到末尾
    for (int end = n - 1; end > 0; end--) {
        swap(a, 0, end);
        siftDown(a, 0, end);
    }
}

private static void siftDown(int[] a, int k, int size) {
    while (true) {
        int l = 2 * k + 1;
        if (l >= size) {
            break;
        }
        int big = (l + 1 < size && a[l + 1] > a[l]) ? l + 1 : l;
        if (a[big] <= a[k]) {
            break;
        }
        swap(a, k, big);
        k = big;
    }
}

    复杂度与特点

    • 最好/平均/最坏都是 O(n log n)，没有最坏退化问题
    • 空间 O(1)，原地排序
    • 不稳定
    • 缓存不友好：父子节点下标跳跃，访问不连续，实测通常比快排慢 2~3 倍

    典型用途

    • 优先队列、定时任务调度（PriorityQueue、DelayQueue 底层都是堆）
    • TopK 问题：求最大 K 个用小顶堆，堆大小固定为 K，时间 O(n log k)
    // 求数组中最大的 3 个元素
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
for (int v : a) {
    minHeap.offer(v);
    if (minHeap.size() > 3) {
        minHeap.poll();
    }
}

    9. 非比较排序：计数、基数、桶

    这三个的共同点：不看元素之间谁大谁小，而是利用值的范围做「落桶」。代价是必须知道值域，且只适合整数（或其他可映射成整数的键）。

    9.1 计数排序

    算法描述

    1. 找出最小值 min 与最大值 max，开一个长度 max - min + 1 的计数数组
    2. 每个元素在对应下标上 +1
    3. 从小到大把计数数组「倒出来」，写回原数组
    public static void counting(int[] a) {
    if (a.length == 0) {
        return;
    }
    int min = a[0], max = a[0];
    for (int v : a) {
        min = Math.min(min, v);
        max = Math.max(max, v);
    }
    int[] count = new int[max - min + 1];
    for (int v : a) {
        count[v - min]++;
    }
    int k = 0;
    for (int v = min; v <= max; v++) {
        while (count[v - min]-- > 0) {
            a[k++] = v;
        }
    }
}
    • 时间 O(n+k)，空间 O(k)，k 是值域大小
    • 稳定（按计数数组顺序写出，同值顺序不变；若要严格稳定，需要用前缀和 + 从后往前填）
    • 致命限制：值域一大（比如 1 和 1 亿），内存直接爆掉

    9.2 基数排序

    算法描述

    1. 按「个位 → 十位 → 百位 …」逐位做一次计数排序（LSD，从低位到高位）
    2. 每一轮分配 10 个桶（0~9），桶内必须先进先出，否则低位排好的顺序会被打乱
    3. 位数跑完，整体有序
    public static void radix(int[] a) {
    int max = 0;
    for (int v : a) {
        max = Math.max(max, v);
    }
    int[] temp = new int[a.length];
    for (int exp = 1; max / exp > 0; exp *= 10) {
        int[] count = new int[10];
        for (int v : a) {
            count[(v / exp) % 10]++;
        }
        for (int i = 1; i < 10; i++) {
            count[i] += count[i - 1]; // 前缀和，得到每个桶的右边界
        }
        // 从后往前填，保证同一轮内先进先出（稳定）
        for (int i = a.length - 1; i >= 0; i--) {
            int d = (a[i] / exp) % 10;
            temp[--count[d]] = a[i];
        }
        System.arraycopy(temp, 0, a, 0, a.length);
    }
}
    • 时间 O(d(n+k))，d 为位数，k 为进制（10）
    • 空间 O(n+k)，稳定
    • 适合定长数字（手机号、身份证、时间戳），不适合负数与浮点（需先做偏移或拆分）

    9.3 桶排序

    算法描述

    1. 把值域均分成若干桶，元素按区间落桶
    2. 每个桶内部单独排序（通常用插入排序或 Collections.sort）
    3. 按桶的顺序把结果拼回去
    public static void bucket(int[] a) {
    if (a.length == 0) {
        return;
    }
    int min = a[0], max = a[0];
    for (int v : a) {
        min = Math.min(min, v);
        max = Math.max(max, v);
    }
    int bucketCount = Math.max(1, (int) Math.sqrt(a.length));
    int width = (max - min) / bucketCount + 1;
    List<List<Integer>> buckets = new ArrayList<>(bucketCount);
    for (int i = 0; i < bucketCount; i++) {
        buckets.add(new ArrayList<>());
    }
    for (int v : a) {
        buckets.get((v - min) / width).add(v);
    }
    int k = 0;
    for (List<Integer> b : buckets) {
        Collections.sort(b); // 桶内用稳定排序，整体才稳定
        for (int v : b) {
            a[k++] = v;
        }
    }
}
    • 平均 O(n+k)，最坏 O(n²)（数据全挤进一个桶，退化成桶内排序）
    • 空间 O(n+k)
    • 稳定性取决于桶内排序算法，用 Collections.sort（TimSort）时是稳定的

    10. 工程实践：Arrays.sort 到底怎么选

    面试里最高频的追问是「JDK 里为什么不用快排排对象？」。答案是稳定性。

    基本类型数组：Arrays.sort(int[])

    • 底层是 DualPivotQuicksort（双轴快排），不稳定
    • 长度小于阈值（各版本约 47）直接切插入排序
    • 有 run 检测：连续升序/降序的片段会被识别，减少无谓分区

    对象数组：Arrays.sort(Object[])

    • 底层是 TimSort（归并 + 插入的混合），稳定
    • 最坏 O(n log n)，但需要额外空间（约 n/2）
    • 业务里多字段排序（先按年龄、再按姓名）必须靠它保住前一次的顺序

    其它入口

    • Collections.sort(list) → list.sort(null) → TimSort
    • list.sort(comparator) 同样走 TimSort
    • Arrays.parallelSort → 并行归并（ForkJoin），数据量大时能吃满多核

    一张选择表

    场景 用什么 原因
    短数组（< 50） 插入排序 常数小，无递归
    基本类型、追求速度 双轴快排 原地、缓存友好
    对象、需要稳定 TimSort / 归并 稳定性 + 最坏保证
    大量重复元素 三路快排 相等元素一次归位
    值域很小的整数 计数排序 O(n)
    定长数字串 基数排序 与 n 无关，只与位数有关
    内存极紧 堆排序 原地且最坏 O(n log n)

    11. 常见坑

    • 交换写成两句赋值：a[i] = a[j]; a[j] = a[i]; 中间不留临时变量，结果两个位置变成同一个值
    • 用异或交换又碰上 i == j：a[i] ^= a[j]; a[j] ^= a[i]; a[i] ^= a[j]; 当 i 与 j 相等时会把元素清零
    • 快排双边循环先动 i：基准在左侧时必须先让 j 走，否则 i 会停在比基准大的位置上，最后交换直接破坏分区
    • 快排固定基准 + 有序输入：直接退化成 O(n²)，甚至 StackOverflowError；生产代码要随机化或三数取中
    • 递归没写终止条件边界：l >= h 写成 l > h 会在单元素区间继续递归，栈直接崩
    • 归并 merge 里用了 < 而不是 <=：相等时先取右边，稳定性当场丢失
    • 归并每层都 new 临时数组：内存抖动严重，正确做法是最外层开一次，递归复用
    • 堆排下沉边界写成 2*k < size：漏掉右孩子，或者 l >= size 没 break，下标越界
    • 计数排序遇到负数或大值域：负下标直接抛 ArrayIndexOutOfBoundsException，值域大则 OOM
    • 基数排序桶内没做先进先出：低位已经排好的相对顺序被打乱，结果看着「差一点但就是不对」
    • 以为 Arrays.sort 一定稳定：对基本类型不稳定，跨类型混用会踩到「排序后同值顺序变了」
    • Comparator 不满足传递性：a>b, b>c, 但 c>a，TimSort 会抛 IllegalArgumentException: Comparison method violates its general contract!

    12. 附：二分查找

    排序之后最自然的动作是查找。二分查找的代码只有十行，但边界写错的方式有十种。

    算法描述

    1. 前提：有已排序数组 A
    2. 定义左边界 L、右边界 R，确定搜索范围，循环执行二分查找
    3. 获取中间索引 M = Floor((L+R)/2)
    4. 中间索引的值 A[M] 与待搜索的值 T 比较
      1. A[M] == T 表示找到，返回中间索引
      2. A[M] > T，中间值右侧的元素都大于 T，去左边找，M - 1 设为右边界
      3. A[M] < T，中间值左侧的元素都小于 T，去右边找，M + 1 设为左边界
    5. 当 L > R 时，表示没有找到，结束循环

    算法实现

    public static int binarySearch(int[] a, int t) {
    int l = 0, r = a.length - 1, m;
    while (l <= r) {
        m = (l + r) / 2;
        if (a[m] == t) {
            return m;
        } else if (a[m] > t) {
            r = m - 1;
        } else {
            l = m + 1;
        }
    }
    return -1;
}

    测试代码

    public static void main(String[] args) {
    int[] array = {1, 5, 8, 11, 19, 22, 31, 35, 40, 45, 48, 49, 50};
    int target = 47;
    int idx = binarySearch(array, target);
    System.out.println(idx); // -1
}

    解决整数溢出问题

    当 l 和 r 都较大时，l + r 有可能超过整数范围，造成运算错误，解决方法有两种：

    int m = l + (r - l) / 2;

    还有一种是：

    int m = (l + r) >>> 1;

    1. 有一个有序表为 1,5,8,11,19,22,31,35,40,45,48,49,50，当二分查找值为 48 的结点时，查找成功需要比较的次数
    2. 使用二分法在序列 1,4,6,7,15,33,39,50,64,78,75,81,89,96 中查找元素 81 时，需要经过（ ）次比较
    3. 在拥有 128 个元素的数组中二分查找一个数，需要比较的次数最多不超过多少次
