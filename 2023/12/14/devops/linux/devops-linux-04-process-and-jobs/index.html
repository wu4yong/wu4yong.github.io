    DevOps Linux 进程与作业管理

    📅 2023-12-14

    进程与作业管理

    服务的本质是一个进程。进程在哪、谁起的、吃了多少 CPU、被谁杀了——这四个问题回答了，线上八成的”服务挂了”就能定性。

    前台、后台与作业队列的挂起和恢复

    4.1 通俗小故事：后厨

    进程是一家后厨的厨师。
    ● 每个厨师有工号（PID），干完活下班（退出），留下状态给前台 (exit code)
    ● 厨师长（父进程）安排工作，儿子干完要回报；厨师长走得急，儿子会被托付给店长（PID 1 / systemd）
    ● 有人堵在门口不干活（D 状态），后面全排队
    ● kill 不是”杀”，是”发通知”，通知内容由信号决定

    懂了”父子、状态、信号”这三件事，ps 的输出就不再是乱码。

    4.2 看进程

    ps aux | head                    # BSD 风格：CPU、内存、启动时间、完整命令
ps -ef                           # System V 风格：PPID 列最有用
ps aux --sort=-%cpu | head -5    # CPU 前五
ps aux --sort=-%mem | head -5    # 内存前五
ps -ef | grep java               # 找 java
pgrep -af java                   # 直接按名字找，不用 grep 自己
pstree -p 1234                   # 进程树，看清谁是谁儿子

    状态码速记：
    ● R 运行中、S 可中断睡眠（最常见）、D 不可中断睡眠（多在等 IO，杀不掉）
    ● Z 僵尸（已退出但父进程没回收）、T 暂停

    4.3 top 与实时观察

    top                              # 默认按 CPU 排序，Shift+P/M 切排序
top -H -p 1234                   # 看某个进程内的线程
htop                             # 有颜色、可翻页、能直接杀（需安装）

    top 上先看三个数：load average（1/5/15 分钟负载）、%wa（IO 等待）、MiB Mem 的 available。负载高但 CPU 闲，通常是 IO 或 D 状态进程堵住了。

    4.4 信号与 kill

    kill -l                          # 列出信号
kill 1234                        # 默认 TERM(15)：请体面退出
kill -9 1234                     # KILL：内核直接收走，不给收尾机会
kill -HUP 1234                   # 重读配置（很多守护进程支持）
pkill -f "java -jar app.jar"     # 按命令行匹配杀
killall nginx

    -9 是最后手段：它不让进程释放连接、不刷盘、不删临时文件，可能留下脏锁和半截文件。先 -15，等几秒，再考虑 -9。

    4.5 前后台与长任务

    long_task &                      # 放后台
jobs -l                          # 看当前 shell 的作业
fg %1                            # 调回前台
bg %1                            # 继续在后台跑
nohup ./start.sh > app.out 2>&1 &   # 断开 SSH 也不死
setsid ./start.sh                # 新会话，彻底脱离终端
disown -h %1                     # 让作业不随 shell 退出收到 HUP

    SSH 里直接跑长任务，一断线就收到 SIGHUP 挂掉。要么 nohup/setsid，要么用 systemd-run 或 tmux：

    tmux new -s deploy               # 断线重连 tmux attach -t deploy
systemd-run --unit=backfill --scope ./backfill.sh   # 交给 systemd 托管

    4.6 优先级

    nice -n 10 ./batch.sh            # 启动时降优先级（-20 最高，19 最低）
renice -n 5 -p 1234              # 运行中调整
ionice -c3 -p 1234               # IO 优先级（c3 = idle）

    备份、批量计算这类任务给低优先级，能避免它把数据库的 IO 抢干。

    4.7 让进程活下去：交给 systemd

    手敲 nohup 是临时方案。生产服务应写成 unit：

    # /etc/systemd/system/app.service
[Unit]
Description=App
After=network.target

[Service]
User=app
WorkingDirectory=/data/app/current
ExecStart=/usr/bin/java -jar app.jar
Restart=always
RestartSec=5
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
    systemctl daemon-reload
systemctl enable --now app
systemctl status app

    Restart=always + LimitNOFILE 这两行，能挡掉”进程莫名退出”和”连接数打满”一半的问题。

    4.8 清单

    1. 先 ps -ef 看父子关系，再 top -H -p 看线程
    2. 杀进程优先 -15，-9 只作最后手段
    3. 长任务不裸跑，用 nohup / tmux / systemd-run
    4. 生产服务交给 systemd，配 Restart 与 LimitNOFILE
    5. 负载高但 CPU 闲，去查 D 状态与 IO 等待
